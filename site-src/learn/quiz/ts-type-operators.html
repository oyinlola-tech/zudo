const ZONES = ["lagos", "abuja"] as const; is followed by type Zone = ZONES;. What does the compiler say, and why?

Values and types live in separate spaces. typeof in a type position is the bridge from a value's name to its type. (typeof ZONES)[number] then gives "lagos" | "abuja".

 After let currency = "NGN";, what is typeof currency in a type position?

A type query returns the declared type, and a let initialized with a string widens to string because it may be reassigned. With const it would be the literal "NGN". (The string "string" is what the JavaScript typeof operator returns at runtime.)

 What is typeof shop for const shop = { city: "Lagos", rating: 4.8 };?

The variable is const, but its properties can still be changed, so they are widened. as const would keep the literals and make the properties readonly.

 For class Invoice { static prefix = "INV"; … }, which type describes the class itself (the thing you call new on)?

In a type position, the class name means the instance type. typeof Invoice is the constructor type, with its static members such as prefix. InstanceType<typeof Invoice> goes back to Invoice.

 Why is type Shop = typeof loadShop(); a syntax error, and what do you write instead?

Types describe code; they never evaluate it. Take the function's type with typeof loadShop, then ask for the return type with the ReturnType utility.

 Card has keys kind, last4, amountKobo; Transfer has kind, bankCode, amountKobo. What is keyof (Card | Transfer)?

A value of a union type could be either member, so the only keys you can safely use are the ones both have. The union of values has the intersection of keys.

 Using the same Card and Transfer, what is keyof (Card & Transfer)?

An intersection has every property of both types, so its keys are all the keys of both. (The intersection itself is impossible to create here, because kind would have to be both "card" and "transfer", but keyof still lists the keys.)

 What is keyof { [reference: string]: Payment }?

JavaScript converts number keys to strings, so payments[42] works on an object with a string index signature. TypeScript therefore includes number in its keyof.

 Why does function label<T>(key: keyof T) { return `field ${key}`; } fail to compile?

Keys can be strings, numbers or symbols. keyof T & string keeps only the string keys; String(key) converts explicitly when symbols can really occur.

 With interface Order { id: string; total: number; status: "pending" | "paid" }, what is Order["total" | "status"]?

Indexing with a union of keys gives the union of the property types. To get an object with just those properties, you would use Pick<Order, "total" | "status">.

 What does Order["lines"][number] mean when lines is an array of line objects?

[number] asks "what do I get when I index this array with any number?": the element type. It is how you name OrderLine without writing its shape again.

 For type Row = [date: string, description: string, amountKobo: number], what are Row["length"] and Row[number]?

A tuple's length is a literal type, because its size is fixed. [number] is any position, so it is the union of all element types.

 interface Order { couponCode?: string }. What is Order["couponCode"]?

An optional property may be missing, and reading a missing property gives undefined, so the looked-up type includes it.

 Why does const STATUSES = ["pending", "paid"]; type Status = (typeof STATUSES)[number]; give string instead of "pending" | "paid"?

A mutable array widens its elements. as const makes it readonly ["pending", "paid"], and then [number] gives the union of the two literals.

 Why check a lookup table with as const satisfies Record<string, number> rather than annotating it : Record<string, number>?

A variable's type is what you declare. satisfies checks the value against a type without changing the value's inferred type, which is what you derive from. Neither checks anything at runtime.

 Why does Object.keys(stock) return string[] even when stock: Stock has only the keys rice and beans?

Structural typing lets { rice: 12, beans: 5, lastCountedBy: "Tunde" } be passed as a Stock. Object.keys would then also return "lastCountedBy". Loop over a known key list instead.

 Why is product[key] = value rejected with "not assignable to type never" when key: keyof Product and value: Product[keyof Product]?

Otherwise updateField(product, "priceKobo", "free") would pass. Reading through a union key gives a union; writing requires the intersection.

 Which signature lets product[key] = value compile while still rejecting updateField(p, "priceKobo", "free")?

A type parameter ties the value's type to the chosen key: each call picks one K, and the value must be Product[K]. The any version compiles but accepts nonsense.

 NEXT[from] has type readonly ["paid", "cancelled"] | readonly []. Why is NEXT[from].includes(to) an error?

Assign to a wider type first, which is safe without an assertion: const next: readonly Status[] = NEXT[from];, then next.includes(to).

 Why does isOrderStatus use Object.hasOwn(ORDER_FLOW, value) rather than value in ORDER_FLOW?

An object literal inherits from Object.prototype. A status coming from JSON could be "toString" or "constructor"; only own properties are real statuses.

 When is a plain written-out union like type Role = "customer" | "staff" a better choice than deriving it from an as const array?

Derive from a value when the program needs that value (a dropdown, validation, iteration). Otherwise the array is extra code, and the union alone is the simplest single source of truth.

In an expression, typeof is JavaScript's runtime operator and returns a string such as "object". The type query in type Shop = typeof shop is erased and prints nothing.
