A server sends a page's HTML once. How can JavaScript make a new task appear on that page without reloading it?

The browser parses the HTML once into the DOM and draws from that tree. Changing the tree changes the screen. The original HTML text is never read again.

childNodes includes the whitespace text nodes: one before the first li, one between them, one after the last. That is 3 text nodes plus 2 elements. children counts only elements.

 What happens when this runs on a page that has no element with the id total? document.querySelector("#total").textContent = "₦12,500";

querySelector returns null when nothing matches, and setting a property on null throws a TypeError. For elements the page needs, check for null and throw an error that names the selector.

 Which of these returns a live collection that changes when elements are added to or removed from the page?

getElementsByClassName and getElementsByTagName return live HTMLCollections. querySelectorAll returns a static snapshot, and copying any collection into an array also freezes it.

 The HTML is indented as usual (<ul>, a line break, then two spaces and the first <li>). Why does ul.firstChild.textContent not give the first task's title?

Line breaks and indentation between tags become text nodes. The …Element… properties (firstElementChild, nextElementSibling) skip them.

 A task title comes from a user. Which line puts it on the page safely?

textContent always treats the string as text. The other three parse it as HTML, so a title containing an element with an event-handler attribute runs the attacker's code: XSS.

 A colleague says: "innerHTML is safe for user text, because a <script> inserted with it never runs." What is wrong with that?

The lesson's example put <img src="data:," onerror="…"> in a title: the image failed to load and the onerror code ran. Attackers have many ways to run code without <script>.

 The HTML says <input name="title" value="Buy detergent">. The user types "Buy gloves". What do input.value and input.getAttribute("value") return?

The attribute is the default value from the HTML; the property is the current value. Typing changes only the property. Read user input from value.

 What does summary.setAttribute("hidden", "false") do?

Boolean attributes (hidden, disabled, checked) are on when present. To switch one off, set the property to false or call removeAttribute.

 A list has three tasks. What does list.append(list.firstElementChild) do?

A node can only be in one place. Inserting a node that is already in the tree moves it. Use cloneNode(true) when you want a copy.

 A row has data-id="2" and the tasks array has { id: 2, … }. Why does tasks.find((t) => t.id === row.dataset.id) return undefined?

Attribute values, and therefore dataset values, are always strings. Convert with Number(row.dataset.id) before comparing.

 What is a DocumentFragment good for?

A fragment is a container node that is not in the page. Appending it moves all of its children into the page at once: one change instead of one per item.

 Which statement about a <template> element is true?

template.content is a DocumentFragment outside the page. Clone it (cloneNode(true)) for each row and fill the data in with textContent.

 A plain <script> in the <head> runs document.querySelector("#tasks") and gets null, although #tasks is in the body. What is the best fix?

The browser runs a plain script as soon as it reaches it, before it has parsed the rest of the page. Deferred and module scripts run after parsing, in order.

 A form is inside main. The user has typed in its input. Then this runs: main.innerHTML += "<p>Draft saved</p>". What happens to the input?

+= reads the whole inside as a string, appends to it, and parses it again into new elements. The old ones, with everything that lived only on them, are thrown away.

 Why does the task list keep its tasks in an array and call render() after every change, instead of adding and counting <li> elements directly?

When the DOM is the data, each change must update every place that depends on it, and one forgotten place (like the summary) makes the page lie. Rendering from state makes the page a function of the data.

 What is the most useful thing a test of the task list checks?

Tests that read the page like a user survive refactoring. Tools like jsdom (a DOM in Node) and Testing Library (find by text and role) are built for exactly that.

 Which loop is likely to make the browser recalculate the layout many times? // A for (const row of rows) { row.style.height = row.offsetHeight + 10 + "px"; } // B const heights = rows.map((row) => row.offsetHeight); rows.forEach((row, i) => { row.style.height = heights[i] + 10 + "px"; });

Reading a layout property after a change forces the browser to calculate layout right then. Alternating reads and writes does that once per row (layout thrashing). Read everything first, then write everything, as in B.

 Why should a "Delete" action be a <button> rather than a <div> with a click listener?

Using the element that means what you want gives you keyboard support, focus and correct screen-reader behaviour. The lesson also gave each button an aria-label naming its task.

 A profile page shows a link to the user's website with a.setAttribute("href", user.website). What must you still check?

setAttribute does not parse HTML, so it is safe from tag injection, but some attributes run code by design. Parse the URL (new URL) and allow only the protocols you expect.

 Why does every element have an addEventListener method?

An <li> is an HTMLLIElement → HTMLElement → Element → Node → EventTarget. Methods live on those prototypes and are shared by every element.

 When would you use innerText instead of textContent?

innerText follows CSS, so it must ask for an up-to-date layout. textContent just returns all the text nodes' text, which is faster and what you want most of the time. Both are safe for setting text.
