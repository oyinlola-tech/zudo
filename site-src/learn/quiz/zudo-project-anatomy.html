Which file does npm run dev start, and which one does npm start run?

The dev script is tsx watch src/server.ts and start is node dist/server.js. src/index.ts only exports createApp for tests and tools.

 Why does src/server.ts call await runtime.start() before server.start()?

Opening the port last means no request arrives while dependencies are still connecting. The same rule as module dependencies, one level up.

 The environment has PORT=80a. What happens when you run npm run dev?

Settings are loaded and checked before anything else. A bad value stops the program with a message that names the variable, before any connection is opened.

 You wrote PostgresExamplesRepository, which implements ExamplesRepository. Which file do you change so the whole app uses it?

The composition root decides which implementation each layer receives. The service depends only on the interface, so nothing else changes.

 src/app.ts calls createContainer() from @zudojs/container and passes it to the runtime. What is registered in it in a freshly generated project?

The name is easy to confuse. The generated composition root is plain TypeScript in src/container.ts; the @zudojs/container container stays empty until you register something in it.

 Which layer is the only one that knows about HTTP (status codes, request bodies, path parameters)?

The controller turns a request into typed input and a result into a response. The service and repository work with plain data, so they can be reused from jobs or scripts.

 Why does ExamplesService.get throw NotFoundError instead of returning a 404 response?

An error from @zudojs/errors carries a status code and expose: true. At the HTTP edge, errorResponse turns it into a response; elsewhere it is just an error.

 POST /api/v1/examples with {"name": ""} gets a 400. Which layers ran?

Input is checked at the edge. Invalid data never reaches the service, which is why the trace showed no service.create line for that request.

 A client sends {name: as the body. What turns it into a 400?

JSON.parse fails inside readJsonBody, which throws badRequest("The request body is not valid JSON."). The catch in dispatch passes it to errorResponse.

 A repository throws new Error("disk full"). What does the client get, and what does the server log in the generated project?

errorResponse ignores errors without an exposed 4xx status, dispatch rethrows, and the HTTP server answers a generic 500. Nothing logs the original error, so add logging in dispatch.

 When does errorResponse(error) return a response instead of undefined?

Only client errors that are marked safe to show become responses. A 5xx or an unmarked error stays hidden behind a generic 500, so internal details never leak.

 Why are the controller's handlers written as public readonly list = async () => … instead of normal methods?

Passing controller.list as a callback detaches a normal method from its object, and this.service would be undefined. Arrow properties capture this when the object is created.

 export type AppConfig = Awaited<ReturnType<typeof loadConfig>>; What is the benefit?

One source of truth. ReturnType gives the function's return type, and Awaited unwraps the Promise because loadConfig is async. AppDependencies uses the same trick.

 A test calls loadConfig({ PORT: "4000" }). Is the developer's .env file read?

The check if (env === process.env) loadDotEnv() keeps tests independent of whatever is on the developer's disk.

 An integration has no health method. How does it appear in /health?

checkIntegrations skips integrations without health. Give an integration a health method when a failure of it should take the app out of rotation.

 While the app is shutting down, every integration still reports "up". What does /health answer?

Readiness includes the runtime state. Answering 503 during shutdown tells the load balancer to stop sending new requests before connections close.

 The generated tests/examples.test.ts passes. Why can the route still be unreachable in the running app?

A unit test of the resource cannot see the wiring. A smoke test that builds the router the way server.ts does catches it.

 Why does src/app.ts pass handleSignals: false to createRuntime?

The HTTP server is not a runtime module, so only server.ts can order "stop taking requests" before "close what requests use". One owner for signals.

 On SIGTERM, the generated server runs drainIntegrations, then server.stop(), then runtime.stop(). Why is runtime.stop() last?

Shutdown reverses startup: stop accepting work, finish it, then release what it used.

 What does the generated signal handler do when a second SIGINT arrives during shutdown?

The stopping flag guards the handler. Note the difference from @zudojs/runtime's own handler, which exits at once on a second signal.

 A handler sets its own content-security-policy. What does the generated securityHeaders() middleware do with it?

It compares header names case-insensitively and only fills the gaps. That is how /docs can load its assets with a looser policy.

 A test calls createApp({ config: await loadConfig({ NODE_ENV: "test" }) }) with no NODE_ENV in the real environment. Which environment does the runtime log?

The generated app reads NODE_ENV in two places. They usually agree, but not when a test passes its own environment object.

 You run three copies of the app behind a load balancer with RATE_LIMIT_MAX=300. How many requests per window can one client really make?

The generated rate limiter keeps its counters in the process. A shared store is needed for a limit across instances.

 Which is not a consequence of the generated in-memory repositories?

A Map in memory is fast. Its problems are durability, sharing between instances, and the size cap that protects memory.

The wiring still refers to the deleted classes. Remove those lines, keep the markers, and the type checker confirms nothing else uses them.
