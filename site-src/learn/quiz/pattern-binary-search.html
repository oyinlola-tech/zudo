Which problem is a "binary search on the answer"?

"The smallest value such that something is possible", with a check you can run for one candidate, is the signal. The others are frequency, sliding-window and two-pointer problems.

 What property must the check have for binary search on the answer to work?

Binary search needs one test at the middle to tell which side the switch is on. A sorted array is just one source of that property; a monotonic check over numbers is another.

 Why is "capacity c ships everything within 5 days" monotonic in c?

If c works, c + 1 works too. So the answers over capacities are no, …, no, yes, …, yes, and the first yes is the minimum capacity.

 What are safe search bounds for the minimum truck capacity?

The lower bound must not exclude the answer, and the upper bound must certainly work. Tighter bounds save a few checks; wrong bounds give wrong answers.

 The naive search tries capacities 45, 46, 47, … and each check fails. What does it waste?

Monotonicity means one check rules out a whole side. Testing the middle rules out half of all remaining candidates at once.

 The candidate capacities run from 1 to 1,000,000. About how many checks does binary search need?

Each check halves the range: ⌈log₂ 1,000,000⌉ = 20. The range can be enormous; the cost is dominated by what one check costs.

 One check simulates loading all n parcels. What is the total cost of binary search on capacities between max and total?

Checks × cost per check: about log₂ of the range, each O(n). The naive search is O(n × range), which grows like n² when the range grows with n.

 What invariant does firstTrue(lo, hi, test) keep?

When lo meets hi, the invariant pins the switch point exactly: everything before is false, everything from there on is true.

 In firstTrue, a true middle sets hi = mid, not hi = mid - 1. Why?

hi = mid goes with while (lo < hi) and an exclusive hi. The loop still ends, because mid < hi always, so the range shrinks every step.

 firstTrue(lo, hi, test) is called and no candidate passes. What does it return, and what should the caller do?

For lower bound, returning the array length ("past the end") is meaningful. For a capacity search, returning an untested capacity would be a silent bug if the bounds were wrong.

 How is the lower bound of a sorted array a special case of firstTrue?

Upper bound is the first true of "items[i] > target". Count of a value = upper − lower. One search function answers all of these.

 When is bisecting commits to find the first failing build valid?

A flaky test or a bug that was fixed and reintroduced gives several switch points. Bisect then returns one of them, not necessarily the one you care about.

 About how many test runs does bisecting 1,000 commits need?

⌈log₂ 1,000⌉ = 10. At 8 minutes per run that is about 80 minutes, instead of days when stepping through commits one by one.

 Why does binary search on the answer pay off most when each check is expensive (a build, a load test)?

With a check that costs microseconds, even a linear scan might be acceptable. With a check that costs 8 minutes, the log is the difference between an hour and a week.

 In a rotated sorted array, items[lo] <= items[mid]. What do you know?

There is only one drop, so at least one half is sorted. If the left end is not bigger than the middle, the drop is not in the left half. Then a range check tells you whether the target can be there.

 Why does plain binary search fail on a rotated array such as [40, 50, 60, 10, 20, 30]?

For target 20 the middle is 60; plain search goes left, where only 40 and 50 are. The rotated search first asks which half is sorted.

 Why can duplicates make rotated-array search O(n)?

In [5, 5, 5, 1, 5] both halves look alike from their ends. Solutions fall back to lo++, which in the worst case visits every element.

 Why does the lesson search repayments in whole kobo rather than in naira with decimals?

Search in the smallest unit (kobo, grams, seconds). If you must search real numbers, run a fixed number of halvings instead of waiting for lo to meet hi.

 What is the benefit of keeping the check (daysNeeded(weights, c) <= maxDays) separate from the search (firstTrue)?

All domain knowledge lives in the check, which you can test on its own. A bug in the check becomes a bug in the answer, so test both.

 You need the largest loan whose monthly payment fits a customer's budget. How do you use firstTrue?

"Last true" of a true-then-false test is "first true of its negation, minus one". The same trick finds the largest integer whose square is at most 50.

 During git bisect run, one test run fails because of a network timeout, not the bug. What happens?

Binary search never looks back at a discarded half. Make the check deterministic (or have the script report "skip", exit code 125, when it cannot decide).

 daysNeeded starts a new day when load + w > capacity. What goes wrong with >=?

The search is only as correct as the check. An edge bug in the check silently shifts the answer; test the check on "exactly full" cases.
