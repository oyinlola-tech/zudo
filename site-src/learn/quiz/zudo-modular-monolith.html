What is a monolith?

The Task API is a monolith: every feature runs in one process. That is simple to run and debug, and most successful products started this way.

 What do developers mean by a big ball of mud?

In a ball of mud, a harmless-looking function in one folder (like a Black Friday price change) can break rules owned by another part of the app.

 What is a modular monolith?

From the outside it is one app. Inside, each module owns one business area, exposes a small public API and owns its data.

 A module owns one area of the business, like catalog or orders. What is such an area called?

In ShopFlow, catalog (products and stock), orders (carts and checkout), users and payments are separate bounded contexts, and each becomes a module.

 Which list shows good module boundaries?

Draw boundaries around business areas, not technical layers. Controllers, services and utils are folders inside a module.

 In a modular monolith, what is shared by all modules?

Infrastructure is shared; only the data and the rules are split. Sharing one database server is fine, sharing tables between modules is not.

 The orders module needs an answer right now: "is this product in stock?". Which way of talking fits?

A direct call to the public API is right when you need an answer. Events are for "something happened". Reading another module's tables or private files breaks the boundary.

 An order was placed, and the e-mail, analytics and loyalty modules may care. How should orders tell them?

If orders called every interested module, it would depend on all of them, and one slow module would slow every checkout. With an event, orders does not even know who listens.

 What may other modules use from the catalog module?

index.ts is the module's public API. Everything else, such as the features/ folder, is private. Every export is a promise you have to keep, so keep the API small.

 What is the composition root?

Modules do not create each other. The composition root wires them together, for example by registering each module's API in the container under a token the module exports.

 TypeScript refuses catalog.products on a CatalogApi. Why is that still not enough to protect the boundary?

Types are a strong fence, but a deep import skips the public API. The team rule is: import another module only through its index.ts, checked by a test or a lint rule.

 ShopFlow gets a PostgreSQL database. How does each module keep owning its data?

Sharing one database server is shared infrastructure, which is fine. Sharing tables between modules is what turns them back into a ball of mud.

 The event bus lives in memory. The process crashes right after the order is saved and before the event is handled. What happens, and what is the fix when that matters?

Memory is gone after a crash. Inside one app that is often acceptable. When it is not, the outbox pattern stores the event with the order, so it can be published later.

 In @zudojs/cqrs, what is the difference between a command and a query?

Separating writes from reads makes each one's intent clear, and lets every write pass through one bus where middleware can log, time or check it.

 What does sending every write through one command bus give a monolith?

Middleware on the bus sees every command without any module doing extra work. That is where an audit log belongs.

 Should every call between modules go through a command or query bus?

Do not put everything through a bus by reflex. CatalogApi.getProduct(sku) is clear and simple. Reach for commands and queries when they add something.

 OrdersModule declares dependencies: ["catalog"] and is listed first. In which order does the runtime start and stop the modules?

The runtime starts a module after the modules it depends on. On shutdown the order is reversed, so orders stops using the catalog before the catalog goes away.

 Why is a modular monolith a good way to prepare for microservices?

If a module only talks through its public API, events and commands, those calls can later cross the network. If it reaches into other modules' tables, there is nothing clean to cut along.
