To find duplicates, you compare every item with every item after it. How many comparisons is that for a list of 10 items?

Item 1 is compared with 9 others, item 2 with 8, and so on down to 1: 9 + 8 + … + 1 = 45, which is 10 × 9 / 2. The formula n × (n − 1) / 2 comes from counting pairs.

 The "compare every pair" approach takes 1 second on a list of 5,000 payments. Roughly how long on 50,000 payments?

The number of pairs grows with the square of the list. Ten times more items means about a hundred times more comparisons. That is why you count the steps of an idea before trusting it on real data.

 Why is the Set version of duplicate detection so much faster than the nested loops?

The Set remembers every value seen so far and answers has instantly. So the work is one step per item instead of one step per pair. The price is the extra memory for the Set.

 The duplicate finder keeps a second Set called reported. What would happen without it, for ["PAY-7", "PAY-7", "PAY-7"]?

The second and third copies are both "already seen", so each would be added to the result. The requirement was to report each duplicated reference once, so the function remembers what it has already reported.

 A counting function does counts[product] = counts[product] + 1; without starting new products at 0. What do the counts become?

A key that was never stored reads as undefined, and undefined + 1 is NaN. Every later + 1 keeps it NaN. Start unseen keys at a known value first.

 Bread and Milk both sold 12, and nothing sold more. Why does bestSellers return both instead of just the first one it found?

Which tied product comes "first" depends only on the order of the data, not on anything the manager cares about. Ties are an edge case to decide on purpose; here the decision is "report them all".

 A support agent searches for an email that no customer has. What should the search function do?

Not finding something is an expected outcome, not a failure of the program. null means "deliberately nothing" and the caller decides what to show.

 The same list of 20,000 customers is searched by email 10,000 times a day. What is the better plan?

Building the table costs one walk through the list. After that each search is one step instead of up to 20,000. This table is called an index, and databases use exactly this idea.

 Dates are stored as text and compared with <. Which format compares correctly?

Text compares character by character from the left. It matches date order only when the biggest unit comes first and every part has a fixed width: four-digit year, two-digit month, two-digit day (the ISO 8601 form).

 Why does the order filter build a new list instead of removing unwanted orders from the original?

A function that changes its input has a side effect every caller must know about. Returning a new list leaves the original as it was, which is what the "original untouched" test checks.

 The board function creates { todo: [], doing: [], done: [], other: [] } before looking at any task. Why?

Grouping only by the statuses that appear would make the Doing column vanish on a day without Doing tasks. Creating the known groups first is a decision about the output shape.

 A task arrives with status "blocked", which the board does not know. What does the workshop do with it, and why?

A task that silently disappears is worse than an odd-looking column. Keeping it visible, with its real status, lets someone notice and fix the data.

 Pages are numbered from 1 and hold 20 products each. At which list position does page 3 start?

Page p starts at (p − 1) × size: (3 − 1) × 20 = 40. Positions 40 to 59 are the 41st to 60th products.

 There are 41 products and 20 per page. How many pages are there?

41 / 20 is 2.05, and the one leftover product still needs a page, so round up with Math.ceil: 3 pages, the last holding one product.

 Someone asks for page 5 when there are only 4 pages. Why does the workshop return an empty page instead of "invalid"?

Page 0 or −1 is always a caller mistake, but a page just past the end can come from normal use. An empty page plus the real total lets the website say "no more products".

 Sales are 900, 700, 700 and 500. With competition ranking (ties share a rank, the next rank skips), what are the ranks?

The two 700s share rank 2. The agent with 500 has three people ahead of them, so they are 4th. (1, 2, 2, 3 is another valid scheme, but it has to be a decision you test.)

 Why does the leaderboard sort tied agents by name?

Tied agents still share a rank. The second rule only fixes the order in which they are listed, so it does not change between runs or look unfair.

 The leaderboard uses agents.toSorted(compare) instead of agents.sort(compare). What is the difference that matters here?

The list of agents belongs to the caller. Rearranging it in place is a side effect that can break other code relying on its order; the test team[0].name checks it was left alone.

 The warehouse has 5 bags of rice. Movements: "sell 8", then "receive 10". What is the stock at the end of the day?

Movements are applied in the order they happened. At the time of the sale there were only 5 bags, so it is rejected; the delivery then brings the stock to 15. The reverse order would give 7.

 Why does endOfDay put impossible movements on a rejected list with a reason, instead of just skipping them?

Silently skipping hides the problem; letting stock go negative corrupts the totals. Rejecting with a reason keeps the numbers right and the problem visible.

 The check helper in this workshop compares JSON.stringify(actual) with JSON.stringify(expected). Why not just actual === expected?

["A"] === ["A"] is false: === on lists asks "is this the same list?", not "do they look the same?". The JSON text of both is ["A"], so comparing text compares contents, including order.
