What is a protocol, such as HTTP?

HTTP is a set of rules for the text a client and a server send each other over a connection. Under the neat req object there is only that text.

 In which order do the parts of an HTTP request arrive?

First POST /tasks?done=false HTTP/1.1, then one name: value header per line, then an empty line meaning "headers finished", then the body.

 What are the three pieces of the request line POST /tasks?done=false HTTP/1.1?

The request line says what to do (POST), to what (/tasks?done=false) and which version of the rules is used (HTTP/1.1). The host goes in the host header.

 How does HTTP end each line of the request line and the headers?

Every line ends with \r\n, and an empty line (\r\n on its own) ends the headers. The lesson prints them as text so you can see them.

 A server sets Content-Length to body.length for a body that contains é. What is wrong?

With a length that is too small, the client stops reading early and the body is cut. Use Buffer.byteLength(body), or leave the header out and let Node send the body in chunks.

 In the output of curl -v, what do lines starting with > and < show?

Lines with * are curl's notes, > lines go out, < lines come back. That makes curl -v the first tool to reach for when an API surprises you.

 What does Connection: keep-alive mean in a response?

Opening a connection takes time. Keep-alive reuses it, which is faster. Node adds this header by itself.

 Which Content-Type does a classic HTML form send by default?

A media type names the body's format: application/json for JSON, text/html for a page, text/plain for plain text, and application/x-www-form-urlencoded for a classic form.

 A client sends Content-Type: text/plain to an endpoint that only accepts JSON. Which status fits?

415 means "I do not accept this format". 400 is for a body in the right format that the server cannot use, such as broken JSON or a missing title.

 The lesson's JSON server reads the whole body with for await. What does a real server add?

A body is outside input. Count the bytes as they arrive and stop with 413 once the limit is passed.

 HTTP does not remember anything between two requests. How does "you are still logged in" work?

A cookie is a small piece of text the browser remembers for the server. Set-Cookie sets it; the browser returns it in the Cookie header.

 What does the HttpOnly cookie attribute protect against?

HttpOnly hides the cookie from document.cookie. Sending only over HTTPS is Secure; blocking most cross-site requests is SameSite.

 What does the Secure cookie attribute do?

Secure is about the connection, not the value: over HTTPS, the whole request is encrypted. It does not hide the value from the user, who can still see and edit it.

 Which cookie attribute blocks many cross-site request forgery (CSRF) attacks?

With SameSite=Lax, the browser does not send the cookie with most requests started by other sites. None turns that protection off (and needs Secure).

 A cookie is set without Max-Age. When does it disappear?

Without Max-Age, it is a session cookie that lasts until the browser closes. Max-Age=3600 keeps it for 3600 seconds, and Max-Age=0 deletes it at once.

 After login, what should the server put in the cookie?

The user can edit their own cookies, so a role or id in a cookie can be changed to anyone else's. A random id that only means something in the server's session store gives nothing away and cannot be guessed.

 Which HTTP methods are safe (they only read)?

Safe methods never change anything on the server, so browsers, caches and search engines may call them freely.

 A developer adds GET /tasks/7/delete to delete a task from a link. Why is that a bad idea?

Tools follow GET links on their own because GET is supposed to only read. Changes belong in POST, PUT, PATCH or DELETE.

 A mobile app sends PUT /tasks/1 and the network drops before the answer arrives. Why is it safe to send it again?

PUT replaces the task with the same data each time. Retrying a POST is different: it could create a second task.

 What does this print? const tasks = []; function post(body) { tasks.push({ id: tasks.length + 1, ...body }); } function put(id, body) { const i = tasks.findIndex((t) => t.id === id); tasks[i] = { id, ...body }; } function remove(id) { const i = tasks.findIndex((t) => t.id === id); if (i === -1) return 404; tasks.splice(i, 1); return 204; } post({ title: "Buy milk" }); post({ title: "Buy milk" }); put(2, { title: "Call Ada" }); put(2, { title: "Call Ada" }); console.log(tasks.length, tasks[1].title); console.log(remove(1), remove(1), tasks.length);

Two POSTs made two tasks; two PUTs left one task in the same state. DELETE is idempotent too: the second call answers 404, but the state is the same, one task left.

 Why does a browser warn you before it resends a form, but reloads a normal page without asking?

Resending a POST could buy something twice or create a duplicate. Repeating a GET only reads again.

 A client gets an error and wonders whether to try again unchanged. Which is right?

A 4xx means the request itself was wrong: fix it first. A 5xx means the server failed, which may be temporary, such as a database that is restarting.

 A response has status 301 Moved Permanently. Where should the client look?

3xx codes mean "it is somewhere else", and Location gives the address. A deleted resource is 404 (or 410).

 A client tries to create a task with a title that must be unique and is already used. Which status fits best?

409 means the request clashes with the current state. 429 is what a rate limiter sends when a client sends too many requests.

 Your code throws an unexpected error while handling a request. What should the client receive?

A 500 is your bug, not the client's. Stack traces can reveal file paths and internals, so log them on the server and never send them.
