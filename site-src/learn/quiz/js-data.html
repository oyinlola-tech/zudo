When should you use an object instead of an array?

Use an array for a list of similar things in order. Use an object for one thing whose parts have names.

 In { name: "Ada", age: 36 }, what is name: "Ada"?

Each piece of an object is a property: a name (the key), a colon, and a value. The value can be anything, even an array or another object.

 What does this print? const user = { name: "Ada", greet() { return "Hello, I am " + this.name; }, }; console.log(user.greet());

A property whose value is a function is a method. Inside it, this is the object the method was called on, here user.

 What is a method?

A method is a function stored as a property. You call it with brackets, like user.greet(). A property holding another object makes a nested object.

 What does this print? const user = { name: "Ada", address: { city: "London", country: "UK" }, }; console.log(user.address.city, user.address.zip);

The chain is read left to right: user, then its address, then city. zip does not exist on address, so it is undefined; that is not an error.

 A user has no address property. What happens with user.address.city?

Reading a missing property gives undefined, but reading a property of undefined crashes: Cannot read properties of undefined (reading 'city').

 What does this print? const user = { name: "Ada", "last-login": "2026-09-01", age: 36 }; const field = "age"; console.log(user["last-login"], user[field], user.field);

Square brackets take a string or a variable: user[field] reads age. user.field looks for a property literally called field, which does not exist.

 When do you need square brackets, like user[key], instead of a dot?

Use the dot when you know the name while writing the code. Use brackets when the name comes from a variable or contains characters like -.

 What does this print? const user = { name: "Ada", phone: undefined }; console.log("phone" in user, "email" in user, user.phone === user.email);

in asks "does this object have a property with this name?". phone exists (with the value undefined); email does not. Reading either one gives undefined.

 You write user.nmae by mistake. What happens?

Reading a property that does not exist gives undefined. That is convenient, but it is also how typos slip through silently.

 What does this print? const user = { name: "Ada", email: "ada@example.com", age: 36 }; user.age = 37; user.city = "London"; delete user.email; console.log(user);

Assigning changes or adds a property, and delete removes it completely. const only stops user from pointing at a different object.

 You want an object that nobody can change. What does the lesson use?

const does not freeze the object; it only stops the name from pointing elsewhere. Object.freeze stops changes to the object's properties.

 What does this print? const user = { name: "Ada", age: 36 }; const sameUser = user; sameUser.age = 99; console.log(user.age, user === sameUser);

A variable holds a reference, an arrow to the object. sameUser = user copies the arrow, not the object, so both names point at the same object.

 What does this print? const a = { name: "Ada" }; const b = { name: "Ada" }; const c = a; console.log(a === b, a === c);

=== on objects asks "is this the same object?", not "do they look the same?". a and b are two separate objects; c points at a.

 What does this print? function birthday(person) { person.age += 1; return person.age; } const ada = { name: "Ada", age: 36 }; console.log(birthday(ada), ada.age);

A function receives the reference, so changing person changes the caller's object. Many backend bugs come from a function quietly changing an object someone else is still using.

 What does this print? function setting(key, value) { return { [key]: value }; } console.log(setting("theme", "dark"), setting("pageSize", 20));

A computed property puts an expression in square brackets; its value becomes the property name when the code runs.

 You want to keep only the text settings of an object. Which approach does the lesson teach?

An object has no map or filter. Turn it into pairs, use the array tools, and turn the pairs back into an object.

 What does this print? const settings = { theme: "dark", language: "en", pageSize: 20 }; const onlyText = Object.fromEntries( Object.entries(settings).filter(([, value]) => typeof value === "string"), ); console.log(onlyText);

filter keeps the pairs whose value is a string, and Object.fromEntries turns the pairs back into an object.

 What does this print? const defaults = { theme: "light", language: "en" }; const chosen = { theme: "dark" }; console.log({ ...defaults, ...chosen }); console.log({ ...chosen, ...defaults });

When two objects have the same property, the one that comes later wins. Put defaults first and the user's choices after them.

 What does this print? const defaults = { pageSize: 20 }; const a = Object.assign({}, defaults, { pageSize: 50 }); const b = Object.assign(defaults, { pageSize: 99 }); console.log(a.pageSize, b.pageSize, defaults.pageSize);

Object.assign writes into its first argument. Passing a fresh {} keeps defaults untouched; passing defaults itself changes it.

 What does this print? const user = { name: "Ada", address: { city: "London" } }; const shallow = { ...user }; shallow.name = "Grace"; shallow.address.city = "Paris"; console.log(user.name, user.address.city);

Spread makes a shallow copy: name is copied, but address is still the same shared object. Changing the copy's city changes the original's.

 What does this print? const defaults = { theme: "light", alerts: { email: true } }; const ada = structuredClone(defaults); const grace = structuredClone(defaults); grace.alerts.email = false; console.log(ada.alerts.email, grace.alerts.email, defaults.alerts.email);

structuredClone makes a deep copy: every level is new, so each user has their own alerts object.

 An object contains another object. Which statement is true?

Spread is a shallow copy: nested objects stay shared. structuredClone is a deep copy. copy = obj is not a copy at all, just a second name.

 What does this print? const user = { id: 7, name: "Ada", passwordHash: "" }; const { passwordHash, ...publicUser } = user; console.log(publicUser); console.log(Object.keys(user).length);

...rest collects every property you did not name into a new object. The original user is not changed; it still has all 3 properties.

 Your API must return a user without its passwordHash. Which approach is right?

Take the secret field out and send the rest. Never trust the client to ignore data it receives. JSON.stringify does not know which fields are secret, and blanking the stored user would destroy the real hash.

 What should a real app store for a user's password?

A real app stores a hash made by a password-hashing library, never the password. The authentication lesson later in the course shows how.

 What does this print? const task = { id: 1, title: "Buy milk", done: false, tags: ["home"] }; const text = JSON.stringify(task); console.log(text); console.log(typeof text, JSON.parse(text).tags[0]);

JSON.stringify turns a value into JSON text, with double quotes and no spaces. JSON.parse turns the text back into a value.

 Which of these is valid JSON?

In JSON, property names and strings must use double quotes, and there are no comments and no trailing commas.

 What does this print? const task = { title: "Buy milk", note: undefined, due: new Date("2026-10-01T09:00:00Z"), describe() { return this.title; }, }; const back = JSON.parse(JSON.stringify(task)); console.log(Object.keys(back), typeof back.due);

JSON only knows strings, numbers, booleans, null, arrays and plain objects. undefined and methods vanish, and the date becomes a string that stays a string after JSON.parse.

 Your API receives JSON with a due date. After JSON.parse, what do you have?

JSON is text, and JSON.parse only builds plain data. Dates arrive as strings. Always check and convert incoming data yourself.

 What does the null, 2 in JSON.stringify(task, null, 2) do?

The third argument sets the indentation. The output is the same data, spread over several lines.

 A user only asked to change their theme. What does this print? function updateProfile(profile, changes) { return { ...profile, ...changes }; } const ada = { id: 1, name: "Ada", role: "user", theme: "light" }; const changes = JSON.parse('{"theme":"dark","role":"admin"}'); console.log(updateProfile(ada, changes).role);

Spreading everything the client sent copied role too, and made the user an administrator. This security bug is called mass assignment.

 How do you fix the mass assignment bug in updateProfile?

An allow-list names exactly which fields are accepted. Removing only role (a block-list) fails as soon as another sensitive field like id is sent. Spreading the profile second would stop all changes, including the allowed ones.

 What does this print? const EDITABLE = ["name", "theme", "bio"]; function updateProfile(profile, changes) { const allowed = Object.entries(changes).filter(([key]) => EDITABLE.includes(key)); return { ...profile, ...Object.fromEntries(allowed) }; } const ada = { id: 1, role: "user", bio: "" }; const updated = updateProfile(ada, JSON.parse('{"bio":"Math fan","id":99,"role":"admin"}')); console.log(updated, ada.bio === "");

Only keys on the allow-list get through, so id and role are ignored. The function returns a new object and never changes its input, so ada.bio is still empty.

 In the profile system, who decides a new profile's role?

createProfile sets role: "user" itself and ignores any role in the input. Anything about permissions must come from the server.

Finish countByStatus(tasks): return an object that counts how many tasks have each status. Use square brackets to read and write the count for each status.

 With const name = "Ada";, what does { name } mean?

That is shorthand: when the property name and the variable name are the same, you write the name once.

 What does a variable like const user = { name: "Ada" }; actually hold?

Variables hold references to objects. Assigning the object to another variable copies the arrow, so both names point at the same object.

 A client sends text that is not valid JSON, and your code calls JSON.parse on it. What happens?

JSON.parse throws a SyntaxError on invalid text. Input from outside can be anything, so a backend must be ready for that; the lesson on errors shows how.
