 TypeScript's checking is called static checking. What does "static" mean here?

The compiler tsc reads the code and its types and reports mistakes before the program ever runs. JavaScript, by contrast, finds mistakes only while the program runs.

 When a TypeScript program runs on Node.js, what does Node.js actually run?

TypeScript only adds type notes. They are removed before the code runs, by tsx, by Node's type stripping, or by compiling with tsc. What runs is ordinary JavaScript.

 The lesson installs TypeScript with npm install -D typescript tsx @types/node. Why -D?

-D saves them as dev dependencies. The type checker and the runner are development tools; the finished app only needs the JavaScript.

 What does "strict": true do in tsconfig.json?

strict switches on all of TypeScript's safety checks. The lesson says: always use it, because it is what makes TypeScript worth having. It changes checking only, not how the code runs.

 With "noEmit": true in tsconfig.json, what does npx tsc do?

noEmit means "emit nothing": tsc is only the checker, and something else (tsx or node) does the running.

 Why does the lesson's tsconfig.json set "skipLibCheck": true?

It skips re-checking the .d.ts type files that come with packages. Your own code is still fully checked.

 What does "verbatimModuleSyntax": true make you do?

With this setting, an import used only for types must be written import type { ... }. ZudoJS code follows this rule.

 The project's package.json has "type": "module" and tsconfig.json has "module": "NodeNext". Which kind of modules does TypeScript produce?

NodeNext means "whatever Node.js does". Because package.json says "type": "module", Node.js treats the files as ES modules.

 In function report(task: Task): string, what is the : string at the end?

An annotation is a colon and a type after a name. After the parameter list, it annotates what the function returns.

 What is the lesson's rule of thumb for writing types?

TypeScript cannot guess what callers will pass to a function, so parameters need types. Most other types are inferred from the values.

 Which command checks your types?

Only tsc checks. tsx and node remove the types and run the code, even when it has type errors.

Node's type stripping replaces types with spaces and runs the rest. It reads no tsconfig.json, checks nothing, supports only erasable syntax, and needs imports to name the .ts file.

 For production, what does the lesson say you usually do?
