Which type is the top type: every value can be assigned to it, and you must check a value before using it?

unknown is the set of all values. any also accepts every value, but it then lets you do anything with it, which is not a place in the hierarchy but an exit from checking.

 Which statement about never is true?

never is the bottom type. Adding the empty set to a union changes nothing, which is why it vanishes there.

 Why is any described as "an exit from the type system" rather than a place in it?

An any value goes into a number parameter, has any method called on it, and passes any on to whatever it touches. The compiler stops checking.

 Why did credit(event.data.walletId, event.data.amount) compile, when credit takes amount: number and the JSON held the string "5000"?

The compiler never saw the JSON text; JSON.parse is declared to return any. Annotate the result as unknown to force checks.

 Which any does strict (noImplicitAny) report?

noImplicitAny only catches any the compiler would have to invent (TS7006). An any that comes from a declaration, or that you write yourself, is explicit and accepted without a word.

 What is the inferred return type of this function, and why does it matter? function amountOf(body: string) { return JSON.parse(body).data.amount; }

any spreads through property reads and return values. A caller far away gets any silently. Annotate the parse as unknown, or give the function a checked return type.

 Given const event: unknown = JSON.parse(body), which line compiles?

An unknown value can only be checked, stored or passed on as unknown. Reading properties, calling methods and passing it as a number are refused (TS18046, TS2345) until you narrow.

 Which of these is not a boundary where data should enter as unknown?

A boundary is where data comes from outside the compiler's view: the network, disk, the database, other services. Your own typed functions are inside it.

 With strict on, what is the type of error in catch (error) { … }, and why?

The useUnknownInCatchVariables flag (part of strict) makes it unknown. Check with error instanceof Error before reading error.message.

 A test deliberately passes a string where a number is expected, to check that the function rejects it. Which spelling is the least bad?

The double assertion says out loud that the test is lying on purpose, and nothing else in the file becomes any. // @ts-expect-error on that line would also work, and would fail if the parameter were ever loosened.

 What does the return type never on function fail(message: string): never let TypeScript do?

A function that never returns ends that path. After if (balance === undefined) fail(…), balance can only be a number.

 Why does const cart = { items: [] }; cart.items.push({ sku: "RICE-5KG" }); report that the argument is not assignable to never?

Give the empty container a type, for example an interface with items: CartItem[]. The same rule as always: annotate empty containers.

 What does TypeScript say about item.price when item has type never?

The empty type has no properties. You usually see this error as a follow-on from a never[] array: its elements are never, so every property read fails.

 What happens with function logTransfer(ref: string): void { return ref.length; }?

On a function you declare, : void means "returns nothing", and the compiler holds the body to it.

 Why is const remember: (ref: string) => void = (ref) => sent.push(ref); allowed, although push returns a number?

This is what lets you pass (x) => list.push(x) to forEach. The result's type is void, so you cannot use it as a number later.

 Why does payouts.forEach(async (p) => { await pay(p); }) compile, even though nothing waits for the payouts?

By the rules of void the code is correct, so only a linter (no-misused-promises) can catch it. Use for…of with await, or await Promise.all(payouts.map(…)).

 Which value can be assigned to the lowercase type object?

object means any non-primitive: plain objects, arrays, functions, dates, maps. Numbers, strings and null are not objects.

 What does the type {} accept?

{} is an object type with no required properties, so any value that is not null or undefined fits, even 42. A parameter data: {} accepts save(42).

 Should you write Object (capital O) as a parameter type?

Like String, Number and Boolean, the capitalised Object is the type of a built-in JavaScript object, not what you mean in a signature.

 Which value is rejected by Record<string, unknown>?

An array type has no string index signature, so it does not fit. Record<string, unknown> is a good type for "a plain object with unchecked values", which is exactly what a JSON object is before you check it.

 When is the lowercase object type the right choice?

It is rare, but real: some APIs need "any non-primitive". For data you will read properties from, prefer a real interface or Record<string, unknown>.

 The compiler accepts an explicit any silently. What finds every place one is used?

The no-unsafe-assignment, no-unsafe-member-access, no-unsafe-call and no-unsafe-return rules report where an any flows, which tsc never does.

 A type test says // @ts-expect-error above const x: string = parseEvent("{}");. What does it detect?

With a real result type, assigning to string is an error, as expected. If the result ever becomes any, it becomes assignable, and tsc reports TS2578.
