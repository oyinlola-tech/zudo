Your Task API saves its tasks to a JSON file. Which problem does the lesson say this causes?

A file has no protection for many writers at once and no way to undo a half-finished write. A database is built exactly for these jobs: safe concurrent writes, crash recovery and fast lookups.

 Which database family stores a value under a key, like a giant Map?

Key-value stores such as Redis and Valkey look up a value by its key. Relational databases store tables of rows and columns; document databases store JSON-like documents.

 Why does the lesson call relational (SQL) databases the right default for most backends?

A relational database enforces column types, required values and links between tables. Everything that is not relational is often called NoSQL.

 What is PGlite?

PGlite needs no separate server and no password, which makes it perfect for learning and for tests. The next lesson installs a normal PostgreSQL server.

 You create a database with new PGlite() and add some rows. What happens to them when the program ends?

Without an argument, PGlite starts an empty database in memory each time. Pass a folder, new PGlite("./data"), to keep it on disk.

 Why does the lesson write db.query("insert into tasks (title) values ($1)", [title]) instead of putting title into the SQL text?

Always pass outside values as parameters. Gluing user input into SQL text allows SQL injection, which the next lesson demonstrates.

 In PGlite, what is the difference between db.exec and db.query as the lesson uses them?

Use exec for fixed SQL such as create table, and query(sql, params) whenever a statement includes values, especially values from outside.

 Which two rules does a primary key enforce?

A primary key identifies each row, so it is unique and not null. It can be a number (id) or a natural key from the data, like a tag's name.

 Why let the database pick ids with generated always as identity instead of computing "highest id + 1" in your code?

Two requests could both read "highest id is 7" and both pick 8. The database hands out the numbers itself, so they never collide.

23505 is a unique violation: the value already exists. That is a conflict with the current state, so 409 fits. Do not forward raw database messages to the client.

 Each comment is on one task, and a task has many comments. Where does the key go?

One-to-many: put the foreign key on the "many" side. A task cannot hold a single comment_id, because it has many comments.

 Students take many courses, and each course has many students. How do you store this?

Many-to-many: neither table can hold a single id for the other, so a third table holds one row per link.

A unique foreign key turns one-to-many into one-to-one. In the lesson's profiles table, user_id is both the primary key and the foreign key.

 What does references users (id) on delete cascade on tasks.user_id mean?

The cascade flows from the referenced row (the user) to the rows that point at it (the tasks). Without any on delete rule, deleting a user who still has tasks is refused.

The API gives clients clear errors. Constraints protect the data from bugs, scripts run by hand, and a second service that forgot a check.

 Which PostgreSQL column type does the lesson name for money?

 Which columns get an index automatically in PostgreSQL?

Foreign keys like tasks.user_id are exactly what you filter and join by, yet they get no index. Add one yourself.

 Why not simply add an index to every column?

Every write must update every index on the table. Add indexes for the columns you actually search, filter, join and sort by.

 What is an index?

Without an index the database reads every row (a sequential scan), which gets slower as the table grows. An index finds the matches directly.

 Which ACID letter means "all or nothing: if one statement fails, every change in the transaction is undone"?

Atomic: the transaction cannot be split. Isolated means others do not see your half-finished changes; durable means a committed change survives a crash.

 The database says "committed", and a second later the power goes out. Which ACID promise says the change is still there after restart?

Durable: once committed, the change survives a crash or power cut. Consistent means every constraint still holds when the transaction ends.

 Tasks need a new due_date column, and production already holds real data. What do you do?

The create table already ran and will not run again, and dropping the table destroys data. A migration is a small change that runs exactly once, in order, on every database.

 Migration 3 already ran on production. You notice it should also have created an index. What is the safe fix?

Every database that ran migration 3 has it recorded and will never run it again, so an edit would never reach them. A new id runs everywhere exactly once.

 Why does the lesson's runner apply each migration inside a transaction together with its schema_migrations row?

The schema change and the "this ran" record succeed or fail together. After a failure you fix the migration and run it again cleanly.

Finish runAll(state, steps) so it behaves like a transaction. Each step is a function that changes the object it gets, and may throw. Work on a copy (structuredClone). If every step succeeds, return the copy. If any step throws, return the original state unchanged.
