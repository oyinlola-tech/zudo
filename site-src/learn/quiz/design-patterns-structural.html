What does an adapter do?

Your services depend on SmsSender; the adapter turns those calls into the vendor SDK's calls and turns the vendor's answers back into SmsResult.

 Which list covers what an SMS adapter must translate?

The login outage came from two missed translations: the number format and a failure reported inside a successful response. An adapter that skips any of the four leaks the vendor into your code.

 A vendor's SDK does not throw for an invalid number; it resolves with status: "InvalidPhoneNumber" inside the response. What should the adapter do?

Callers only understand your result type. Mapping the vendor's in-band failure into it is the adapter's job; retrying a permanent failure would never succeed.

 Why does the lesson normalise phone numbers in one shared nigerianE164 function before each adapter converts to its vendor's format?

Validation is shop knowledge (DRY), while "no plus sign" or "plus sign" is vendor knowledge. Keeping them apart means a new vendor needs only its own small conversion.

 What is an anti-corruption layer?

If a vendor's response type appears in a service's signature, the layer has a hole. Everything inside the layer speaks your domain's language.

 How does a facade differ from an adapter?

A checkout() in front of pricing, payment and stock is a facade. termiiSender is an adapter. Wrappers around big SDKs are often a bit of both.

 Why run one contract test against every SMS adapter?

This is Liskov substitution in practice. The contract would have caught the login outage before the vendor switch shipped.

 What makes an object a decorator?

Because the interface is the same, callers cannot tell a decorated sender from a plain one, and decorators can be stacked. TypeScript's @decorator syntax is a separate language feature.

 Which SMS failure should a retry decorator retry?

Only transient failures can succeed on a second try. Invalid numbers and rejections are permanent; retrying wastes time and money.

 A retry after a dropped connection sends the message again, but the provider had actually received the first request. When is that acceptable?

A dropped connection does not tell you whether the request arrived. A duplicate login code is harmless; a duplicate charge is not.

 Why do production retries wait longer between attempts (backoff) and add some randomness (jitter)?

Immediate, synchronised retries can turn a short outage into a longer one. Backoff spreads the load over time; jitter spreads it across clients.

 withLogging(withRetry(sender)) versus withRetry(withLogging(sender)), for a send that fails twice and then succeeds. Which is true?

The outermost decorator sees one call in and one result out. A decorator inside the retry sees every attempt.

 Why is the wait function injected into withRetry instead of calling setTimeout directly?

Time is part of the outside world, like the network. Injecting it (a wait function, a clock) makes timing behaviour testable and deterministic.

 Why does the logging decorator write +234****567 instead of the full phone number?

A logging decorator sees every argument of every call. Masking belongs in it, so no call site can forget.

 A caching decorator is put in front of getAccountSummary(token) and caches by the URL path only. What goes wrong?

Anything that depends on who is asking must include the caller in the key, or not be cached at all.

 A proxy and a decorator can look identical in code. What is the difference?

Lazy creation, permission checks and forwarding over the network are access control. Logging and retries are added behaviour. The names help readers understand why the wrapper exists.

 A lazy proxy does if (real === undefined) real = await create(). Two requests arrive at the same moment. What happens, and what is the fix?

The check and the assignment are separated by an await, which lets the other request run in between. A promise exists immediately, so the second caller finds it.

 The lazy proxy caches the creation promise. The first creation fails because the font files are missing. What should happen next time?

A cached rejection turns a temporary problem into a permanent one until restart. Remove it in a catch and rethrow.

 A protection proxy checks role === "admin" before exportAllCustomers. When does it protect nothing?

An access check that can be walked around is decoration. The raw service must never be handed out; only the guarded one is.

 Which of these is a remote proxy?

The caller uses a normal interface; the proxy hides serialization and the network. That convenience also hides latency and partial failure, which callers must still handle.

 Why does calling a method through new Proxy(account, {}) fail when the method reads a #private field?

Private fields belong to real instances only. This is one reason plain wrapper objects are usually clearer than the built-in Proxy for these patterns.

 What problem does a repository solve?

When the total column was renamed, four files broke. With a repository, one file changes and services never see column names.

 What is wrong with a generic Repository<T> that offers findWhere(filter: any)?

The point of a repository is to hide storage. A method that takes a storage-shaped filter hides nothing.

 An order and its lines are always saved and loaded together. How many repositories should they have?

Two repositories invite saving an order without its lines. One repository keeps the aggregate consistent.

 A repository loads 50 orders, then runs one query per order to load its lines. What is this called, and why is it a problem?

Load related data in one query (a join) or one query per kind (all lines for these 50 orders).

 Why does the PostgreSQL repository cast total_kobo::int, and why does the contract check that amounts are numbers?

Only a contract run against the real database sees what the driver actually returns. The in-memory version would never show it.

 Why is the repository's save written as an upsert (INSERT … ON CONFLICT (id) DO UPDATE)?

The contract checks it: after saving ORD-2 twice, there is one ORD-2 with the new status.
