When does the @audited decorator function itself run for class PaymentService { @audited charge() {…} }?

The decorator runs once while the class is being defined and returns a replacement method. Only the wrapper it returns runs on every call. That is why setup work belongs in the decorator and the per-call work in the wrapper should stay small.

 A method decorator returns a new function. What happens to it?

For methods, getters and setters, a returned function replaces the original. Returning nothing keeps the original. The replacement usually calls the original with method.apply(this, args).

 Which plain JavaScript is closest to what @audited on the method charge does?

An instance method lives on the prototype. The decorator receives the original method and a context object, and its return value is written back in its place. The compiled code does exactly this inside a static block.

 Why does node account.ts (Node.js 24 type stripping) fail with SyntaxError: Invalid or unexpected token at @logged?

Decorators are a JavaScript feature, not a TypeScript type, so stripping leaves them in place. Until engines ship them, a compiler (tsc, esbuild via tsx, Babel with the decorators plugin) must rewrite them.

 Why are the decorator examples in this lesson marked "Node.js only"?

The terminal's Babel setup rejects the syntax with "Support for the experimental syntax 'decorators' isn't currently enabled". On your computer, tsx or tsc compiles them. Applying a decorator by hand, as a function call, works everywhere.

 What does a field decorator receive as its first argument?

Fields are created per instance, during construction. A field decorator can only return an initializer function that transforms each instance's initial value.

 You want to reject negative values every time stock is assigned. Why is a field decorator not enough?

accessor stock = 5 turns the field into a getter and setter pair over private storage, and an accessor decorator can wrap get, set and init.

 A class has accessor stock = 5. Why is stock missing from Object.keys(product) and JSON.stringify(product)?

Auto-accessors store their value like #private fields. Code that serialises objects (API responses, logs) will not see them unless you add a toJSON method or map the object explicitly.

 In @retry(3), what is retry(3)?

Anything after @ is an expression that must evaluate to a decorator function. A factory lets the decorator take settings, captured in a closure.

 @retry(3) is typed for methods that return a Promise. What happens when you put it on a synchronous balance(): number?

TypeScript checks a decorator as if it were called with the decorated value and its context (TS1241 for methods), and also checks that its return value can replace the original (TS1270).

 A method has @audit above @retry. When the method is called, whose wrapper runs first?

Decorators are applied from the closest outward, like function composition: audit(retry(method)). At call time the outermost wrapper runs first. So @audit @retry logs one audit entry per call, however many retries happen inside.

 When is a class decorator applied, relative to the decorators on its members?

A class decorator receives the finished class, with its decorated members already in place, so it can register or wrap the class as a whole.

 A method decorator calls context.addInitializer(fn) for an instance method. When does fn run?

Instance initializers run for every new object. Initializers added by static members and class decorators run once, right after the class is defined. That is why @bound can bind the method on each instance.

 Why does const { total } = cart; total() work with @bound and fail without it?

In JavaScript, this depends on how a function is called, not where it was defined. Binding in an initializer gives every instance its own bound function, which also makes it safe to pass as a callback.

 Decorators wrote to context.metadata while defining Product. Where can other code read that object afterwards?

All decorators of one class share one metadata object, which is attached to the class under Symbol.metadata. Reflect.getMetadata is the unrelated legacy mechanism from the reflect-metadata library.

 Why does the lesson polyfill Symbol.metadata with Symbol.for("Symbol.metadata") rather than Symbol("Symbol.metadata")?

A symbol from Symbol() is unique, so esbuild-compiled classes would store metadata under a different key than your code reads. Symbol.for returns the same symbol for the same name everywhere in the process.

 A @column decorator does (context.metadata.columns ??= {})[name] = type. A subclass adds one column. Why does the parent class now list it too?

Metadata objects form a prototype chain like the classes do. Before writing, check Object.hasOwn(metadata, "columns") and, if missing, start from a copy of the inherited value.

 What does adding "ESNext.Decorators" to lib in tsconfig.json do?

lib describes what the runtime provides; it never adds anything. Declaring Symbol.metadata without providing it is a promise only a polyfill keeps.

 In the JavaScript tsc emits for a decorated class, where is the decorator actually called?

The static block runs once at definition time. __esDecorate builds the context object, calls the decorators closest-first, and writes the result onto the prototype with Object.defineProperty.

 A decorator is declared as function logged(target: object, propertyKey: string, descriptor: PropertyDescriptor). Which kind is it?

Legacy method decorators receive the prototype, the key and the property descriptor. Standard ones receive the method and a context object. The same @ syntax hides two incompatible calling conventions.

 Can you write constructor(@Inject("clock") clock: Clock) with standard decorators?

Parameter decorators were left out of the standard (a separate proposal covers them). Standard-decorator frameworks pass dependency tokens explicitly, for example in a class decorator's arguments.

 With emitDecoratorMetadata, a constructor parameter typed as the interface Clock is emitted as Object. Why?

Only classes survive compilation as values. That is why legacy DI frameworks still need @Inject(TOKEN) for interfaces, and why type-based autowiring is less automatic than it looks.

 A NestJS-style project injects dependencies correctly after tsc, but in tests run through tsx (esbuild) every injected dependency is undefined. What is the likely cause?

Emitting parameter types needs the type checker, which esbuild does not have. The lesson's tsx example printed undefined for the same reason. Use a compiler that emits metadata for tests too, or explicit tokens.

 Handlers register themselves with a class decorator. In production, order.refund has no handler, although refund-order.ts is decorated correctly. What is the most likely cause?

Registration by decorator happens when the module is evaluated. A module nobody imports (or one a bundler dropped as unused) registers nothing, and no compiler warns you. Import handler modules explicitly and check registrations at startup.

 What does @CommandHandlerFor("order.place") from @zudojs/cqrs do on its own?

The decorator attaches the handler type to the class. A container or your startup code reads it and calls bus.register. It works with both decorator modes because it only uses the class it receives.

 Which is the best use of a decorator?

Decorators suit cross-cutting rules that apply to many members and are not their business logic: auditing, retries, timing, permissions, registration. Logic that belongs to one method is clearer written inside it.
