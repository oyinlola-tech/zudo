Record<K, V> is defined as { [P in K]: V }: one required property of type V per key.

 interface Row { readonly id: string; note?: string }. Which mapped type keeps id readonly and note optional?

A mapped type over keyof T is homomorphic and copies each property's modifiers. Looping over some other union of the same keys does not.

 What happens to note?: string in { [K in Extract<keyof Row, string>]: Row[K] }?

The keys no longer come straight from keyof Row, so the modifier is not copied. The looked-up type Row["note"] still includes undefined, so the property is required but may hold undefined.

 What is Partial<[string, number]>?

Homomorphic mapped types keep arrays and tuples as arrays and tuples, mapping each element. For a tuple, ? makes each element optional.

 What does { -readonly [K in keyof T]: T[K] } do?

- removes a modifier and + (or no sign) adds it. The keys themselves stay; only the modifier changes. There is no built-in Mutable for this.

 With interface Options { pageSize?: number }, what is { [K in keyof Options]-?: Options[K] }?

-? removes the optional mark and the undefined it added to the property type. That is exactly Required.

 Is { +readonly [K in keyof T]: T[K] } different from { readonly [K in keyof T]: T[K] }?

The plus sign is optional and exists for symmetry with -. Both forms are shallow and compile-time only.

 What are the keys of { [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K] } for T = { balance: number; currency: string }?

The as clause computes a new name for each key. Capitalize uppercases the first letter of each literal, and the template literal adds the prefix.

 Why does the renaming use K & string instead of just K?

Capitalize<S extends string> needs a string. K & string is K for string keys and never for symbols, so symbol keys disappear from the result.

 In { [K in keyof T as T[K] extends Function ? never : K]: T[K] }, what happens to a method?

Mapping a key to never in the as clause filters it out. That is how you remove keys by value type or by name while keeping the mapped type homomorphic.

 With type KeysOfType<T, V> = keyof { [K in keyof T as T[K] extends V ? K : never]: T[K] }, why is discountKobo?: number not in KeysOfType<Invoice, number>?

The check compares the full property type. Use KeysOfType<Invoice, number | undefined> if optional numbers should be included, and handle the undefined case in the code that uses them.

 What is { [E in PaymentEvent as E["type"]]: E }, where PaymentEvent is a union discriminated by type?

After in you may loop over any union, as long as as turns each member into a key. This builds an event map from a discriminated union, the base of typed handlers.

 What does the pattern { [K in keyof S]: Something<S[K]> }[keyof S] give you?

Indexing an object type with a union of its keys gives the union of its value types. Building a mapped type first lets you compute a value per key, then collect them, as EnvVarName does for every variable name in a schema.

 Why does DeepReadonly return Date unchanged instead of mapping over it?

A homomorphic mapped type visits every key, including methods such as getUTCFullYear, but only public ones: a class with a #private field, once mapped, is no longer assignable to that class. Stop the recursion at class instances you use, such as Date and Map.

 Why is the first branch of DeepReadonly<T> T extends (...args: any[]) => any ? T?

A mapped type only copies properties. A function's ability to be called is a signature, not a property, so the recursion must leave functions as they are.

 What does type Prettify<T> = { [K in keyof T]: T[K] } & {} change?

An identity mapped type visits every key of an intersection and produces a single object type, so editors and Equal see { id: string; roomId?: string } instead of Omit<…> & Partial<…>.

 Why does validators[key](transfer[key]) fail to compile when key: keyof Transfer?

This is the correlated-union limit. Use a generic helper with K extends keyof T, or a local, commented assertion.

 In setting<T, const E extends string>(d: { env: E; parse: (raw: string) => T; default?: NoInfer<T> }), what does NoInfer prevent?

Without NoInfer, a parser returning number and a default of "3" would infer T as number | string and compile. With it, the default is only checked against T.

 What does const E extends string do for a call like setting({ env: "PORT", … })?

A const type parameter asks for the narrowest inference, like as const would. The literal is what lets EnvVarName list "PORT" rather than string.
