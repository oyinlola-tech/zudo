Why is it a problem to write the database password straight into src/server.ts?

Git keeps every old version, so a committed secret stays in the history. Secrets must come from outside the code, usually from environment variables.

 What is the "twelve-factor" rule for configuration that the lesson follows?

Deploying should never mean changing code. The same build runs on your laptop and in production; only the environment around it differs.

 Which of these is configuration?

Configuration is every value that changes between environments. The title rule is the same everywhere, so it is a business rule and stays in the code.

 Two config sources both give port. Which value does the manager use?

The manager merges all sources. For a key given twice, the higher priority wins; keys that only one source gives are kept from that source.

 From lowest to highest priority, what is the usual order of layers?

Defaults are safe values for a developer's computer. The file holds reviewed, non-secret settings. Environment variables are set by whoever runs the app, so they win, and they are the only place for secrets.

 Why does createEnvironmentConfigSource({ prefix: "TASKS_" }) use a prefix?

The environment is full of unrelated variables. With a prefix, only TASKS_… names are read, and the prefix is removed from the key.

 What does failing fast mean for configuration?

Validate the whole configuration at startup. A typo found at 09:00 during deploy is much cheaper than one found at 12:00 by a user.

 Why does the config schema use schema.coerce.number() for port?

A plain number schema would refuse the string "8080". coerce converts it first, then the checks (int, min, max) run on the number.

 Where should the Task API's jwt_secret come from?

Secrets never live in code or in a committed file. They come from the environment, which whoever runs the app controls.

 Why must a missing secret stop the app instead of falling back to a default like "change-me"?

If production quietly uses "change-me", everyone who has read the code knows your signing key. Refusing to start is the safe answer.

 You want to log the loaded configuration at startup. Which is right?

toObject() returns the real values, secrets included. toSafeObject() replaces sensitive values with "[REDACTED]". Never log the whole process.env.

 A teammate stores an API key as TASKS_NOTE. What happens in toSafeObject()?

Both the config manager and the logger look at names such as secret, password, token, api_key. Give secrets obvious names, like TASKS_API_KEY.

 You find that the JWT secret was printed in production logs last week. What should you do?

Logs are copied to many places and kept for months. Once a secret has been logged, you cannot know who read it, so it must be replaced.

 Why does loadConfig build its error message from setting names and schema messages, never from the values?

An error message usually ends up in a log. "jwt_secret: String must be at least 32 characters" tells you what to fix without showing the secret.

 NODE_ENV is not set. What does resolveEnvironment() from @zudojs/constants return?

With no NODE_ENV, you get "development". Production must be switched on on purpose, and then the stricter rules apply.

 What is the right way to handle a .env file for development?

.env may hold real passwords, so it is never committed. .env.example shows which variables exist, so a new developer knows what to set.

 In development the Task API's host defaults to 127.0.0.1, in production to 0.0.0.0. Why?

0.0.0.0 listens on every network interface, so anyone on the same Wi-Fi could reach your dev server. In production the server must be reachable, so it uses 0.0.0.0.
