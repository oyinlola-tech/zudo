Why should you build file paths with path.join instead of adding strings with +?

path.join follows the path rules of the system the program runs on: one separator between parts, .. handled, \ on Windows. It does not touch the disk, and it keeps a relative path relative (that is path.resolve's job).

 What does this print on macOS or Linux? import path from "node:path"; console.log(path.join("data/", "/tasks.json")); console.log("data/" + "/tasks.json");

path.join removes the extra separator. Adding the strings keeps both slashes, which is exactly the bug the lesson warns about.

 What does this print on macOS or Linux? import path from "node:path"; console.log(path.join("data", "..", "notes", "today.txt")); console.log(path.join("a", "b", "..", "..", "c"));

.. means "the folder above", and path.join applies it. Each .. cancels the part before it, so a/b/../../c is just c.

 What does this print? import path from "node:path"; const file = "/home/ada/backup.tar.gz"; console.log(path.extname(file)); console.log(path.basename(file)); console.log(path.dirname(file));

extname only gives the last extension, with its dot. basename is the whole file name, and dirname is the folder it is in, without a slash at the end.

 What does this print? import path from "node:path"; console.log(JSON.stringify(path.extname("README"))); console.log(JSON.stringify(path.extname("notes.md")));

A file name without a dot has no extension, so extname returns an empty string (not undefined). When there is one, the dot is included.

 What does path.resolve("tasks.json") return?

path.resolve builds an absolute path from the current working directory, the folder the program was started from. That is not always the folder your script is in.

 Your script needs data/tasks.json, which sits next to the script. It must work whatever folder the program is started from. Which path should you use?

import.meta.dirname is the folder of the current file. The other three all start from the working directory, so they break when you run the program from another folder.

 Why should a server not call readFileSync while it handles a request?

Sync functions stop the whole program while they wait. That is fine once at start-up, but in a request handler it freezes all other requests. Use node:fs/promises and await.

Handle only the error you expect, and throw the rest again. Returning defaults for every error hides real problems like broken JSON or EACCES (no permission).

 You need a token for a password-reset link. Which is safe?

Tokens must be unguessable. Math.random() can be predicted, a time can be guessed, and a hash of the e-mail is the same every time for anyone who knows the e-mail. node:crypto uses the system's secure random source.

 What does this print? import { randomBytes, randomUUID } from "node:crypto"; console.log(randomUUID().length); console.log(randomBytes(16).toString("hex").length); console.log(randomUUID() === randomUUID());

A UUID is 36 characters (32 hex digits and 4 dashes). Each byte becomes 2 hex characters, so 16 bytes give 32. Every call gives a new random value.

The same input always gives the same hash, and a small change gives a different one. The length is fixed: SHA-256 in hex is always 64 characters, however long the input is.

 Which sentence about a hash like SHA-256 is true?

A hash is one-way: same input, same fingerprint, but no way back. That makes it good for checking whether a file has changed. Encryption is different, because it can be undone with a key.

 Why should you not store passwords as SHA-256 hashes?

Speed is good for file fingerprints and bad for passwords. A password hash must be slow and salted so guessing is expensive. You will use one, scrypt, in the node:crypto lesson.
