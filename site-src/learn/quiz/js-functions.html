Which of these is not a reason the lesson gives for writing functions?

Functions are about reuse, clear names and testing. They do not make code faster than a loop; a function often contains a loop.

 What does it mean to call a function?

Running a function is calling it. You write the name followed by parentheses with the arguments.

 In function formatTask(title, done) { … } and the call formatTask("Buy milk", true), what are title and done?

Parameters are the names in the definition. Arguments are the actual values in the call: "Buy milk" and true.

 What does this print? function formatTask(title, done) { const mark = done ? "x" : " "; return `[${mark}] ${title}`; } console.log(formatTask(true, "Buy milk"));

The first argument goes to the first parameter, whatever its name. So title is true and done is "Buy milk", which is truthy.

 What does this print? function logTask(title) { console.log(`Task: ${title}`); } const result = logTask("Buy milk"); console.log(result);

logTask prints, but it has no return, so it gives back undefined. Printing and returning are different things.

 What does this print? function show(a, b) { return `${a}-${b}`; } console.log(show(1)); console.log(show(1, 2, 3));

A parameter without an argument is undefined. Extra arguments are ignored. JavaScript does not throw for either.

 Why is a function that returns a value usually more useful than one that prints it?

A returned value can be used in many ways. A function that only prints forces one use, and makes testing harder.

 What does this print? const double = function (n) { return n * 2; }; console.log(double(21), typeof double);

A function is a value, so it can be stored in a variable. That is a function expression. typeof reports it as "function".

 This arrow function has braces but no return. What does it print? const double = (n) => { n * 2; }; console.log(double(4));

With braces, the body is a block and needs return, like a normal function. Without it, the function returns undefined. Drop the braces or add return.

 How do you write an arrow function with no parameters that returns "Hello!"?

No parameters means empty parentheses (). A single-expression body is returned without the return keyword.

 What does this print? console.log(square(4)); function square(n) { return n * n; }

Function declarations are hoisted: JavaScript sets them up before running the other lines, so you can call them before the line where they are written.

 What does this print? try { console.log(cube(2)); } catch (error) { console.log(error.message); } const cube = (n) => n ** 3;

A function stored in a const is not hoisted like a declaration. It cannot be used before the line that sets it has run.

 Which habit does the lesson describe for choosing between the two styles?

Both styles are fine. The common habit is declarations for the main functions and short arrows for callbacks.

 What does this print? function greet(name = "friend", greeting = "Hello") { return `${greeting}, ${name}!`; } console.log(greet()); console.log(greet("Ada", "Welcome back"));

A default is used when the argument is missing. When you pass a value, it replaces the default.

 A default parameter is used when the argument is missing or undefined. What does this print? function greet(name = "friend") { return `Hello, ${name}!`; } console.log(greet(undefined)); console.log(greet(null));

Only undefined (or a missing argument) triggers the default. null is a real value you passed, so it is used as it is.

 What does this print? function sum(...numbers) { let total = 0; for (const n of numbers) total += n; return total; } console.log(sum(1, 2, 3), sum(10), sum());

The rest parameter collects all the arguments into an array. With no arguments it is an empty array, so the loop never runs and the total stays 0.

 Which function definition is valid?

The rest parameter collects everything that is left, so it must be the last parameter, and there can be only one.

 What is a callback?

Because functions are values, you can pass one to another function. The receiving function "calls it back". A function that calls itself is recursion.

 What makes a function a higher-order function?

repeat(times, action) takes a function, and multiplier(factor) returns one. Both are higher-order functions.

 What does this print? function repeat(times, action) { for (let i = 1; i <= times; i++) { action(i); } } repeat(2, (i) => console.log(`Reminder ${i}`));

repeat decides how often; the callback says what to do. It is called with i = 1, then 2.

 What does this print? function applyToAll(numbers, transform) { const results = []; for (const n of numbers) results.push(transform(n)); return results; } console.log(applyToAll([1.4, 2.6], Math.round)); console.log(applyToAll([1, 2], (n) => n * 10));

Any function can be a callback, including a built-in like Math.round. results.push adds each result to the end of the array.

 You want to pass Math.round as a callback to applyToAll. Which call is correct?

Pass the function itself, without parentheses. Math.round() would call it straight away and pass its result (NaN) instead of the function.

 What does this print? function multiplier(factor) { return (n) => n * factor; } const triple = multiplier(3); const half = multiplier(0.5); console.log(triple(10), half(10), typeof triple);

multiplier returns a new function each time. triple remembers factor = 3, and half remembers 0.5.

 Which function is pure?

A pure function gives the same result for the same arguments and changes nothing outside itself. Changing total and printing are side effects, and Math.random() gives a different result each time.

 What does this print? let total = 0; function addToTotal(amount) { total += amount; return total; } console.log(addToTotal(5), addToTotal(5), total);

addToTotal changes a variable outside itself, so the same call gives different results. That is why it is impure and harder to test.

 A backend must save data to a database, which is a side effect. What habit does the lesson recommend?

A backend cannot be pure everywhere, but pure logic is easy to test and trust. Keep side effects few and in clear places, like the thin keyboard part of the guessing game.

 What does this print? const appName = "Tasks"; function makeTitle(title) { const prefix = `[${appName}]`; return `${prefix} ${title}`; } console.log(makeTitle("Buy milk")); console.log(typeof prefix);

A function can read variables from outside, like appName. But prefix exists only inside makeTitle. typeof on a name that does not exist gives "undefined" instead of throwing.

 What does this print? function createCounter() { let count = 0; return () => { count++; return count; }; } const a = createCounter(); const b = createCounter(); console.log(a(), a(), b(), a());

Each call to createCounter makes a new, separate count. The returned function remembers its own count even after createCounter finished. That is a closure.

 What is a closure?

A closure keeps access to the variables of the place where it was created, even after that outer function has finished.

 In createCounter, how can code outside change count?

Nothing outside can reach count directly. That makes closures a simple way to keep data private. Calling createCounter() again makes a new, separate counter.

 What happens when a recursive function has no base case?

The base case is where the function stops calling itself and just returns. Without it, the calls never stop until the call stack is full.

 What does this print? function factorial(n) { if (n <= 1) return 1; return n * factorial(n - 1); } console.log(factorial(4), factorial(1), factorial(0));

factorial(4) is 4 × 3 × 2 × 1 = 24. For 1 and 0, the base case n <= 1 returns 1 straight away.

 What does this print? function countSubtasks(task) { let count = 0; for (const sub of task.subtasks) { count += 1 + countSubtasks(sub); } return count; } const project = { subtasks: [ { subtasks: [{ subtasks: [] }] }, { subtasks: [] }, ], }; console.log(countSubtasks(project));

The project has 2 direct subtasks, and the first one has 1 more: 3 in total. A task with no subtasks is the base case: the loop runs zero times and returns 0.

 Where does recursion fit better than a simple loop?

Recursion shines on nested data: each subtask is handled by the same function. Flat lists and counting are simpler with loops.

 What does this print? function sum(...numbers) { let total = 0; for (const n of numbers) total += n; return total; } const values = [2, 4, 9]; console.log(sum(...values), sum(values.length));

Three dots in a call spread an array out into separate arguments, the opposite of a rest parameter. sum(values.length) just passes the number 3.

 The calculator throws Not a number: 2 for calculator.add("2", 3). Why is that better than returning a result?

With a string, + joins text instead of adding. A silent wrong answer is worse than a clear error, so the library checks its inputs first.

 Every calculator function first calls requireNumbers. What is the benefit?

Putting a check used by many functions in one helper avoids copying it. When the rule changes, you fix one place.

 What does this print? function divide(a, b) { if (b === 0) throw new Error("Cannot divide by zero"); return a / b; } function check(label, run, expected) { let actual; try { actual = run(); } catch (error) { actual = `error: ${error.message}`; } console.log(`${actual === expected ? "PASS" : "FAIL"} ${label} -> ${actual}`); } check("divide", () => divide(9, 3), 3); check("zero", () => divide(1, 0), "error: Cannot divide by zero"); check("float", () => 0.1 + 0.2, 0.3);

check runs the callback inside try, so a thrown error becomes a result instead of a crash. The float test fails because 0.1 + 0.2 is not exactly 0.3.

 Why does check(label, run, expected) take a callback run instead of the result value?

If you passed calculator.divide(1, 0) directly, it would throw before check even started. Passing () => calculator.divide(1, 0) lets check call it inside try.

Write a recursive countdown(n) that returns a string like "3 2 1 go". For 0 or less it returns "go" (the base case).

0.1 + 0.2 === 0.3 is false. Write a pure arrow function closeTo(a, b) that returns true when the two numbers differ by less than 0.000001. The program should print true false.
