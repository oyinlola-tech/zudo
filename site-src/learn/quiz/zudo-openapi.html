What is an OpenAPI document?

It answers the questions every API user asks: which paths exist, what do I send, what comes back, which errors can happen. Because it is plain JSON or YAML, both people and programs can read it.

 Which of these is not something the lesson says tools do with an OpenAPI document?

The document only describes the API. It protects nothing. Authentication still has to be enforced by your server on every route.

 Why does the lesson build the document with @zudojs/openapi instead of writing the file by hand?

When the document is built from the same schemas that validate requests, it cannot drift away from what the API really does.

 What are the three main parts of an OpenAPI document?

info holds the API's name and version, paths every URL and what each method does there, and components the shared pieces, such as schemas.

 In OpenAPI, what is an operation?

GET /tasks/{id} and DELETE /tasks/{id} are two operations on the same path. Each has its own operationId, parameters and responses.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ version: "3.1.0", info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addRoute({ method: "get", path: "/tasks/:id", metadata: { openapi: { operationId: "tasks.get", parameters: [{ name: "id", in: "path", schema: { type: "integer", minimum: 1 } }], responses: { "200": { description: "The task" } }, } }, }); console.log(Object.keys(manager.generate().paths));

The router style :id becomes {id}, the way OpenAPI writes a path parameter. The keys of paths are URLs, not operation ids.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addRoute({ method: "get", path: "/tasks/:id", metadata: { openapi: { operationId: "tasks.get", parameters: [{ name: "id", in: "path", schema: { type: "integer", minimum: 1 } }], responses: { "200": { description: "The task" } }, } }, }); console.log(JSON.stringify(manager.generate().paths["/tasks/{id}"].get.parameters));

OpenAPI demands required: true for every path parameter, so the manager adds it. A URL without the id would simply be a different path.

 What is operationId used for?

A generated client might offer tasks.get(...) for the operation with operationId: "tasks.get". It must be unique in the document.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const plain = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); const branded = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" } }); console.log("x-logo" in plain.generate().info, "x-logo" in branded.generate().info);

By default the manager adds the ZudoJS logo to info as x-logo, a field some viewers read. branding: false leaves it out and keeps the output short.

 What does this print? import { createComponentReference } from "@zudojs/openapi"; console.log(JSON.stringify(createComponentReference("schemas", "Task")));

A reference is an object with a $ref that points into the document. An operation uses it to say "the body is a Task" without copying the whole schema.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; import { schema } from "@zudojs/schema"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addSchema("NewTask", schema.object({ title: schema.string().trim().min(3).max(100) })); console.log(JSON.stringify(manager.generate().components.schemas.NewTask));

addSchema translates your schema into OpenAPI's schema language and stores it under components.schemas. .min(3).max(100) become minLength and maxLength, and title is required.

 The schema has no .max(). What does this print? import { convertSchema } from "@zudojs/openapi"; import { schema } from "@zudojs/schema"; const { schema: converted } = convertSchema(schema.object({ title: schema.string() }), { version: "3.1.0" }); console.log(JSON.stringify(converted.properties.title));

@zudojs/schema applies a limit of 255 characters to every string by default. The document tells clients the real limit, so they are not surprised by a 422.

 What does this print? import { convertSchema } from "@zudojs/openapi"; import { schema } from "@zudojs/schema"; const { schema: converted } = convertSchema(schema.number().int().min(1), { version: "3.1.0" }); console.log(JSON.stringify(converted));

.int() becomes "type": "integer" and .min(1) becomes "minimum": 1. min includes the value itself, so it is not exclusive.

 What do addSecurityScheme("bearerAuth", { type: "http", scheme: "bearer" }) and addSecurityRequirement({ bearerAuth: [] }) do together?

The scheme says how callers prove who they are; the requirement says it applies everywhere. Both only describe the API. Your server still has to check the token.

 What does security: [] on the /health operation mean?

An empty list overrides the document-wide requirement for that operation. It is right for a health check that load balancers call without a token.

 When should you choose OpenAPI 3.0 instead of 3.1?

3.1 is the current version and matches JSON Schema. Choose 3.1 unless a tool forces you to use 3.0. The manager writes the right keywords for whichever you pick.

 What does this print? import { convertSchema } from "@zudojs/openapi"; import { schema } from "@zudojs/schema"; const dueBefore = schema.nullable(schema.string().max(30)); for (const version of ["3.0.3", "3.1.0"]) { console.log(version, JSON.stringify(convertSchema(dueBefore, { version }).schema)); }

A value that may be null is written "nullable": true in 3.0 and as a list of types, ["string", "null"], in 3.1.

 What does this print? import { convertSchema } from "@zudojs/openapi"; import { schema } from "@zudojs/schema"; const priority = schema.number().int().gt(0); for (const version of ["3.0.3", "3.1.0"]) { console.log(version, JSON.stringify(convertSchema(priority, { version }).schema)); }

gt(0) means "greater than 0, not equal". 3.1 writes "exclusiveMinimum": 0; 3.0 writes "minimum": 0 plus "exclusiveMinimum": true.

 Your openapi.json parses fine with JSON.parse. Is the document correct?

validate() checks the OpenAPI rules and returns { valid, errors, warnings }. Being valid JSON only means the brackets match.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addRoute({ method: "get", path: "/tasks", metadata: { openapi: { operationId: "tasks.list", security: [{ bearer: [] }], responses: { "200": { description: "All tasks" } }, } } }); const result = manager.validate(); console.log(result.valid, result.errors.length);

The operation asks for a security scheme called bearer that the document never declares. Such a document looks protected, but tools cannot tell how to send a token. Declare it with addSecurityScheme.

 Why is an undeclared security scheme a real problem and not just a style issue?

A generated client would not know to add an Authorization header, and readers are misled about how to call the API. The validator catches it.

 What does this print? import { createComponentReference, OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addRoute({ method: "get", path: "/tasks", metadata: { openapi: { operationId: "tasks.list", responses: { "200": { description: "All tasks", content: { "application/json": { schema: createComponentReference("schemas", "Task") }, } } }, } } }); console.log(manager.validate().errors.map((issue) => issue.message));

The $ref points at a Task schema that was never added with addSchema. The validator follows every reference and reports the ones that go nowhere.

 What does this print? import { createComponentReference, OpenAPIManager, OpenAPIValidationError } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); manager.addRoute({ method: "get", path: "/tasks", metadata: { openapi: { operationId: "tasks.list", responses: { "200": { description: "All tasks", content: { "application/json": { schema: createComponentReference("schemas", "Task") }, } } }, } } }); try { manager.generate(true); console.log("generated"); } catch (error) { console.log(error instanceof OpenAPIValidationError); }

generate(true) validates first and throws an OpenAPIValidationError when something is wrong. In a build script, that stops a broken document from being written.

 What does the lesson advise about the responses of each route?

Only you know what a route really answers: a DELETE that answers 204, a create that answers 201, the errors a client must handle. A document that guesses is a document that lies.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ version: "3.1.0", info: { title: "Task API", version: "1.0.0" }, branding: false }); console.log(manager.toYAML().split("\n").slice(0, 4).join("\n"));

YAML writes the same data with indentation instead of braces. Nested fields such as title are indented under info:.

 Why does the build script call toJSON(true) and toYAML(true)?

Validating before saving means the committed files are always valid. If something is wrong, the script throws instead of writing a bad file.

 Why commit openapi.yaml to git?

A diff in openapi.yaml is an easy-to-read summary of an API change. An accidental breaking change is spotted in review instead of by your users.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); const answer = manager.toResponse(); console.log(answer.status, answer.headers["content-type"], typeof answer.body);

toResponse() gives { status, headers, body } with the document as JSON text. It works with any HTTP server: you copy the status, headers and body into your response.

 What does this print? import { OpenAPIManager } from "@zudojs/openapi"; const manager = new OpenAPIManager({ info: { title: "Task API", version: "1.0.0" }, branding: false }); const page = manager.toUIResponse({ specUrl: "/openapi.json", title: "Task API" }); console.log(page.headers["content-type"], "content-security-policy" in page.headers);

toUIResponse gives a complete HTML page with Swagger UI, which loads the document from specUrl. It comes with a content security policy that only allows scripts from the pinned CDN and the page's own known inline script.

 The docs page loads Swagger UI from a CDN. How does the manager protect it if the CDN file is ever changed by an attacker?

An integrity hash is a fingerprint of the exact file. If one byte changes, the fingerprint does not match and the browser blocks the script. The CSP header also limits where scripts may come from.

 Which of these is safe to put in an operation's description or example?

Everything in the document is visible to anyone who can open /docs. Use made-up examples only, never secrets, internal hosts or real tokens.

 A route is marked hidden: true, so it is left out of the document. Is it protected?

Hiding a route from the docs is not security. Attackers guess paths, read old documents and front-end code. Every route needs its own authentication and permission checks.

 In the last section, what does the loop over registry.getAll() give you?

The registry already knows each operation's name, input and output schemas, description and tags. Building the document from it means a new operation is documented the next time you build.

 The check-docs.ts script finds problems. How does it make the CI job fail?

CI looks at the exit code, not at the text. A non-zero exit code fails the build, so a broken reference never reaches the people who use your API.

Write a tiny validator. Finish brokenRefs(document, refs): each ref looks like #/components/schemas/Task. Return the refs whose schema name is not a key of document.components.schemas. The program should print [ '#/components/schemas/NewTask' ].

Finish unknownSchemes(requirements, schemes). requirements is an operation's security list, like [{ bearer: [] }]. Return the scheme names used there that are not keys of schemes. The program should print [ 'bearer' ] and then [].
