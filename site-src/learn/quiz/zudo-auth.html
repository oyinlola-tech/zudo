Ada is logged in and tries to delete Linus's task. Which question decides whether she may do it?

Authentication proves who is calling: Ada is already proven. Whether she may delete someone else's task is authorization, the topic of the Permissions lesson.

 The lesson ties every token to a server-side session. What does that give you that a plain JWT alone cannot?

A plain JWT lives until it expires; the server cannot take it back. With a session, the server looks it up per request, so deleting the session ends the login immediately.

 How should the users table store passwords?

A hash is one-way: it cannot be turned back into the password, so a leaked table does not leak passwords. Encryption and base64 can both be reversed. There is never a password column.

 Why does @zudojs/auth hash passwords with scrypt, which is slow on purpose?

scrypt is slow and needs a lot of memory. One login barely notices, but an attacker trying millions of guesses against stolen hashes is slowed down enormously.

A hash cannot be turned back into the password, so you can only make a new one when you have the plain password: right after verifyPassword succeeds at login.

The secret is what makes a signature trustworthy. It comes from an environment variable (a .env file that git ignores, or your hosting platform), and the app refuses to start without it.
