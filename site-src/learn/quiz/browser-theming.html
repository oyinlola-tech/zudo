Why does the lesson name colours by role (--surface, --ink) instead of by value (--white, --navy)?

--white that turns navy in dark mode is a lie in the stylesheet. --surface is "a card" in both themes, so a rule written once stays correct when the dark block gives it a new value.

 Ada swapped every black for white and every white for black, and the muted grey hint text became unreadable in dark mode. What went wrong?

The lesson lifts the muted grey in dark mode rather than inverting it, and keeps body text at 4.5:1 or better on both surfaces. Arithmetic on colours is not a substitute for checking the ratio.

 After the tokens are declared, what does switching the whole page to dark require?

document.documentElement.setAttribute("data-theme", "dark") is the whole switch. The :root[data-theme="dark"] block redefines the tokens, and the rules that use var() do not know anything happened.

 Why does the lesson keep the preference ("system", "light", "dark") separate from the resolved theme ("light", "dark")?

A visitor on "system" sees dark at night and light by day without touching anything. Storing the resolved theme would freeze that; storing the preference keeps the OS in the loop.

 resolveTheme("banana", false) returns "light". Why is that the right result?

The safe default for a preference nobody recognises is the OS answer. With the OS not preferring dark, that is light.

 Why does writePreference(storage, "system") remove the key instead of storing the string "system"?

Storing only explicit choices keeps the meaning of "nothing stored" clear, and it means the boot script's default (follow the OS) and the visitor's choice of "system" are the same state.

 Ada's page is painted light for a moment and then goes dark on every reload. Where must the code that sets the theme attribute run to stop the flash?

The browser will not paint until the stylesheet has arrived, so an inline script placed above the stylesheet is guaranteed to run before the first paint. Anything deferred runs after it.

 The boot script reads localStorage inside try … catch even though the catch block does nothing. Why?

The boot script must never throw. If storage is unavailable, the catch leaves saved as null, which resolves to the OS answer, and the page is still themed correctly.

 Tab A changes the theme to dark. What does Tab B, open on the same site, receive?

The storage event fires in every other tab of the same origin when localStorage changes. The tab that made the change does not receive it, because it already knows. A key of null means the other tab cleared everything.

 The code editor on this site switches its own colour scheme when the site theme changes. How does the theme module tell it, without knowing the editor exists?

One event, any number of listeners. The theme module has one job and never imports the editor, the chart or anything else that happens to care.

 What does color-scheme: dark on the root element change?

color-scheme tells the browser which theme the page is, so its built-in widgets match. Your tokens are still yours to define.

 In the lesson's stylesheet the dark block does not redefine --accent. What is the effect?

A custom property resolves to the nearest declaration that applies. The dark block only overrides what it declares; everything else keeps the value from :root.

 Why is a defer script the wrong place to set the theme attribute?

The first paint happens once the blocking stylesheet is in; deferred scripts run later. The boot block goes inline in <head>, above the stylesheet, precisely because inline scripts block parsing.

 The OS switches to dark at sunset. Which event tells the page, and what should the page do if the visitor explicitly chose light?

A visitor who chose light stays light at sunset. The change listener checks the stored preference and only re-applies when it is "system".

 Tab A calls localStorage.setItem("theme", "dark"). Does Tab A itself receive a storage event?

The storage event exists to tell other documents. The tab that wrote the value updates itself directly.

 A storage event arrives with event.key === null. What happened?

A null key means the whole storage was cleared. The lesson's handler treats it like "our value is gone" and re-applies "system".

 Because the boot script resolves "system" itself and always sets data-theme to "light" or "dark", what does the CSS need?

Resolving in one place avoids two copies of the dark tokens that could drift apart. The trade-off is that without JavaScript the page is always light, which the lesson accepts.

 Which of these is the theme module allowed to know about?

The theme module has one job and one event. Listeners come and go without the module changing.
