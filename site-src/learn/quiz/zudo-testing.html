What does @zudojs/testing add to Vitest?

It does not run tests; Vitest still does that. It gives you a test double for each moving part of a ZudoJS app, and structural assertions.

 Why install vitest and @zudojs/testing with -D?

-D saves them under devDependencies. A production install can leave them out, which keeps the deployed app smaller.

 Why does the task service receive now, logger, events and mailer instead of creating them itself?

This is dependency injection. In production you pass () => new Date() and a real mailer; in a test, a test clock and a mock. The service code does not change.

 Why is a test that reads the real clock a problem for "remind me about overdue tasks"?

A test must give the same result every time. A test clock only moves when you tell it to, so "two days later" takes no time at all.

 What does this print? import { createTestClock } from "@zudojs/testing"; const clock = createTestClock("2026-10-01T09:00:00Z"); clock.advance(90_000); console.log(clock.now.toISOString()); clock.add({ days: 2, hours: 3 }); console.log(clock.now.toISOString());

advance(ms) moves forward by milliseconds: 90 000 ms is 1 minute 30 seconds. add takes days, hours, minutes or seconds, so 2 days and 3 hours later is 12:01:30 on 3 October.

 What does this print? import { createTestClock } from "@zudojs/testing"; const start = new Date("2026-10-01T09:00:00Z"); const clock = createTestClock(start); clock.add({ days: 5 }); clock.set(start); clock.add({ minutes: 30, seconds: 15 }); console.log(clock.now.toISOString());

set(date) jumps to any time, here back to the start. Then 30 minutes and 15 seconds are added.

 Your test clock started at 1 October 2026. After some add calls you want to go back to the start. What should you call?

Watch out: clock.reset() jumps to the real current time, not back to your start. set(start) goes exactly where you want.

 What does this print? import { createMockFn } from "@zudojs/testing"; const send = createMockFn(); send.mockReturnValue("queued"); console.log(send("ada@example.com", "Overdue: Buy milk")); send("bo@example.com", "Overdue: File taxes"); console.log(send.callCount, send.calls[1][0]);

A mock function records every call. calls is a list of argument lists, so calls[1][0] is the first argument of the second call. mockReturnValue sets what it returns.

 What does this print? import { createMockFn } from "@zudojs/testing"; const send = createMockFn(); console.log(send("ada@example.com"), send.callCount);

Without mockReturnValue or mockResolvedValue, a mock returns undefined. It still records the call.

 The mailer's send is async. How do you make its mock return a promise of undefined?

mockResolvedValue(v) makes the mock return a promise that resolves to v, like a real async function. mockRejectedValue(error) makes it fail.

 The mail server is down. What does this print? import { createMockFn } from "@zudojs/testing"; const send = createMockFn(); send.mockRejectedValue(new Error("SMTP server unreachable")); try { await send("ada@example.com", "Overdue: Buy milk"); } catch (error) { console.log(error.message, send.callCount); }

mockRejectedValue makes every call fail with that error, so you can test what your code does when the mail server is down. The failed call is still recorded.

 What does this print? import { createSpyLogger } from "@zudojs/testing"; const logger = createSpyLogger("tasks"); logger.info("task created", { taskId: 1 }); logger.warn("mailer slow"); console.log(logger.calls.map((call) => `${call.method} ${call.message}`));

A spy logger is a complete logger that prints nothing and remembers every line in calls, with its method, message and metadata. A test can check what was logged without reading the terminal.

 You want to record the calls of a real object's method and later put the original back. Which helper fits?

createSpyMethod wraps the real method and records its calls until you call restore(). createStub makes a new object whose methods do nothing unless you write them.

 What does this print? import { createSpyMethod } from "@zudojs/testing"; const greeter = { greet(name) { return `hi ${name}`; } }; const spy = createSpyMethod(greeter, "greet"); console.log(greeter.greet("ada"), spy.calls.length); spy.restore(); console.log(greeter.greet("bo"));

A spy calls the real method, so it still returns hi ada, and it records the call. After restore() the original method is back and works as before.

 Why does the lesson test through the app's real registerTasks wiring with createTestContainer, instead of building the service by hand?

The test swaps only the outside world (clock, logger, events, mailer, config) and uses the real wiring. So the wiring itself is tested too.

 What does createTestContainer({ overrides: [...] }) give you?

Each override is a token plus the value to use, such as { token: CLOCK, useValue: () => clock.now }. Then you call the app's real registration code on it.

 A test needs tasks.maxOpenTasks to be 1. What does the lesson use?

A test config manager is a real ConfigManager, so the wiring reads it exactly as in production. Changing environment variables or files would leak into other tests.

 A test starts an HTTP server and forgets to stop it. What can happen?

Open servers, queues and timers keep running after a test. A cleanup manager holds an "undo" function for each, and dispose() runs them all.

 What does this print? import { createCleanupManager } from "@zudojs/testing"; const cleanup = createCleanupManager(); const stopped = []; cleanup.register(() => stopped.push("database"), "database"); cleanup.register(() => stopped.push("queue"), "queue"); cleanup.register(() => stopped.push("server"), "server"); await cleanup.dispose(); console.log(stopped, cleanup.disposed);

dispose() runs the cleanups in reverse order: last started, first stopped. A server must stop before the queue and database it uses are closed.

 One cleanup fails. What does this print? import { createCleanupManager } from "@zudojs/testing"; const cleanup = createCleanupManager(); const stopped = []; cleanup.register(() => stopped.push("database"), "database"); cleanup.register(() => { throw new Error("queue stuck"); }, "queue"); try { await cleanup.dispose(); } catch (error) { console.log("reported:", error.message); } console.log(stopped);

A failing cleanup does not stop the others: the database was still closed. At the end, dispose() reports every cleanup that failed, by name.

 What should you pass to createTestApplication, according to the lesson?

The defaults would print log lines in your test output and make time depend on when the test runs. Passing a spy logger and a test clock keeps tests quiet and repeatable.

 What does this print? import { deepEqual } from "@zudojs/testing"; const a = { tags: new Set(["home"]) }; const b = { tags: new Set(["work"]) }; console.log(JSON.stringify(a) === JSON.stringify(b), deepEqual(a, b));

This is the trap: JSON.stringify turns every Set into {}, so two different sets look equal. deepEqual compares their members and sees the difference.

 What does this print? import { deepEqual } from "@zudojs/testing"; console.log( deepEqual({ due: new Date(0), id: 1 }, { id: 1, due: new Date(0) }), deepEqual([1, 2], [2, 1]), deepEqual(new Date(0), new Date(1)), );

Object keys may come in any order. Array items must be in the same order. Dates are compared by the time they hold, and 0 ms and 1 ms are different.

 What does this print? import { findDifference } from "@zudojs/testing"; const difference = findDifference({ task: { tags: ["home", "urgent"] } }, { task: { tags: ["home", "later"] } }); console.log(difference.path);

findDifference names the path of the first difference, so you see exactly where it broke: the second tag (index 1) of the task.

 What does this print? import { assertResponseBody, createHTTPResponse } from "@zudojs/testing"; const response = createHTTPResponse(201, { id: 1, title: "Buy milk", done: false }); try { assertResponseBody(response, { id: 1, title: "Buy milk", done: true }); console.log("matched"); } catch (error) { console.log(error.message); }

An assertion throws when a value is wrong, and names the path of the difference: body.done. The id and title matched; only done did not.

 What does this print? import { ConflictError } from "@zudojs/errors"; import { assertErrorCode, assertRejects } from "@zudojs/testing"; const error = await assertRejects(async () => { throw new ConflictError("You already have 3 open tasks."); }, "open tasks"); assertErrorCode(error, "ERR_CONFLICT"); console.log("rejected with", error.name);

assertRejects(fn, text) checks that the async function fails with a message containing text, and returns the error so you can check more, such as its code.

 The function does not fail. What does this print? import { assertRejects } from "@zudojs/testing"; try { await assertRejects(async () => "created", "open tasks"); console.log("passed"); } catch (error) { console.log(error.message); }

A test that expects a failure must fail itself when no error comes. Otherwise a bug that removes the limit would still pass the test.

 Which assertion checks that a synchronous function throws?

assertRejects is for async functions (a rejected promise). For code that throws right away, use assertThrows.

 What does an integration test check that a unit test with fakes does not?

The 409 in the lesson comes from a ConflictError thrown deep in the service and mapped to a status by the route. Only a test that runs the whole chain checks that mapping.

 Why does the integration test start the server on port 0?

A fixed port like 3000 may already be used by your dev server or another test. Port 0 always works; the test reads the real port from server.address.

 What does this print? import { assertCreated, assertResponseBodyContains, assertResponseStatus, createHTTPResponse } from "@zudojs/testing"; const created = createHTTPResponse(201, { id: 1, title: "Buy milk", done: false }); assertCreated(created); assertResponseBodyContains(created, { id: 1, title: "Buy milk" }); try { assertResponseStatus(created, 200); } catch (error) { console.log(error.message); }

assertCreated checks for 201, and assertResponseBodyContains only checks the fields you list, so both pass. assertResponseStatus(created, 200) fails, because a create answers 201.

 Why does the Vitest suite create fresh doubles in beforeEach?

Shared state between tests makes the result depend on the order they run in. New doubles for every test keep them independent.

 Why is cleanup.dispose() in afterEach, not at the end of each test?

A failing assertion throws and skips the rest of the test. Cleanup at the end of the test body would never run, and the open server would break the next test.

 After the suite passes, the lesson changes clock.add({ days: 2 }) to clock.add({ hours: 12 }). Why?

A test that can never fail proves nothing. After 12 hours nothing is overdue, the reminder count is 0, and the test fails. The clock really drives the result.

 Why does the lesson also check that no sms.send message was dispatched?

Tests usually check that something happened. Checking that something harmful did not happen catches a different, often more dangerous, class of bugs.

Catch the error first, then decide outside the try. If you threw "did not reject" inside the try, your own catch would swallow it and the check would silently pass.
