What is REST?

REST is not something you install. It is a way of designing an API: URLs name resources, methods are the verbs, and the body carries a representation. Follow the habits and developers can guess how your API works.

 Which request deletes task 7 in REST style?

The item URL is /tasks/7, and the method DELETE is the verb. A GET must never change data, so ?action=delete is the worst choice of all.

 An old API has POST /tasks/7/markDone. What is the REST way to mark task 7 as done?

Marking a task done changes one field of an existing resource, which is exactly what PATCH is for. The URL stays the plain item URL.

 A client sends POST /tasks and the task is created. What should the success response be?

201 Created says a new resource exists. The body returns it (with its new id), and Location gives its URL, for example /tasks/8.

 What does a successful DELETE /tasks/7 usually return?

204 No Content means "it worked, and there is nothing to send back". 404 is for a task that did not exist when the request arrived.

 What is the difference between PUT /tasks/7 and PATCH /tasks/7?

With PUT you send the complete new representation. With PATCH you send only what changes, such as {"done": true}.

 Which URL follows the naming habits from the lesson?

Use plural nouns, lower case, and hyphens between words. /getTaskLists also hides a verb in the URL.

 Comment 2 belongs to task 7, which belongs to project 3. Task 7 has its own id. Which URL does the lesson recommend for the task's comments?

Nest at most one level. Once a task has its own id, address it directly as /tasks/7; the project is not needed in the URL.

 Why does the lesson say to write the API contract before writing code?

The contract (URLs, bodies, status codes) is a promise. Web apps, mobile apps and other teams depend on it, so decide it carefully up front.

 Why should a list endpoint return {"data": [...], "meta": {...}} instead of a bare array?

A bare array has nowhere to put extra information. With an object, adding meta.total or a cursor later is an additive change that old clients simply ignore.

 What does this print? const params = new URLSearchParams("limit=5&done=false"); console.log(typeof params.get("limit"), params.get("done") === false, params.get("sort"));

Every query value arrives as a string, so "false" is not the boolean false. A missing parameter gives null, not undefined.

 A client sends ?limit= with nothing after the equals sign. What does this print? const params = new URLSearchParams("limit="); const n = Number(params.get("limit")); console.log(params.has("limit"), n, Number.isInteger(n) && n >= 1);

The parameter is present, with the empty string as its value. Number("") is 0, which is below the minimum of 1, so a range check rejects it.

 This is the check the lesson uses for limit. What does it print? function ok(text) { const n = Number(text); return Number.isInteger(n) && n >= 1 && n <= 100; } console.log(ok("20"), ok("2.5"), ok("abc"), ok("500"));

Number.isInteger is false for 2.5 and for NaN (from "abc"). 500 is a whole number but above the maximum of 100.

 What does this print? const sort = "-createdAt"; const field = sort.replace(/^-/, ""); console.log(field, sort.startsWith("-"));

The regular expression /^-/ removes a minus sign only at the start. The leading minus is the usual way to ask for descending order.

 A client sends ?sort=password. Why must the server check the field against an allow-list?

Never sort by whatever the client sends. An allow-list such as ["id", "title", "createdAt"] keeps private columns out of reach and turns anything else into a clear 400.

Both the search text and each title are lowered before comparing, so the search ignores upper and lower case and finds both tasks.

 Two tasks have the same createdAt. When you sort by createdAt in SQL, what should you add?

toSorted keeps equal items in their original order, but a database gives no such promise. Without a tie-breaker, equal rows can swap places between pages.

 With ?limit=3&offset=3, which items are sent? const items = ["a", "b", "c", "d", "e", "f", "g"]; const limit = 3; const offset = 3; console.log(items.slice(offset, offset + limit));

Offset means "skip this many": skip 3 (a, b, c), then take 3. slice stops before its end index.

 A client reads the newest items, two per page. Between page 1 and page 2, item 5 is deleted. What does this print? let ids = [6, 5, 4, 3, 2, 1]; const page1 = ids.slice(0, 2); ids = ids.filter((id) => id !== 5); const page2 = ids.slice(2, 4); console.log(page1, page2);

After the delete, everything shifts one place forward. Item 4 moved to position 1, which was already read, so the client never sees it. Offset pagination can skip or repeat items when data changes.

 What does this print? const cursor = btoa(JSON.stringify({ before: 5 })); console.log(cursor); console.log(JSON.parse(atob(cursor)).before);

btoa turns text into Base64 and atob turns it back. The cursor is the same one the lesson's server produced for "ids smaller than 5".

 Why does the lesson encode the cursor with Base64 instead of sending {"before": 5} as plain JSON?

Base64 is not encryption: anyone can decode it. It only signals "do not look inside". The server must still validate every cursor it receives.

 This is the lesson's cursor decoder. What does it print? function decodeCursor(cursor) { try { const { before } = JSON.parse(atob(cursor)); return Number.isInteger(before) ? before : null; } catch { return null; } } console.log(decodeCursor("eyJiZWZvcmUiOjV9"), decodeCursor("hello!"), decodeCursor(btoa('{"before":"x"}')));

What does this print? const tasks = [1, 2, 3, 4, 5, 6, 7]; const page = (before, limit) => tasks.filter((id) => id < before).toSorted((a, b) => b - a).slice(0, limit); const p1 = page(Infinity, 3); tasks.push(8); const p2 = page(p1.at(-1), 3); console.log(p1, p2);

The cursor remembers where page 1 ended (id 5), not how many items to skip. The new task 8 is larger than 5, so it cannot push anything onto page 2 twice.

 A mobile app has an activity feed with infinite scroll. New activity arrives all the time. Which pagination fits best?

The user only scrolls forward and data changes constantly. A cursor never repeats or skips items when new ones arrive.

 What media type does an RFC 9457 problem details response use?

application/problem+json tells the client from the header alone that the body is a problem details object.

 Which problem details field is a URL that names the kind of problem, so clients can compare it in code?

type never changes for a given kind of problem, so it is safe to compare. title is for humans, and detail describes this one occurrence.

 What does this print? function problem(status, type, title, detail, extra = {}) { return { type: `https://example.com/problems/${type}`, title, status, detail, ...extra }; } const body = problem(404, "not-found", "Not Found", "No task 9"); console.log(body.status, body.type, Object.keys(body).length);

The type is built into a full URL. With no extra, the object has four keys: type, title, status and detail.

 A database query fails inside GET /v1/tasks. What belongs in the problem details detail sent to the client?

Attackers read error messages too. Stack traces, SQL and file paths reveal how your server is built. Log them on the server and send a plain message.

 Which change is a breaking change that needs a new API version?

Renaming or removing a field makes working clients fail, because they still read done. The other three are additive: old clients keep working.

 What is the most common way to version a REST API, as used in the lesson?

A path version is visible in every log line and easy to route. Some APIs use a header such as Accept-Version: 2 instead.
