Which part of an uploaded file can your server actually verify?

The name, the declared type and any size header are written by the client, and an attacker writes whatever gets past you. The bytes are what you store, so you check those.

 A handler saves uploads with writeFile(join("uploads", file.filename), bytes). What can a client do with the file name ../../app/config.json?

join resolves .., which is exactly what climbs out of the folder. Never use a client's name as a path; generate the key and keep the cleaned name as a label.

 Which object key is the best choice for an attachment of task 12?

A generated random key contains nothing the user typed, cannot collide, cannot be guessed, and the tasks/12/ prefix still lets you list a task's files. A timestamp can collide and is guessable; an email in a key leaks personal data into logs and URLs.

Limits only help if they act before the work they limit. The parser runs inside your handler, after the body has been read. The adapter's limit is the first gate, and it answers 413 on its own.

 Your API accepts up to 3 files of 2 MB each in one request, and JSON bodies elsewhere. What is a sensible maxBodySize?

maxBodySize applies to every route, so choose the largest real request and no more. Anything much bigger than a few megabytes should go directly to object storage with a presigned URL instead.

 What is a "magic number" in a file?

Most binary formats begin with a fixed signature. Reading it to decide the real type is content sniffing, and it is far harder to fake by accident than an extension or a header.

 Saving an attachment writes the bytes to object storage and a row to the database. They cannot share a transaction. Which order does the lesson use, and why?

A row without bytes is a broken link users can click. Bytes without a row are invisible and can be cleaned up by a sweeper. Choose the order whose failure is harmless.

 A request carries three files, and the third is not an allowed type. Why does uploadAll run checkFile on every file before storing any?

Validate everything that can be validated up front. Failures that can only happen while storing (storage down) are then handled by removing the files already saved.

 Why does the service rely on the foreign key on attachments.task_id to answer 404 for a missing task, instead of only checking "does the task exist?" first?

"Check, then act" has a gap. A pre-check can still be useful to avoid storing bytes you will delete, but the constraint is what makes the rule hold.

 What does the response header X-Content-Type-Options: nosniff do for a download?

Without it, some browsers "help" by rendering content that looks like HTML as HTML, which turns an uploaded file into a page on your domain. Saving instead of opening is Content-Disposition: attachment's job.

 Why build the Content-Disposition header with createAttachmentDisposition(name) instead of `attachment; filename="${name}"`?

File names are user input, and headers have their own syntax. Set-Cookie smuggled through a file name is a real attack. Let the helper do the quoting and the filename* encoding.

 Why does the download route send Cache-Control: private?

private allows the user's own browser to cache the response but forbids shared caches. Attachments usually belong to a person or a team.

An in-memory lock only coordinates code in one process. The database's fence check stays the same, but the fence numbers must come from something all servers share.

 Which situation leaves an orphaned object that compensation cannot clean up?

Compensation is code that runs after an error your code sees. A crash or a failing delete leaves bytes nobody references. A sweeper finds and removes them later.

 Why does the orphan sweeper only delete objects older than a grace period?

The grace period must be longer than any upload can take between the two writes. Anything younger might still be in progress.

ObjectStorage is an interface, so a test can put a failing implementation in its place. Fault injection makes rare failures happen on demand, which is the only way to test recovery code.

 Users need to upload 500 MB videos. What is the usual design?

Large files should not pass through your API process's memory at all. A presigned URL allows exactly one upload of one key for a short time, and the API still checks size and type before trusting it.
