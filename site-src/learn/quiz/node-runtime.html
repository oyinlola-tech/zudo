What is a JavaScript runtime, such as Node.js or a browser?

The JavaScript language has no way to read a file or open a connection. The runtime adds those: a browser gives you window and document; Node.js gives you files, servers and process.

 Which is true about the browser runtime compared with Node.js?

The browser protects your files for safety. Node.js is a runtime for servers and your own computer, so it can read and write files and start servers.

 Run with Node.js. What does this print? console.log(typeof window, typeof document, typeof process);

Node.js has no web page, so there is no window or document. Instead there is process, an object that describes the running program.

 Run with Node.js. What does this print? console.log(typeof process.version, process.version.startsWith("v"), typeof process.versions.v8);

process.version is text like "v24.19.0". process.versions lists the version of each part, including the V8 engine, also as text.

 Which part of Node.js reads your JavaScript, turns it into machine code and runs it?

V8 is the JavaScript engine, written by Google for Chrome. That is why Chrome and Node.js print the same error messages.

 What does libuv do inside Node.js?

libuv is a C library. It waits for files, the network and timers, so your JavaScript does not have to, and queues the callbacks when the answers are ready.

 How do the Node.js APIs such as node:fs fit in?

You import them with the node: prefix. They are built in, so nothing needs installing, and they use libuv underneath to reach the computer.

 What does the event loop do?

When a file has been read or a timer is due, libuv puts the callback in a queue. The event loop runs queued callbacks one by one. When nothing is left to wait for, the program ends.

 Node.js runs your JavaScript on one thread. How can one server still answer thousands of people?

A backend mostly waits for databases and networks. That waiting does not use the JavaScript thread, which runs whichever callback is ready next.

 Which two kinds of callbacks are called microtasks in the lesson?

Microtasks are small jobs that run right after the current code, before the event loop moves on to I/O, setImmediate and timers.

 At the top level of a file, you schedule setTimeout(A, 0) and setImmediate(B). B must happen after A. What should you do?

Outside an I/O callback, which of the two runs first depends on how fast the program started. Never write code that depends on which timer wins.

 A route must process a huge file. What does the lesson recommend instead of one long synchronous job?

While long synchronous code runs, every timer and every other request waits. setTimeout(work, 0) only delays the blocking; it does not remove it.

 How do you load Node.js's built-in file module in an ES module project?

Built-in modules use the node: prefix and need no install. require is CommonJS and does not exist in an ES module.

 Which built-in module would you use for random ids and hashes?

node:crypto gives random ids, hashes and encryption. node:path builds file paths, node:os gives facts about the computer, node:events announces that something happened.

fetch, URL and Buffer are global in Node.js. require belongs to CommonJS and does not exist in an ES module.

 What does an exit code of 0 mean?

Scripts, test runners and tools like Docker read the exit code to know whether your program worked. 0 is success; anything else is failure.

 What is the difference between process.exitCode = 1 and process.exit(1)?

Setting process.exitCode is gentler: the program ends normally with that code when there is nothing left to do. process.exit stops immediately.

 Why write a usage message with console.error instead of console.log?

Both appear in your terminal, but they are separate streams. You still set process.exitCode = 1 yourself to report failure.

 You run node learn-node/where.js from the folder above learn-node. What is process.cwd()?

process.cwd() is the working directory, not the file's folder; import.meta.dirname gives the file's folder. A relative path like "tasks.json" is looked up from the working directory.

 Run with Node.js. What does this print? const { rss, heapUsed } = process.memoryUsage(); console.log(typeof rss, typeof process.pid, rss >= heapUsed);

process.memoryUsage() reports bytes as numbers. rss is all the memory the process holds; heapUsed is the part your JavaScript objects use, so it is smaller.

 A server's heapUsed keeps growing for days and never goes down. What does that usually mean?

The garbage collector frees only objects nothing can reach. A cache or list that only ever grows keeps everything reachable, so memory climbs until the server fails.

 Why should a database password come from an environment variable instead of being written in the code?

Settings that change between your computer and the server, and secrets above all, belong outside the code. Node.js puts environment variables in process.env.

 Run with Node.js. What does this print? process.env.QUIZ_LIMIT = 5; console.log(typeof process.env.QUIZ_LIMIT, typeof process.env.QUIZ_SURELY_NOT_SET);

Every value in process.env is a string (even the 5 became "5"), or undefined when it is not set. Convert and check it before you use it as a number.

 Run with Node.js, with QUIZ_PORT not set. What does this print? const port = Number(process.env.QUIZ_PORT ?? 3000); console.log(port, typeof port);

The variable is undefined, so ?? uses the default 3000. A port is not a secret, so a default is fine.

 The server needs TASKS_API_KEY. What should it do when the variable is not set?

A secret never gets a default. A server that starts without its key fails later in a confusing way, or runs without protection. Fail loudly at start-up.

 The config code wants to confirm the API key was loaded. What is the safe thing to print?

Secrets do not belong in logs. Logs are shared and stored, so the lesson prints only the key's length.

 You run PORT=5000 node --env-file=.env config.js, and .env has PORT=4000. Which port does the program see?

Values set before the command win. On a server, the hosting platform sets the real values this way, and the code only reads process.env.

 On a server that sets real environment variables, there is no .env file. Which flag lets Node.js start anyway?

With --env-file=.env, a missing file stops Node.js before your code runs. --env-file-if-exists treats the file as optional.

 How should a project handle its .env file with Git?

.env holds real secrets and must never be committed. .env.example tells others which variables to set, without any real values.

 You pushed a real API key to GitHub by mistake. What must you do?

Once pushed, a secret stays in the Git history and may already be copied. Deleting the file does not help. Replace (rotate) the secret.
