A repository finds out that book 42 does not exist. What should it throw?

Code deep inside the app should not need to know HTTP. It says what went wrong with a typed error. One function in the HTTP layer, toErrorResponse, maps each type to its status code.

 Which mapping does the BookStore's toErrorResponse use?

400: fix your request, the issues say what is wrong. 404: the thing in the URL does not exist. 409: the request is fine but clashes with the current data. Unknown errors are still a generic 500.

 Which situation is a 409 Conflict in the BookStore?

The order is well-formed, but it clashes with the current data. The same goes for creating a second author with a name that already exists. A wrong field is 400, and a missing resource in the URL is 404.

 Why do the helpers text and whole push a message to issues and return a placeholder, instead of throwing?

After all fields are read, done throws one ValidationError with every issue. The client can fix everything in one go. The placeholders are never saved, because done throws first.

 Why does every check have a maximum, such as a title of at most 200 characters and a quantity of at most 100?

Valid-looking but huge values waste memory and storage, or place absurd orders. A check that only looks at the type is not enough: always set a sensible range.

 A client sends {"name": "Ada", "id": 1, "isAdmin": true} to POST /authors. What does parseNewAuthor return?

The parser builds a new object from the fields it checked. Extra fields like id or isAdmin are dropped here and can never reach the database.

 What is PGlite?

It is the real database engine with no server to install. It keeps data in memory, or in a folder if you give it one. The SQL is the same, so moving to a PostgreSQL server later changes one file.

 Why is PGlite installed with npm install @electric-sql/pglite, without -D?

TypeScript, tsx and @types/node are development tools (-D). The database library is used by the server when it runs, so it goes in dependencies.

 author_id integer NOT NULL REFERENCES authors (id). What does REFERENCES do?

A foreign key makes the database protect its own data. Even a bug in your TypeScript cannot create a book pointing at a missing author, or delete an author who still has books.

 The code already validates bodies. Why also add UNIQUE, CHECK (stock >= 0) and foreign keys to the tables?

Validation checks the shape of one request. Only the database sees all the data at once, so rules like "no duplicate names" and "stock never below 0" belong there too. Both layers work together.

 Why do the migrations use CREATE TABLE IF NOT EXISTS?

openDatabase runs the migrations every time the server starts. Without IF NOT EXISTS, the second start would fail because the tables are already there. Real projects use a migration tool that remembers which steps ran.

 PostgreSQL throws an error with code: "23505" when creating an author. What happened, and what does the repository throw?

23505 means "unique rule broken" and becomes a 409 conflict. 23503 means "foreign key broken", which the book repository reports as a 400 validation issue (authorId 7 does not exist).

 search comes from a query string. Which query is safe?

With $1, the SQL and the value travel to PostgreSQL separately, so the value is only ever data, never SQL. Pasting it into the string, even with quotes removed or changed, lets crafted input rewrite the query: SQL injection.

 The book repository writes `SELECT ${COLUMNS} FROM books WHERE id = $1`. Why is pasting COLUMNS into the SQL safe?

The danger is outside input in SQL. A constant you wrote yourself cannot be changed by a client. Every value from outside still goes in as $1, $2, …

 Why does placing an order take the stock and insert the order in one SQL statement?

With a separate "read stock" and "write order", both requests could read "1 left" and both succeed. UPDATE … WHERE stock >= $2 inside the same statement only changes the book if there is enough stock.

 Where does an order's total_cents come from?

The price comes from the database, never from the client, so nobody can send their own price. The client only says which book and how many.

 Why is moving from PGlite to a PostgreSQL server (with pg) only one new file?

Repositories get a Queryable through their constructor: "run this SQL with these parameters and give me rows". connectPostgres wraps a pg.Pool in that shape, and no repository changes.

 DATABASE_URL looks like postgres://postgres:PASSWORD@localhost:5440/bookstore. How should you handle it?

The URL contains the password. It belongs in the environment of the server. The lesson even creates a random password in a shell variable, so it never appears in a file.

 A client deletes an author who still has books. PostgreSQL throws error 23503. What should the API answer?

The foreign key refuses to leave books without an author. The repository turns that code into a ConflictError, so the client learns why with a 409 instead of a generic 500.
