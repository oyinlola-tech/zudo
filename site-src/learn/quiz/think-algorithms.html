A step says: "Keep checking the shoebox until Mr Okafor's receipt appears." Which property of an algorithm does it break?

If the receipt is not in the box, you check forever. An algorithm must always stop, so it needs a rule for the "not there" case: stop after the last receipt and report "not found".

 A step says: "Count the big sales." Which property does it break?

"Big" means different things to different people, so two people following the step get different counts. A precise version says "sales above ₦10,000", and even then you must decide whether exactly ₦10,000 counts.

 A method says: "Look through every receipt in the box, one by one." Nothing else. What is missing for it to be an algorithm?

It does work, and it stops, but it produces no result. An algorithm must give at least one output, such as the matching receipt or "not found".

 Which step breaks the effective property, that every step can actually be carried out?

Nobody, and no computer, can do that step with the information available. The other steps are simple actions on data you have.

 Which three shapes of step are enough to build any algorithm?

Steps one after another (sequence), choosing a path (decision, if) and doing steps again (repetition, loops). Searching, counting and sorting are all built from these three.

 "If the item is a medicine, charge no VAT; otherwise charge 7.5%." Which shape is this?

It chooses between two paths based on a condition. In JavaScript that is if and else.

 "For each shelf, from the first to the last, check how many items are left." Which shape is this?

The same step is done again for every shelf. In JavaScript that is a loop, such as for (const shelf of shelves).

 A list has 1,000 customer names in no particular order. Using linear search, how many names must you look at to be sure that "Nwosu" is not in it?

Any name you skip could be the one. To prove something is missing, linear search has to look at every item. That is why "not found" is the slowest case.

 You can find a word in a paper dictionary without reading from "A". Why?

Sorted data lets you rule out half of what is left with each look. That faster method, binary search, only works because the order is known.

 In the search loop, what does break do when the name matches?

break leaves the loop it is in. Once the receipt is found there is no reason to keep looking, and the position counter stays at the match.

 To find the best day's profit, why start "best so far" at the first item of the list rather than at 0?

With profits of -2000, -500 and -1200, nothing is bigger than 0, so 0 would be reported. Starting with a real item guarantees the answer is one of the actual values.

 Which algorithm usually gives you a list with fewer items than you started with?

Filtering keeps only the items that match a rule. Transformation and sorting keep every item; totalling gives a single number.

 You transform a list of 8 prices from naira to kobo. How many items does the new list have?

A transformation makes one new item from every item, so the result has the same length. Checking that the lengths match is a quick test for any transformation.

 "Make a list of all invoices that have not been paid." Which algorithm is this?

It keeps the items that match a rule (unpaid) and produces a new, shorter list. Searching would find just one; counting would give a number.

 "Add 7.5% VAT to every price on the board." Which algorithm is this?

Every item becomes a new item by the same rule. The board has as many prices afterwards as before.

 "How many students scored above 70?" Which algorithm answers this?

Start at 0 and add 1 for every score that matches the rule. The output is a single number.

 Selection sort on the pile 9, 4, 7, 1: each round moves the smallest item from the pile to the end of the sorted row. What is the sorted row after two rounds?

Round 1 finds 1, the smallest of 9, 4, 7, 1. Round 2 finds 4, the smallest of what is left (9, 4, 7). The row is 1, 4, and the pile is 9, 7.

 Why does [4500, 12000].sort() put 12000 first?

Without instructions, sort compares text. For numbers, pass (a, b) => a - b. The general lesson: never trust a sort until you have checked it on an input whose right order you know.

 A day has no sales. The average algorithm divides the total by the number of sales. What should the program do?

0 divided by 0 is NaN ("not a number"). An empty list is a normal input, so the algorithm needs a proper output for it. Dividing by 1 would report an average of ₦0, which is also wrong.

 Which set of test inputs is best for a search algorithm?

Bugs hide at the edges: loops that stop one step early miss the last item, bad starting values break the first, and the "not found" path is the one people forget.

 The list has two receipts for "Okafor", at positions 2 and 4. The search uses break when it finds a match. Which does it report?

The search stops at the first match. Whether "the first one" is what Mrs Adeyemi needs (perhaps she wants the latest) is a question to ask; duplicates belong in your test list.

 In a test that searches for several names, one after another, why must position and found be set back to their starting values at the start of each search?

If found is still true from the first search, a later missing name looks "found". Every accumulator must start fresh for each run of the algorithm.

7.5% of 8,000 is 8,000 × 7.5 ÷ 100 = 600. The steps run in sequence, each using the result of the one before.
