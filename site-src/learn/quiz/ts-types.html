Which annotation should you write for a task title?

TypeScript's basic types are lowercase: string, number, boolean. String with a capital S is JavaScript's wrapper object, which you almost never want.

 A task has priority = 2 and estimateHours = 0.5. Which types do they get?

TypeScript has one number type for whole numbers and decimals alike, just like JavaScript has one kind of number.

 What does this print? const title: string = "Buy milk"; const priority: number = 2; const estimateHours: number = 0.5; const done: boolean = false; function label(title: string, priority: number): string { return `${title} (P${priority}, ${estimateHours}h)`; } console.log(label(title, priority), done);

The annotations only describe the values; they do not change them. The program prints the same thing plain JavaScript would.

 Which type means exactly the same as string[]?

string[] and Array<string> are two spellings of "an array of strings". [string] is different: a tuple with exactly one string.

 What does this print? const tags: string[] = ["home", "shop"]; const estimates: Array = [0.5, 2, 1]; function total(numbers: readonly number[]): number { let sum = 0; for (const n of numbers) sum += n; return sum; } tags.push("urgent"); console.log(tags, total(estimates));

tags is a normal string[], so push works. total only reads its readonly array: 0.5 + 2 + 1 is 3.5.

 Which line inside total does tsc reject? function total(numbers: readonly number[]): number { const first = numbers[0]; // line 2 numbers.push(0); // line 3 const count = numbers.length; // line 4 return numbers.reduce((a, b) => a + b, 0); // line 5 }

A readonly array can be read in every way, but it has no methods that change it, such as push, pop or sort. reduce only reads.

 Why would a function take readonly number[] instead of number[]?

readonly is a promise checked by the compiler: the function cannot call push, sort and so on. It does not freeze anything at runtime; the type is removed before running.

 A function returns a pair: the number of open tasks and the number of done tasks. Which return type describes that fixed shape?

A tuple has a fixed length and a type for each position. The labels open and done are only documentation. number[] would allow any length.

 What does this print? const entry: [number, string] = [1, "Buy milk"]; function countTasks(doneFlags: boolean[]): [open: number, done: number] { const done = doneFlags.filter((flag) => flag).length; return [doneFlags.length - done, done]; } const [open, done] = countTasks([true, false, false]); console.log(entry[1].toUpperCase(), open, done);

entry[1] is the string, so it can be uppercased. One flag is true, so done is 1 and open is 3 − 1 = 2. Destructuring takes the tuple apart in order.

 With const entry: [number, string] = [1, "Buy milk"];, which line does tsc accept?

Destructuring a tuple gives id: number and title: string. The others are errors: the tuple has no index 2, the positions are swapped, and entry[1] is a string, not a number.

 When does the lesson say an object is better than a tuple?

Tuples are fine for small, obvious pairs like [min, max]. With more positions, named properties are easier to read than remembering what index 4 means.

 What does this print? function describe(task: { id: number; title: string; done: boolean }): string { return `#${task.id} ${task.title}${task.done ? " (done)" : ""}`; } console.log(describe({ id: 1, title: "Buy milk", done: false })); console.log(describe({ id: 2, title: "Call Ada", done: true }));

The object type is written straight on the parameter. When done is false, the ternary adds an empty string, so only the second line gets " (done)".

 With type Task = { id: number; title: string; done: boolean }, which line does tsc accept?

The order of properties does not matter. a is missing done, and b and c have properties the type does not know; in an object literal an extra property is an error, because it is almost always a typo.

 With strict on, what is the type of task here? type Task = { id: number; title: string }; const tasks: Task[] = [{ id: 1, title: "Buy milk" }]; const task = tasks.find((t) => t.id === 2);

find gives undefined when nothing matches, and TypeScript remembers that. The | makes a union: "a task, or undefined".

 After const task = tasks.find((t) => t.id === 2);, you write console.log(task.title);. What does tsc say?

This is strictNullChecks, switched on by strict. Without it, the program could crash with Cannot read properties of undefined, one of the most common JavaScript errors.

 What does this print? type Task = { id: number; title: string; note: string | null }; const tasks: Task[] = [{ id: 1, title: "Buy milk", note: null }]; const task = tasks.find((t) => t.id === 2); if (task === undefined) { console.log("task 2 not found"); } else { console.log(task.title); } console.log(tasks[0]?.title); console.log(task?.title ?? "(no title)"); console.log(tasks[0]?.note ?? "(no note)");

No task has id 2, so the if branch runs and task?.title is undefined. ?? replaces both undefined and null, so the missing title and the null note both get the fallback text.

 Inside if (task !== undefined) { ... }, TypeScript treats task as a Task, not Task | undefined. What is this called?

A check makes the type smaller: that is narrowing. The compiler follows your if, typeof and === checks to know which case you are in.

 What does this print? const estimate: number | null = 0; const note: string | null = null; console.log(estimate ?? 1, estimate || 1, note ?? "(no note)");

?? uses the fallback only for null or undefined, so 0 ?? 1 keeps the 0. || also replaces falsy values like 0, which is usually a bug for numbers.

 The list is empty. What does this print? type Task = { id: number; title: string }; const tasks: Task[] = []; console.log(tasks[0]?.title, tasks.find((t) => t.id === 1)?.title ?? "none");

?. stops and gives undefined when the value on its left is missing, instead of crashing. Only the second expression has a ?? fallback, so only it prints none.

 The lesson (and ZudoJS) uses a convention for undefined and null. Which one?

A property like note: string | null is always present, but may be deliberately empty. That is also how a database NULL column arrives in your code.

 With the lesson's tsconfig.json, what is the type of tasks[0] when tasks is a Task[]?

Indexing an array gives the element type. Only the stricter noUncheckedIndexedAccess setting makes it Task | undefined. That is why the lesson writes tasks[0]?.title to be safe.

 This file passes tsc. What does it print? let input: any = "Buy milk"; console.log(input.toUpperCase()); try { console.log(input.toFixed(2)); } catch (error) { console.log(String(error)); }

any turns checking off, so tsc accepts toFixed, a number method, on a string. The mistake only shows at runtime, as a TypeError.

 What is the difference between any and unknown?

Both can hold any value. With any, every mistake gets through. With unknown, you must first check the value (for example with typeof), and then TypeScript narrows it.

 What does tsc say about this code? const input: unknown = "Buy milk"; console.log(input.toUpperCase());

The compiler goes by the type, not the value. For an unknown, you must check first, for example if (typeof input === "string").

 Which type should a function use for a request body that comes from outside the program?

Outside data could be anything, so be honest: unknown. The compiler then makes you check it. Typing it as Task or any would let bad data straight through.

 What does this print? function shout(input: unknown): string { if (typeof input === "string") { return input.toUpperCase(); } if (typeof input === "number") { return input.toFixed(2); } return "(not text)"; } console.log(shout("Buy milk")); console.log(shout(3)); console.log(shout({ title: "Buy milk" }));

Each typeof check narrows input in its branch. The number 3 becomes "3.00", and the object is neither a string nor a number.

 What does the return type void mean?

Functions that only print or save something return void. A function that never returns (it always throws) has the return type never.

 What does this print? function logTask(title: string): void { console.log(`- ${title}`); } const result = logTask("Buy milk"); console.log(result);

A void function has no return value, and in JavaScript calling it gives undefined. void is only a type; it does not exist at runtime.

 What does this print? function fail(message: string): never { throw new Error(message); } try { fail("database is down"); console.log("after fail"); } catch (error) { console.log(String(error)); }

fail always throws, so the line after it never runs. String(error) gives the error's name and message.

 What does this print? type Status = "todo" | "doing" | "done"; function statusLabel(status: Status): string { switch (status) { case "todo": return "To do"; case "doing": return "In progress"; case "done": return "Done"; default: { const unreachable: never = status; throw new Error(`Unknown status: ${unreachable}`); } } } console.log(statusLabel("todo"), statusLabel("done"));

Each status has its own case, so the default branch never runs. It is there only for the compiler: when every case is handled, status has type never there.

 A teammate adds "blocked" to type Status = "todo" | "doing" | "done" but does not update the switch with the const unreachable: never = status; default. What happens?

Now "blocked" can reach default, so status is not never there. The compiler points at the incomplete switch, even in a file the teammate never opened. This is an exhaustiveness check.

"nothing left"); console.log(nextTask([])?.title ?? "nothing left");

task.estimate ?? 0 turns the null estimate into 0, so the sum is 3.5, not NaN. nextTask([]) is undefined, so ?. and ?? give the fallback text.

 This line fails with Object is possibly 'undefined'. Which fix is the one the lesson wants? return titles.find((t) => t.id === id).title;

Handle the missing case: ?. gives undefined instead of crashing, and ?? picks the fallback. any, ! and turning off strict only silence the compiler; the crash would still happen.

 What does this print? function toCount(value: unknown): number { let n = 0; if (typeof value === "number") n = value; if (typeof value === "string") n = Number(value); return Number.isInteger(n) && n >= 0 ? n : 0; } console.log(toCount("2.5"), toCount(true), toCount(7), toCount("12"));

"2.5" becomes 2.5, which is not a whole number, so 0. true is neither a number nor a string, so n stays 0. "12" converts to 12.

 What does this print? function minMax(numbers: readonly number[]): [min: number, max: number] | undefined { if (numbers.length === 0) return undefined; return [Math.min(...numbers), Math.max(...numbers)]; } console.log(minMax([7])); console.log(minMax([]));

With one number, it is both the smallest and the largest. The empty array returns early with undefined. Tuple labels like min are only documentation; at runtime it is a plain array.
