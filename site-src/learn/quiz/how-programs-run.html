What is the only thing a computer's processor understands directly?

The processor runs machine code. You write source code, which people can read, and another program turns it into something the processor can do.

 In the lesson's first program, each line console.log("…"); is called a…

A program is made of statements, instructions that run one after another. By default they run from top to bottom.

 What does a compiler do?

A compiler works ahead of time, like translating a whole book and then printing it. An interpreter carries out the code while it runs, like translating as people speak.

 What is an interpreter good at, compared with a compiler?

An interpreter can start at once, so you edit and rerun without building first. Compiled programs are usually faster once they run.

 Which of these languages is usually compiled ahead of time?

C, C++, Go and Rust are compiled before they run. Python, Ruby and early JavaScript were run by interpreters.

 How do modern JavaScript engines use JIT ("just in time") compilation?

JIT gives both a quick start and fast code. The engine watches which parts run again and again and compiles those in the background. You never run a compiler yourself.

 What is the runtime?

The engine only runs the language. The runtime adds the extra tools around it. console.log is one of them: the runtime gives it to your code.

 How does TypeScript code run?

TypeScript adds a compile step back: the TypeScript compiler produces plain JavaScript, which the engine runs like any other JavaScript.

 Which JavaScript engine is inside Node.js?

Node.js is V8, Google's engine (also used in Chrome and Edge), plus the tools a server needs. SpiderMonkey is Firefox's engine, JavaScriptCore is Safari's, and ECMAScript is the standard they all follow.

 Why does the same JavaScript run in Chrome, Firefox and Safari, even though they use different engines?

V8, SpiderMonkey and JavaScriptCore are different programs, but they all follow the ECMAScript standard. That standard defines what JavaScript code means.

 What does node -p process.versions.v8 do?

node -p runs one expression and prints its result. Here that is the version of V8 your Node.js contains, which depends on your Node.js version.

 Which of these is available to JavaScript in the browser, but not in Node.js?

The browser runtime gives you the page (document) and window. Node.js has no page, but has process, files and network servers. console.log and Math exist in both.

 A sign-up page checks in the browser that the password is long enough. Is that enough?

Any code sent to the browser can be read and changed by the visitor. A check in the page is a convenience for the user; the real check always happens on the server.

 Who controls JavaScript that runs on your Node.js server?

Server code stays on your server, so visitors cannot read or change it. Browser code is sent to the visitor, who can do anything with it.

 How are Java and JavaScript related?

They were made by different people and work differently. Java must be compiled and wants the type of every variable. JavaScript runs from the source and does not ask for types.

 Is your file order.js an executable program?

node (or node.exe) is the executable: the operating system can start it directly. Your .js file is source text that Node.js reads and runs.

 Which sentence describes the difference between a library and a framework?

With a library, you decide what to call and when. A framework is in charge: you hand it your pieces, and it decides when they run. ZudoJS works this way.

 Your project needs the package @zudojs/errors. What is that package to your project?

A package is published code with a name and a version. The packages your project needs are its dependencies, listed in package.json.

 In package.json, what does the line "@zudojs/schema": "^1.1.1" under dependencies say?

Each line under dependencies is a package name and the versions the project accepts. npm is where these packages are published.

 A file has a missing ) on line 5. What happens to lines 1 to 4 when you run it?

The engine reads the whole file before running it. If the grammar is broken anywhere, nothing runs at all, not even the lines before the mistake.

 A program prints three lines, then stops with TypeError: Cannot read properties of undefined. What kind of error is it?

The grammar was fine, so the first lines ran. Then one statement could not be carried out and the program stopped. That is a runtime error. A syntax error would print nothing.

 A shop's total shows 5 when it should show 50, and there is no error message. What kind of mistake is this, and how do you catch it?

Logic errors print no message: the code runs but computes the wrong thing. You only find them by comparing the real output with the expected one, which is what tests do.

 Node.js prints broken.js:2, the line, a row of ^, and SyntaxError: missing ) after argument list, then lines starting with at. What should you read first?

Read from the top. The file name and line tell you where, the ^ marks the place, and the message tells you what is wrong. For a syntax error, the at lines are Node.js's own internals.

 What is a stack trace?

After a runtime error, the stack trace shows where the program was. Its first line usually points at your file, with a line and column number.

 Why must a backend catch runtime errors instead of letting them crash the program?

A server answers many people. If one bad request crashed it, everyone would lose the service. With try/catch, the error is handled and the program keeps running.

Statements run from top to bottom, in the order you wrote them. Each console.log prints its own line.

Node.js has no web page, so there is no document. It does have process, which describes the running program. In a browser tab it is the other way round.

 This should print the average of three prices. What does it really print? const average = 10 + 20 + 30 / 3; console.log("Average price:", average);

Division happens before addition, so this is 10 + 20 + 10, which is 40. It is a logic error: no message, just a wrong answer. The fix is (10 + 20 + 30) / 3.

 What does this print? const average = (10 + 20 + 30) / 3; console.log("Average price:", average);

Brackets are done first, so the sum 60 is divided by 3, giving 20.

 What does this print? const task = undefined; try { console.log(task.title); } catch (error) { console.log("Name:", error.name); } console.log("Still running");

Reading .title of undefined throws a TypeError at run time. catch receives it, prints its name, and the program carries on to the last line.

The code runs until the error on task.title. From there it jumps straight into catch, so After is never printed.

 What does this print? try { console.log("Saving task"); } catch (error) { console.log("Error:", error.message); } console.log("Done");

When nothing goes wrong inside try, the catch part is skipped completely. Then the program carries on.

As in maths, * and / come before + and -, so the first line is 2 + 12. Brackets change the order: 5 * 4.

Math is JavaScript's small built-in library. Math.round(2.4) is 2, Math.max picks the biggest, Math.min the smallest.
