Mama Ngozi's son wants to "write a program" for her shop's totals. Which part of that work is the real core of programming?

A computer does exactly what it is told and never fills a gap with common sense. Most of programming is deciding those exact steps: what goes in, in what order, and what to do in every case. Typing them is the smaller part.

 What is the difference between an algorithm and a program?

"Start at 0 and add price × quantity for each item" is an algorithm. You could follow it on paper. Written in JavaScript, Python or Go, it becomes a program. One algorithm can become many programs.

 Which of these steps could not appear in an algorithm?

An algorithm's steps must be precise: anyone following them must get the same result. "If it seems fair" depends on judgement, so two people would do different things. The rule must say exactly when delivery is added.

 A set of steps says: "1. Set the counter to 1. 2. Add 1 to the counter. 3. Go back to step 2." Why is this not a correct algorithm?

Algorithms may repeat, but they must be finite: every repetition needs a condition that eventually stops it. The savings exercise stops when the savings reach the goal. This one has no stopping rule, so it has no output.

 A currency app takes an amount in naira and today's exchange rate, and shows the amount in dollars. What is the processing?

The naira amount and the rate are the input. The number shown on the screen is the output. The calculation that turns one into the other is the processing.

 In the IPO model, what is the input of a web server?

A request comes in (input), the server finds or changes data (processing), and a response goes out (output). Every backend you will write sits in the middle of that.

 The laundry charges ₦500 per shirt and ₦800 per trousers, with ₦1,000 off from 10 pieces. Which of these is an input to the bill program?

The prices and the discount are fixed rules written on the board. What changes from one customer to the next is how many shirts and trousers they bring, so those are the inputs. The amount to pay is the output.

 In the problem-solving loop, which step comes right before "implement"?

The order is understand, break down, inputs, outputs, design steps, implement, test, improve. You write the algorithm in plain language first, then turn those steps into code.

 Why should you work out the expected answer before running a program?

The first laundry program printed ₦6,200 with no complaint. Only someone who had already worked out ₦5,200 could see it was wrong. Looking at an output and thinking "seems fine" is how bugs survive.

 The rule is "orders of ₦20,000 or more get free delivery". Which set of test inputs is best for finding a boundary bug?

Boundary bugs, like writing > where the rule says "or more", only show up at the value where the answer switches. Test just below, exactly on, and just above it. Values far away give the same answer for both the right and the wrong code.

 What is source code?

You write source code, such as a .js file. An engine like V8 translates it into machine code, which is what the processor actually runs.

 Your JavaScript file calls console.log, but you never wrote a function by that name. Where does it come from?

A runtime is the engine plus the extra tools a program needs: printing, files, network, timers. console.log is one of those tools.

 A shop's board says: "Buy 3 or more, get 10% off." You are at step 1 of the loop, understand. Which question is most worth asking the owner?

The rule can be read two ways, and each reading gives different bills. No amount of careful coding fixes an unclear rule. Asking takes seconds; guessing wrong makes every bill wrong.

 A delivery fee of "500" comes from a web form. Why can 3600 + deliveryFee give the wrong total?

3600 + "500" gives the text "3600500". Input from a keyboard or form is text until you convert it, for example with Number(deliveryFee). Never use an input before you have checked what it really is.

 A receipt program prints Change: ₦-400 and no error. What went wrong?

The arithmetic was right; the design was incomplete. The fix is a decision: if the amount paid is less than the total, print what is still owed. Most real bugs are missing cases like this, and none of them produce an error message.

 A checkout rule says: "Members get 10% off. Delivery is free when the price after discount is ₦15,000 or more." Which order of steps is correct?

Delivery depends on the discounted price, so the discount must be worked out first. Deciding delivery on the price before discount gives free delivery to some members who should pay for it.

 Which input value do people forget to think about most often, and is worth a test in almost every program?

Zero is the smallest normal input and the easiest to forget. In the receipt, a quantity of 0 is fine; a customer with 0 items might not be. Either way, you only know if you asked.

 The receipt program runs for two different customers. Between the two runs, what should change?

The processing is written once and works for every customer; only the input changes, and so the output changes with it. That is what makes a program worth writing.

 Look at the chain problem → algorithm → source code → machine code → output. Which arrows are the programmer's job?

You think of the steps and write them as source code. The engine translates it into machine code and the processor carries it out; that software was written by someone else. That is why most of programming happens in the first two arrows.

 All the laundry tests pass. Then the owner adds a rule: "20 pieces or more: ₦2,500 off". What does the problem-solving loop tell you to do?

A new rule is a new problem to understand. It adds a new boundary, so it needs new tests just below and on it. The old tests stay, because the 10-piece rule still applies to 10 to 19 pieces.

 Which input should a program check most carefully before using it?

Anything that comes from outside the program, such as a keyboard, a form or a network request, can be mistyped or even sent on purpose to cause harm. Values the program set or calculated itself are under your control.

+ works from left to right. "Total: ₦" + items is text, so adding delivery to it glues 500 on the end. Brackets fix it: "Total: ₦" + (items + delivery) adds the numbers first.
