A route does const updated = { ...user, ...body } with the client's JSON body. What is this bug called, and what can an attacker do with it?

Spreading an untrusted body copies every field it contains. Adding "role":"admin" to a profile edit turns a customer into an admin. Parse the body into a DTO with an allow-list of fields instead.

 Why is type UserResponse = Omit<User, "passwordHash"> risky for a response type?

Omit means "everything except". When someone adds resetTokenHash to the entity next month, it is in the response without anyone deciding so. A response type that names its fields is an allow-list.

 In the lesson's BookStore, where does a new user's role come from at registration?

CreateUserDTO has no role, the parser refuses the key, and UserService.register writes role: "customer" itself. Admins are created by operators, never through the public API.

 An update DTO has displayName?: string | null. What do "the key is absent" and "the key is null" mean?

A partial update must tell "not mentioned" from "set to nothing". The parser only sets the property when the key is in the body, and the SQL uses a flag so that NULL is written only when it was asked for.

 A client sends {"title":"Kindred","id":7} to update a book. Why does the lesson answer 400 instead of silently ignoring id?

Silently dropping fields hides bugs in clients ("why does my id change never stick?") and hides probing. Refusing unknown keys, with a clear issue, is safer and easier to debug.

 Which layer should enforce "only admins may change a book's price"?

The rule depends on who is asking, which the parser does not know, and it is a business rule, which the repository should not know. The service sees the principal and the request, and every caller (HTTP, scripts, jobs) goes through it.

 Which layer turns the column price_cents into the property priceCents?

Only the repository knows column names. Its private row type and toBook mapper keep snake_case inside the database layer, so no other code changes when a column is renamed.

 A request to create a book arrives with a valid token for a customer. Which status is right?

401 means "we don't know who you are" (authentication failed). 403 means "we know who you are, and the answer is no" (authorization failed). The customer is authenticated, so it is 403.

 Why does the lesson put permission checks in the services instead of only in the controllers?

Put a rule where every path passes. A background job that calls BookService.update directly must be checked just like an HTTP request.

 The Authenticator reads only the user id from the token and loads the user to get the role. What does that buy you?

A role copied into a token is a snapshot. Loading the user each time costs one query but always uses the current role. (Signing, not loading, is what makes a token unforgeable.)

 Why do the services receive a Clock instead of calling new Date()?

The current time is an input from outside, like a database. Injecting it lets a test say "it is 10:00" and check the result exactly.

 Which sentence describes dependency inversion in the lesson's code?

The high-level code states what it needs as an interface (a port). The low-level code fits that interface. The composition root connects them, which is why a test can pass a fake.

 Why does BookService.list ask the repository for limit + 1 rows?

The extra row is only a probe. The page shows limit items; nextCursor is set only when the probe row came back. Counting a large table for every page would be much slower.

 The cursor is a base64url string the server created itself. Why does parsePageQuery still validate it?

Anything that arrives in a request is client input, even if you generated it earlier. An unchecked cursor could become a SQL error, a crash or a way to read unexpected rows.

 What does as const satisfies Record<Failure["kind"], number> on the STATUS table guarantee?

satisfies checks the object against the type without widening it. Adding a new kind to Failure without a status becomes a compile error pointing at this table.

 A controller promises ApiResponse<UserResponse> and returns { status: 200, body: user }, where user is the entity with a passwordHash. When does this compile?

TypeScript is structural: an object with more properties fits a type with fewer. Excess-property errors only apply to fresh object literals. In the lesson, only the Date vs string mismatch stopped it; an explicit mapper is the real protection.

 Ada asks for GET /users/3, another customer's private profile. Why might you answer 404 instead of 403?

The difference between 403 and 404 leaks information. For private resources, "you may not see it" and "it does not exist" should look the same to the caller.

 toErrorResponse receives an error that is not an AppError. What does it do, and why?

An unexpected error is your bug, not the client's mistake. Its message can reveal SQL, paths or internals. Log it for yourself; tell the client only that something went wrong.

 What is special about createApp in src/app.ts?

This is the composition root. Services and controllers only know interfaces and each other's types; swapping PGlite for a PostgreSQL server, or scrypt for another hasher, changes this file only.

 The unit test gives BookService an in-memory fake repository. Which mistake can that test not catch?

The fake replaces the SQL, so the SQL is not exercised. Rules and paging logic are tested fast with the fake; the repository needs its own integration test against a real database.

 Why does the user repository check the row's role with isRole before building the entity?

The row type can only honestly say string. The guard turns it into "customer" | "admin" with proof, so a bad row fails loudly at the edge instead of confusing permission checks later.

Promise<ApiResponse<Page<BookResponse>>> documents and checks the endpoint's contract. With body: unknown, anything would compile.
