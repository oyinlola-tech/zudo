In 2 + 3, what are 2 and 3 called?

The operator is the symbol, +. The values it works on are its operands. An operator produces a new value from them.

 What does this print? console.log(7 / 2, 7 % 2, 2 ** 3);

/ divides and keeps the decimals, % gives what is left after dividing (7 = 2 × 3 + 1), and ** is power: 2 × 2 × 2.

 What does this print? console.log(-7 % 3); console.log(7 % -3);

The remainder keeps the sign of the left side. So -7 % 3 is -1, and 7 % -3 is 1.

 What does n % 2 === 0 check?

An even number divided by 2 leaves nothing over, so its remainder is 0. For odd numbers the remainder is 1 (or -1 for negative odd numbers).

 What does this print? let a = 1; console.log(a++); console.log(a); console.log(++a);

a++ gives the old value (1), then adds 1. ++a adds 1 first, then gives the new value (3).

 How does the lesson tell you to use count++?

a++ and ++a give back different values, which confuses readers. On its own line, both forms simply add 1, so there is nothing to confuse.

 What is total *= 2 short for?

A compound assignment does the calculation and stores the result in one step. x op= y means x = x op y.

 What does this print? let total = 10; total += 5; total -= 3; total *= 2; total /= 4; console.log(total);

Step by step: 10 + 5 = 15, 15 − 3 = 12, 12 × 2 = 24, 24 / 4 = 6.

 What does this print? let log = "start"; log += " > step 1"; log += " > step 2"; console.log(log);

+= also works on strings: it joins the new text to the end. After two joins, the log holds all three parts.

 What kind of value does a comparison like 5 > 3 always give back?

Comparison operators (>, <, >=, <=, ===, !==) always give true or false.

 What does this print? console.log("10" < "9"); console.log(10 < 9); console.log(Number("10") < Number("9"));

Strings are compared character by character, like words in a dictionary, and "1" comes before "9". Convert text to numbers first to compare them as numbers.

 What is the difference between === and ==?

Strict equality === never converts. Loose equality == applies coercion first, so "1" == 1 is true while "1" === 1 is false.

 What does this print? console.log("1" == 1, "1" === 1); console.log("" == 0, "" === 0);

== converts both sides first: "1" becomes 1 and "" becomes 0. === sees a string and a number, so it says false.

 What does this print? console.log(null == undefined, null === undefined, NaN === NaN);

== treats null and undefined as equal; === does not, since they are different types. NaN is never equal to anything, not even itself.

 Which comparison should you write to check that status is the number 0?

Always use ===. status == 0 is also true for "" and false, status = 0 assigns instead of comparing, and !status is true for every falsy value.

 The lesson allows one common use of ==. Which one?

value == null is true only for null and undefined, which is a useful and safe shortcut. Everywhere else, use ===.

 What does this print? const priority = 3; const done = false; console.log(priority > 2 && !done); console.log(priority > 5 || done); console.log(!!"hello");

Both sides of the && are true. Neither side of the || is true. Two nots turn any value into a boolean, and a non-empty string is truthy.

 What is short-circuiting?

With &&, a falsy left side ends it. With ||, a truthy left side ends it. In both cases the right side is skipped.

 What does this print? console.log("Ada" || "anonymous"); console.log("" || "anonymous"); console.log("Ada" && "logged in"); console.log(0 && "never checked");

&& and || give back one of their values: the one where they stopped. 0 is falsy, so && stops there and gives 0.

 What does this print? const isAdmin = false; isAdmin && console.log("Deleting everything"); console.log("done");

The left side of && is false, so JavaScript already knows the answer and never runs the right side.

 A user picked priority 0 ("lowest"). Why is chosenPriority || 2 a bug?

|| replaces every falsy value, including 0 and "", which are often perfectly valid. Use ?? for defaults.

 When does a ?? b give b?

?? replaces only nullish values: null and undefined. 0, "" and false are kept.

 What does this print? console.log(0 ?? 20, false ?? true, null ?? 20, undefined ?? 20);

?? keeps 0 and false, because they are not nullish. Only null and undefined are replaced.

 What does this print? const name = ""; console.log(`[${name || "anonymous"}]`); console.log(`[${name ?? "anonymous"}]`);

The empty string is falsy, so || replaces it. It is not nullish, so ?? keeps it, and the brackets show nothing between them.

 What does this print? let pageSize; pageSize ??= 25; pageSize ??= 50; console.log(pageSize);

??= assigns only when the variable is null or undefined. The first line sets 25; the second does nothing, because pageSize is already set.

 What does guest.profile?.name do when guest.profile is null?

Optional chaining ?. checks the value on its left. If it is null or undefined, it stops and gives undefined instead of crashing.

 What does this print? const guest = { profile: null }; try { console.log(guest.profile.name); } catch (error) { console.log("Crash:", error.name); } console.log(guest.profile?.name); console.log(guest?.profile?.name ?? "Guest");

Reading .name of null throws a TypeError. With ?. it gives undefined instead, and ?? then supplies the default.

 Your backend receives request.user, which may be null. Which line reads the user's name safely, with "guest" as the default?

?. avoids the crash when user is null, and ?? supplies the default only when the name is really missing. Without ?., reading .name of null throws.

 What does this print? console.log("Total: " + 1 + 2); console.log("Total: " + (1 + 2)); console.log(1 + 2 + " items");

+ runs left to right. Once a string appears, every later + joins text. In the last line the numbers are added first (3), and only then joined with the text.

 What does this print? console.log(true || false && false); console.log((true || false) && false);

&& binds tighter than ||, so the first line is true || (false && false), which is true. Parentheses change the order in the second line.

 What does !a === b mean?

! runs before ===, so it flips a first. If you mean "a is not equal to b", write a !== b.

 Which of these is a syntax error in JavaScript?

JavaScript refuses to guess whether -2 ** 2 means (-2) ** 2 or -(2 ** 2), so it is a syntax error. Add parentheses to say which you mean.

 You write a || b ?? c. What happens?

Mixing ?? with || or && without parentheses is not allowed. Add parentheses to make the order clear.

 You are not sure which operator in a long expression runs first. What does the lesson recommend?

Parentheses remove the doubt, for you and for the next reader. You do not need to memorise the whole table.

 What is the value of typeof 1 + 2?

typeof is a unary operator, and unary operators run before +. So it is (typeof 1) + 2: the string "number" joined with 2. To get the type of the sum, write typeof (1 + 2).

 Old code drops the decimals of an amount in kobo with amount | 0. Why should you replace it with Math.trunc(amount)?

Every bitwise operator first converts its operands to 32-bit integers. 7.9 | 0 is 7, as intended, but 3000000000 | 0 is -1294967296. Math.trunc works on every number.
