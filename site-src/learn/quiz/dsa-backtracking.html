What does a backtracking algorithm do when a partial answer breaks a rule?

Backtracking builds a candidate step by step and returns to the previous decision point as soon as the current path cannot work. Filtering at the end is brute force; backtracking avoids exploring dead branches at all.

 In the choose, explore, undo template, why is the undo step needed?

Changing one shared state going down and changing it back coming up means the whole search needs memory only for the current path. Forget the undo and later branches start from a corrupted state.

 Backtracking explores the decision tree in which order, and what does that mean for memory?

Backtracking is a depth-first walk. A tree with a million leaves and depth 20 needs only about 20 levels of state at any moment.

 A rule is monotone for a search that adds items one at a time. What does that mean, and why does it matter?

"At most three coupons" and "discount at most 40%" only get worse as coupons are added. For such rules, pruning at the first violation is safe and cuts off whole subtrees.

This rule is not monotone: adding a coupon fixes it. Pruning on it would cut off every branch at the first step, silently returning nothing. A test comparing the pruned search with brute force catches this immediately.

 Why does the permutation search use a used set instead of a start index?

A start index only moves forward, which is right for combinations (order irrelevant) but would only ever produce one ordering. Permutations need "every item not yet used".

 A rider has 12 stops. How many different visiting orders are there, and what does that say about trying them all?

n! grows faster than 2n: 12! is about 479 million, 15! about 1.3 trillion. Exhaustive route search only works for a handful of stops, even with pruning.

 What is branch and bound?

It prunes on "cannot be better" rather than "cannot be valid". The route search pruned a partial route when its length plus the distance back to the depot was already at least the best route found.

 In branch and bound, the estimate of the remaining cost must never be more than the true remaining cost. Why?

A valid lower bound guarantees that pruned branches truly cannot win. "You must at least drive back to the depot" never overestimates, so pruning with it keeps the answer exact.

 The route search can start with best.length set to the greedy route's length plus one. What does that achieve?

Without a starting bound, nothing can be pruned until the first complete route is found. A fast heuristic answer supplies a bound immediately. Using exactly the greedy length would prune an equally short route and could leave best.route empty.

Moving down-right adds 1 to both row and column (difference unchanged); moving up-right subtracts 1 from the row and adds 1 to the column (sum unchanged). Sets of those values make the attack check constant time.

 The sudoku solver chooses the empty cell with the fewest legal digits next. Why does that help so much?

On the classic puzzle the rule needed 51 guesses (one per empty cell, never wrong) against more than 4,000 for the first empty cell. Hard puzzles still need backtracking, but much less.

 When seating guests in a row, the solver only checks the newly seated guest against their left neighbour. Why is that enough?

Checking only what changed keeps the work per node small. Re-validating the whole partial answer at every node gives the same results, just slower.
