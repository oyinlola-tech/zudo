A PostgreSQL server listens on a network port. Which port is the default?

PostgreSQL uses port 5432 unless you choose another. 3000 and 8080 are typical for your own web servers, and 443 is HTTPS.

 In Docker, what is the difference between an image and a container?

docker pull postgres:17 downloads the image. docker run starts a container from it. You can run several containers from one image.

 What does -p 5434:5432 mean in docker run ... -p 5434:5432 ... postgres:17?

The left number is on your computer (the host), the right one inside the container. You then connect with psql -p 5434.

 docker run ... -p 5432:5432 ... fails with address already in use. What does the lesson do?

Another program already uses 5432 on this computer. Docker created the container anyway, so docker rm pg frees the name pg. Then a different left number avoids the clash.

 How does the lesson set the password for the postgres user in Docker?

A made-up password typed into commands ends up in notes, chats and shell history. A random value in an environment variable stays out of the command text, and psql reads PGPASSWORD by itself.

 What happens to the database's data when you run docker stop pg and later docker rm pg?

A stopped container still exists with its data. Removing it deletes the data with it. docker rmi additionally deletes the downloaded image.

 In psql, which command connects you to the database taskdb?

Lines starting with a backslash are psql's own commands. \c connects, and the prompt changes to taskdb=#.

 You are connected with psql. Which command lists the tables, and which describes the tasks table?

\dt lists tables, and \d tasks shows the columns, types, defaults and indexes of one table. \q quits.

 In psql you type select * from tasks and press Enter, but nothing happens and the prompt changes. Why?

psql runs a statement when it sees the ;. Type ; and press Enter. Backslash commands like \dt need no semicolon.

 What does create database taskdb; do?

One server can hold one database per project, for example. After creating it, connect with \c taskdb and create tables inside it.

PostgreSQL returns rows in whatever order it finds them. The lesson's delete ... returning came back as 1, 5, 2 because row 2 had just been updated.

 How do you write the text value Buy milk directly in SQL (for example, in psql)?

SQL text values use single quotes. Double quotes mean something else in PostgreSQL: a name, such as a column name. In your programs, pass values with placeholders instead.

 Why does every query in a real API include user_id = $n in its where?

Ids are easy to guess (1, 2, 3, …). Scoping every query to the logged-in user means a guessed id from someone else matches no row.

 update tasks set done = true where id = $1 and user_id = $2 reports affectedRows 0. What should the PATCH /tasks/:id handler answer?

Nothing matched: the task does not exist for this user. A 404 also avoids telling a stranger that a task with that id exists for somebody else.

 Someone forgot the where. What does this print? import { PGlite } from "@electric-sql/pglite"; const db = new PGlite(); await db.exec(` create table tasks (id integer primary key, done boolean not null default false); insert into tasks (id) values (1), (2), (3), (4); `); const result = await db.query("update tasks set done = true"); console.log(result.affectedRows); await db.close();

 This code glues input into SQL text. What SQL does it build? const userId = 1; const title = "x' or '1'='1"; const sql = `select * from tasks where user_id = ${userId} and title = '${title}'`; console.log(sql);

What does this print? import { PGlite } from "@electric-sql/pglite"; const db = new PGlite(); await db.exec(` create table tasks (user_id integer not null, title text not null); insert into tasks values (1, 'Buy milk'), (1, 'Call Ada'), (2, 'Fix bike'), (2, 'Read book'); `); const title = "x' or '1'='1"; const { rows } = await db.query("select title from tasks where user_id = $1 and title = $2", [1, title]); console.log(rows.length); await db.close();

The SQL text and the values travel separately, so the input can never become part of the query. It is just a strange title that no task has.

 Why do $1 placeholders stop SQL injection?

Placeholders do not clean anything. The database parses the SQL first and only then plugs the values in as data, whatever characters they contain.

 The client sends ?sort=title. How do you use it in order by safely?

Placeholders work only for values, not for column names or asc/desc. For names, choose from a fixed list in your code.

 Which query is the safe one? title and sort come from the client.

Only the placeholder version is safe. Pasting sort is injectable, and cleaning input by hand fails sooner or later (and breaks titles like Ada's book).

 db.query("select * from tasks where id = " + Number(id)) happens to be safe today. Why does the lesson still reject it?

Safety should not depend on one easy-to-miss function call. With $1, the query stays safe whatever changes around it.

 What do the flags in psql -h localhost -p 5434 -U postgres mean?

The password is not a flag: psql reads it from the PGPASSWORD environment variable, so it never appears in the command text.

 You set PGPASSWORD with export in one terminal window, then open a new window and run psql. What happens?

An environment variable set with export (or $env: in PowerShell) only lives in that terminal window and the programs it starts.

 Someone tries to make input "safe" by removing quotes. What does this print? const title = "Ada's book"; const cleaned = title.replaceAll("'", ""); console.log(`select * from tasks where title = '${cleaned}'`);

Cleaning by hand breaks real data: the task is called Ada's book, so this finds nothing. And sooner or later an attacker finds a trick the cleaning missed. Use a placeholder instead.

 A query builder numbers its placeholders like this. What does it print? const values = [1]; const where = ["user_id = $1"]; for (const [column, value] of [["done", false], ["priority", 3]]) { values.push(value); where.push(`${column} = $${values.length}`); } console.log(where.join(" and "), values);

Each placeholder number is the position of its value in the array. Pushing the value first and then using values.length keeps them in step. The values themselves never enter the SQL text.

 An attacker's input turns the condition into user_id = 1 and title = 'x' or '1'='1'. Why does it match every row?

It reads as (user_id = 1 and title = 'x') or ('1'='1'). The right side is always true, so every row matches, including other users' rows.
