What is the one rule of CQRS?

A command asks for a change and returns little. A query asks for data and must not change anything. Separate databases are an advanced version, not the rule itself.

 Which of these is a query?

GetTaskCount only reads. The others change data, so they are commands.

 SearchTasks returns matching tasks and also saves the search term for analytics. What should you do?

As described it is both, which breaks the rule. Split it: then the search can be cached and retried safely, and analytics happens on its own.

 Why is it valuable that a query can never change anything?

Running a pure query twice or a hundred times has no effect on your data, which makes caching and retries safe. Queries still check who is asking, because they return private data.

 CreateTask returns { id: 1 }. The caller wants the whole task. What should it do?

Commands usually return little: an id, or nothing. Reading is the query side's job, and it may be shaped and cached for the screen that needs it.

 Commands are named CreateTask and CompleteTask, events task.completed. What is the difference in meaning?

A command is in the imperative: "complete task 7". The handler may refuse it. An event in the past tense reports a fact that cannot be undone.

 Why does a command bus allow exactly one handler per type?

A command is a single job with a single result. A second handler throws DuplicateHandlerError at registration, while the app starts.

 You execute CompleteTsk (a typo) on a command bus. How is this different from the message bus?

On a command bus a missing handler is a bug, and a status of 500 says so. You find the typo at once instead of wondering why nothing happened.

 Why does it matter that createCommand("CompleteTask", body) ignores a type field inside body?

The type you pass always wins. If the body's type won, the client would choose which handler runs.

 Why would you write a handler as a class like CompleteTaskHandler extends CommandHandler?

Both forms work. A class gets its dependencies from outside, so the container can wire it and a test can pass in fakes.

 A handler throws new NotFoundError("Task 9 not found"). What does the caller of execute get?

Unlike the message bus, there is no result object: execute returns the handler's value or throws its error. The HTTP layer can turn the 404 into the right response.

 A CompleteTask command carries { taskId, userId } from the request body, and the handler checks owner === command.userId. What is wrong?

Who is asking must never come from data the client sends. The HTTP layer reads the user from the verified login token and puts it in the execution context.

 Linus tries to complete Ada's task 1. Why does the handler throw NotFoundError (404) instead of a 403?

A 403 leaks that the task exists and belongs to someone else. For another user's private data, "not found" is the safer answer. A caller with no user at all gets 401.

 What does withUser(request, "ada") do?

Contexts are frozen, and nothing is changed in place. That is why one base context can produce an Ada context and a Linus context safely.

 A command causes another command. What does createChildExecutionContext(parent) give the second one?

It keeps the chain intact: the same operation (correlation id), a clear parent (causation id), and its own new request id.

 What is the rule for calling next in CQRS middleware?

A second call throws. Not calling it skips the handler silently, which is a bug unless the middleware deliberately answers or refuses the request.

 What does errorMiddleware() do with a plain Error("connection to the database was reset")?

Internal messages can leak details about your system. Errors from @zudojs/errors, like NotFoundError, pass through unchanged, because they are meant for the client.

 A guard middleware throws AuthenticationError when the context has no user. Can the handlers drop their ownership checks?

The guard is a safety net for "is anyone signed in?". Only the handler knows who owns the task, so it must still refuse other users' tasks.

 When is CQRS probably not worth it?

CQRS adds a bus, a type per operation and a handler per type. For a small app, a service class with methods is clearer. Indirection costs reading time.
