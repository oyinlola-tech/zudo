What is the inferred return type of async function countOrders() { return 42; }?

An async function always returns a promise. Its value type comes from the return statements, widened like any inferred return type, so it is Promise<number>.

 Why does async function getBalance(): number { return 250000; } fail to compile?

Error TS1064: the function returns a promise whatever its body does, so the annotation must say Promise<number>. The body still returns the plain number.

 Inside async function getRate(): Promise<number> { … }, which return statement does not compile?

The return expression is checked against the awaited type, number. A number or a promise of a number are both fine, because promises flatten. A string is not a number.

 What is the type of const rate = new Promise((resolve) => resolve(1540.25));?

The constructor's T is not inferred from what you pass to resolve. Without a type argument or a contextual type (such as a function's return type), it is unknown. Write new Promise<number>(…).

 What is Awaited<Promise<Promise<string>> | number>?

Awaited unwraps promises recursively, like await does, and leaves non-promise types alone. It applies to each member of a union.

 A helper is async function logged<T>(task: () => T) { return await task(); }. Which return type is honest?

If task returns a promise, T is that promise, but await unwraps it. Promise<T> would claim the helper resolves to a promise. Promise<Awaited<T>> describes what really happens for both sync and async tasks.

 loadUser() returns Promise<User> and countOrders() returns Promise<number>. What does await Promise.all([loadUser(), countOrders()]) give?

With an array literal, Promise.all keeps the positions: a tuple with the awaited type of each input. await removes the outer promise.

 Now the promises are stored first: const jobs = [loadUser(), countOrders()]; const results = await Promise.all(jobs);. What is the type of results?

jobs is inferred as an array of a union, (Promise<User> | Promise<number>)[], so the positions are gone. as const on jobs, or passing the literal directly, keeps the tuple.

 What is the type of await Promise.all(accountIds.map((id) => loadAccount(id))), where loadAccount returns Promise<Account>?

map produces Promise<Account>[], an array of one kind of promise, and Promise.all turns it into Account[]. An array type is exactly right when every element has the same type.

 What is the type of await Promise.race([loadName(), countOrders()]), where they return Promise<string> and Promise<number>?

race settles with whichever input settles first, so the result may come from either: the union of the awaited types.

 A timeout helper creates new Promise<never>((_, reject) => …) and races it against a Promise<T>. Why never?

never is the type with no values: exactly what a promise that only rejects produces. It disappears from unions, so Promise.race([task, timeout]) keeps the type Promise<T>.

 In a PromiseRejectedResult from Promise.allSettled, what is the type of reason?

Rejections have no type in TypeScript, and the library types this property as any. Treat it as unknown and narrow it, the same rule as for catch variables.

 const [rate] = await Promise.allSettled([loadRate()]); How do you safely read the rate?

PromiseSettledResult<T> is a union discriminated by status. Only the fulfilled member has value, so the compiler requires the check.

 Why does orders.filter(async (order) => await isPaid(order)) keep every order?

filter is synchronous and tests the callback's return value right away. A pending promise is an object, and objects are truthy. The compiler accepts it because filter's callback may return unknown.

 A function runs orderIds.forEach(async (id) => { await sendReceipt(id); }) and then logs "done". When is "done" logged?

forEach starts each callback, ignores the promise it returns, and returns immediately. Use for...of with await, or await Promise.all(orderIds.map(sendReceipt)).

 Which typescript-eslint rule reports an async function passed where a callback's return value is ignored, as in forEach(async …)?

no-misused-promises catches promises in places that expect void or a boolean-ish value; its sibling no-floating-promises catches promises that nobody handles. The compiler cannot see either.

 What does the return type AsyncGenerator<Transaction, number, undefined> say about an async function*?

The three parameters are the yield type, the return type (seen as value when done is true) and the type next(value) accepts.

 What must an object have so that for await (const item of object) compiles against AsyncIterable<T>?

The async iteration protocol starts at Symbol.asyncIterator. An async *[Symbol.asyncIterator]() generator method is the shortest way to provide it, and implements AsyncIterable<T> lets the compiler check it.

 A pager is an async generator that fetches the next page only when the previous page's items are used up. A loop over it hits break on page 2 of 10. How many pages were fetched?

A generator only runs when the loop asks for the next value, and break finishes it. So only the pages needed to reach the break are requested.

 What is the type of await response.json() with TypeScript's DOM types, and what should you do about it?

The DOM's json() returns Promise<any>, which silently switches off checking for everything downstream. const data: unknown = await response.json() closes the hole, and a parser turns it into a checked type. (In a Node-only project, with "lib": ["ES2024"] and @types/node, json() is already typed Promise<unknown>; the annotation costs nothing and keeps the code safe under either.)

 Why does the timeout helper declare let timer: ReturnType<typeof setTimeout> | undefined?

Deriving the type from the function avoids hard-coding either environment's timer type. The | undefined is because it is assigned inside the promise executor.

 What does Promise.withResolvers<PaymentEvent>() give you?

It is new Promise with the two functions handed back to you, typed by the same T. It suits results that arrive later from somewhere else, such as a webhook.
