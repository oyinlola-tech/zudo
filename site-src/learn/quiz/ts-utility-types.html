Why is Partial<User> a poor type for the body of a "customer edits their profile" request?

Partial keeps every key and makes it optional. A profile patch should allow only the editable fields: Partial<Pick<User, "name" | "phone">>, backed by runtime code that copies only those fields.

 For interface Options { pageSize?: number }, what is Required<Options>["pageSize"]?

Required is { [K in keyof T]-?: T[K] }. The -? modifier removes the optional mark and the undefined that it added.

 const user: Readonly<User>, where User has name: string and address: { city: string }. Which line compiles?

Readonly is shallow: it marks the properties of User, so address cannot be replaced, but the object inside it keeps its own, writable city.

 What does Readonly<T> do at runtime?

All types are erased. For a runtime guarantee, use Object.freeze (which is also shallow).

 What happens with type PublicUser = Omit<User, "passwrodHash"> (a typo)?

Omit's key parameter is constrained to keyof any, not keyof T, so any string is accepted. Pick checks its keys. A StrictOmit<T, K extends keyof T> fixes it.

 Which definition matches the standard library's Omit?

"Omit these keys" is "pick every key that is not one of them". Exclude removes the omitted keys from the key union, and Pick builds the object.

 type Payment = { id: string; kind: "card"; last4: string } | { id: string; kind: "wallet"; phone: string }. What is Omit<Payment, "id">?

keyof of a union gives only the shared keys (id and kind), so the result is one flattened object with just kind. The union and its member-specific fields are lost. A distributive version applies Omit to each member.

 Why does type DistributiveOmit<T, K extends keyof any> = T extends unknown ? Omit<T, K> : never keep the union intact?

T extends unknown is always true; its only job is to trigger distribution. The results for each member are joined back into a union.

 const labels: Record<"customer" | "staff" | "admin", string> = { customer: "Customer", staff: "Staff" }; What does the compiler say?

Record<K, V> is { [P in K]: V }: one required property per key. That is why it is great for lookup tables over a union: adding a role forces a new label.

 With const stock: Record<string, number> = { rice: 12 };, what is the type of stock.garri (without noUncheckedIndexedAccess)?

Record<string, number> promises a number for every string key. The promise is false for missing keys. noUncheckedIndexedAccess adds | undefined to such reads; a Map is another option.

 What is Exclude<"pending" | "paid" | "cancelled", "cancelled" | "refunded">?

Each member of the first union is tested: kept unless it is assignable to the second. "refunded" is simply never matched; Exclude does not check that the excluded members exist.

 What does Extract<Payment, { kind: "card" }> give, for a discriminated union Payment?

Extract keeps the members assignable to the second type. The card member has kind: "card" plus other fields, so it is assignable to { kind: "card" } and is kept whole.

 The standard library defines NonNullable<T> as T & {}. Why does that work?

{} accepts strings, numbers, objects and every other non-nullish value. Intersecting with it keeps those and drops null and undefined, even for a type parameter that is not known yet.

 A function has two overloads: (id: string): Booking and (ids: string[]): Booking[], in that order. What is its ReturnType?

When infer matches an overloaded function type, it uses the last signature. If you need the other result type, name it directly.

 What is Parameters<typeof quote> for function quote(zone: "lagos" | "abuja", weightKg: number, express = false)?

Parameters gives a labelled tuple. A parameter with a default value becomes an optional element, because callers may leave it out.

 Why is ReturnType<quoteDelivery> an error, when quoteDelivery is a function?

Utility types take types. typeof turns the function's name into its function type.

 For class Room { constructor(name: string, priceKobo: number) {} }, what are ConstructorParameters<typeof Room> and InstanceType<typeof Room>?

Both take the constructor type, typeof Room: one extracts what new takes, the other what new gives, which is the instance type Room.

 In type MyAwaited<T> = T extends PromiseLike<infer V> ? MyAwaited<V> : T, why does the true branch use MyAwaited<V> rather than V?

With just V, Promise<Promise<number>> would give Promise<number>. The recursion keeps unwrapping; Awaited<Promise<Promise<number>>> is number.

 What does ThisType<S & A> do when it appears in the type of an object literal's contextual type?

ThisType is an empty marker interface the compiler recognises (with noImplicitThis). It changes only the type of this; the runtime value of this still depends on how a method is called.

 For the public view of a user, why does the lesson prefer Pick<User, "id" | "name" | "role"> to Omit<User, "passwordHash">?

Deny-lists fail open: a new secret leaks until someone remembers to omit it. Allow-lists fail closed. Neither type changes the data; the view must still be built field by field.

 findUser is (id: string) => Promise<User | undefined>. What is NonNullable<Awaited<ReturnType<typeof findUser>>>?

Read from the inside out: ReturnType gives Promise<User | undefined>, Awaited removes the promise, and NonNullable removes undefined.

 Why is ReturnType's constraint T extends (...args: any) => any rather than (...args: unknown[]) => unknown?

Parameters are compared contravariantly: a function that needs a string cannot stand in for one that promises to accept anything. any in the parameter position switches that check off, so every function fits.
