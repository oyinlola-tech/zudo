In a loop, what is one iteration?

A loop runs its block again and again. Each single run of the block is one iteration.

 You must print one line for every task in a list, and you do not know how long the list will be. What should you use?

A loop runs the same code as many times as needed, even when you do not know the number in advance. Writing lines by hand only works for a fixed, small number.

 In for (let i = 1; i <= 5; i++), when does i <= 5 run?

let i = 1 runs once at the start, the condition i <= 5 is checked before every iteration, and i++ runs after every iteration.

 In a for loop, what does the third part (for example i++) do?

The third part runs after each iteration. It does not have to be i++: n -= 2 or i-- work too.

 What does this print? let line = ""; for (let i = 0; i < 4; i++) { line += i; } console.log(line);

The counter starts at 0 and the loop stops when i < 4 is false, so it runs for 0, 1, 2 and 3. line is a string, so += joins the digits instead of adding them.

 What does this print? let total = 0; for (let n = 10; n > 0; n -= 2) { total += n; } console.log(total);

The counter goes 10, 8, 6, 4, 2 and then stops, because 0 is not greater than 0. 10 + 8 + 6 + 4 + 2 is 30.

 What does this print? let runs = 0; for (let i = 1; i <= 10; i++) { runs++; } let runs2 = 0; for (let i = 0; i < 10; i++) { runs2++; } console.log(runs, runs2);

1 to 10 inclusive is 10 values, and 0 to 9 is also 10 values. Watch < versus <=: they decide whether the last value runs.

 What does this print? let i; for (i = 0; i < 3; i++) { console.log("tick", i); } console.log("end", i);

After the last iteration, i++ makes i 3, then the check 3 < 3 is false and the loop ends. So i is 3 after the loop.

 When is a while loop the best choice?

Use while when you only know when to stop, like "until the balance reaches 200". For each item of a list, for...of is simpler.

 What does this print? let value = 1; let steps = 0; while (value < 20) { value = value * 2; steps++; } console.log(steps, value);

The value goes 2, 4, 8, 16, 32. After 16 the check 16 < 20 is still true, so one more step makes it 32. Then 32 < 20 is false and the loop stops.

 What does this print? let n = 5; while (n < 3) { console.log("while", n); n++; } do { console.log("do", n); n++; } while (n < 3);

while checks the condition before the body, and 5 < 3 is false, so its body never runs. do...while checks after the body, so it always runs at least once.

 Which task fits a do...while loop best?

do...while always runs its body once, then checks. That matches "do this, then ask whether to do it again", like asking for input until it is valid.

 This loop never ends: let balance = 100; while (balance < 200) { console.log(balance); }. Why?

A loop stops when its condition becomes false. If nothing in the body moves balance towards 200, that never happens. Always check that something inside the loop moves it towards the end.

 Your program hangs in the terminal because of an infinite loop. How do you stop it?

Ctrl+C stops the running program. Node does not stop a loop by itself; it runs forever.

 What does this print? const titles = ["Buy milk", "Call Ada"]; for (const title of titles) { console.log(`- ${title}`); }

for...of gives you each item of the list in turn, with no counter to manage.

 What does this print? let out = ""; for (const letter of "abc") { out += letter.toUpperCase() + "."; } console.log(out);

for...of also works on strings, one character at a time. Each letter gets upper-cased and a dot is added after it.

 Why can you write for (const title of titles) with const, even though title gets a different value each time?

With for...of, every iteration creates a new title. Nothing reassigns it, so const is fine and is the usual choice.

 What does this print? const task = { title: "Buy milk", done: false }; for (const key in task) { console.log(`${key}=${task[key]}`); }

for...in gives the keys (property names). task[key] reads the property whose name is stored in key.

 Someone used for...in on an array. What does this print? const titles = ["Buy milk", "Call Ada"]; for (const x in titles) { console.log(x, typeof x); }

On an array, for...in gives the positions, and as strings, not the items. Use for...of for arrays.

 Which loop should you use to go over the items of an array?

for...of gives the items. for...in is for the keys of an object; on arrays it gives the positions as strings.

 What is the difference between break and continue in a loop?

break ends the loop immediately. continue works like a guard clause for one iteration: it jumps to the next one.

 What does this print? const items = ["a", "", "b", "STOP", "c"]; let out = ""; for (const item of items) { if (item === "") continue; if (item === "STOP") break; out += item; } console.log(out);

The empty string is skipped with continue. At "STOP", break ends the loop, so "c" is never reached.

 What does this print? let line = ""; for (let i = 1; i <= 6; i++) { if (i % 2 === 0) continue; line += i + " "; } console.log(line.trim());

For even numbers, continue skips the rest of the iteration, so only the odd numbers are added. The loop itself keeps going until 6.

 How many times does the inner line run? let cells = 0; for (let row = 1; row <= 3; row++) { for (let col = 1; col <= 4; col++) { cells++; } } console.log(cells);

For every iteration of the outer loop, the inner loop runs completely. 3 rows × 4 columns = 12.

 What does this print? for (let row = 1; row <= 2; row++) { let line = `row ${row}:`; for (let col = 1; col <= 3; col++) { if (col === 2) break; line += ` ${col}`; } console.log(line); }

A break inside the inner loop only stops the inner loop. The outer loop goes on to row 2, where the inner loop starts again.

 You nest two loops, each over a list of 1000 items. About how many times does the inner body run?

Nested loops multiply: 1000 × 1000 is a million iterations. Keep that in mind before nesting loops over big lists.

 What does this print? console.log("[" + String(7).padStart(4) + "]"); console.log("[" + String(12).padStart(4) + "]");

padStart(4) adds spaces in front until the text is 4 characters long. That is how the multiplication table lines up its columns.

 You need both each item of a list and its position. Which loop does the lesson use?

A counting for loop gives you i, and list[i] reads the item at that position. for...of gives only the items.

 Which loop will you use most often for lists and strings?

for...of gives each item with no counter to manage. Use for when you need a counter or position, and for...in only for object keys.

 What does this print? const titles = ["Buy milk", "Call Ada", "Write the quarterly report", "Pay rent"]; for (let i = 0; i < titles.length; i++) { if (titles[i].length > 10) { console.log(`Found at position ${i}: ${titles[i]}`); break; } }

Positions start at 0, so the third title is at position 2. break stops after the first match; "Pay rent" is only 8 characters anyway.

 The checks are in the wrong order. What does this print? let line = ""; for (let i = 13; i <= 15; i++) { if (i % 3 === 0) line += "Fizz "; else if (i % 15 === 0) line += "FizzBuzz "; else if (i % 5 === 0) line += "Buzz "; else line += `${i} `; } console.log(line.trim());

15 is a multiple of 3, so the first branch matches and the others are skipped. The check for 15 must come first.

 Why does the guessing game put the rules in checkGuess and play, separate from the keyboard code?

Code that reads the keyboard is hard to test. Put the logic in a function you can test with fixed input, and keep the keyboard part thin.

 A bad guess should not cost a try. What does this print? function isNumber(input) { return String(input).trim() !== "" && Number.isInteger(Number(input)); } let tries = 0; for (const input of ["50", "abc", "", "25"]) { if (!isNumber(input)) continue; tries++; } console.log(tries);

"abc" is not a whole number and "" is empty, so continue skips them before tries++. Only "50" and "25" count.

 In the real game the secret number comes from Math.random(). Why is it a parameter of play(secret, guesses)?

A random secret would make the output different on every run. Passing it in lets the test fix it, so the output can be checked.

 The interactive game uses node:readline/promises to read what the player types. Where does it run?

node: modules are built into Node.js, not the browser. The lesson runs the tested rules in the browser, and the keyboard game on your computer.

 Why are 7 tries always enough for a number from 1 to 100, if you always guess the middle?

Guessing the middle halves the numbers that are left. With 7 guesses you can always find the secret among up to 127 numbers (27 − 1), which covers 100. This is binary search.
