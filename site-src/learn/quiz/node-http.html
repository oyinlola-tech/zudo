In createServer((req, res) => { … }), when does Node.js call the function, and what are req and res?

The function is the request handler. Node.js calls it for each request with a fresh req and res.

 The lesson's examples call server.listen(0). What does port 0 mean?

Port 0 lets the system choose a free port, so a test never clashes with another program. Read the real port from server.address().port after the "listening" event.

 What does this print? import { once } from "node:events"; import { createServer } from "node:http"; const server = createServer((req, res) => { res.statusCode = 200; res.setHeader("Content-Type", "text/plain; charset=utf-8"); res.end("Hello"); }); server.listen(0); await once(server, "listening"); const response = await fetch(`http://localhost:${server.address().port}/anything`); console.log(response.status, response.headers.get("content-type"), await response.text()); server.close();

This handler answers every path the same way, so /anything gets 200 too. The status, the header and the body are exactly what the handler set.

 A handler sets the status and headers but forgets to call res.end(). What happens?

Every request must end with exactly one res.end. Without it, the client waits until it gives up.

 What does the response header Content-Type: application/json do?

A header is information about the response. You still turn the object into text yourself with JSON.stringify.

 The client sends headers with capital letters. What does this print? import { once } from "node:events"; import { createServer } from "node:http"; const server = createServer((req, res) => { res.end(`${req.method} ${req.headers["x-task-owner"]} ${req.headers["X-Task-Owner"]}`); }); server.listen(0); await once(server, "listening"); const response = await fetch(`http://localhost:${server.address().port}/`, { method: "PATCH", headers: { "X-Task-Owner": "Ada" }, }); console.log(await response.text()); server.close();

Header names arrive in lower case, whatever case the client used. So read req.headers["x-task-owner"]; the capitalised name is not there.

 Which is the right way to find the path to route on?

req.url includes the query string, so /tasks?done=true would not equal /tasks. URL needs a base because req.url is only the path; pathname is the path without the query.

 Your server has only GET /tasks. A client sends PUT /tasks. Which status code fits best?

The path exists, but not with this method: that is 405. A path the server does not know at all is 404.

 Why does the lesson write a small sendJson(res, status, body) helper?

Repeating three lines in every route invites mistakes, such as a forgotten header. One helper keeps every answer consistent.

 A route parameter id arrives from /tasks/42. Which statement is true?

Everything in a URL is text, and anybody can send anything, such as /tasks/abc or /tasks/-3. Validate the text, then convert it.

 What does this print? function parseId(text) { if (!/^[1-9][0-9]{0,8}$/.test(text)) return null; return Number(text); } console.log(["7", "007", "0", "7.0", " 7", "123456789"].map(parseId));

The pattern allows only a digit from 1 to 9 followed by up to eight more digits, with nothing before or after. Leading zeros, decimals and spaces are refused.

 Why does the lesson check the text with a pattern instead of just calling Number? What does this print? console.log(Number("12abc"), Number(""), Number(" 42 "), Number("4.5"));

Number turns empty text into 0, ignores spaces and accepts decimals. None of those is a valid id. Checking the text first is safer than converting and hoping.

 How does the body of a POST request reach your handler?

With no framework, nothing parses the body for you. Read it with for await (const chunk of req), join the chunks, then decode and parse.

 Why must a server limit the size of a request body?

An unlimited body is an easy attack. Count the bytes as they arrive and answer 413 as soon as the limit is passed, instead of reading everything first. Real JSON limits are often 100 KB to 1 MB, but never missing.

 This server reads a JSON body like the lesson's readJson. Plain text gets 415 (wrong Content-Type), broken JSON gets 400, a body over the limit gets 413, and the good one gets 200. Each problem has its own status code.

 Why does readJson join the chunks with Buffer.concat before calling toString("utf8")?

This is the café problem from Streams and buffers. req.setEncoding("utf8") is another correct way: the stream then decodes across chunks for you.

 JSON.parse fails on a request body. What should the server send back?

Broken input is the client's mistake, so 400. The message should be your own: error messages you did not write can reveal details about your code, so keep them on the server.

 What does the first digit of a status code tell you?

Clients check the status code first. A 4xx means "fix your request"; a 5xx means "not your fault, the server broke".

 A logged-in user who is not an admin tries to delete another user's account. Which status fits?

401 means "who are you? log in first". Here the server knows who the user is, and they may not do this: that is 403.

 A POST /tasks request created a new task. What is the usual answer?

201 says a new record was made, and Location: /tasks/2 says where it lives. 204 means there is no body at all.

 What does this print? import { STATUS_CODES } from "node:http"; for (const code of [201, 204, 405, 415]) { console.log(code, STATUS_CODES[code]); }

STATUS_CODES from node:http holds the standard phrase for each code. 415 is about the type of the body; 413 is about its size.

 When should your server answer 500 Internal Server Error?

5xx means the server failed. Invalid JSON is 400, a missing task is 404, and a missing login is 401: those are all the client's side.

 The build checks typeof body?.title !== "string" || body.title.trim() === "" || body.title.length > 200. Why the ?.?

JSON.parse("null") works and gives null. body?.title gives undefined instead of throwing, so the request gets a clean 400.

 Why does server.js start listening only when process.argv[1] === import.meta.filename?

process.argv[1] is the script Node.js was started with. When a test imports server.js, they differ, so the test can start its own copy on port 0.

 In curl -i -X POST http://localhost:3000/tasks -H "Content-Type: application/json" -d '{"title":"Call Ada"}', what does -d do?

-i prints the status line and headers, -X sets the method, -H adds a header and -d sends a body.

 The build keeps tasks in an array in memory. What happens to them when you stop the server?

Memory belongs to the running process. To keep data, you need a file or, better, a database.
