 What is the rule ZudoJS follows for interface and type?

Interfaces describe objects (and classes), can be extended, and show their name in errors. Unions, tuples and function types need a type alias.

An interface only describes object shapes. A union of literals, a tuple or a function type needs type, for example type Status = "todo" | "done".

The shared property (often kind or status) tells the shapes apart. Checking it in a switch or if narrows the value to one shape.

With many optional properties, nonsense combinations compile and every read needs a check. With a discriminated union, each state carries exactly its own data.
