What is a byte?

Computers store everything as bytes, numbers from 0 to 255. A character can take one byte or several, depending on the character and the encoding.

 What is an encoding such as UTF-8?

An encoding maps characters to bytes and back. UTF-8 is the one used almost everywhere. It does not hide or compress anything.

 What does this print? const text = "héllo"; const buf = Buffer.from(text, "utf8"); console.log(text.length, buf.length);

The string has 5 characters. In UTF-8, plain English letters take one byte each, but é takes two, so the buffer has 6 bytes.

 What does this print? const buf = Buffer.from("hi"); console.log(buf); console.log(buf[0], buf.toString("hex"));

Node.js prints each byte of a buffer in hexadecimal: 68 is h. Reading buf[0] gives the byte as a normal number, 104. toString("hex") writes the bytes as hex text.

 What does this print? const buf = Buffer.from("ABC"); console.log(buf[0], buf[2], buf.length);

A buffer works like an array of numbers. A is byte 65 and C is 67. (In hexadecimal they are 41 and 43, which is how console.log(buf) shows them.)

 What does this print? const encoded = Buffer.from("hello world").toString("base64"); console.log(encoded); console.log(Buffer.from(encoded, "base64").toString("utf8"));

toString("base64") writes the bytes as base64 text. Buffer.from(encoded, "base64") reads that text back into the same bytes, and toString("utf8") turns them into the original words.

 A developer stores an API key in a config file as base64 and says "it is encrypted now". Is that right?

hex and base64 are ways to write bytes with safe, printable characters. They hide nothing: Buffer.from(text, "base64") gets the secret back. Keep secrets in environment variables, not in files.

 What does this print? const text = "ok ✅"; console.log(text.length, Buffer.from(text).length);

✅ is one character in JavaScript, but it takes three bytes in UTF-8. "ok " is three one-byte characters, so the total is 6 bytes.

 What does this print? const buf = Buffer.from("café"); const first = buf.subarray(0, 4); const rest = buf.subarray(4); console.log(buf.length); console.log(first.toString() + rest.toString() === "café"); console.log(Buffer.concat([first, rest]).toString() === "café");

The cut at byte 4 falls inside é, so each half decodes to the replacement character �. Join the bytes first with Buffer.concat, then decode, and the word is whole again.

 A program prints caf� instead of café. What most likely happened?

� means "these bytes are not valid text". UTF-8 stores é in two bytes; if a chunk ends between them, decoding each chunk alone breaks the character.

 Why is readFile a bad choice for a 10 GB log file?

readFile holds all the data at once. A stream handles it chunk by chunk, so memory stays small whatever the file size.

 Which kind of stream is gzip compression (createGzip())?

A transform is both writable and readable: you write the original bytes in and read compressed bytes out. That is why it sits in the middle of a pipeline.

 In Node.js, process.stdout (where console.log writes) is which kind of stream?

You write data to process.stdout, so it is writable. That is why you can put it at the end of a pipeline.

 In an HTTP server, what kinds of stream are the incoming request and the response you send back?

The request body arrives piece by piece, so you read it. The response is something you write to. You will use both in the HTTP server lesson.

 Inside a loop, out.write(line) returns false. What should your code do?

false means "my bucket is full, stop for a moment". The line was accepted; do not write it again. Wait for "drain", then carry on. This is backpressure.

 What problem does backpressure solve?

If a loop keeps calling write faster than the disk saves, the waiting data grows in memory. Backpressure is the destination pushing back: write returns false until it has room again.

 This writable stream holds at most 10 bytes before it asks you to wait. What does this print? import { Writable } from "node:stream"; const out = new Writable({ highWaterMark: 10, write(chunk, encoding, callback) { setImmediate(callback); }, }); out.on("drain", () => console.log("drain")); console.log(out.write("12345"), out.write("67890"));

After the first write, 5 bytes are waiting, which is below the limit. After the second, 10 bytes are waiting, so write returns false. Once the stream has saved them, it emits "drain".

 You finished writing a file with a writable stream. What do out.end() and the "finish" event mean?

After end(), you may not write any more, but data may still be on its way to the disk. Wait for "finish" (for example await once(out, "finish")) before you rely on the file.

 What does once(out, "drain") from node:events give you?

once turns an event into a promise. await once(out, "drain") pauses your loop until the stream has room again.

 You read a 7.7 MB file with for await (const chunk of createReadStream(file)). What is each chunk?

A file read stream gives Buffer chunks of up to 65,536 bytes. A chunk ends wherever 64 KB ends, not at the end of a line.

 What does this print? import { Readable } from "node:stream"; const got = []; for await (const chunk of Readable.from(["buy ", "milk", "\n"])) { got.push(chunk); } console.log(got.length, JSON.stringify(got.join("")));

Readable.from turns each item of the array into one chunk, so the loop runs 3 times. Joining the chunks gives the full text back.

 Why should you not split each chunk with chunk.toString().split("\n") to read a file line by line?

Chunks are cut every 64 KB, wherever that falls. Lines get split in two and characters can break. readline's createInterface joins the pieces back into whole lines.

 The line breaks fall in the middle of the chunks. What does this print? import { createInterface } from "node:readline"; import { Readable } from "node:stream"; const input = Readable.from(["task 1 op", "en\ntask 2 d", "one\n"]); const lines = createInterface({ input, crlfDelay: Infinity }); for await (const line of lines) { console.log(`[${line}]`); }

readline collects the chunks and gives you complete lines, without the \n, however the chunks were cut.

 What does crlfDelay: Infinity do in createInterface({ input, crlfDelay: Infinity })?

Windows ends lines with \r\n. This option makes sure readline sees those two characters as a single line break, even when they arrive in different chunks.

 Why does the lesson prefer pipeline from node:stream/promises over a.pipe(b)?

Both handle backpressure. But with .pipe(), a failing stream does not close the others or report the error in one place, so files stay open and errors go unnoticed.

 What does this print? import { createReadStream, createWriteStream } from "node:fs"; import { mkdtemp, rm } from "node:fs/promises"; import os from "node:os"; import path from "node:path"; import { pipeline } from "node:stream/promises"; import { createGzip } from "node:zlib"; const dir = await mkdtemp(path.join(os.tmpdir(), "quiz-")); try { await pipeline( createReadStream(path.join(dir, "no-such.log")), createGzip(), createWriteStream(path.join(dir, "out.gz")), ); console.log("compressed"); } catch (error) { console.log("pipeline failed:", error.code); } await rm(dir, { recursive: true });

The first stream fails because the file is missing. pipeline closes the other streams and rejects with that error, so one try/catch covers the whole chain.

 What does this print? import { Readable, Transform } from "node:stream"; import { pipeline } from "node:stream/promises"; const shout = new Transform({ transform(chunk, encoding, callback) { callback(null, chunk.toString().toUpperCase() + "!\n"); }, }); await pipeline(Readable.from(["buy milk", "call ada"]), shout, process.stdout);

The transform gets each chunk and passes on a changed one with callback(null, newChunk). Each of the two chunks becomes an upper-case line ending in !.

 In a Transform, what is the first argument of callback(null, newChunk)?

Node.js callbacks put the error first. Pass null when all went well, or an Error to make the stream (and the pipeline) fail.

 A transform may pass nothing on. What does this print? import { Readable, Transform } from "node:stream"; import { pipeline } from "node:stream/promises"; const onlyDone = new Transform({ transform(chunk, encoding, callback) { const line = chunk.toString(); callback(null, line.includes(" done") ? line + "\n" : undefined); }, }); await pipeline( Readable.from(["task 1 open", "task 2 done", "task 3 done"]), onlyDone, process.stdout, );

Calling callback(null, undefined) says "done with this chunk, nothing to pass on". So only the lines that contain done reach process.stdout.

 What does this print? import { gunzipSync, gzipSync } from "node:zlib"; const text = "task open buy milk\n".repeat(1000); const packed = gzipSync(text); console.log(text.length > packed.length); console.log(gunzipSync(packed).toString() === text);

Text that repeats a lot compresses well, so the gzip bytes are much smaller. Decompressing gives back exactly the original text; gzip loses nothing.

 The line-counting program uses about 5 MB of memory for a 7.7 MB file. About how much would it use for an 8 GB file?

That is the point of streams: memory depends on the chunk size, not on the size of the data.

 A hash can take its data in pieces. What does this print? import { createHash } from "node:crypto"; const whole = createHash("sha256").update("buy milk").digest("hex"); const parts = createHash("sha256"); parts.update("buy "); parts.update("milk"); console.log(whole === parts.digest("hex"));

update can be called many times; the hash is the same as for the joined data. That is how you hash a huge file chunk by chunk with a stream.

 The build counts words with split(" ") and a filter. What does this print? const line = "task 7 done "; console.log(line.split(" ").length); console.log(line.split(" ").filter((word) => word !== "").length);

Two spaces in a row, and a space at the end, give empty strings when you split. Filtering out "" leaves the 3 real words.

 Data arrives in several Buffer chunks and you need the full text. What is the safe way?

Decoding each chunk alone can break a character that sits across two chunks. Joining the bytes first keeps every character whole.

Finish collectLines(chunks), a small version of what readline does. The chunks are strings that may end in the middle of a line. Return an array of the complete lines, without the \n. A last piece with no \n after it is also a line (if it is not empty).

 function collectLines(chunks) { // your code here } console.log(JSON.stringify(collectLines(["task 1 op", "en\ntask 2 d", "one\ntask 3"]))); console.log(JSON.stringify(collectLines(["a\n", "b\n"]))); function collectLines(chunks) { const lines = []; let rest = ""; for (const chunk of chunks) { const parts = (rest + chunk).split("\n"); rest = parts.pop(); lines.push(...parts); } if (rest !== "") lines.push(rest); return lines; } console.log(JSON.stringify(collectLines(["task 1 op", "en\ntask 2 d", "one\ntask 3"]))); console.log(JSON.stringify(collectLines(["a\n", "b\n"]))); ["task 1 open","task 2 done","task 3"] ["a","b"]

Keep the unfinished end in rest. Add each new chunk to it, split on \n, and keep the last piece (which has no line break yet) for the next round. At the end, the leftover is the last line.

Finish countLog(lines) like the build: count the lines, the words (split on spaces, ignoring empty strings), and the lines that contain " done ". The program should print {"lineCount":3,"wordCount":15,"doneCount":1}.

Finish utf8Length(text), which counts how many bytes text takes in UTF-8, without using Buffer. Loop with for (const ch of text) and use ch.codePointAt(0): below 128 takes 1 byte, below 2048 takes 2, below 65536 takes 3, and anything bigger takes 4.

 function utf8Length(text) { // your code here } console.log(utf8Length("hello"), utf8Length("héllo"), utf8Length("€"), utf8Length("done ✅"), utf8Length("😀")); function utf8Length(text) { let bytes = 0; for (const ch of text) { const code = ch.codePointAt(0); if (code < 128) bytes += 1; else if (code < 2048) bytes += 2; else if (code < 65536) bytes += 3; else bytes += 4; } return bytes; } console.log(utf8Length("hello"), utf8Length("héllo"), utf8Length("€"), utf8Length("done ✅"), utf8Length("😀")); 5 6 3 8 4

UTF-8 uses 1 byte for English letters and more bytes for other characters. for…of walks real characters, and the code point decides how many bytes each one needs.

A file was read in chunks. Finish chunkStats(sizes), which gets the size of each chunk and returns how many chunks there were, the total bytes, and the biggest chunk. The program should print {"chunks":3,"bytes":140000,"biggest":65536}.

 function chunkStats(sizes) { // your code here } console.log(JSON.stringify(chunkStats([65536, 65536, 8928]))); function chunkStats(sizes) { let chunks = 0; let bytes = 0; let biggest = 0; for (const size of sizes) { chunks++; bytes += size; biggest = Math.max(biggest, size); } return { chunks, bytes, biggest }; } console.log(JSON.stringify(chunkStats([65536, 65536, 8928]))); {"chunks":3,"bytes":140000,"biggest":65536}

This is the same loop as the lesson's chunk reader: count, add the size, and keep the maximum with Math.max. Only one number per chunk is kept, never the data.

The fake stream's write returns false when its bucket is full; stream.drain() empties it. Finish writeAll(stream, lines): write every line, and each time write returns false, call stream.drain() and count one pause. Return the number of pauses. The program should print 3 10.

 function makeStream(limit) { let waiting = 0; const stream = { written: [], write(line) { stream.written.push(line); waiting += line.length; return waiting < limit; }, drain() { waiting = 0; }, }; return stream; } function writeAll(stream, lines) { // your code here } const stream = makeStream(10); const lines = Array.from({ length: 10 }, (_, i) => `ln${i}\n`); console.log(writeAll(stream, lines), stream.written.length); function makeStream(limit) { let waiting = 0; const stream = { written: [], write(line) { stream.written.push(line); waiting += line.length; return waiting < limit; }, drain() { waiting = 0; }, }; return stream; } function writeAll(stream, lines) { let pauses = 0; for (const line of lines) { if (!stream.write(line)) { pauses++; stream.drain(); } } return pauses; } const stream = makeStream(10); const lines = Array.from({ length: 10 }, (_, i) => `ln${i}\n`); console.log(writeAll(stream, lines), stream.written.length); 3 10

Like the lesson's generator: if (!out.write(line)), wait for room (here drain()), then carry on. The line that returned false was still written, so do not write it again.

 How do you get Buffer in a Node.js program?

Buffer is built into Node.js and available everywhere, like console. It is not in the browser, which uses other tools for bytes.

 What does this print? import { once } from "node:events"; import { createWriteStream } from "node:fs"; import { mkdtemp, readFile, rm } from "node:fs/promises"; import os from "node:os"; import path from "node:path"; const dir = await mkdtemp(path.join(os.tmpdir(), "quiz-")); const file = path.join(dir, "log.txt"); const out = createWriteStream(file); for (let i = 1; i <= 3; i++) out.write(`task ${i}\n`); out.end(); await once(out, "finish"); const text = await readFile(file, "utf8"); console.log(out.bytesWritten, text.split("\n").filter((l) => l !== "").length); await rm(dir, { recursive: true });

Each line "task 1\n" is 7 bytes, so 3 lines are 21 bytes. After "finish" everything is saved, so reading the file finds all 3 lines.
