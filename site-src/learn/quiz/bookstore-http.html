Why does the BookStore API start with no framework at all?

Routing, JSON bodies, errors, validation: you write each one yourself. At the end of the three lessons you list what hurts. Type-safe API layers fixes part of that list with typed layers; the rest is the reason frameworks, and ZudoJS, exist.

 What does npm pkg set type=module do for the BookStore project?

Without "type": "module", Node.js treats .js files as CommonJS. The whole course uses ES modules with import and export.

 The scripts are "dev": "tsx watch src/server.ts", "start": "tsx src/server.ts" and "typecheck": "tsc --noEmit". Which is true?

tsx runs TypeScript without checking types; watch makes it restart on every change. Type errors are found by npm run typecheck, which is tsc --noEmit: check, write nothing.

 The port, the database address and secrets can differ between your laptop and a server. Where should they come from?

Configuration never goes into the code. It comes from process.env. One module reads it, checks it at startup, and turns it into a typed Config object that everything else uses.

 Why does loadConfig(env) take the environment as a parameter instead of reading process.env itself?

A function that takes its input as a parameter is easy to test: loadConfig({ PORT: "eighty" }) checks the error case without changing the real environment.

 You start the server with PORT=eighty npm start. What should a well-written config.ts do?

This is failing fast. If the server quietly used 3000, the person who set PORT would look for it in the wrong place. A clear error at startup is much easier to fix than a confusing failure later.

 Why do BookStore handlers take a small ApiRequest object and return an ApiResponse, instead of using the node:http request and response?

The node:http objects are big and awkward to fake. A handler that turns plain data into plain data can be called directly in a test, with no server running.

 In ApiRequest, why is body typed unknown and not the shape the route expects?

Any client can send anything. unknown forces the handler to narrow the value with typeof and in before touching a field like body.name.

 type Handler = (request: ApiRequest) => ApiResponse | Promise<ApiResponse>. What does the return type allow?

Simple handlers return { status, body } at once; handlers that wait for a database are async. app.ts writes await match.handler(request), which works for both.

 A route is registered with the pattern /books/:id. Which path does it match, and what are the params?

A pattern and a path match when they have the same number of parts and every fixed part is equal. A part starting with : matches anything and is saved as a string: every id in a URL is text until you convert it.

 The router has only GET /books/:id. A client sends DELETE /books/1. What should the API answer?

"The path exists, but not with this method" (405) is different from "the path does not exist" (404). That is why match returns three cases, and the 405 message lists the allowed methods.

 match returns a union with kind: "found" | "wrong-method" | "not-found". Why can the code read match.params inside if (match.kind === "found") but not before it?

Only the "found" case has params, and only "wrong-method" has allowed. Checking kind tells TypeScript which case it has, so each field is allowed exactly where it exists.

 A handler has a bug, and a TypeError (not an HttpError) reaches toErrorResponse. What does the client get?

An HttpError was thrown on purpose, so its message is safe to show. Anything else is a bug: log it with console.error and send { error: "internal_error" }. A stack trace tells an attacker how your code is built.

 Why does readJson stop reading after 100,000 bytes and answer 413?

Every chunk is kept in memory until the body is complete. A size limit (413 Content Too Large) protects the server from one client using up all its memory.

 You run curl -X POST http://localhost:3000/authors -d 'name=Octavia'. What does the BookStore answer, and why?

readJson refuses any body whose content-type does not start with application/json: 415 Unsupported Media Type. Add -H 'content-type: application/json' and send real JSON.

 A client sends {"name": with content-type: application/json. What happens in readJson?

The try/catch around JSON.parse turns broken JSON into a clear 400 Bad Request instead of an unexpected error. The content type was right, so it is not 415.

 Why does the BookStore store prices as whole cents, like priceCents: 1299 for 12.99?

Whole numbers add up exactly; decimal fractions like 0.1 cannot be stored exactly in a JavaScript number. Keep money in cents and divide by 100 only to display it.

 Why does toId reject ids above 2_147_483_647?

JavaScript can hold much bigger whole numbers, but the database column cannot. Refusing it at the edge with a clear 400 is better than an odd error from deep inside the database.

 What status does POST /authors return when it creates an author?

201 Created is the status for "I made a new thing". The body is the new author, with the id the server gave it.

 The check script calls createApp(createRouter()).listen(0). What does port 0 mean?

Port 0 lets the operating system pick a free port, so the test never clashes with a server that is already running. server.address() tells you which port it picked.

 Where are thrown errors turned into responses in the BookStore?

Handlers just throw new HttpError(404, …). The single try/catch around the router, body reading and handler turns every error into a status code and a JSON body.
