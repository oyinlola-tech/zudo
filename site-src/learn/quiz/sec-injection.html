Why is building a SQL statement by gluing user text into a string unsafe?

The statement and the data share one channel, so the data can change the statement's structure. Parameterized queries put them in separate channels.

 What does a parameterized query (db.query("… WHERE name = $1", [name])) actually do differently?

No escaping or filtering is involved: the value is simply never parsed as SQL. That is why it also works for names with apostrophes and notes containing SQL words.

 A colleague suggests rejecting any product name that contains ', ; or the word drop, "to stop SQL injection". What is the best answer?

Blocklists of "dangerous characters" corrupt legitimate data and always miss something. Keep data in the data channel instead of trying to guess which data is dangerous.

 The product list can be sorted by a column the user chooses in the URL (?sort=price). How should the column get into the SQL?

Placeholders stand for values, not identifiers, so ORDER BY $1 sorts by a constant. The user's input should only choose between strings you wrote. Use Object.hasOwn so keys like constructor do not find inherited properties.

 A search uses name ILIKE $1 with `%${term}%` as the value. The query is parameterized. What is still wrong when a user searches for 50%?

The parameter keeps the value out of the SQL, but LIKE interprets the value's contents as a pattern. That second, smaller language needs its own escaping: replace \, % and _ with escaped versions and add ESCAPE '\'.

 Which of these PGlite calls is safe with a user-supplied sku? // A await db.query(`SELECT * FROM products WHERE sku = '${sku}'`); // B await db.sql`SELECT * FROM products WHERE sku = ${sku}`;

B is a tagged template: the tag function receives the fixed text and the values separately and turns each value into a placeholder. A is an ordinary template string, which glues the value into the text before the database sees it.

 Why should db.exec(…) (which runs several statements and takes no parameters) never receive user data?

Multi-statement "simple query" functions are fine for fixed scripts such as creating tables. Anything involving data goes through a parameterized call, which also refuses multiple statements.

 What limits the damage if one query in the importer has an injection bug despite every precaution?

Least privilege does not prevent the bug, but it bounds what the bug can do. Migrations and admin tasks run under a different, more powerful user.

 Why is execFile(program, [arg1, arg2]) safe with a file name from outside, when exec(`program ${name}`) is not?

exec hands one string to a shell, which interprets spaces, quotes, ;, $ and more. Without a shell there is no second language to inject into.

 With an argument array and no shell, a file name that begins with - can still cause trouble. Why, and what helps?

This is argument injection: the name is one argument, but the program itself decides what arguments mean. -- tells most programs that everything after it is an operand, not an option.

 Why does the lesson pass env: { PATH: process.env.PATH } to execFile?

Least privilege applies to processes too. A tool that crashes and dumps its environment, or logs it, cannot leak secrets it never received.

 Why does the confinement check use full.startsWith(base + sep) rather than full.startsWith(base)?

A prefix check on text compares letters, not folders. Adding the separator makes it mean "inside this folder".

 Why is "refuse any name that contains .." a poor path-traversal defence?

Confinement is about the final location. path.resolve applies every rule of the path language, then one prefix check answers the real question.

 A name passes the resolve-and-prefix check, but the file is a symbolic link pointing outside the folder. What catches it?

The text check only sees the name; realpath asks the file system where the path really leads. For folders other people can write to, also consider that a link can be swapped between check and open.

 What is the strongest defence against path traversal for uploaded images?

If no outside text reaches the file system's path rules, there is nothing to traverse with. Confinement checks are for the cases where the name must come from outside.

 For outbound URLs, why does the lesson prefer an allow-list of hosts over a deny-list of dangerous hosts?

An allow-list fails closed: anything unexpected is refused. A deny-list fails open: anything you forgot is allowed. The private-address check is a second layer on top, not a replacement.

 An importer looks up a host name, checks that every address is public, and then calls fetch(url), which looks the name up again. What is DNS rebinding, and what closes the gap?

Check-then-use with two separate lookups leaves a window. The lesson's guardedLookup is passed as the HTTP client's lookup, so there is only one lookup and it is checked.

 An allowed supplier host answers a catalogue request with a redirect to an internal address. What should the importer do?

Each hop is a new outbound request and needs the same checks. With fetch, pass redirect: "manual" or "error" and handle redirects yourself.

 What makes request smuggling possible?

If the front server and the back server read the framing differently, bytes the front server treated as a body can become a separate request for the back server, one that the front server never inspected.

 What is the defence against request smuggling?

Route code runs after framing has been decided, so it cannot help. If no parser guesses, no two parsers can guess differently. Node.js's parser is strict by default.

 A pull request adds insecureHTTPParser: true to http.createServer "because an old client sends odd headers". What should a reviewer say?

Leniency is exactly what lets two parsers disagree. It exists for legacy interoperability and should not appear in a service behind a proxy.

 Why is it dangerous to deep-merge a parsed JSON body into another object without skipping any keys?

Reading target["__proto__"] on a normal object returns Object.prototype itself. Anything written there appears on every object in the program.

 What does creating result objects with Object.create(null) add to a safe merge?

Null-prototype objects (and Map) are the natural containers for data-controlled keys. They are a second layer behind skipping the forbidden keys.

 Why can one slow regular-expression match take down a whole Node.js server, not just one request?

The event loop is blocked for the whole match. That is why an exponential-time pattern on a crafted input is a denial of service.

 Both patterns accept names made of words separated by single spaces. Which one runs in linear time on long inputs that almost match, and why? const A = /^(\w+\s?)*$/; const B = /^\w+(?:\s\w+)*$/;

In A the space is optional, so a run of letters can be divided between repetitions in a huge number of ways, and the engine tries them all before failing. In B the repetitions cannot overlap. The lesson shows B's style on SKUs; you never need to run A to see the problem, only to count the ways it can match.
