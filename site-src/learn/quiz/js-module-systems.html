A project's package.json has "type": "module". Which files are CommonJS?

.cjs is always CommonJS and .mjs always ESM. .js follows the nearest package.json "type", here "module".

 A package.json has no "type" field. How does Node.js 24 treat a .js file in that package?

No "type" means CommonJS by default, with syntax detection as a fallback. Setting "type" explicitly avoids the guess and the warning.

 Why can an ES module import not be placed inside an if block?

The parse and link phases need to know every import without running code. For a conditional load, use await import(…).

 An ES module starts with console.log("start") and then imports a name that the other module does not export. What happens?

Linking connects every imported name before evaluation. A missing export stops the whole graph from running. CommonJS, by contrast, would run until the missing value was used.

With require, you get an ordinary object, and destructuring a missing property gives undefined without complaint. The mistake only surfaces when the value is called, which is what CommonJS code does in practice.

 What is this at the top level of a file?

ES modules run in strict mode without a module object. CommonJS wraps each file in a function called with this set to module.exports.

 An ES module needs the folder it lives in. __dirname is not defined there. What should it use?

process.cwd() is where the process was started, which is often a different folder. import.meta describes the current module.

 This file is an ES module. What does it print? try { orderTotal = 1500; console.log("created", orderTotal); } catch (error) { console.log(error.name); }

Modules are always strict, and in strict mode assigning to an undeclared name throws instead of creating a global. A CommonJS file without "use strict" would have created the global.

 An ES module imports from itself to show how imports behave. What does it print? import { ordersToday as seenByImport } from "./live-binding.js"; export let ordersToday = 0; function record() { ordersToday += 1; } record(); record(); console.log(seenByImport);

An import is a live binding to the exporter's variable, not a copy. Each record() updates the variable, and the imported name shows the current value. (Importing a module from itself is only a trick to fit the demonstration into one file.)

 This simulates what destructuring a require result does. What does it print? let count = 0; const moduleExports = { count, record() { count += 1; }, }; const { count: copied, record } = moduleExports; record(); record(); console.log(copied, moduleExports.count, count);

 Code does import { vatRate } from "./config.js"; and later vatRate = 0.1;. What happens?

Imports are views, not variables of the importer. If other modules must be able to change a value, the owner exports a function that does it.

 An ES module does import { refund } from "./payments.cjs" and gets "Named export 'refund' not found", although refund is on module.exports at run time. Why?

ESM needs export names at link time. The default import (import payments from "./payments.cjs") always works, and then you destructure the object.

 What does the default import of a CommonJS module give you?

Importing CommonJS from ESM always maps module.exports to the default import. That is why import pkg from "old-lib" is the reliable form.

 In Node.js 24, a CommonJS file calls require("./money.js"), where money.js is an ES module with export default and export const VAT_RATE. What does it get?

require(esm) is synchronous and returns the namespace object, as long as nothing in the module's graph uses top-level await.

 require("./settings.js") throws ERR_REQUIRE_ASYNC_MODULE. What does that tell you, and what works instead?

require must return immediately, and a module that awaits at the top level cannot finish immediately. import() is asynchronous and always works.

 Why is adding a top-level await to a published library a breaking change?

Top-level await belongs in application entry points and small config modules. Libraries should expose an explicit async setup function instead.

 What does this print? console.log("config: loading"); const config = await new Promise((resolve) => setTimeout(() => resolve({ vatRate: 0.075 }), 10)); console.log("config: ready", config.vatRate);

Top-level await is allowed in ES modules. The module pauses at the await, and anything that imports it would wait too.

 Which specifier is a bare specifier?

A bare specifier is a package name, optionally with a subpath. It is found through node_modules and the package's "exports" map. node: names are built-ins.

 In an ES module, import { toNaira } from "./money" fails with ERR_MODULE_NOT_FOUND although money.js exists. Why?

CommonJS tries .js, .json and /index.js. ESM, like browsers, resolves exactly what you wrote.

 A file at /app/src/orders/create.js imports "zod". Where does Node.js look first?

Resolution walks up from the importing file's folder. That is how a monorepo root node_modules can serve many packages, and how nested folders can hold different versions.

 A package's "exports" lists only "." and "./money". What happens to import "shop-core/src/internal/rates.js" from another package?

The exports map is the package's public API. Internal files can be moved or renamed without breaking anyone, because nobody outside can import them.

 An exports entry is { "default": "./a.js", "import": "./b.js" }. What does import load?

Node takes the first matching condition. "default" matches everything, so it must come last.

 What is the "imports" field (names starting with #) in package.json for?

# specifiers resolve through the package's own "imports" map and are not available to other packages.

 An app imports shop-errors (ESM build) while an older dependency requires it (CJS build). An error thrown by the dependency fails err instanceof PaymentError in the app. Why?

This is the dual package hazard. Ship one implementation, or check errors by name, a code or a Symbol.for brand, which work across copies.

A module is evaluated once per specifier and cached. Importing it again, statically or with import(), returns the same namespace object with the same values.

import() returns a promise for the namespace object. The default export is the default property.

 A route does await import(`./carriers/${req.query.carrier}.js`). What is wrong?

Importing runs a file's code with full permissions. Never build a specifier from input you do not control.

 When should a service load its plugins with import()?

Loading at startup turns deployment mistakes into startup errors instead of slow or failing customer requests.

 Modules format.js and tax.js import each other. tax.js runs first and calls formatNaira, a function declaration exported by format.js. What happens?

Hoisted function declarations are ready as soon as the module is linked. A const arrow function or a class would still be in the temporal dead zone and throw.

A const exists from the start of its scope but cannot be read until its line runs: the temporal dead zone. An ESM import in a cycle points at such a binding, which is why the error is "Cannot access … before initialization".

 A CommonJS app crashes with TypeError: Class extends value undefined is not a constructor or null right after someone added a require. What is the most likely cause?

In a cycle, require returns the half-finished exports object. Destructuring copies undefined, and extends undefined fails.

 Which change does not remove a circular dependency?

File names do not matter; the direction of imports does. The first three make the dependencies point one way or delay the lookup until both modules have loaded.
