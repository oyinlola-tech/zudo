Why is { message: "task created", taskId: 7, userId: "ada" } easier to use later than the sentence "Task 7 created by ada"?

A structured entry is a record: a short fixed message plus named fields. You can search userId === "ada" exactly, like a database column. With sentences you must guess every way the text could be worded.

 In a structured log entry, what is the metadata?

The message says what happened ("task created") and stays the same every time. The details that change (taskId, userId) go into metadata fields.

The formatter turns an entry into text. The transport receives the entry and sends the text somewhere. A transport can be a plain function.

A logger made with createLogger inside a service ignores every setting of the main one: level, formatter, transports. A child shares them and adds its own name and metadata.

 Why put a request id on every log line a request writes?

A server handles many users at once, so their lines interleave. With the same id on every line of one request, you can pull out exactly that request's lines.

 Several services pass the same id along, so one user action can be followed through all of them. What is this id called?

A request id follows one request in one service. When the same id is passed from service to service, it is called a correlation id.
