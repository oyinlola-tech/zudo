A handler contains const body = request.body as RefundBody;. What does the as RefundBody part do when the program runs?

A type assertion is a promise to the compiler, and types are erased when TypeScript compiles to JavaScript. At runtime the body is whatever the client sent. Only runtime validation (a schema or a hand-written check) looks at the actual value.

 A customer sends a perfectly well-formed refund request for their own order, with a valid session. Support staff should approve refunds, not customers. Which layer must stop this request?

The request is well-formed, so the schema accepts it, and the compiler never sees runtime data at all. Only a security control that knows who the caller is (from the session) and what they may do can refuse it.

 Which of these problems can TypeScript's type checker catch on its own?

Types protect developers from mistakes in the source code they write. Everything that arrives while the program runs (requests, rows, files, environment variables) is invisible to the compiler and needs runtime checks.

 Where should a refund handler get the caller's role from?

The caller writes the whole request: body, headers and query. Validating a role field only proves it is one of the allowed words, not that it is true. The role is a fact the server knows, so it comes from the server's session store or database.

With either schema, later code only sees the parsed result, which has no role. Rejecting makes the unexpected field visible: a client bug gets fixed, and repeated attempts to send fields like role show up in your logs.

Identity first, so unauthenticated callers do no work; then a well-formed request; then the server's own data about the object; then the decision, which needs all of these; and only then the action, followed by the audit record.

The field name is enough for a client to fix the request. Copying raw input into responses (and logs) is how injection reaches pages and how passwords end up in log files.

Limits bound the cost of one request. They work together with a body size limit that is checked before JSON.parse runs; the schema's limits cannot help if a 500 MB body has already been parsed.
