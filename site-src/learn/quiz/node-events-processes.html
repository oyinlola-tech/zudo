 A customer's name is used to run an invoice program. Which call is safe?

execFile passes each argument straight to the program; no shell reads it, so characters like ; or $( ) mean nothing. Every other option hands the text to a shell, and removing one kind of quote does not stop the others.

 A child program produces a 300 MB CSV export on stdout. Which function should start it?

execFile and exec collect all output in memory before handing it over. For big output, spawn lets you process it piece by piece, for example piping it into a file, with constant memory.

 Your server has a SIGTERM handler that takes 45 seconds to finish. Kubernetes uses its default 30-second grace period. What happens?

SIGKILL cannot be caught or delayed. The grace period is a hard limit, so a shutdown must finish well within it, which is why the lesson's shutdown has its own shorter deadline.

 A container stops and Docker reports exit code 137. What does that tell you?

Shells and Docker report a death by signal as 128 + the signal number. 137 = 128 + 9, SIGKILL. The out-of-memory killer and an expired grace period both send SIGKILL.

 A report loops over 10 million orders and takes 2 seconds of pure calculation. A developer makes the function async. What changes?

async only lets a function pause while it waits for something with await. A loop that only calculates never pauses. Moving it to a worker thread is what frees the event loop.

 Which job is the best fit for a worker thread?

Workers are for heavy JavaScript calculation. Waiting for databases and files is already handled by the event loop, and git is another program, which needs a child process.

 What is the right thing to do in a process.on("uncaughtException") handler of a server?

The error stopped some code halfway, so the program's state may be broken: half-finished transfers, locks never released. A fresh process is the only state you can trust.

 You read a child's stdout line by line. Which event tells you that you have received every line?

"exit" fires when the process ends, but its output streams may still hold data. "close" fires after the process has ended and its streams are closed.

 execFile rejects with ERR_CHILD_PROCESS_STDIO_MAXBUFFER. What happened?

The buffered functions keep all output in memory, up to maxBuffer (1 MiB by default). Past that limit the child is killed. Use spawn for large output.

 Which order is right for a graceful shutdown of a payment server?

First stop new work, so the amount of work can only shrink. Then finish what was started, which may still need the database, and only then close the connections.

 Why is the shutdown deadline timer unref()ed?

An active timer keeps a Node.js process running. unref() tells Node.js not to count it, so the timer only matters when other work is still holding the process open.

 Your logs show MaxListenersExceededWarning: ... 11 reloaded listeners added to [PriceList]. What should you do first?

The warning is a leak detector. The eleventh listener was added. Raising the limit only hides the leak until memory runs out.

 In the supervisor you built, why does a job that crashed the worker twice go to the dead letters instead of being retried forever?

A job that crashes the worker every time is a poison job. Retrying it forever turns one bad invoice into a total outage. One retry covers a fluke; after that, set it aside for a person to look at.

 A child prints ready and then registers process.on("SIGTERM", …). The parent sends SIGTERM as soon as it reads ready. What can happen?

This is a race: whether the handler exists depends on which process happens to be faster. Announce readiness only after everything, handlers included, is set up.

 You await once(worker, "exit"), and the worker throws an error before it exits. What happens at the await?

events.once treats "error" specially and rejects with it. If a failure is expected, listen for "error" yourself and wait for "exit" with a plain promise, as the lesson's worker example does.

 execFile("invoice-pdf-renderer", []) rejects with error.code === "ENOENT". What does that mean?

ENOENT means "no such file". The program is not installed or not on the PATH. There is no exit code, because no process ever started. Checking required programs at startup turns this into a clear message.

 What happens when you postMessage({ total() {} }) to a worker?

Structured cloning copies data, not code. Send plain data and let the worker's own code act on it.

 Why start a Node.js server in Docker with CMD ["node", "server.js"] rather than through a shell script?

With a wrapper shell, the shell receives the signal and may not pass it on. Node.js then never hears SIGTERM, and Docker kills it with SIGKILL after the grace period.

 A parent process is killed with SIGKILL while two child processes run. What happens to the children?

Killing a parent does not kill its children. A graceful shutdown should stop its children itself, and a SIGKILL gives it no chance to, which is another reason to keep shutdowns short.

 A server starts a new worker thread for every incoming report request. What is the main risk?

Each worker is a whole JavaScript engine. A fixed-size pool, usually about one worker per core, queues extra work instead of multiplying the cost.

 You spawn a program that does not exist and only listen for "close". What goes wrong?

A child that fails to start emits "error". Like on any emitter, an "error" event with no listener throws. Always listen for "error" on child processes.

 What should you know about signals on Windows?

Windows has no real POSIX signals. Write your shutdown for SIGTERM and SIGINT, and test it on Linux, where servers usually run.
