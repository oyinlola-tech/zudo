Which feature needs first-in, first-out (FIFO) order?

Receipts should go out in arrival order: a queue. The other three always need the most recent item first: a stack.

 Why is an undo history a stack rather than a queue?

Undoing the oldest change first would reverse something that later changes depend on. Last in, first out matches how people expect undo to work.

 What does it mean that a queue is an abstract data type?

The same queue ADT can be built with two stacks, a ring buffer or a linked list. Callers depend on the operations, so the implementation can change without breaking them.

 The lesson's Stack.pop() throws a RangeError when the stack is empty instead of returning undefined. Why?

Array pop returns undefined on an empty array, which is exactly the silent behaviour the wrapper avoids. Callers that expect emptiness check isEmpty() first.

 After undoing two changes, the user types something new. Why does the editor clear the redo stack?

History becomes a branch at that point. Simple editors drop the undone branch; that is what every mainstream editor's redo does.

 In removeLine(index), the command's undo uses removed and index from the moment the change was made. What would go wrong if undo instead read the line from this.lines[index] when it runs?

A command must capture everything needed to reverse itself at the moment it runs. The closure keeps removed and index alive for as long as the command is in a stack.

 Why can a counter per bracket kind not check ([)] correctly?

When ) arrives, the most recent opener is [, so the pairs cross. A stack's top is always "the bracket that must close next".

 What is the worst-case extra space of the stack-based bracket checker for a formula of length n?

The stack holds every opener that is still waiting. In the worst case that is every character. Time is O(n) because each character is pushed or popped at most once.

 A queue built on an array uses push to enqueue and shift to dequeue. What does one dequeue cost when 30,000 jobs are waiting?

Engines sometimes optimise shift on small arrays, but you cannot rely on it at scale. Two stacks or a ring buffer never move the items.

 Why is the two-stack queue O(1) amortized per operation, even though one dequeue can move thousands of items?

The expensive pour is paid for by all the cheap enqueues that filled the inbox. Spread over the sequence, the cost per operation is constant.

 A real-time system must answer every request within 1 millisecond. Why might the two-stack queue be a poor fit, while a ring buffer is fine?

Amortized O(1) is a guarantee about totals, not about each operation. Deadline-driven systems care about the worst single operation.

 A ring buffer has capacity 8, head = 6 and size = 3. At which index does the next enqueue write?

The items sit at indexes 6, 7 and 0. The next free slot wraps around to 1. The modulo is what lets the buffer reuse the space that dequeued items left behind.

 The lesson's RingBuffer.enqueue returns false when the buffer is full. What is that signal good for?

A bounded queue turns "the server slowly runs out of memory" into an explicit decision at the edge, such as an HTTP 503 with a retry hint.

 Why does the ring buffer set this.#slots[this.#head] = undefined when it dequeues?

Old slots are only overwritten when the buffer wraps around. Clearing them avoids holding large job objects in memory longer than needed.

 An editor caps its undo history at 100 commands. When the 101st arrives, the oldest must be dropped. Which structure makes both operations O(1)?

An array's shift is O(n). A deque built on a ring buffer adds and removes at both ends in O(1).

 Why does the job worker put a failed job at the back of the queue instead of retrying it immediately?

Retrying immediately blocks every job behind a broken one. Production systems also add a growing delay between attempts (exponential backoff).

 What is a dead-letter list (or dead-letter queue) for?

Without a limit, a permanently failing job loops forever; without a dead-letter list, it disappears silently. The list keeps the failure visible.

 A durable queue delivers each job at least once. What must the receipt handler do?

If a worker crashes after sending but before acknowledging, the job is delivered again. An idempotent handler turns a duplicate delivery into a no-op instead of a duplicate email or payout.

 The worker process holds 5,000 jobs in an in-memory Deque and is restarted for a deploy. What happens to the jobs?

Process memory disappears when the process exits. In-memory queues are fine only for work you can lose or recompute.

 Password-reset emails wait behind 50,000 marketing emails in one FIFO queue. What is the best fix?

FIFO is fair by arrival, not by importance. A priority queue (built with a heap in a later lesson) or a dedicated queue for urgent work keeps important jobs fast.

 A function walks a deeply nested JSON body recursively and crashes with "Maximum call stack size exceeded" on a hostile request. What is a robust fix?

The call stack is small and shared. An explicit stack lives on the heap and has no such limit, and a depth limit stops abuse early.

 Which two numbers best tell you whether a job queue's workers are keeping up?

A length that keeps growing, or an oldest job that keeps getting older, means the consumers are slower than the producers.
