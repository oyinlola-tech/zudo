Half the lines in a pull request only changed quotes and indentation. Which tool prevents this?

A formatter makes layout mechanical: everyone's code comes out the same, so diffs only show real changes.

 A discount is applied twice. The code is valid, formatted and correctly typed. Which tool can catch it?

Static tools know the language, not your business rules. Only a test that states the expected result can catch wrong behaviour.

 Code reads order.totl instead of order.total. Which tool is best placed to catch it before running?

no-undef only catches unknown variables. A misspelled property needs knowledge of the object's type, which is TypeScript's job (or // @ts-check with JSDoc in a JavaScript file).

 ESLint's use-isnan rule flagged this check. What does it print? const total = 0.1 * "abc"; console.log(total === NaN, Number.isNaN(total));

NaN is not equal to anything, itself included, so === NaN is always false and the check can never fire. Number.isNaN is the correct test.

 Why does the eqeqeq rule exist? What does this print? const discountCode = 0; console.log(discountCode == "", discountCode == false, discountCode === "");

== converts types before comparing, so 0 equals both "" and false. === never converts. The rule forces the comparison you almost always mean.

 What does this print? let code = "NONE"; let total = 100; if (code = "SAVE10") total = total * 0.9; console.log(code, total);

= assigns, and the value of the assignment ("SAVE10") is truthy, so every order gets the discount and code is overwritten. ESLint's no-cond-assign rule reports it.

 Why did eslint --fix change let to const but leave == alone?

Changing == to === changes the result whenever types differ, so it needs a human decision. A const that is never reassigned behaves exactly the same.

 In eslint.config.js, a rule is set to "warn". How does that differ from "error"?

The exit code is what CI looks at. Many warnings that nobody fixes become noise; decide per rule whether it matters (error) or not (off).

 A regex-based "linter" checks each line for ==. What does it print? const lines = [ 'if (code == "SAVE10") apply();', 'const tip = "never use == in this project";', 'if (a === b) done();', ]; const flagged = lines.map((line, i) => (/[^=!]==[^=]/.test(line) ? i + 1 : null)).filter(Boolean); console.log(flagged);

 What is an abstract syntax tree (AST)?

Linters, formatters, transpilers and bundlers all parse code into an AST, work on the tree, and (except linters) print new code from it.

 Saving a file makes the editor switch quotes back and forth between two styles. What is the likely cause?

Let Prettier own layout and ESLint own correctness. Current ESLint has no formatting rules in its recommended set for exactly this reason.

 Which Prettier command belongs in CI?

--check changes nothing and exits with 1 when a file is not formatted, which fails the build. --write would "fix" files on the CI machine, where nobody sees the result.

 esbuild turns a TypeScript file with a type error into JavaScript without complaint. Why?

Transpiling and checking are separate jobs. Fast transpilers (esbuild, SWC, Node.js type stripping) skip checking, so projects run tsc as a separate check.

 Your code calls Array.prototype.findLast, and you transpile to an old target for an old browser. What happens in that browser?

findLast is a function the runtime must provide. A polyfill is a script that defines it when it is missing.

 Which is not a reason browser apps use a bundler?

Browsers run ES modules natively with <script type="module">. They just cannot find npm packages by name, and hundreds of separate files are slow to download.

 Does a typical Node.js API server need a bundler?

Bundling a server is an optional optimisation, for example for faster cold starts on serverless platforms. It is required for browsers, not for Node.js.

 A browser bundle is built with --define:process.env.PAYMENT_SECRET_KEY='"sk_live_..."'. What is the problem?

Browsers have no environment variables, so bundlers inline the values. Only public keys may ever go into browser code; secret keys stay on the server.

 Why does Vite only expose environment variables whose names start with VITE_ to browser code?

An allow-list by prefix means a new DATABASE_URL or PAYMENT_SECRET_KEY stays server-only unless someone deliberately renames it.

 What does a source map contain?

sources, names and mappings are the core fields. It may also carry sourcesContent, the full original code, which is why teams think about where maps are published.

A later env file overrides an earlier one, and a variable already set in the real environment beats every file. That is how hosting platforms override settings without touching files.

 Environment variables are always strings. What does this print? const env = { PORT: "3000", DEBUG: "false", RETRIES: "" }; console.log(env.PORT + 1); console.log(Boolean(env.DEBUG)); console.log(Number(env.RETRIES));

"3000" + 1 joins text, the non-empty string "false" is truthy, and Number("") is 0, not an error. Convert and validate every setting once, in one config module.

 A .env file contains PORT=30O0 (a letter O). What does this print? const port = Number("30O0"); console.log(port, Number.isInteger(port), port || 3000);

Number returns NaN for text that is not a number. The || 3000 fallback quietly hides the typo, which is why the lesson's config loader reports it as an error instead.

 Which setting should never have a default value in code?

A missing database address must stop the server. A default could point staging at the wrong database, as in the lesson's opening story. Harmless settings like the port may have defaults; secrets and addresses of real systems may not.

 What does this print? "use strict"; const config = Object.freeze({ port: 4000, logLevel: "info" }); try { config.logLevel = "debug"; } catch (error) { console.log(error.name); } console.log(config.logLevel);

In strict mode (which ES modules always use), writing to a frozen object throws a TypeError. Settings are read once at startup and cannot be changed later by accident.

 The check script is npm run lint && npm run format:check && npm test. Lint fails. What happens?

&& runs the next command only if the previous one succeeded. Putting the fastest check first gives the quickest feedback.

 Why install ESLint and Prettier as dev dependencies instead of globally?

Two versions of a formatter can format the same file differently, and two versions of a linter can report different problems. Pinning them removes "works on my machine" from tooling.

 Everyone has format-on-save in VS Code. Why still run prettier --check in CI?

Someone will use another editor, edit a file on GitHub, or have the extension disabled. The automated check is what guarantees the rule.

 What does // @ts-check at the top of a .js file do in an editor like VS Code?

It is a gentle first step towards TypeScript: same file, same runtime behaviour, but the editor now catches misspelled properties and wrong argument types.

 After adding a build step, npm run lint reports 3,000 problems in dist/app.js. What is the fix?

Generated files are rewritten on every build; checking them is noise. Lint and format the sources, not the output.
