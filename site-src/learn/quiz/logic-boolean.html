Which of these is a proposition?

A proposition is a statement that is either true or false. "The balance is at least ₦5,000" is one. A question with a number as its answer, an instruction, or a bare value is not.

 What kind of value does balance >= amount produce?

Every comparison operator (>, >=, <, <=, ===, !==) answers a yes/no question, so it produces a boolean.

 Which variable name best fits a boolean that says whether a customer may withdraw?

Boolean names should read as a yes/no question: canWithdraw, isActive, hasEnoughMoney. withdraw sounds like an action, and a double negative like isNotUnableToWithdraw forces the reader to flip it twice.

 In the truth table of a && b, how many of the four rows are true?

AND is true only when both inputs are true, which is one row out of four. That strictness is why AND suits permission to do something risky.

 In the truth table of a || b, how many of the four rows are true?

OR is false only when both inputs are false. The other three rows, including "both true", are true.

 When is a XOR b true?

Exclusive or means one or the other, but not both and not neither. Equivalently: the two inputs are different.

 payByCard and payByTransfer are booleans. Which expression is true when exactly one payment method is chosen?

XOR is true when the two inputs differ, and !== on two booleans says exactly that. || would also accept both methods at once, which would charge the customer twice.

 Why does the lesson say not to use ^ for boolean XOR?

^ is bitwise XOR: true ^ false is 1. Use a !== b on real booleans. Powers are written **.

 A shipping rule depends on five true/false inputs. How many rows does its full truth table have?

Each input doubles the number of rows: 2 × 2 × 2 × 2 × 2 = 25 = 32.

 Why does adding one more boolean input double the number of truth-table rows?

Every old combination is still possible, and each can now be paired with either value of the new input. Two copies of every row: the count doubles.

 How does JavaScript group a || b && c?

&& binds before ||, like multiplication before addition. Add parentheses whenever you mix them, so no reader has to remember this.

 The business says: "Admins can always edit an order. Owners can edit it only before it ships." Which expression says that?

Admin alone is enough, so it sits on one side of an OR. The owner case needs two things, so it is an AND group. The first option would stop admins editing shipped orders: a different rule.

 A code review finds if (isAdmin || true) { deleteUser(); }. What does the condition simplify to?

a || true is always true: one way in that always works opens the door to everyone. The author almost certainly left a debugging shortcut in.

 What can you say about the code inside if (isOpen && !isOpen) { … }?

a && !a is always false: nothing is true and false at once. The block is dead code, which usually means the author typed the wrong variable.

 Which expression is always equal to a, whatever boolean a is?

Adding a condition that always holds changes nothing, so a && true is a. The others are always false, always true and always true.

 "If the film is age-restricted, the customer must be 18 or older." Which expression is true exactly when this requirement is met?

The requirement fails only when the film is restricted and the customer is not an adult. In every other case it holds, which is "not restricted, or adult". restricted && isAdult would wrongly refuse children at unrestricted films.

 The cash machine bug (|| instead of &&) passed testing. What testing habit would have caught it?

The tested accounts were "fully fine" and "fully closed", where AND and OR agree. The bug lived in the two rows nobody tried. A rule with two inputs has only four rows, so test them all.

 Which of these values is truthy?

The falsy values you will usually meet are false, 0, "", null, undefined and NaN. "false" is a non-empty string, so it is truthy, a classic trap when a form or a file sends booleans as text.

 Before combining inputs with logic, the lesson turns itemsInCart into itemsInCart > 0. Why?

&& and || return one of their values, and !== on a string and a number just asks whether they differ. Comparisons give real booleans, and boolean logic is only reliable on booleans.

 A user record has no isBlocked field, so user.isBlocked is undefined. Which login check falls to the safe side?

Only an explicit false should let the user in. !undefined is true and undefined !== true is true, so the first and third checks treat "we don't know" as "not blocked". The last one lets everyone in.

 A condition has grown to ten boolean inputs. What does the lesson recommend?

Ten inputs mean 210 = 1,024 cases. Naming sub-rules such as const canManageFile = isOwner || isAdmin; keeps each piece small enough to reason about and test.

 What does this print? const isLocked = true; console.log(!isLocked, !!isLocked, !!!isLocked);

Each ! flips the value. One flip gives false, two give back true, three give false again.

The account is active and not locked, but 8000 >= 10000 is false. One false part in a chain of ANDs makes the whole thing false.

 What does this print? const isAdmin = false; const isOwner = false; const isSupport = true; console.log(isAdmin || isOwner || isSupport); console.log(isAdmin || isOwner);

An OR chain is true if any part is true. The first line has isSupport; the second has no true part.

 What does this print? const isAdmin = true; const isOwner = false; const hasShipped = true; console.log(isAdmin || isOwner && !hasShipped); console.log((isAdmin || isOwner) && !hasShipped);

The first line is read as isAdmin || (isOwner && !hasShipped): admin is enough. The second forces the OR first, then requires the order not to have shipped, which fails.

 What does this print? console.log(true !== true, true !== false, false !== false);

On booleans, !== is XOR: true only when the two sides differ. Only the middle pair differs.

Three nested loops of two values each run 2 × 2 × 2 = 8 times: one run per truth-table row.

 How many rows does this count? let count = 0; for (const a of [false, true]) { for (const b of [false, true]) { for (const c of [false, true]) { if (a && (b || c)) count = count + 1; } } } console.log(count);

a must be true (4 rows left). Among those, b || c is false only when both are false, so 3 of the 4 remain.

 In what order does this print the rows? for (const a of [false, true]) { for (const b of [false, true]) { console.log(a, b); } }

The outer loop picks a and holds it while the inner loop tries both values of b. So b changes fastest.

 && and || return one of their values. What does this print? const itemsInCart = 0; const couponCode = "SAVE10"; console.log(itemsInCart && couponCode); console.log(couponCode && itemsInCart > 0);

&& stops at the first falsy value and returns it: 0. In the second line the string is truthy, so it returns the right side, the boolean 0 > 0, which is false.

 What does this print? const couponCode = "SAVE10"; const itemsInCart = 2; console.log(couponCode !== itemsInCart); console.log((couponCode !== "") !== (itemsInCart > 0));

On raw values, a string is always different from a number, so the first line is true. On real booleans, both are present (true !== true), so "exactly one" is correctly false.

 What does this print? const customer = { name: "Ada" }; console.log(!customer.emailVerified); console.log(customer.emailVerified === false);

The field is missing, so it is undefined. !undefined is true, but undefined === false is false: "unknown" is not the same as "no".

 Chaining XOR is not "exactly one". What does this print? const card = true; const transfer = true; const wallet = true; console.log(card !== transfer !== wallet);

It is read left to right: true !== true is false, then false !== true is true. A chain of XORs is true when an odd number of inputs are true, so all three methods pass. Count instead.

 This loop checks one expression for both values of a. What does it print? for (const a of [false, true]) { console.log(a, (a || !a), (a && !a)); }

a || !a is always true and a && !a is always false. A two-row loop is a complete proof, because a has no other values.
