In a conditional type T extends U ? X : Y, what does the extends test ask?

The test is assignability, the same check as const u: U = someT. It is not equality: "NGN" extends string is true, but string extends "NGN" is false.

 What is HasBalance<{ id: string; balanceKobo: number; frozen: boolean }>? type HasBalance = T extends { balanceKobo: number } ? "yes" : "no";

Object types are compared by shape. Extra properties never make a type fail an extends test; the type only has to have a balanceKobo that is a number.

 What is HasBalance<{ balanceKobo?: number }> with the same HasBalance? type HasBalance = T extends { balanceKobo: number } ? "yes" : "no";

An optional property might be missing, so a value of that type is not guaranteed to have a balanceKobo. It is not assignable to a type that requires one.

 What is IsText<any>? type IsText = T extends string ? "text" : "not text";

any might pass the test and might fail it, so TypeScript returns the union of both branches. One stray any quietly widens every conditional type it reaches.

 What is IsText<unknown>? type IsText = T extends string ? "text" : "not text";

unknown is not a union and not any. It could be anything, so it is not assignable to string: the false branch.

 What is IsText<never>? type IsText = T extends string ? "text" : "not text";

T is a naked type parameter, so the type distributes over unions. never is the empty union: zero members, zero evaluations, and the union of zero results is never.

 What is IsApproved<boolean>? type IsApproved = T extends true ? "approved" : "pending";

boolean is the union true | false. The conditional type distributes: true gives "approved", false gives "pending".

 What is ToList<string | number>? type ToList = T extends unknown ? T[] : never;

The naked T distributes: string becomes string[], number becomes number[], and the results are unioned. A value is either a list of strings or a list of numbers, never a mix.

 Which version gives (string | number)[] for string | number?

Distribution only happens when the checked type is a naked type parameter. Wrapping it in a one-element tuple, [T], asks one question about the whole union.

 What is MyExclude<"pending" | "paid" | "refunded", "refunded" | "disputed">? type MyExclude = T extends U ? never : T;

It runs once per member of T. "refunded" matches and becomes never, which disappears from the union. "disputed" is in U but not in T, so it never appears.

 Which type correctly answers true for never and false for string?

The first one distributes over zero members and gives never. The third is true for every type, because never is assignable to everything. Only the tuple form asks the question once.

 What is Direct? type Direct = "NGN" | 42 extends string ? true : false;

Distribution only happens when a generic type parameter is instantiated with a union. Here the union is written directly, so the whole union is tested once, and 42 is not a string.

 What is ResultOf<typeof refund>? type ResultOf = F extends (...args: never[]) => infer R ? R : never; function refund(reference: string, amountKobo: number): Promise { return Promise.resolve(amountKobo > 0 && reference.length > 0); }

infer R captures the declared return type as it is, promise included. That is how the built-in ReturnType works; add Awaited to get boolean.

 Why does ResultOf constrain with (...args: never[]) => … instead of (...args: unknown[]) => …?

(reference: string) => … is not assignable to (...args: unknown[]) => …: someone could call it with a number. It is assignable to (...args: never[]) => …, because nobody can produce a never to pass. So never[] matches every function.

 What is CurrencyFirst<[1_500_000, "NGN"]>? type CurrencyFirst = T extends readonly [infer C extends string, ...unknown[]] ? C : never;

infer C extends string only matches when the captured part is a string. The first element is a number, so the pattern fails and the false branch, never, is taken.

 What is Fields<{ success: "paid"; failure: 402 }>? type Fields = T extends { success: infer V; failure: infer V } ? V : never;

The same infer name found two candidates in ordinary (output) positions, so TypeScript combines them with a union. In parameter positions it would use an intersection.

 What is Unwrap<Promise<Promise<User>> | undefined>? type Unwrap = T extends Promise ? Unwrap : T;

It distributes over the union. The promise member is unwrapped twice by recursion until the base case, User. undefined does not match the pattern and is returned unchanged.

 Why does real code use the built-in Awaited<T> instead of T extends Promise<infer V> ? Unwrap<V> : T?

Unwrap<PromiseLike<User>> stays PromiseLike<User>, but await would give a User. Awaited handles thenables and is maintained and tested by the TypeScript team.

 A recursive type fails with TS2589 "Type instantiation is excessively deep and possibly infinite". What is the best first move?

There is no tsconfig option for the limit. Tail-position recursion lets the compiler evaluate about a thousand steps; anything more means the type is doing work that belongs in runtime code, or it never terminates.

 What is Kind<Date>? type Kind = T extends object ? "group" : T extends Date ? "date" : "other";

The first matching branch wins, like if/else if. A Date is an object, so the broad test swallows it. Put the most specific tests first.

 A form type uses InputKind<T[K]> for each field. For the optional field launchDate?: Date it gives "date" | "unsupported". Why?

An optional property's type includes undefined, and the conditional type handles each member. Use InputKind<NonNullable<T[K]>>.

 Why does return "text"; fail to compile inside function label<T extends string | number>(value: T): T extends string ? "text" : "number", even after if (typeof value === "string")?

Inside the function T is still unknown: it could even be the union string | number. The return type stays unresolved, and almost nothing is assignable to it. Use overloads, or one cast in the implementation plus tests.

 When is a conditional return type better than overloads?

Overloads are clearer for a few fixed cases, but a call with a union or an unresolved T matches none of them. A conditional return type follows whatever T is. Neither way checks the implementation against the return type.

 Why is type NaiveEqual<A, B> = A extends B ? (B extends A ? true : false) : false a bad equality test?

The naive version distributes over A and gives in to any. The Equal helper built from two generic function types does neither, which is why type tests use it.

 What does a // @ts-expect-error line in a type test prove?

It is a test for a rejection. @ts-ignore hides errors silently; @ts-expect-error demands one, so a rule that stops being enforced is noticed.

 A retry wrapper is applied to every method of a payments client. Which method is not safe to retry automatically?

Retrying is safe for idempotent operations, where doing them twice has the same effect as once. A charge that timed out may have succeeded, so a retry can charge the customer twice, unless the processor supports idempotency keys.

 With Retried<T> from the lesson, what is the type of payments.baseUrl when the client has baseUrl: string? type Retried = { readonly [K in keyof T]: T[K] extends (...args: infer A) => infer R ? (...args: A) => Promise> : T[K]; };

A string is not a function, so the conditional type takes the false branch and keeps T[K]. The mapped type adds readonly.

 What does this print? const nested = Promise.resolve(Promise.resolve(Promise.resolve(250_000))); const value = await nested; console.log(typeof value, value);

A promise resolved with another promise adopts its value, so nesting flattens at runtime. That is why Promise<Promise<T>> is a type that describes no real value, and why Awaited unwraps recursively.

Any object with a then method is awaited like a promise. The type of value is string because Awaited models thenables. An Unwrap that only matches Promise would get this wrong.
