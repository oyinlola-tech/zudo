Why are the language's hooks (such as the iteration method) stored under symbols instead of string names like "iterator"?

Adding a hook under a string name would change the behaviour of every object that happened to have that property. A symbol created by the language cannot collide with anything already written.

 What does this print? const a = Symbol("orderId"); const b = Symbol("orderId"); console.log(a === b, a.description === b.description);

Every Symbol() call creates a new, unique value. The description is only a label for people, and two symbols can share one.

 What does this print? const note = Symbol("note"); const order = { note: "leave at gate" }; order[note] = "internal: VIP"; console.log(order.note, "|", order[note]);

The string key "note" and the symbol stored in note are different keys, so both values live side by side. That is the point of symbol keys.

Object.keys and JSON.stringify skip symbol keys. Reflect.ownKeys returns string and symbol keys, so it sees two.

 What does this print? const brand = Symbol("brand"); const original = { sku: "RICE-5", [brand]: true }; const copy = { ...original }; const viaJson = JSON.parse(JSON.stringify(original)); console.log(copy[brand], viaJson[brand]);

Object spread copies own enumerable properties, symbol keys included. JSON has no way to represent a symbol key, so it drops it.

 Is data stored under a symbol key private?

Symbols hide data from ordinary listing tools, not from code that looks for it. For real privacy use #private class fields or closures.

 What does this print? const a = Symbol.for("shop.cart"); const b = Symbol.for("shop.cart"); const c = Symbol("shop.cart"); console.log(a === b, a === c, Symbol.keyFor(c));

Symbol.for returns the same registered symbol for the same name. Symbol() makes a new, unregistered one, so Symbol.keyFor has no name for it.

 Your app and a plugin load two different versions of the same package. The package checks value[CHARGE] === true, where const CHARGE = Symbol("Charge"). A charge made by one copy is passed to the other. What happens?

Each copy of a module runs its own top-level code, so each gets its own unique symbol. A protocol that must work across copies should use Symbol.for("package.Charge").

 Why should registry symbols have namespaced names like Symbol.for("shop.log.redact") rather than Symbol.for("redact")?

Symbol.for gives the same symbol to everyone who asks for the same name. That is the goal within one protocol, and a risk between unrelated ones.

Multiplication wants a number. A template literal wants text. Binary + does not know yet whether it will add or join, so it passes "default", even when the other side is a string.

When [Symbol.toPrimitive] exists, JavaScript calls it for every conversion and never consults valueOf or toString.

 Why can valueOf alone not give a money type "text is fine, arithmetic is an error"?

Without a hint, valueOf has to answer every numeric request the same way. Symbol.toPrimitive(hint) knows what the operation wants and can refuse some operations only.

 Which Symbol.toPrimitive policy fits a Money type best?

Formatted text is always safe to show. A bare number loses the currency, so arithmetic should go through methods like plus that check currencies and fail loudly otherwise.

 For a Duration stored in seconds, the lesson allows the "number" hint to return seconds. Why is that fine for durations but not for money?

The right policy depends on whether the number still means the whole value. Seconds do; kobo without "NGN" do not.

The tag is a label the object provides. It is good for logs and debugging, not for decisions that must not be fooled.

It works, but it hides a duck-type check behind an operator with a well-known meaning. Explicit names are easier to read and search for.

using works like a try/finally written for you: disposal runs however the block ends, and the error continues to the caller afterwards.

 The logger's redaction protocol calls value[redact]() where redact is a symbol. Why not call a method named "redact"?

A protocol keyed by a string could be triggered by accident by ordinary data. In the lesson, a payment's own redact field was logged as plain data because it was not the symbol.

A display hook changes what one tool prints. Secrets must be kept out of logged objects, or everything logged must pass through one sanitising function.

 What does new Symbol("id") do?

Call Symbol("id") without new. Like numbers and strings, symbols are primitive values.

 Why does the lesson's Money define toJSON() returning { minor, currency } instead of relying on its "string" conversion?

JSON.stringify looks for a toJSON method, then serialises own enumerable string-keyed properties. Store and send exact data; format only for people.

 Why is the lesson's Money immutable (frozen, with operations returning new objects)?

Objects are shared by reference. A value type such as money is safest when nobody can change it after creation.

 What is a symbol's description (the text in Symbol("orderId")) used for?

Only Symbol.for(name) uses a name to find a symbol. For Symbol(description), the text is just a label to make debugging easier.

 A worker receives an order through structuredClone (or postMessage). What happens to properties stored under symbol keys?

The structured clone algorithm copies string-keyed data only. Symbol-keyed metadata is local to the objects in memory and does not travel.

 Where do well-known symbols such as Symbol.iterator and Symbol.toPrimitive come from?

Well-known symbols are built in. They are not in the global registry (Symbol.keyFor(Symbol.iterator) is undefined), but every piece of code sees the same values through Symbol.iterator and friends.

 What must a [Symbol.toPrimitive](hint) method return?

The whole point of the hook is to produce a primitive. The hint is a request, not a rule: returning a string for the "number" hint is allowed, and the operation then converts that string.

 You need a field on an object that outside code must never read or change, not even on purpose. What should you use?

Symbol keys can be listed with Object.getOwnPropertySymbols and are copied by spread. Private fields and closure variables cannot be reached from outside at all.
