What is the strategy pattern?

Each delivery method is a strategy with the same available and feeKobo methods. The checkout uses whichever the customer picked.

 In one shippingFeeKobo function, a "free over ₦50,000" line meant for standard delivery also made express free. Why does moving each method into its own strategy prevent this?

In the shared function, every line above a method's branch applies to it. Separate strategies have no shared lines to leak through.

 The mobile app sends the method id "sameday" instead of "same-day". What should strategyFor do?

The old return 150_000 at the end of the if chain hid the typo. Unknown input is a bug to surface, not a case to guess.

 Who should choose which strategy is used?

The code that uses a strategy only calls it. Keeping the choice outside is what makes strategies interchangeable and testable.

 When is a strategy best written as a plain function type instead of an object with methods?

A function is the smallest possible strategy. The shipping strategies are objects because each has an id, an availability rule and a fee rule.

 Same-day delivery is only offered before 14:00 Lagos time. Why does available(order, now) take the time as a parameter?

The clock is part of the outside world. Passing it in keeps the rule pure and testable, as in earlier lessons.

 In the observer pattern, what does the publisher know about its observers?

That ignorance is the point: new reactions are added by subscribing, and the checkout does not change.

 Why does OrderPlacedTopic.publish use Promise.allSettled instead of Promise.all?

With allSettled, a failing analytics observer is reported by name while the e-mail and warehouse observers still complete.

 Which reaction to a new order should not be an observer that may fail independently?

If stock is not reduced atomically with saving the order, two customers can buy the last item. It is a rule of the use case and must succeed or fail with it.

 Why can "refuse the order if the account is blocked" not be an observer of order.placed?

An event says "this happened" in the past tense. Anything with a veto must run before that is true.

 The order is saved, and the process crashes before the in-memory event reaches the warehouse observer. What is the standard fix for events that must not be lost?

An in-memory event only exists in one process's memory. Storing it atomically with the order means it is delivered after a restart.

 The loyalty observer assumes the e-mail observer has already run. Why is this fragile?

Promise.allSettled starts all observers together. If one step truly depends on another, that is a sequence inside one handler or the use case, not two observers.

 Why does subscribe return a function?

A topic holds a reference to every observer. Unsubscribing releases it, which is how long-running servers avoid leaking listeners.

 What does the command pattern do?

Once "set rice to ₦7,650" is an object, a history can execute it, keep it, undo it and write down who did it.

 When should changePrice record the previous price for undo?

A command created in the morning and run in the afternoon must undo to the afternoon's price. Capturing at creation would restore a stale value.

 A batch command runs A, then B, then C. In which order must it undo them?

Later steps may depend on earlier ones (B may change what A set). Undoing in reverse is the only order that is always correct.

 What is the job of CommandHistory (the invoker)?

Because it only uses the Command interface, the same history works for price changes, deactivations and any future command.

 Why must a command sent through a job queue be plain data rather than an object with methods?

After JSON.parse(JSON.stringify(command)), execute is undefined. So the data says what, and the worker's handler says how.

 Queues deliver messages at least once. What does that require of a job handler such as "send invoice e-mail"?

After a worker crash the same message can be delivered again. Idempotent handlers turn "at least once" into "effectively once".

 Why does the worker validate each queued message with parseJob before handling it, even though the web server wrote it?

The rejected DeleteAllOrders message shows why: without a check, the worker would trust whatever arrives.

 What is a chain of responsibility?

Web middleware is this pattern: logging, authentication and authorization are links in front of every route.

 Why must the error-handling middleware be the first (outermost) link?

Each middleware wraps everything after it, like an onion. The outermost layer sees every error on the way out.

 Should a rate limiter run before or after authentication?

If the limiter runs after authentication, a request with a wrong token is rejected with 401 before it is ever counted, so guessing is unlimited.

 What does it mean when a middleware short-circuits?

authenticate short-circuits with 401 when there is no valid token: the export handler is never reached.

 A middleware accidentally calls next() twice. What can happen, and how does the lesson's chain respond?

A guard in the composer turns a dangerous, silent bug into an immediate error during development.

 In the refund approval chain (support up to ₦5,000, manager up to ₦100,000, finance up to ₦1,000,000), what happens to a request for ₦5,000,000?

A well-built chain always gives exactly one answer, including an explicit "no" at the end of the chain.

 With @zudojs/middleware's createPipeline and the default settings, what happens when the handler throws?

The default error mode is "capture", so callers check outcome.success. "throw" and "continue" are the other modes.

 A function picks between two tax rates with one if, and the rates have not changed in five years. Should it become a strategy?

Use the pattern when the symptom is real: a switch that grows with every campaign. Two stable branches are clearest as they are.
