The code that picks a payment provider by country is copied in the checkout, the refund handler and the webhook. What problem does a factory solve here?

The Kenyan refunds went to the wrong provider because one copy was not updated. With one factory, adding a country is one change that every caller sees.

 What should a provider factory do for a country it does not know?

A silent default is exactly how refunds ended up at Stripe. Unknown input is a configuration or programming error and should fail loudly and early.

 A customer paid in Kenya through M-Pesa and later moved to Ghana. Which provider must refund them, and how does the code know?

Money can only be refunded by the provider that took it. Routing (country to provider) can change; the recorded provider of a past charge cannot.

 Why does the lesson keep routes (country to provider name) separate from builders (provider name to object)?

Changing the routing table affects new payments only. Refunds and webhooks look up the builder by the recorded provider name.

 Why are the factory's tables typed as Record<Country, ProviderName> instead of Record<string, ProviderName>?

The compiler becomes the checklist that the copied if chains never had. A Record<string, …> accepts any subset of keys.

 What does building every routed provider once at application start achieve?

The compiler checks that the tables are complete; only running the factory checks that the environment actually has every secret key.

 When is a static factory method such as Money.fromNaira(12.5) better than a public constructor?

A named constructor says what its argument means and can refuse bad input before an object exists. A private constructor makes it the only door.

 A service calls createPaymentProvider(...) directly inside its methods. What is the problem, and the fix?

A factory hides which class, but calling it directly still fixes which factory. Receiving it as a dependency moves that choice to the composition root.

 A factory reads process.env.PAYSTACK_KEY inside itself. Why does the lesson advise against this?

Pass configuration in, as createPaymentProvider(name, keys) does. The composition root reads the environment once.

 Staging used STORAGE=disk and QUEUE=redis. The worker on another machine could not find uploaded files. What kind of problem is this?

Each setting was valid alone; the combination was not. An abstract factory makes the family the unit of choice, so a mix cannot be configured.

 What does an abstract factory give you that two separate factories do not?

localInfrastructure() returns disk storage and an in-process queue; cloudInfrastructure() returns shared storage and a shared queue. There is no way to ask for disk plus Redis.

 A project has one environment and one kind of storage and queue. Should it introduce an abstract factory now?

Patterns earn their place by solving a problem you have. With one family, the pattern adds names and indirection and hides nothing (YAGNI).

 A function takes eight positional parameters and two of them were swapped in a call. What should you reach for first in TypeScript?

An options object fixes the swap with the least code. A builder is for step-by-step construction with rules, such as a query.

 Which situation calls for a builder rather than an options object?

The query is built in steps, has rules that span steps (placeholder numbering), and is assembled at the end: exactly what a builder is for.

 What is a fluent interface?

Fluent style is common for builders. Whether each method returns this or a new object is a separate choice, and it matters.

 Why does the lesson's OrderQuery return a new builder from every method instead of changing itself and returning this?

With a mutable builder, paid.where(a) and paid.where(b) change the same object, so both "derived" queries contain both filters.

 Why does the query builder keep user input in values and put only $1, $2 in the SQL text?

Placeholders are how parameterised queries work. The builder's job is to make the safe way the easy way, including the placeholder numbering.

 sortBy(column: "placed_at" | "total_kobo", direction: "ASC" | "DESC") goes directly into the SQL text, not into values. Why is that safe?

Identifiers and keywords cannot be parameters. The union narrows them to known-safe literals in code; at run time, input from a URL must be validated against the same list first, since types do not exist at run time.

 Which two problems did the AppConfig.getInstance() singleton cause?

Tests became order-dependent because one test's setting stayed in the shared instance, and no test could hand the function a configuration of its own.

 export const pool = createPool(process.env.DATABASE_URL) at the top of a module is also a singleton. What extra problem does it add?

ES modules are evaluated once and cached, so every importer shares the object, and the side effect happens as soon as anything imports it. Create it in the composition root instead.

 What is the key difference between the singleton pattern and a singleton lifetime in a DI container?

"There is one of these" is a wiring decision. Made in the composition root, it is visible, and tests can make their own instance.

 A singleton service stores currentUser in a field, set at the start of each request. What goes wrong under load?

Single-threaded does not mean one request at a time: requests interleave at every await. Per-request data needs a per-request (scoped) lifetime or explicit parameters.

 With @zudojs/container, a factory registered with ContainerScope.SINGLETON runs how often?

That is what makes the container lifetime test-friendly: each test creates a fresh container and gets a fresh "singleton", with nothing shared with the application.

 The lesson's loadConfig returns Object.freeze({ ... }) and the one object is shared by the whole app. Why is this sharing harmless?

The singleton's problems come from shared mutable state and global access. Frozen and passed in, the configuration has neither.

 For test data, when does makeOrder({ status: "paid" }) (defaults plus a Partial of overrides) replace a full test data builder?

Test data builders shine when construction has steps or rules (.paid() also sets a charge id and paid date). For plain overrides, the function is simpler.
