What type does TypeScript infer for const row = ["2026-09-01", "Airtime", -500];?

An array literal on its own is inferred as an array: any length, and every element may be any of the element types. You need an annotation, a return type, as const or a const type parameter to get a tuple.

 What does a tuple type such as [string, number] describe?

A tuple fixes the length and the type at each position. At runtime it is an ordinary JavaScript array.

 For const t: [string, string, number] = ["ACC-1", "ACC-2", 500];, what is the type of t.length?

A tuple knows its length, so length has the literal type 3. For a tuple with optional elements it becomes a union, such as 2 | 3.

 What does this print? function splitBill(totalKobo: number, people: number): [share: number, remainder: number] { const share = Math.floor(totalKobo / people); return [share, totalKobo - share * people]; } const [each, left] = splitBill(1000001, 4); console.log(each, left);

The tuple return gives two values, and destructuring names them in order: the first element is the share, the second the leftover kobo that cannot be split evenly.

 What do the labels in [from: string, to: string, kobo: number] change?

[from: string] and [string] are the same type. Labels are for people reading the code and hovering in the editor.

 What happens with const [a, b, c] = pair; when pair is typed [number, number]?

TypeScript knows which indexes exist in a tuple, so destructuring or reading past the end is caught before the code runs.

 What does this print? type Fee = [label: string, kobo: number, waivedFor?: string]; const fees: Fee[] = [["SMS alert", 400], ["Transfer", 1075, "Premium"]]; for (const [label, kobo, waivedFor] of fees) { console.log(label, kobo, waivedFor ?? "-"); } console.log(fees[0].length, fees[1].length);

An optional element that is left out is simply missing, so destructuring gives undefined and ?? prints -. The arrays have 2 and 3 elements; the type of length is 2 | 3.

 Which tuple type is invalid?

A required element cannot follow an optional one, because TypeScript could not tell which position a value belongs to. Optional elements go at the end.

 What does this print? type BranchRow = [branch: string, ...dailyKobo: number[]]; const rows: BranchRow[] = [["Lekki", 500, 700], ["Wuse"]]; for (const [branch, ...daily] of rows) { console.log(branch, daily.length, daily.reduce((sum, k) => sum + k, 0)); }

The rest element means zero or more numbers after the branch. A rest pattern in destructuring always gives an array, empty for "Wuse", and reduce with a start value of 0 handles the empty case.

 What does [...path: string[], kobo: number] describe?

A rest element can appear at the start, in the middle or at the end, as long as there is only one. Here it collects the leading strings, and the final position is always a number.

 This compiles. What does it print? const rate: [currency: string, nairaPerUnit: number] = ["USD", 1550]; rate.push(1600); console.log(rate.length, rate);

A tuple is a real array, and plain tuple types still allow push. The type keeps saying "two elements" while the array has three. A readonly tuple would refuse the push.

 Which of these compiles on const pair: readonly [string, number] = ["USD", 1550];?

A readonly tuple removes every method that changes the array, and assignment to elements. toSorted returns a new array and leaves the original alone, so it is allowed.

 What does this print? const topUps: readonly [number, number, number] = [5000, 1000, 20000]; const sorted = topUps.toSorted((a, b) => b - a); console.log(sorted, topUps[0]);

b - a sorts from largest to smallest. toSorted returns a new array, so topUps is unchanged and its first element is still 5000.

 Why is a parameter typed readonly [string, number] friendlier than [string, number]?

A mutable tuple can be passed where a readonly one is expected, but not the other way round. readonly on inputs is both more flexible and a promise.

 What type does const pair = ["NGN", 1] as const; have?

as const makes the literal a readonly tuple of literal types: the most precise type possible, which is often more precise than you need for values that are not constants.

 function rate(c: string) { return [c, 1550]; } has no return type. What do callers get?

The returned literal is inferred as an array. Adding the return type [currency: string, rate: number] turns it into a tuple, and every caller keeps the positions.

 What does the const in function tuple<const T extends readonly unknown[]>(...items: T): T do?

A const type parameter (TypeScript 5.0) asks for the narrowest inference, without the caller writing as const at every call site.

 Why does React's useState return a tuple rather than an object like { value, setValue }?

Destructuring a tuple assigns by position, so names are free. An object would force every caller to rename: const { value: count, setValue: setCount } = ….

 What does this print? function createState(initial: T): readonly [get: () => T, set: (next: T) => void] { let value = initial; return [() => value, (next: T) => { value = next; }] as const; } const [cartItems, setCartItems] = createState(2); const [otherCart] = createState(10); setCartItems(cartItems() + 3); console.log(cartItems(), otherCart());

Each call to createState has its own value, captured by both returned functions. Setting one cart does not affect the other.

 With createState<T>(initial: T), why do you write createState<string | null>(null) for a coupon code?

Inference uses the initial value. null alone gives T = null. Passing the type argument says what the state will hold over its lifetime.

 What is the type of results in const results = await Promise.all([loadUser(), loadBalance()]), where the two functions return Promise<User> and Promise<number>?

Promise.all maps a tuple of promises to a tuple of their results, so each position keeps its own type. await unwraps the outer promise.

Object.entries returns an array of [key, value] pairs, typed [string, number][]. The first pair is printed as a two-element array.

 What does this print? function transfer(from: string, to: string, kobo: number): string { return `${from}>${to}:${kobo}`; } const queued: Parameters[] = [ ["A", "B", 100], ["B", "C", 250], ]; console.log(queued.map((args) => transfer(...args)).join(" "));

Parameters<typeof transfer> is the tuple [from: string, to: string, kobo: number]. Spreading a tuple into the call passes each element as a separate argument, checked by position.

The union of tuples narrows on the null element even after destructuring, so amount * 100 compiles in the success branch. The explicit empty-string check matters: Number("") is 0, not NaN.

 Why does [error: string, row: null] | [error: null, row: Row] narrow after if (error !== null) return;?

A unit type like null (or a literal) in the same position of each member lets TypeScript tell the members apart, exactly like a kind property in a discriminated union.

 What does this print? const cells = "2026-09-04,Refund,".split(","); console.log(cells.length, JSON.stringify(cells[2]), Number(cells[2]));

A trailing comma produces an empty last cell, so there are three cells. Number("") is 0, which is why a parser must reject an empty amount explicitly instead of trusting Number.isFinite.

 A client sends {"rate": ["USD", 1550]}. What type does JSON.parse give rate, and what should you do?

JSON has arrays, not tuples, and JSON.parse returns any. A tuple from outside is outside data like any other, so its length and every position must be checked.

 Which value is the best fit for a tuple rather than an object?

Tuples suit short, obvious groups that callers take apart at once and name themselves. Records with many fields, public JSON and optional settings are clearer as objects with named properties.

 After const [date, description, amount, reference] = line.split(",");, what type does TypeScript give reference with strict on and noUncheckedIndexedAccess off (it is not part of strict)?

split returns string[], and without noUncheckedIndexedAccess, every element read from an array is typed as the element type. That option adds | undefined so you cannot forget the check. (The tsconfig.json that tsc --init writes turns it on.)

 What does this print? const fees = new Map([ ["transfer", 1075], ["sms", 400], ]); fees.set("sms", 500); console.log([...fees], fees.size);

A Map is built from [key, value] tuples and spreads back into them. Setting an existing key replaces the value, so there are still two entries.
