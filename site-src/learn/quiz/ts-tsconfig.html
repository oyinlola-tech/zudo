A project has "target": "ES2020" and calls orders.at(-1) (added in ES2022). What happens?

target rewrites syntax; it never adds functions. What TypeScript believes exists comes from lib, which defaults to the target's version. Raise the target, or add a newer lib if the runtime really has the function.

 A Node.js backend's tsconfig has no lib line. A developer writes localStorage.getItem("cart") in server code. What happens?

Without an explicit lib, TypeScript assumes a browser may be involved and includes the DOM types. A backend should write "lib": ["ES2024"] so browser APIs are compile errors.

 In TypeScript 7, a fresh project with @types/node installed reports "Cannot find name 'process'". Why?

Older versions loaded every package in node_modules/@types. TypeScript 7 loads only the ones you name, which also keeps test-framework globals out of application code.

 Under "module": "NodeNext", what decides whether a .ts file is emitted as an ES module or as CommonJS?

NodeNext mirrors Node.js: "type": "module" makes .js files ESM, otherwise CommonJS. That is why the same source produced import in one project and require in the other.

 A project with "type": "commonjs" and verbatimModuleSyntax uses import/export in its .ts files. What does tsc say?

verbatimModuleSyntax promises that imports are emitted exactly as written. Turning import into require would break that promise, so tsc refuses (errors such as TS1287 and TS1295). Use ESM, or write import x = require() in CommonJS.

 Which module settings fit a React app built by Vite, where imports are written without extensions?

The bundler resolves and emits the code, so TypeScript should resolve like a bundler (extensionless imports allowed) and leave imports as written. NodeNext would demand .js extensions that the bundler does not need.

 Which of these is not turned on by "strict": true?

noUncheckedIndexedAccess is separate, because it reports many errors in existing code. Turn it on yourself for new projects.

 What does strictNullChecks change about orders.find(...)?

The runtime behaviour does not change: find always could return undefined. The flag makes the type say so, so the compiler can make you handle it.

 tsc reports "Property 'balanceKobo' has no initializer and is not definitely assigned in the constructor." What is the best fix when the wallet starts empty?

Give the field its real starting value. The ! form only tells the compiler to trust you; at runtime the field would still be undefined, and += would give NaN.

 Why does useUnknownInCatchVariables make the catch variable unknown instead of any?

throw "timeout" is legal JavaScript. With any, error.message compiles and is undefined at runtime; with unknown, you write error instanceof Error ? error.message : String(error).

 How do you fix "'this' implicitly has type 'any'" in function describeWallet() { return this.owner; } while keeping it a plain function?

The this parameter is only a type annotation; it is erased from the JavaScript. Callers must then call it with a suitable this, for example describeWallet.call(wallet). An arrow function would take this from outside, which is not what you want here.

 strictFunctionTypes rejects assigning (p: CardPayment) => void to (p: Payment) => void. Why is that correct?

A function that needs more from its argument cannot stand in for one that accepts any payment. Parameters must be checked in the opposite direction from return values (contravariance).

 With noUncheckedIndexedAccess on, which line still gives order the type Order (without | undefined)?

A for...of loop only visits items that exist. Index and record lookups can miss, so they get | undefined. That is exactly the distinction the flag makes.

 What does exactOptionalPropertyTypes change about phone?: string?

"Missing" and "present with the value undefined" behave differently: the second shows up in Object.keys and overwrites when spread. The flag keeps them apart unless the type says string | undefined.

 With noImplicitOverride, a subclass writes override close(). Later the base class renames close to shutDown. What happens?

Without the keyword, the subclass method would silently stop overriding anything. With it, the rename becomes a compile error that points straight at the dead method.

 What is the difference between allowJs and checkJs?

With allowJs, a wrong call from TypeScript into a JavaScript file is caught. With checkJs, mistakes inside the JavaScript file are caught too, using inference and JSDoc comments.

 A project has src/server.ts and test/server.test.ts, "outDir": "dist", and no rootDir or include. Where does server.js end up?

The default include picks up test/ too, so the computed root moves up one level. Set "rootDir": "src" and "include": ["src"].

 With "paths": { "@shop/*": ["./src/*"] }, the code passes tsc and runs under tsx, but node dist/main.js fails with ERR_MODULE_NOT_FOUND. Why?

tsx and bundlers read paths themselves, which hides the problem during development. For Node.js, use package.json "imports" (keys starting with #), which both Node.js and NodeNext resolution understand.

 Which alias works in both tsc (NodeNext) and plain node without extra tools?

Subpath imports are a Node.js feature, resolved at runtime. TypeScript's NodeNext resolution reads them too, and maps dist back to the sources while you edit.

 With sourceMap on, what does tsc add to each emitted .js file?

The comment is how Node.js (with --enable-source-maps) and browsers find the map, so that stack traces and breakpoints use your .ts lines.

 A config extends a shared base and sets a few options on the command line. How do you see which options are really in effect?

--showConfig prints the final merged configuration, including options implied by others (such as isolatedModules from verbatimModuleSyntax), without compiling.

 The base config has "include": ["src", "test"]. The project config extends it and sets "include": ["src"]. What is included?

compilerOptions are merged option by option, but include, exclude and files are replaced entirely by the extending file.

 What does skipLibCheck skip?

Published declaration files were checked when they were built. Re-checking them is slow and can fail on conflicts between packages you cannot fix. Your own code is still fully checked.

 Under verbatimModuleSyntax, what is the difference between import type { AuditEvent } from "./audit.js" and import { type AuditEvent } from "./audit.js"?

import type marks the whole statement as type-only. A type modifier on one name marks only that name; the import statement itself is kept as written.

 A project uses verbatimModuleSyntax. What does TypeScript 7 emit for an exported const enum OrderStatus used in another file?

verbatimModuleSyntax implies isolatedModules and preserveConstEnums: each file must compile without reading others, so the value cannot be inlined across files. The const enum compiles like a normal enum.

 strict is already true by default in TypeScript 7. Why still write "strict": true?

An explicit line means the same thing to every tool and every version, and it documents the decision for the next reader.

 Turning on strictNullChecks in a large project reports 400 errors. Which approach is best?

Each error is a place where a missing value was not handled. Silencing them with ! or as keeps every bug and hides it. Fixing gradually, with a count that only goes down, keeps the project shippable meanwhile.

 How can a test make sure nobody quietly turns off noUncheckedIndexedAccess?

@ts-expect-error fails when there is no error on the next line. That turns "this flag is on" into something tsc checks on every run.
