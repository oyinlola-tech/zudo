Three services each contain a pasted copy of the payment code. A double-charge bug is fixed in one of them. What does moving the code into @mycompany/zudo-payments change?

A package turns "remember every copy" into "release once, bump three version numbers". It also forces you to decide what is public, which pasted code never does.

 Why is @zudojs/errors a peerDependency of the payments package rather than a regular dependency?

With a regular dependency, npm may install a private copy for your package whenever the versions differ. Two copies mean two class hierarchies, which breaks instanceof and any module-level state.

 The same @zudojs packages are listed in both peerDependencies and devDependencies. Why both?

Installing your package in an app never installs its devDependencies. In your repository, though, you need a real copy to compile and test against, and devDependencies provide it.

 Why does createFakeProvider live in its own entry point, @mycompany/zudo-payments/testing?

A separate entry makes the purpose visible in every import line. It is still published: apps need it for their tests.

 With "files": ["dist"], which of these ends up in the tarball?

files is an allow-list, and npm adds the manifest, README and license on its own. npm pack --dry-run shows the real list; the lesson's check found no sources, tests or configuration.

 The package's src/index.ts uses export { A, B } from "./x.js" and never export * from. What does that protect against?

export * publishes whatever the file exports, today and in the future. Named re-exports make each public name a decision, like the barrels of @zudojs/adapters and @zudojs/plugins.

 dist/internal/money.js is inside the published tarball. Can an app import it?

The file must ship because the service needs it at run time. Being in the tarball is not the same as being importable; the exports map decides that.

 Why are all amounts in the package integers in kobo instead of naira with decimals?

Binary floating point cannot represent most decimal fractions exactly. Integers up to Number.MAX_SAFE_INTEGER are exact, which is why the service rejects anything that is not a safe positive integer.

 A card is declined. Which base class and status fit PaymentDeclinedError best?

The provider worked correctly; it said no. That is a business outcome, exposed to the customer so they can try another card. 502 would claim your provider failed, and 500 would hide the reason.

 Why does PaymentProviderError reach the client as "An unexpected error occurred." instead of its own message?

A provider name, "ECONNRESET" or a hostname helps an attacker and means nothing to a customer. expose: false keeps them internal, and cause keeps the original for your log.

 Why does isPaymentError check isBaseError(value) && value.code.startsWith("ERR_PAYMENT_") instead of value instanceof PaymentDeclinedError || …?

isBaseError falls back to a brand from the global symbol registry, and codes are plain strings, so both survive duplicate copies. The prefix also means a new error class is covered without changing the function.

 You want to rename ERR_PAYMENT_DECLINED to ERR_CARD_DECLINED. No function signature changes. Which version bump is it?

Error codes are part of the public API precisely because clients branch on them. Add a new code if you must, keep the old one, and remove it only in a major.

 A customer double-clicks "Pay". Both requests reach payments.charge with reference ORD-1001 while the provider is still answering the first. What happens?

The service keeps the promise of every charge in progress, keyed by reference, and a completed payment in a second map. Only a different amount under the same reference is a conflict.

 Order ORD-1001 was charged ₦12,500. Later a request arrives with the same reference and ₦9.99. What should the service do, and why?

An idempotency key promises "this is the same operation". Different content under the same key means that promise is broken, so fail loudly with ERR_PAYMENT_CONFLICT.

 Why does createPaystackProvider accept a fetch option?

Injecting the one function that touches the network makes the adapter fully testable: the tests check the URL, headers and body that would have been sent.

 The adapter's 15-second timeout fires during a charge. What do you know about the customer's card?

A timeout is the third outcome of a network call: unknown. Reporting "failed" can lead to a second charge; the fix is to ask the provider about that reference, or wait for its webhook.

 You add a required method verify(reference) to the exported PaymentProvider interface. Your own service calls it. Which bump is honest?

Adding to an interface people call is safe; adding a required member to an interface people implement breaks them. Add it as optional in a minor, then make it required in the next major.

 An app depends on "@mycompany/zudo-payments": "^0.1.0". You publish 0.2.0. Does the app get it on its next fresh install?

^0.1.0 means >=0.1.0 <0.2.0. That is why, in 0.x, a breaking change bumps the minor.

 When is a changeset file written in the changesets workflow?

The person who knows whether a change breaks anything records it when they make it. changeset version later adds all pending files up into version bumps and changelog entries.

 Three pending changesets for the package say: patch, minor, patch. The package is at 0.1.0 (and you treat minors as features). What does changeset version produce?

The highest bump wins and is applied once. All three sentences still appear in CHANGELOG.md, grouped under minor and patch changes.

 The manifest has "prepublishOnly": "npm run typecheck && npm test && npm run build". When does it run?

prepublishOnly is the last gate before a release. npm pack does not run it, which is why the lesson builds first and then checks the tarball.

Only errors make a result invalid; broken links are warnings. Fail the build on any issue (the lesson's script sets process.exitCode), or on the warning codes you care about.

Package self-referencing makes the script a faithful consumer: it can only reach what the exports map allows, so the internal-import test in the lesson proves what an app would see.

Behaviour is part of the contract, not only signatures. A stricter default breaks working callers even though every call still compiles.
