What does text.length count in JavaScript?

A string is stored as UTF-16 code units, and length, indexes and slice all work on them. Most emoji take two code units.

 What does this print? const pot = "🍲"; console.log(pot.length, [...pot].length);

U+1F372 is above U+FFFF, so it is stored as a surrogate pair: two code units. Spreading iterates by code point, giving one element.

 The Nigerian flag emoji is two regional indicator symbols. What does this print? const flag = "🇳🇬"; const segmenter = new Intl.Segmenter("en", { granularity: "grapheme" }); console.log(flag.length, [...flag].length, [...segmenter.segment(flag)].length);

Two code points, each a surrogate pair, so 4 code units and 2 code points. A reader sees one flag, and the segmenter groups both into one grapheme cluster.

 What is a grapheme cluster?

👩🏾‍🍳 is four code points (woman, skin tone, zero width joiner, pan) but one grapheme cluster. Intl.Segmenter finds these boundaries.

 A sign-up form says "display name: at most 20 characters". Which count should the server check?

The limit is about what people see. A name with a flag or a skin-toned emoji would be rejected unfairly by length, which counts several units per visible character.

 Which count matters for "the request body may be at most 1 MB"?

Storage and network limits are in bytes. In UTF-8, ₦ takes 3 bytes and many emoji take 4, although each is one grapheme.

 What does this print? const encoder = new TextEncoder(); console.log(encoder.encode("N").length, encoder.encode("₦").length, encoder.encode("🍲").length);

UTF-8 uses 1 byte for ASCII, 3 bytes for code points like U+20A6 (₦), and 4 bytes for code points above U+FFFF.

 What does this print? const name = "Egusi 🍲"; const cut = name.slice(0, 7); console.log(JSON.stringify(cut), cut.isWellFormed());

"Egusi " is 6 code units, so index 7 cuts the emoji's surrogate pair in half. The result contains a lone surrogate, which is not well-formed; JSON.stringify shows it as an escape.

 What happens when you call encodeURIComponent on a string that ends with a lone surrogate?

A lone surrogate cannot be turned into UTF-8, so encodeURIComponent throws "URI malformed". TextEncoder instead replaces it with U+FFFD. Cutting at grapheme boundaries avoids both.

 What does this print? const parts = []; for (const ch of "₦🍲") parts.push(ch); console.log(parts.length, "₦🍲".split("").length);

for...of iterates by code point: ₦ and 🍲. split("") splits into code units: ₦ is one, 🍲 is two.

 What does this print? const a = "Café"; const b = "Café"; console.log(a === b, a.normalize() === b.normalize(), a.length, a.normalize().length);

a is "e" plus a combining accent (5 code units), b uses the precomposed é (4). normalize() defaults to NFC, which composes a into the same 4 code units as b.

 Where should a shop apply normalize("NFC") to product names?

Normalising at the boundary means the rest of the program can trust stored text. Comparing un-normalised text leads to invisible duplicates and failed searches.

 What does this print? console.log("ＲＩＣＥ ②".normalize("NFKC"), "ＲＩＣＥ ②".normalize("NFC") === "ＲＩＣＥ ②");

NFKC applies compatibility mappings: full-width letters become normal letters and the circled digit becomes 2. NFC does not, and the string was already composed, so NFC leaves it unchanged.

 Why should you usually not store product names in NFKC?

Store what the user meant, in NFC. Build forgiving keys with NFKC or NFKD for searching and matching.

 What does this print? const key = (text) => text.normalize("NFD").replace(/\p{M}/gu, "").toLowerCase(); console.log(key("Àkàrà"), key("Àkàrà") === key("akara"));

NFD splits each accented letter into base letter plus a combining mark, \p{M} removes the marks, and lower-casing finishes the key.

 When is stripping accents from text a mistake?

In languages like Yorùbá, tone marks change the word. Removing them is fine for forgiving matching, but wrong wherever values must be exact.

 What does this print? const street = "Hauptstraße"; console.log(street.toUpperCase(), street.length, street.toUpperCase().length);

ß has no single upper-case letter in the default mapping, so it becomes "SS" and the string grows by one. Case mapping is not always one-to-one.

 Why should a server use email.toLowerCase() rather than email.toLocaleLowerCase()?

Identifiers need language-neutral rules that give the same result everywhere. Locale-aware casing is for text shown to people in a known language, with the locale passed explicitly.

 What does this print? console.log(["zainab", "Émeka", "Ade", "obi"].sort().join(" "));

Without a comparator, sort compares UTF-16 code units. Capital letters (65-90) come before small ones (97-122), and É (201) comes after all of them.

 What does this print? const names = ["zainab", "Émeka", "Ade", "obi"]; console.log(names.toSorted(new Intl.Collator("en").compare).join(" "));

An English collator sorts like a reader: case and accents are secondary differences, so É sorts with E, between A and O.

 What does this print? const sizes = ["Rice 10kg", "Rice 5kg", "Rice 25kg"]; console.log(sizes.toSorted(new Intl.Collator("en").compare).join(", ")); console.log(sizes.toSorted(new Intl.Collator("en", { numeric: true }).compare).join(", "));

By default digits compare as characters: "1" before "2" before "5". With numeric: true, each run of digits compares by its value.

 What does this print? const base = new Intl.Collator("en", { sensitivity: "base" }); const accent = new Intl.Collator("en", { sensitivity: "accent" }); console.log(base.compare("Akara", "àkara") === 0, accent.compare("Akara", "akara") === 0, accent.compare("akara", "àkara") === 0);

base ignores both case and accents. accent ignores case but not accents, so "akara" and "àkara" differ.

 Why does the lesson create one Intl.Collator at module level instead of calling a.localeCompare(b, "en") inside a sort comparator for 50,000 products?

Same comparison, less repeated set-up. A sort makes roughly n log n comparisons, so per-call costs add up.

 A Swedish shop sorts ["öl", "ost", "zebra"]. With new Intl.Collator("sv") the result is ost, zebra, öl. With "de" it is öl, ost, zebra. What should the server do?

In Swedish, ö is a separate letter after z; in German it sorts with o. Neither is wrong. Passing the locale explicitly keeps the server's own settings out of it.

 What does this print? const sku = "OIL-1L-007"; console.log(sku.slice(-3), sku.substring(-3).length, sku.slice(4, 2) === "", sku.substring(4, 2));

slice counts negative indexes from the end and returns "" when start is after end. substring treats negatives as 0 (the whole string, length 10) and swaps its arguments, giving characters 2 and 3: "L-".

 A customer's shop name is used in a message. What does this print? const shopName = "Deals $& More"; console.log("Welcome, NAME!".replace("NAME", shopName)); console.log("Welcome, NAME!".replace("NAME", () => shopName));

In a replacement string, $& means "the matched text". A replacement function's return value is used literally, which is what you want for data.

 What does this print? console.log(`[${"🍲".padEnd(3, "-")}]`, `[${"Tea".padEnd(3, "-")}]`);

padEnd(3) pads to 3 code units. The emoji already uses 2, so only one dash is added, and columns of text with emoji stop lining up.

 What does this print? function tag(strings, ...values) { return `${strings.length} pieces, ${values.length} values`; } const item = "Suya"; const qty = 3; console.log(tag`${qty} x ${item}`);

There is always one more text piece than there are values. Here the pieces are "", " x " and "", because the template starts and ends with a value.

 Why is an html tag that escapes every ${value} safer than escaping values by hand?

With hand-written escaping, one forgotten call is a cross-site scripting hole. The tag makes the safe way the only way: literal pieces are yours, values are always escaped.

 An escaping function replaces < with &lt; first and & with &amp; second. What goes wrong?

Escape & first, then the other characters. Otherwise you escape your own entities.

 What does this print? const rules = new Intl.PluralRules("en"); const ordinal = new Intl.PluralRules("en", { type: "ordinal" }); console.log(rules.select(1), rules.select(0), ordinal.select(2), ordinal.select(12));

English cardinal rules have only "one" and "other"; 0 is "other". For ordinals, 2 is "two" (2nd) but 12 is "other" (12th).

 What does this print? const list = new Intl.ListFormat("en-GB", { type: "conjunction" }); console.log(list.format(["rice"]), "|", list.format(["rice", "beans"]), "|", list.format(["rice", "beans", "plantain"]));

ListFormat handles one, two and many items. British English uses no comma before "and"; "en-US" would add one.

 slugify("Àkàrà") and slugify("Akara") both return "akara". Where should uniqueness be enforced?

slugify should be deterministic: same input, same output. Only the storage layer knows which slugs are taken, so it decides how to make them unique.

 A new seller registers the shop name "Mаma Put" where the second letter is Cyrillic а (U+0430). What does NFKC normalization do about it?

Look-alike ("confusable") characters are not normalization variants. Guard identifiers by restricting allowed characters or checking Unicode's confusables list.

 [..."👍🏽"].reverse().join("") no longer shows a brown thumbs-up. Why?

Spread keeps surrogate pairs together, so each code point is valid, but a grapheme made of several code points falls apart. Reverse graphemes from Intl.Segmenter to keep them whole.

 A delivery SMS is 150 characters of plain English and costs one message. Someone adds "₦" to the text. Why can it suddenly cost three messages?

SMS limits depend on the encoding of the whole message. One character outside GSM-7 changes the encoding and the per-part limit, so "length" must be measured the way the channel measures it.

 A receipt line fits 16 graphemes. Why does truncate keep only 15 graphemes of a long name before adding …?

The limit is about the printed result, so everything that ends up on the line counts, including the ellipsis.

 What does text.toWellFormed() do?

It fixes only broken halves of surrogate pairs. isWellFormed() tells you whether there are any.

 Why count words with Intl.Segmenter (granularity "word", keeping segments where isWordLike is true) rather than text.split(" ").length?

"Great jollof! Thanks" split on spaces gives an empty word for the double space and counts "jollof!" with its punctuation. The segmenter returns real words and marks punctuation and spaces as not word-like.

Write slugify(text): decompose with NFKD, remove combining marks (/\p{M}/gu), lower-case, turn every run of characters outside a-z0-9 into one hyphen, remove hyphens at both ends, and return "product" if nothing is left.

Decomposing first turns accented letters into plain letters plus marks, so removing the marks keeps the letters. The fallback stops an emoji-only name from producing an empty URL segment.
