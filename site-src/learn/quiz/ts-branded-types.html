A type alias creates a new name, not a new type. Structurally, both parameters are string, so swapped ids compile. A brand adds a member that makes the types different.

The brand is a phantom: it is erased with the rest of the types. That is why branded ids cost nothing and still work as map keys, in logs and in SQL parameters.

An unanchored pattern tests for a match anywhere inside the string. Anchor both ends and bound the length: /^ORD-\d{1,12}$/.

A user typing a bad id is normal, not a bug, so it belongs in the return type. Inside the program, where a bad id means a bug, a throwing variant (like orderId(raw)) is simpler. Offering both is common.
