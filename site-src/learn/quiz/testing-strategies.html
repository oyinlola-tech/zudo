VAT is rounded down instead of to the nearest kobo. What is the cheapest test that catches this?

The rule lives in one pure function. A unit test with a carefully chosen boundary value catches it in milliseconds, with no server or database.

 The SQL that saves an order writes the total into the subtotal column. Which test catches it?

A fake store has no SQL, so it cannot have this bug. Only running the real SQL against a real database (PGlite is enough) exercises it.

 All tests use a hand-written payment fake that takes naira; the real provider takes kobo. Which kind of test is designed to catch this?

The bug is a difference between the fake and reality. Only a test that runs the same expectations against both can see it.

 Customer B can read customer A's order by changing the id in the URL. What must a test do to catch it?

This is an IDOR (insecure direct object reference). A test with a single user can never see it; it needs two real users and an attempt to cross the line between them.

 What is a dummy?

A dummy exists because a constructor or function needs something. Making it throw when used, as the lesson's mailer does, also proves that the path under test really does not use it.

 What is the difference between a stub and a mock?

A stub is about inputs to your code ("the card is declined"). A mock is about outputs of your code ("you must charge exactly this amount, once"). Libraries often call every double a mock, which is where the confusion comes from.

 A checkout must send exactly one receipt with the formatted total. Which double fits best?

The receipt is the observable effect. A spy records the call so the test can assert on the count and the arguments without sending mail.

 When is a fake (a working in-memory implementation) the right double?

A fake is written once and reused by many tests. It behaves like the real thing in a simple way. Because it is code with its own behaviour, it should be kept honest by a contract suite.

 Why does the lesson warn against mocking your own pure code, such as priceCart?

Mock the edges you do not control (providers, mail, the clock, the network). Your own pure logic is fast and deterministic, so use the real thing.

 What do builders like aLine({ quantity: 0 }) give you over copying object literals into every test?

The default lives in one function. The override states the test's intent. And because each call returns a new object, one test cannot change another test's fixture.

 A test passes in the full suite but fails when run alone. What is the most likely cause, and how can you find such tests on purpose?

Shared state (a module variable, database rows, the clock) makes results depend on order. A random order exposes it, and --test-random-seed lets you reproduce the exact order that failed.

 Each database test runs inside a transaction that is rolled back. Which assertion becomes unreliable?

Rows are rolled back, but sequences are not: serial ids keep counting across tests. Assert on data you control, not on generated ids.

 When can you not isolate a test by wrapping it in a transaction that is rolled back?

Other connections cannot see (or be rolled back by) the test's open transaction, and nested BEGINs do not work the way the code expects. Give those tests a fresh database instead.

 The end-to-end tests use a real database but a fake payment provider. Why is that a sensible boundary?

Calling a real sandbox on every commit makes the suite slow and flaky. The contract suite, run against the sandbox on a schedule, is what keeps the fake trustworthy.

 How does the lesson run the payment gateway contract suite?

The fake run is fast and keeps your code honest against the contract. The sandbox run keeps the fake honest against reality. Without its settings, that suite is skipped with a reason instead of failing.

 What is consumer-driven contract testing?

The consumers state what they depend on, so the provider learns before a release whether a change would break one of them. Pact is a common tool for it.

 What does fast-check do when it shrinks a failing input?

A random failing cart may have five lines of huge prices. Shrinking turns it into something like "one free item and a 1 kobo voucher", which points straight at the bug.

 A property test failed in CI but passes on your laptop. What in fast-check's report helps you reproduce it?

fast-check's generator is pseudo-random. The same seed gives the same sequence of inputs, and the path jumps straight to the shrunk counterexample.

 Which property is an oracle?

An oracle compares the real code with a simpler reference calculation. The others are an invariant, a symmetry and a round trip.

 Fuzzing found that the product code "toString" gets a "price". Why, and what is a correct fix?

CATALOG["toString"] finds an inherited method. Freezing does not change inheritance, and a type annotation changes nothing at runtime. A Map only contains the entries you put in it.

 Why does a load test report p95 and p99 latency instead of only the average?

If 95 requests take 20 ms and 5 take 3 seconds, the average looks fine while 1 in 20 customers waits 3 seconds. Budgets are usually stated as percentiles for this reason.

 Where should the lesson's k6 checkout scenario run?

A load test is a controlled attack on your own system. Running it on production can take the shop down and create real charges. Staging with fakes gives useful numbers safely.

 A test fails about once in twenty runs with no code change. What should the team do?

A suite people have learned to re-run teaches them to ignore red. Flakiness almost always comes from shared state, real time or the network, which are the same isolation problems the lesson covers.

 What is the right way to use test coverage?

Coverage says which lines ran, not whether the assertions were meaningful. A test with no real assertions can cover every line.
