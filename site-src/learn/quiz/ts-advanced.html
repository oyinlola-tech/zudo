The Task API needs a full task, a create input, a patch and a summary. Why does the lesson derive them from one Task interface instead of writing four interfaces?

With four hand-written interfaces, someone adds priority to one and forgets the others. Computing types from one definition keeps a single source of truth.

 What does type Settings = typeof defaults; mean?

In a type position, TypeScript's typeof means "the type of this variable". JavaScript's typeof x, which runs in the program and gives a string, is a different thing.

 With const defaults = { pageSize: 20, sort: "newest", showDone: false };, what is keyof typeof defaults?

keyof gives the union of property names. The value types come from indexed access: Settings["pageSize"] is number.

 What does this print? const defaults = { pageSize: 20, sort: "newest", showDone: false }; type Settings = typeof defaults; type SettingName = keyof Settings; function setting(settings: Settings, name: K, value: Settings[K]): Settings { return { ...settings, [name]: value }; } const mine = setting(setting(defaults, "sort", "oldest"), "pageSize", 50); console.log(mine, defaults.pageSize);

Each call returns a new object with one property replaced; defaults itself is not changed. The spread keeps the property order of the original.

 For function setting<K extends keyof Settings>(settings: Settings, name: K, value: Settings[K]) with Settings = { pageSize: number; sort: string; showDone: boolean }, which call does tsc accept?

K must be one of the property names, and Settings[K] ties the value's type to that name. showDone is a boolean, so true fits. The others use a wrong value type or a name that does not exist.

 keyof exists only for the compiler. What does this print? const defaults = { pageSize: 20, sort: "newest", showDone: false }; type SettingName = keyof typeof defaults; const name: SettingName = "sort"; console.log(Object.keys(defaults), defaults[name]);

At runtime you get the property names from Object.keys, the JavaScript way. name is just the string "sort", so defaults[name] reads that property.

 What is the type of STATUSES in const STATUSES = ["todo", "doing", "done"] as const;?

as const tells TypeScript the array never changes, so it keeps the exact values and positions. Without it, the type would be string[].

 With that STATUSES, what is (typeof STATUSES)[number]?

T[number] is "the type of any element" of an array type. For the as const tuple, that is the union of the three words.

 You forget as const: const STATUSES = ["todo", "doing", "done"];. What does type Status = (typeof STATUSES)[number] become?

Without as const, the array is a string[], because it might change later. Its element type is string, and the Status type stops protecting you.

 What does this print? const STATUSES = ["todo", "doing", "done"] as const; type Status = (typeof STATUSES)[number]; interface Task { readonly id: number; title: string; status: Status; tags: string[]; } type TaskId = Task["id"]; type Tag = Task["tags"][number]; const id: TaskId = 7; const tag: Tag = "home"; console.log(STATUSES.length, STATUSES.join("/"), id, tag);

STATUSES is a real array at runtime, so it has a length and can be joined, looped over or shown in a dropdown. TaskId is number and Tag is string, but only for the compiler.

 What does this print? const STATUSES = ["todo", "doing", "done"] as const; console.log(Object.isFrozen(STATUSES), STATUSES.includes("done"));

as const only changes the type: the compiler treats the array as read-only, but nothing is frozen at runtime. Use Object.freeze if the runtime must enforce it.

 With type NewTask = Omit<Task, "id">, which is true?

Omit removes the listed properties from the type. So a client cannot choose its own id: { id: 99, ... } is an error. It is a compile-time check only; outside data must still be copied field by field.

 What is Partial<Omit<Task, "id">>?

Read it inside out: Omit removes id, then Partial makes every remaining property optional. That is a patch: the client sends only what changes.

 This compiles. What does it print? interface Task { readonly id: number; title: string; status: "todo" | "doing" | "done"; } type TaskSummary = Pick; function summaryOf(task: Task): TaskSummary { return task; } const task: Task = { id: 1, title: "Buy milk", status: "todo" }; console.log(Object.keys(summaryOf(task)));

Pick only changes the type. A full task has everything a summary needs, so return task compiles, but the object still has status at runtime. To really drop fields, build a new object by name.

 What does this print? interface Task { readonly id: number; title: string; } const frozen: Readonly = { id: 1, title: "Call Ada" }; const renamed: Task = { ...frozen, title: "Call Grace" }; console.log(frozen.title, "|", renamed.title, renamed.id);

Readonly<Task> forbids frozen.title = .... To "change" a read-only value, you make a new object with the spread; the original stays as it was.

 What does this print? interface Task { readonly id: number; title: string; status: "todo" | "doing" | "done"; dueDate: string | null; } type TaskPatch = Partial>; function applyPatch(task: Task, patch: TaskPatch): Task { return { ...task, title: patch.title ?? task.title, status: patch.status ?? task.status, dueDate: patch.dueDate === undefined ? task.dueDate : patch.dueDate, }; } const task: Task = { id: 1, title: "Buy milk", status: "todo", dueDate: "2026-10-01" }; const a = applyPatch(task, { status: "doing" }); const b = applyPatch(task, { dueDate: null }); console.log(a.status, a.dueDate, "|", b.status, b.dueDate);

Leaving dueDate out (undefined) keeps the old date. Sending null means "remove the due date", so it is copied. That is why the code checks === undefined and not ??.

 Why does applyPatch copy title, status and dueDate one by one instead of writing { ...task, ...patch }?

Types do not remove extra properties from outside data. Copying allowed fields by name is the fix for mass assignment you met in the user module.

 const labels: Record<Status, string> = { todo: "To do", doing: "In progress", done: "Done" }; What happens when you add "blocked" to STATUSES?

Record<K, V> needs a property for every key in K. So the labels can never fall behind the list of statuses.

 What does this print? type Status = "todo" | "doing" | "done"; const labels: Record = { todo: "To do", doing: "In progress", done: "Done" }; interface ListOptions { pageSize?: number; sort?: "newest" | "oldest"; } function resolveOptions(options: ListOptions): Required { return { pageSize: options.pageSize ?? 20, sort: options.sort ?? "newest" }; } console.log(labels.doing); console.log(resolveOptions({}), resolveOptions({ pageSize: 5 }));

resolveOptions fills in a default for every missing option, which is what Required<ListOptions> promises: code that gets the result never has to check for undefined.

 For async function loadStats(userId: number, includeDone: boolean) { return { userId, open: 3, done: 0 }; }, what is Awaited<ReturnType<typeof loadStats>>?

ReturnType gives what the function returns, a Promise of the object. Awaited removes the Promise, like await does.

 What does this print? async function loadStats(userId: number, includeDone: boolean) { return { userId, open: 3, done: includeDone ? 5 : 0 }; } type StatsArgs = Parameters; type Stats = Awaited>; function printStats(stats: Stats): void { console.log(`user ${stats.userId}: ${stats.open} open, ${stats.done} done`); } const args: StatsArgs = [2, false]; printStats(await loadStats(...args));

The tuple [2, false] is spread into the call, so includeDone is false and done is 0. await gives the object whose type is Stats.

 What does this print? function addHours(start: number, extra: number) { return start + extra; } type AddArgs = Parameters; type Hours = ReturnType; const args: AddArgs = [2, 3]; const total: Hours = addHours(...args); console.log(total, args.length);

Parameters gives the tuple [start: number, extra: number], and ReturnType gives number. At runtime, args is a normal array of two numbers, spread into the call.

 With type Status = "todo" | "doing" | "done", what is Exclude<Status, "done">?

Exclude<U, X> keeps the members of union U that are not in X. It is a conditional type: U extends X ? never : U, applied to each member.

 What does this print? type Status = "todo" | "doing" | "done"; type OpenStatus = Exclude; type Email = NonNullable; const open: OpenStatus[] = ["todo", "doing"]; const maybeEmails = ["ada@example.com", null, "", undefined]; const emails: Email[] = maybeEmails.filter((email) => email != null); console.log(open.length, emails);

email != null removes both null and undefined, but keeps the empty string, which is a real string. NonNullable matches: it only removes null and undefined from the type.

 What does the mapped type type Touched<T> = { [K in keyof T]: boolean } make?

A mapped type loops over the keys of another type, like for ... in over an object. For each name K it makes a property with the type after the colon.

 What does this print? interface NewTask { title: string; status: "todo" | "doing" | "done"; dueDate: string | null; } type Touched = { [K in keyof T]: boolean }; type Errors = { [K in keyof T]?: string }; const touched: Touched = { title: true, status: false, dueDate: false }; const errors: Errors = { title: "too short", dueDate: "not a date" }; const shown = Object.keys(errors).filter((field) => touched[field as keyof NewTask]); console.log(shown);

Both title and dueDate have an error message, but only title was touched, so only its error is shown. Errors makes every property optional, which is why status can be left out.

 How is the built-in Required<T> written as a mapped type?

Inside a mapped type, -? removes the optional mark and -readonly removes readonly. ? alone adds the mark, which is how Partial is written.

 With type Unwrap<T> = T extends Promise<infer V> ? V : T;, what are Unwrap<Promise<number>> and Unwrap<string>?

A conditional type tests with extends. For a promise, infer V captures the inside type, number. A string is not a promise, so the "else" branch gives T itself. That is roughly how Awaited works.

 How many strings are in type EventName = `${"task" | "user"}.${"created" | "updated" | "deleted"}`?

With unions, a template literal type makes every combination: 2 entities × 3 actions = 6, from "task.created" to "user.deleted".

 With type ApiPath = `/${string}`, which line does tsc accept?

`/${string}` is any string that starts with /. "tasks" and "tasks/" do not, and 7 is not a string at all.

 What does this print? type Entity = "task" | "user"; type Action = "created" | "updated" | "deleted"; type EventName = `${Entity}.${Action}`; const handlers = new Map(); function on(event: EventName, handlerName: string): void { handlers.set(event, [...(handlers.get(event) ?? []), handlerName]); } on("task.created", "sendWelcomeEmail"); on("user.deleted", "removeSessions"); on("task.created", "updateStats"); console.log(handlers.size, handlers.get("task.created"));

There are two different event names, so the map has two keys. The second on("task.created", ...) adds to the existing list. The type EventName lists six possible names, but the map only holds what was added.

 What does this print? type Action = "created" | "deleted"; type HandlerName = `on${Capitalize}`; const handlers: Record string> = { onCreated: () => "made", onDeleted: () => "gone", }; console.log(Object.keys(handlers), handlers.onDeleted());

Capitalize makes the first letter upper case, so HandlerName is "onCreated" | "onDeleted", and the Record needs a function for each. A key like oncreated would not compile.

 What does this print? interface User { id: number; email: string; name: string; passwordHash: string; role: "member" | "admin"; } type PublicUser = Omit; function toPublic(user: User): PublicUser { return { id: user.id, email: user.email, name: user.name, role: user.role }; } const ada: User = { id: 1, email: "ada@example.com", name: "Ada", passwordHash: "(a real hash)", role: "admin" }; console.log(Object.keys(toPublic(ada)));

toPublic builds a new object with only the fields it lists by name, so the hash is not in it. That is what you want to send to a client.

 Someone rewrites toPublic(user: User): PublicUser as return user;. What happens?

A full User has every property a PublicUser needs, so it fits; extra properties are only refused in a fresh object literal. Types are erased, so the hash is still in the object. Build the public object by name.

 Why should toPublic list the fields to keep instead of copying the user and deleting passwordHash?

With "delete what to hide", a new secret leaks until someone remembers to delete it too. With "list what to keep", forgetting means a missing field, not a leaked secret.

 What does this print? type Nullable = { [K in keyof T]: T[K] | null }; interface Task { id: number; title: string; dueDate: string; } const legacyRow: Nullable = { id: 3, title: "", dueDate: null }; console.log([legacyRow.title ?? "(untitled)", legacyRow.dueDate ?? "(no due date)", legacyRow.id]);

Nullable allows null for every property. ?? only replaces null and undefined, so the empty title stays '', while the null due date gets the fallback.

Finish setting: return a new settings object with the property name set to value, without changing the original. The program should print { pageSize: 50, sort: 'newest', showDone: true }.
