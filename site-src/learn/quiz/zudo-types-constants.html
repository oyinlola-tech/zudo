Which package would you import each from: a type guard like isEmail, and the branded type UserId?

Guards, converters, utility types, Clock and Random are in @zudojs/types. Branded ids and their factories, and the shared constants, are in @zudojs/constants.

 What makes function isPaymentEvent(value: unknown): value is PaymentEvent a type guard?

The guard checks at runtime and narrows at compile time. It changes nothing about the value; it only proves something about it.

 Why is typeof body === "object" not enough to check a JSON request body?

isPlainObject accepts only plain objects (including null-prototype ones) and refuses null, arrays and instances such as new Date().

 Which check is right for an amount in kobo from a webhook?

Kobo amounts are whole and positive. typeof accepts NaN and Infinity, isFiniteNumber accepts -100 and 2.5, and Number(x) turns the string "250000" into a number instead of refusing it.

 Why does isArrayOfType read every index instead of using Array.prototype.every?

A sparse array has no elements at the empty indexes, and every never calls its callback for them. Reading each index tests a hole as undefined.

 When should you prefer a @zudojs/schema schema over hand-written guards?

Guards are the building blocks and fit small checks. A schema composes checks, reports every failing path, and gives you the type with Infer.

 ?pageSize= arrives empty. What does toNumber(query.get("pageSize"), 20) return, and why is that better than Number(...)?

Number("") is 0, which quietly turns into a page size, a price or a limit. toNumber treats blank text as "not given".

 What does safeJsonParse<Order>(text, fallback) guarantee?

"Safe" means no exception and no prototype-polluting keys. Validate the result with guards or a schema before trusting its shape.

 Why are __proto__ keys dangerous even though JSON.parse keeps them as ordinary properties?

This is prototype pollution: one request could add, say, isAdmin: true to every object. Dropping the keys at parse time removes the risk for everything downstream.

 What does DeepReadonly<ShopSettings> do at runtime?

Types are erased when TypeScript compiles. Pair the type with Object.freeze (deeply, for nested objects) when the data truly must not change.

 Why does cancelOrder(userId, orderId) compile when both parameters are string, and how does a brand fix it?

A brand like string & { readonly __brand: "OrderId" } exists only for the compiler. At runtime the id is still a plain string.

 What does createUserId("") return?

Only some factories validate (createTenantId, createTimestamp, createEmailAddress, createUrl and the encoded-string ones). Check the format yourself before branding an id from outside.

 Where should as OrderId appear in a well-built code base?

A brand is a promise. Making it in one checked place keeps the promise true, and the rest of the code can rely on it without re-checking.

 Why does createTenantId(" Shop-NG ") return "shop-ng" instead of refusing it?

A tenant id ends up in cache keys, log lines and paths. Normalising first, and refusing separators like /, closes a whole class of isolation bugs.

 A request timed out and you do not know whether the server handled it. Which methods may a client safely send again?

An idempotent request has the same effect whether it arrives once or twice. Repeating a payment POST can charge twice, which is what idempotency keys prevent.

 What is the main benefit of HttpHeader.CONTENT_TYPE over typing "Content-Type"?

HTTP header names are case-insensitive on the wire, but a misspelt name is a different header. The constant turns that typo into a compiler error.

 A server is deployed with NODE_ENV=prodution. What does resolveEnvironment() do, and how do you make it fail instead?

The lenient default keeps local tools running. A deploy check with strict: true stops a typo from running a development configuration in production.

 With NODE_ENV=staging, what are resolveEnvironment() and isProduction()?

staging is one of the four environments. Code that must behave like production in staging should check for both, not rely on isProduction.

 Why is formatDuration fine for logs but not for an invoice line "Parking: 1h 59m 59s"?

Two rounded-down units are readable in a log. Billing needs exact values computed from the milliseconds.

 Why does OrderService take a Clock in its constructor instead of calling Date.now()?

Injecting time turns it from a hidden global into a parameter the test controls. The same goes for randomness.

 A service computes createdAt and payBy with two separate clock.now() calls. Why did the FixedClock tests pass while production showed 1,800,002 ms instead of 30 minutes?

Controlled test doubles hide some bugs. Read time once and derive every related value from that reading, and keep one test with the real clock.

 Why can't you pass new SeededRandom(1) to a function that takes Random?

Anyone who knows the seed can predict every value. The compiler error keeps test generators away from tokens and session ids.

 You import systemClock from @zudojs/constants and call systemClock.now(), but pass it to code expecting the @zudojs/types Clock. What should you know?

Both packages export a systemClock and a systemRandom. The @zudojs/types versions are the ones the framework is moving to.

 What does using new SeededRandom(42) in a test give you?

Determinism is the point. Change the seed and the expected values change with it; keep it fixed in the test.
