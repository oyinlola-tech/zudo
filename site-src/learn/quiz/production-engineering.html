One build, many environments. The code reads its settings from the environment; only the values change between your laptop, staging and production.

Failing at startup means the deployment fails, not a customer's request. Listing every problem, not just the first, saves you a deploy for each missing value.

A local .env holds throwaway values and is never committed. On a server, the host provides secrets to the process, and only the app's user can read them.

Rotate whenever someone who knew a secret leaves, and at once if it may have leaked. Because the code reads it from the environment, rotating is a configuration change, not a code change.

Nobody watches the terminal in production. A log tool searches millions of lines; that works when each event is structured the same way. Pretty output is for development.

Writing to stdout keeps the app simple and lets the platform decide where logs go. The app should not manage log files itself.

A failed liveness check means "restart me". Restarting cannot fix a database outage. Dependencies belong in the readiness check, which only stops traffic.

Readiness means "can I serve traffic right now?". When it fails, traffic goes to other servers. When the database comes back, the app becomes ready again by itself.
