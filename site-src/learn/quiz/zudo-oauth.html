With "Sign in with Google", what does your server learn about the user's Google password?

The whole point of OAuth sign-in is that someone else checks the password. Your server never sees it.

 In the authorization code flow, which part travels through the user's browser?

Only the code comes back through the browser (step 4). Your server then trades it, with its client secret, directly with Google (steps 5 and 6), so the token and the secret never pass through the browser.

 Which order of steps is right?

Your server starts by redirecting to Google, gets a code back after the user approves, trades it for a token server to server, then reads the profile and creates its own session.

 Your app gets a client id and a client secret from Google. Which is which?

The client id appears in the browser's address bar, so it cannot be secret. The client secret is like the JWT secrets: environment only, never in code or git.
