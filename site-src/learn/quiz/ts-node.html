A new TypeScript project imports node:fs/promises and tsc says Cannot find name 'node:fs/promises'. Where do the missing types come from?

Node.js ships no TypeScript types. The DefinitelyTyped project publishes them as @types/node: .d.ts files that only describe the API. You install it and list "node" in the types field of tsconfig.json.

 Why is @types/node installed with -D (as a development dependency)?

Declaration files contain no runnable code. The compiler reads them; the running server never does. So they belong with the other build tools in devDependencies.

 Your servers run Node.js 24, but the project installed the newest @types/node, which describes a later Node.js. What can go wrong?

The types only describe an API; they do not check which Node.js will run the code. If they describe a newer release, you can call something your runtime lacks and get is not a function in production. Pin @types/node to the Node.js major version you deploy.

 With @types/node and strict on, what is the type of process.env["TOKEN_SECRET"]?

Environment variables are always text, and any of them can be missing. That is exactly what string | undefined says, so the compiler makes you handle the missing case.

 A developer adds interface ProcessEnv { TOKEN_SECRET: string } inside declare global { namespace NodeJS { … } }. What does that change?

Declaration merging is a promise to the compiler that nothing verifies. When the server starts without the variable, code that trusted the type crashes, often far from startup. Parse the environment in code instead.

 Why does loadConfig(env: Env) take the environment as a parameter instead of reading process.env inside?

A function whose inputs are all parameters is easy to test: pass { PORT: "-1" } and check the error. The server passes process.env, which fits the Env type.

 Why does the lesson's loadConfig collect every problem before throwing, instead of throwing at the first one?

A deployment with three wrong settings should take one fix, not three restarts. The server still refuses to start; it just says everything that is wrong.

 At startup you want to log the configuration the server is using. What should the log line contain for tokenSecret?

Logs are copied, shipped to other services and read by many people. A secret in a log is a leaked secret; even part of one helps an attacker. base64 is an encoding, not protection. Log that it is set and how long it is.

 What is the type of data in const data = await readFile("prices.json");?

readFile has overloads. Without an encoding it returns the raw bytes as a Buffer; with "utf8" it returns a string. The compiler picks the return type from the arguments.

 readTextIfExists returns undefined when the error code is ENOENT, and throws every other error again. Why not return undefined for every error?

Only "the file does not exist" is an expected, harmless case. EACCES or EISDIR mean something is broken; hiding them turns a loud failure into silent data loss.

 Why does the lesson write const data: unknown = JSON.parse(text);?

With any, data.quantity.toFixed() compiles whatever the file contains. Storing the result as unknown means nothing can touch it until a type guard proves its shape.

 Inside a server's request handler, why is req.url typed string | undefined?

For a server, Node.js always fills in the method and URL. But IncomingMessage also represents the response an HTTP client receives, which has neither. A fallback like req.url ?? "/" handles the type honestly.

 After server.listen(0), what can server.address() return, according to its type?

That is why the lesson checks address === null || typeof address === "string" before reading address.port. Writing as AddressInfo would silently ignore two real cases.

 A request arrives with the Idempotency-Key header twice, with the values t-1 and t-2. What does req.headers["idempotency-key"] give, and how do you insist on exactly one value?

For most headers Node.js joins repeated values with a comma, so req.headers cannot show that there were two. req.headersDistinct keeps each value separately. For a security-relevant header, two values are suspicious, and "missing" (a 400) is the safe answer.

 Why does sendJson set content-length with Buffer.byteLength(text) instead of text.length?

"₦" has length 1 but is 3 bytes. A too-small content-length makes the client cut the body off; a too-large one makes it wait for bytes that never come.

 You write a function that hashes bytes. Which parameter type makes it work with both Buffers and the output of TextEncoder?

Buffer is a subclass of Uint8Array, so a Buffer fits a Uint8Array parameter. A plain Uint8Array does not fit a Buffer parameter, because it lacks methods such as toString("hex").

 A stage is declared as async function* toLines(chunks: AsyncIterable<string>) and receives a file stream opened without an encoding. What happens?

Types are erased at runtime, and a stream's chunks are any, so nothing checks the annotation. It is a claim you must make true at the source, for example with { encoding: "utf8" }.

 A report reads a file in small chunks and decodes each chunk with chunk.toString(). Some customer names come out with � in them. What is the fix?

A multi-byte character can be cut between two chunks, and decoding each half alone produces replacement characters. The stream's own decoder carries the unfinished bytes over to the next chunk. Bigger chunks only make the bug rarer.

 With new EventEmitter<ShopEvents>() from @types/node, which mistake does tsc report?

For names in the map, arguments are checked. Names outside the map are allowed on purpose and get any[], so a typo compiles and the emit goes nowhere. A small wrapper whose methods take keyof Events closes that gap.

 You call spawn(cmd, args, { stdio: ["ignore", "inherit", "inherit"] }). What is the type of child.stdout?

@types/node reads your stdio option. With "inherit", the child writes straight to your terminal and there is no stream to read, so the type is null. With "pipe" it is a Readable.

 A supervisor sends SIGTERM to a worker and later sees exit code 0 and signal null. What does that tell you?

A process killed by a signal reports code: null and the signal's name. Code 0 with no signal means the worker's SIGTERM handler ran and the process ended normally: a graceful shutdown.

 Your server runs with tsx src/server.ts in production. A pull request adds a type error. What stops it from being deployed?

tsx and Node.js 24 strip types without checking them. Only tsc checks. Make tsc --noEmit a required step in CI.

 You run node src/status.ts with Node.js 24, and the file declares an enum. What happens, and which tsconfig option warns you earlier?

Node.js only deletes type syntax. An enum or a parameter property produces JavaScript, so it cannot simply be deleted, and Node.js refuses the file. erasableSyntaxOnly makes tsc reject that syntax up front.
