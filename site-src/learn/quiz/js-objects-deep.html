Your shop creates thousands of product objects, and every price must be a whole number of kobo. Which form of object creation fits best?

A factory function is one place that every product has to pass through, so the check is written once and cannot be skipped. Literals repeat the shape by hand, and Object.create(null) solves a different problem (dictionaries with outside keys).

 A word counter uses const counts = {} and counts[word] = (counts[word] || 0) + 1. For the word "constructor" it stores a long string instead of 1. Why?

Every object literal inherits names such as constructor and toString. Reading one gives the inherited function, and function + 1 is string concatenation. A dictionary made with Object.create(null), or a Map, has no inherited names.

 You store each user's cart in a plain object keyed by the user object: carts[ada] = […], carts[grace] = […]. What goes wrong?

Property keys are strings or symbols. Any other key is converted to a string first, and every plain object becomes "[object Object]". A Map keeps object keys by identity.

 Which properties does { ...source } copy?

Spread copies own (not inherited) and enumerable (listed) properties. Nested objects are shared, not copied, so spread is a shallow copy. Methods on a class's prototype are inherited, so they are not copied.

 An object has a getter get totalKobo() { … }. What does { ...obj } put in the copy under totalKobo?

Spread reads each property, which runs the getter, and stores the result as an ordinary data property. The copy's total never changes afterwards. To copy the getter itself, use Object.defineProperties({}, Object.getOwnPropertyDescriptors(obj)).

 What is the real difference between Object.assign(target, source) and { ...target, ...source }?

Both copy own, enumerable properties one level deep. Object.assign assigns into its first argument, so it mutates that object and triggers any setters on it. Spread creates a fresh object.

 After Object.defineProperty(order, "id", { value: "ORD-7" }), what are the attributes of id?

defineProperty sets every attribute you leave out to false. So this one line makes id read-only, hidden from Object.keys and JSON, and impossible to delete. Properties made by normal assignment get true for all three.

 What happens when code assigns to a read-only (non-writable) property?

Strict mode turns silent failures into errors. Modules and classes are always strict, so you see the problem at the exact line. In old scripts the assignment does nothing and your code carries on with the old value.

 A teammate suggests storing a user's password hash as a non-enumerable property "so nobody can see it". What is wrong with that?

Enumerable controls listing, not access. user.passwordHash and Object.getOwnPropertyNames still reveal it. Keep secrets out of objects that leave your server by building the outgoing object from an allow-list.

 You want to stop typos from creating new properties on an account, but the balance must still change. Which call fits?

seal fixes the shape: no new properties and no deletions, but existing values can still be changed. freeze would also stop the balance from changing.

 Which lock still allows delete obj.note but refuses obj.extra = 1?

preventExtensions only stops additions. seal also stops deletions, and freeze also stops changes to values.

 What does Object.freeze(config) return?

All three locking functions change the object in place and return it, which is why const config = Object.freeze({ … }) works. Freezing cannot be undone.

 What do you get from structuredClone(new Account("Ada")), where Account is a class with a deposit method?

structuredClone copies data, not behaviour. The prototype link is lost, so the methods are gone. It throws only when it meets a function stored in a property.

 An order has placedAt: new Date(…) and tags: new Set(["gift"]). After JSON.parse(JSON.stringify(order)), what are they?

JSON only knows strings, numbers, booleans, null, arrays and plain objects. A date turns into its ISO string and stays a string; a set has no enumerable properties, so it becomes {}. structuredClone keeps both.

 new Set([{ sku: "RICE-5" }, { sku: "RICE-5" }]).size is 2. Why?

Like ===, a Set checks whether it is the same object, not whether the contents look the same. To deduplicate by content, use a key that identifies the data, such as the SKU.

 Where does Object.is(a, b) give a different answer from a === b?

For objects both compare identity. The only differences are the two number edge cases. That makes Object.is a good default inside an equality helper.

 const { passwordHash, ...publicUser } = user removes the hash before sending a user to the client. What is the long-term risk?

Removing known bad fields lets every unknown field through. For data leaving your server, list the fields that may go (an allow-list), so new fields stay private until someone decides otherwise.

 What happens when this setter runs? set priceKobo(value) { this.priceKobo = value; }

this.priceKobo = value is an assignment to the very property the setter guards, so it triggers the setter again. Store the real value somewhere else: a closure variable, a #private field or a differently named property.

 Reading report.summary runs a getter that loops over 200,000 orders and writes a log line. What is the problem?

Getters are not cached; each read runs them again. Keep getters cheap and free of side effects. A method call makes the cost visible to whoever calls it.

 What does Object.defineProperty(obj, "vat", { value: 7.5, get() { return 7.5; } }) do?

A property either stores a value or runs accessor functions. Mixing the two kinds in one descriptor is refused.

 A price list is loaded once at start-up and only ever read by request handlers. Each handler currently calls structuredClone(priceList) before reading it. What is the better design?

Copying protects against changes. If nobody changes the data, sharing it is safe, and freezing it turns "nobody changes it" into a rule the engine enforces. Cloning a large object on every request wastes time and memory.

Integer-like keys come first, sorted as numbers. The other string keys follow in the order they were added, not alphabetically.
