Which sentence describes a client and a server?

The client asks and the server answers. A browser, a phone app and curl are all clients. The backend you build is a server.

 You open a web page that shows ten images, for the first time, and each image is a separate file. How many requests does the browser make to show it?

One request gets one response. The browser asks once for the page, then once for each image: 1 + 10 = 11. On a later visit it may reuse images it saved, and send fewer.

 What is an IP address?

Every computer on the internet has an IP address, such as 104.20.23.154. The name example.com is a domain name, which DNS turns into an IP address.

 Which of these is a valid IPv4 address?

IPv4 is four numbers from 0 to 255. 300 is too big, and three numbers are too few. The form with colons is IPv6.

 Why does IPv6 exist?

IPv4 has a limited number of addresses and they ran out. IPv6 is a longer form with far more of them.

 What does DNS do?

DNS, the Domain Name System, looks up a name like example.com and returns its IP addresses. Encryption is HTTPS's job, and the port picks the program.

 nslookup example.com shows several addresses for one name. Why do big sites have several?

If one machine fails, clients can use another address. Your answers can also differ from someone else's: the numbers change over time and between countries.

 You start a server on your own computer while developing. Which address reaches it?

localhost always means "this computer", and its IPv4 address is 127.0.0.1. It is how you reach servers running on your own machine.

 One computer runs a web server and a database. How does a request reach the right program?

The IP address finds the computer. The port, a number from 1 to 65535, finds the program on it.

 Which port does https://shop.example.com/cart use?

The URL names no port, so the default for https is used: 443. The default for plain http is 80.

 Which port is the standard one for PostgreSQL, the database used later in the course?

PostgreSQL listens on 5432. 80 and 443 are for the web, and 3000 or 8080 are common choices for your own server while you develop.

 In https://api.example.com/tasks?done=false&limit=10, which part is the query?

The query comes after ? and holds options as name=value pairs joined by &. /tasks is the path and api.example.com is the hostname.

 What does the HTTP method GET say?

GET asks for something. POST means "here is something new". The method, the path and the headers together describe what the client wants.

 Which three parts does an HTTP response have?

A response starts with a status code (how it went), then headers (extra information), then the body: the page, image or data. Method and path belong to the request.

 What do the status codes 200 and 404 mean?

200 means success. 404 means the server does not know the path you asked for.

 What does curl -I https://example.com print?

With -I, curl asks only for the status line and headers. Without it, curl prints the body, the HTML of the page.

 You are in Windows PowerShell and want the real curl. What do you type?

In Windows PowerShell, plain curl is a different command with different options. curl.exe is the real curl, which comes with Windows 10 and 11.

 A response has the header content-type: application/json. What is in its body?

The content-type header says what the body is. text/html is a web page; application/json is data, typical for an API.

 What does HTTPS add to HTTP?

HTTPS sends HTTP through an encrypted TLS connection, so nobody on the way can read or change it. The certificate proves the server's identity: that is the padlock.

 Your login form will be used by real people. Which address should it send the password to?

Plain HTTP travels as readable text, so anyone on the same network or on the way can read it. Every public site and API must use HTTPS. Plain HTTP is only acceptable on localhost.

 When is plain http:// acceptable?

On localhost, the request never travels over a network, so nobody can read it. Everything that real users reach must use HTTPS.

 Where in the browser can you see every request a page makes, with its method, status code and headers?

Open the devtools with F12, choose Network and reload the page. Each row is one request; click it to see the details.

 What is a web API?

A web page is made for people; an API is made for programs. It usually answers with JSON, a text format for data that looks like JavaScript objects.

 The tiny API calls server.listen(0, "127.0.0.1"). What does that mean?

Port 0 means "any free port"; the operating system picks one. 127.0.0.1 is localhost, so only your own computer can reach the server.

 The tiny API keeps its tasks in a list inside the program. What is the problem with that for a real app?

Real data must survive restarts and be shared by many copies of the server. That is what a database is for: a separate program built to store data safely and find it fast.

 In a well-built app, who does the browser talk to?

The browser never talks to the database directly. The backend stands between them, checks each request and who is asking, and only then reads or changes data.

 Someone opens a task app. What happens first?

The browser first needs an address: DNS turns the domain into an IP address. Then it connects on port 443, sets up HTTPS and only then sends the HTTP request.

What does it print? import { createServer } from "node:http"; const server = createServer((request, response) => { if (request.method === "GET" && request.url === "/tasks") { response.writeHead(200, { "content-type": "application/json" }); response.end(JSON.stringify([{ id: 1, title: "Buy milk" }])); return; } response.writeHead(404, { "content-type": "application/json" }); response.end(JSON.stringify({ error: "Not found" })); }); await new Promise((resolve) => server.listen(0, "127.0.0.1", resolve)); const base = `http://127.0.0.1:${server.address().port}`; for (const path of ["/tasks", "/nothing-here"]) { const response = await fetch(base + path); console.log("GET", path, "->", response.status); } server.close();

The server checks the method and path. GET /tasks matches and gets 200. Any other path falls through to the 404 answer. One request, one response each.
