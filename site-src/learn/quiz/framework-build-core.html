The opening script did Number(env.PORT ?? "3000") with PORT=80x. Why is this worse than it looks?

Number("80x") is NaN, not an error. The config loader parses with a pattern and reports PORT must be a whole number… before anything connects.

 Why does loadConfig collect every problem instead of throwing at the first one?

Every failed deploy costs time. Reporting all problems at once turns three round trips into one. The app still does not start: the error is thrown after the loop.

 What does ConfigOf<typeof schema> give you?

It is a mapped type: each key of the schema becomes a readonly property of the type inside its Setting. The runtime check is loadConfig; the type follows from the same object.

 loadConfig(schema, envFile, processEnv): the .env file says LOG_LEVEL=debug, the real environment says LOG_LEVEL=warn. What is the result, and why is that order right?

Defaults, then files, then the environment: each layer is more specific to where the process runs. An operator must be able to change a setting without editing files in the image.

 Why log safeView(schema, config) instead of config?

Logs are copied, shipped, searched and kept for months by many people and systems. A secret that reaches them is effectively leaked.

 Why does the container dispose instances in reverse creation order?

Dependencies are always created before their dependents, so reverse creation order closes dependents first. Closing the pool first would break the repository's last operations.

 The mini container does not track transient instances for disposal. Why?

A transient resolved a million times would mean a million references held forever: a memory leak. The garbage collector frees memory, but it never calls dispose, so a transient that holds a connection must be closed by its owner.

 A singleton ReportService depends on the scoped Cart. Why does the container refuse?

That is a captive dependency: a longer-lived object capturing a shorter-lived one. The container catches it at resolve time and names the chain.

 What does logger.child({ requestId: "req-7" }) give you?

Bound fields save every call site from repeating them, and they cannot be forgotten. The framework creates one child per request and per module.

 The logger's sink throws "disk full". What should happen to the request that called logger.info?

Logging observes the work; it is not the work. A real logger also counts dropped entries so the outage is visible in metrics.

 Components start in the order database, queue, http, and http fails. What does the mini lifecycle do?

Rollback stops what already started, in reverse order, so nothing stays half-open, and the error tells you which component failed and why.

 On the same failure, @zudojs/lifecycle also calls stop on http, the component that failed. What does that ask of component authors?

Stopping a half-started component frees what it did manage to open (a bound port, a file). The price is that stop must be safe in any state.

 Why wrap every start in a timeout?

A named timeout turns "the deploy is stuck" into "search-index start timed out after 5000 ms", and the rollback still runs.

 withTimeout calls clearTimeout in a finally block. What goes wrong without it?

An active timer keeps the event loop busy, so a process that should exit after stop hangs until every forgotten timer fires.

 Two signals arrive at once and stop() is called twice. What does the mini lifecycle do?

Storing the in-progress promise makes stop idempotent. Stopping a database pool twice would throw or hang in many drivers.

 During shutdown, the queue's stop throws. What should happen to the database's stop, which comes after it?

Leaving the database open because the queue misbehaved is worse than a noisy log. Shutdown is best-effort for every component.

 What is SIGTERM, and what does Node do with it when no handler is installed?

Kubernetes and systemd send SIGTERM, wait a grace period, then kill the process. The handler turns that window into a graceful stop.

 What happens if you register a service with @zudojs/container's registerFactory and no scope option?

The default is transient. A connection pool registered without a scope would be created again for every resolve; pass ContainerScope.SINGLETON for shared resources.

 @zudojs/config's toSafeObject redacted database_url although it was never marked secret. Why?

Value-based detection catches secrets hidden in settings with harmless names. Your mini loader only knows what the schema marks secret.

 With @zudojs/logger, logger.error("payment failed", { cause: new Error("card declined") }) logged "cause":{}. Why?

JSON.stringify(new Error("x")) is {}. Your mini logger converted Error fields to name and message; with the package, log the message explicitly.
