Which sentence describes a library?

Your loop called formatPrice; formatPrice did not know the loop existed. With a library, the control flow is yours. With a framework, it is the other way round.

 What is inversion of control?

With a framework, you write pieces and the framework calls them at the right time. It is often summed up as "don't call us, we'll call you".

 Which part of the BookStore already used inversion of control?

You gave handlers to the router and never called them yourself. The router decided when, based on the incoming request. That is exactly how a framework treats your code.

 Why does the lesson say inversion of control is "not a loss"?

Giving up the control flow means giving up a lot of tedious, risky work: ordering, error handling, shutdown. The framework has done that work a thousand times before.

 startOrder puts every module after the modules it depends on. What is this kind of ordering called?

Visiting each module's dependencies before the module itself gives a topological sort: an order where every item comes after the things it needs.

 What is the visiting set in startOrder for?

visiting holds the modules whose dependencies are being visited right now. Meeting one of them again means a loop that can never start, so the framework throws a clear error.

 Why does stop walk the started modules in reverse?

The server must stop taking requests before the database it uses is closed. Reverse start order guarantees that every module stops while the things it needs are still running.

 What does await module.start?.(); do when a module has no start function?

Optional chaining calls the function only if it exists. A module without start is simply skipped, and await undefined continues at once.

 In the mini framework, http needs database, and database needs cache, which is not registered. When is the mistake found?

start first computes the whole order with startOrder, which throws on a missing dependency. A broken setup is refused before anything runs.

 orders needs payments, payments needs mailer, and mailer needs orders. How do you fix it?

In a cycle none of the modules can go first, and the listing order does not change the dependencies. Break the loop by moving what they share into a module with no dependency back on them.

 What is a rollback when an app starts?

Without rollback, a failed database start leaves the config module (and others) running and never stopped. @zudojs/runtime does this for you.

 Which ZudoJS packages take over the lifecycle job: start in order, stop in reverse, react to SIGTERM, report readiness?

Runtime and lifecycle start and stop your parts in the right order and undo a half-finished start. The container handles dependency injection, not start order.

 In the BookStore, createRouter built every repository and passed the secret through by hand. What does a container give you instead?

A dependency-injection container knows how to build each service and hands it out where needed. In ZudoJS it is @zudojs/container.

 What does a framework's validation give you, compared with the BookStore's hand-written parsers?

In the BookStore, the parser and the interface were written separately and could drift apart. A schema (@zudojs/schema) is one description that gives both. TypeScript types alone never check data at runtime.

 What does a framework's configuration job include?

@zudojs/config merges several sources, checks them, and keeps secrets out of logs. Secrets never belong in source code or log lines.

 The BookStore had no rate limit and no security headers. Which ZudoJS package gives you rate limiting, CORS, CSRF and security headers with safe defaults?

@zudojs/security covers these, and @zudojs/auth covers password hashing and JWTs. Using tested, safe defaults is better than writing each one by hand.

 What does a framework give you for application architecture?

In the BookStore you chose folders and layers yourself. A standard layout from zudojs-cli means any developer can find their way in any project.

 Which is a real cost of using a framework?

The lesson names three costs: learning time, the framework's opinions about structure, and depending on its future. Pick one that is maintained and whose parts you can replace.

 For which project is a backend framework most likely too much?

For a small script, learning a framework costs more than it saves. For a real backend, the jobs a framework does must be done anyway, by it or by you.
