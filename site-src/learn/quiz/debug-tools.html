The debugger is paused on const subtotal = cartSubtotal(lines);. You want to see the first line inside cartSubtotal. Which command?

Step into enters the function called on the current line. Step over would run the whole call and stop on the next line of checkoutTotal.

Step out finishes the current function (it still runs; nothing is skipped) and pauses in the caller. Debuggers cannot go backwards.

 What does a debugger; statement do when the program runs normally, with no debugger attached?

debugger is a breakpoint written in code. Without an attached debugger it is ignored. With DevTools open, it pauses, which is why you should never commit one.

 A loop processes 20,000 orders and order 7431 comes out wrong. What is the best breakpoint?

A conditional breakpoint only pauses when its expression is true, so the program runs at full speed until the one iteration you care about.

 A payment request times out after 5 seconds. Pausing at a breakpoint inside it makes it time out every time. What should you use to see the values?

Pausing freezes the program, and timers keep counting in the other system. A logpoint behaves like a console.log added without editing the code, so the timing stays realistic.

 What is a watch expression?

Watches save you from typing the same exec at every pause. They can be any expression: typeof delivery, cart.length, total > 10_000_000.

 What is the difference between breakOnException and breakOnUncaught in node inspect?

Pausing on every exception is noisy in code that throws and catches on purpose; pausing on uncaught ones only shows the crashes. Both leave you paused with the variables alive.

 A script crashes within 50 milliseconds of starting, before you can attach Chrome DevTools. Which flag helps?

--inspect-brk pauses before the first line until a debugger attaches. --inspect would let the script run (and crash) straight away.

 Why must a production server never run with --inspect=0.0.0.0:9229?

The inspector protocol can evaluate any expression in your process: read secrets, change data, spawn programs. It listens on 127.0.0.1 by default; keep it that way, and reach a remote server through an SSH tunnel.

 A staging server runs node --inspect app.js (listening on 127.0.0.1). How do you debug it from your laptop safely?

The SSH tunnel makes the remote port appear on your own machine without exposing it to the network. The inspector still only accepts local connections on the server.

 In a VS Code launch configuration, what does "skipFiles": ["<node_internals>/**"] do?

Skipped files still run; the debugger just steps through them as if they were one line. Adding node_modules/** does the same for libraries.

The JavaScript Debug Terminal attaches VS Code's debugger to Node.js processes it starts, including those started through npm scripts, tsx or test runners.

DOM change breakpoints pause at the line of JavaScript that changes the element, with the full call stack of who asked for the change.

The status says whether it worked at all, the content type says what kind of body to expect, and only then does the body make sense. Many parsing errors are really wrong statuses.

 What does node --enable-source-maps dist/main.js change?

The map records which output position came from which source position. Node uses it to rewrite each frame of a stack trace.

 Why does the mappings string in a source map store differences between positions instead of the positions themselves?

Neighbouring positions are close together, so their differences are tiny, and VLQ writes small numbers in one character. Absolute line and column numbers would make the map several times larger.

 A stack trace from your server points at a line of TypeScript that is a blank line. What should you suspect first?

A map only makes sense for the exact output it was generated with. If one was rebuilt and the other not, every position is translated wrongly.

 What happens when a public website serves its .map files?

Source maps usually contain (or point to) the original sources. That is fine for open source; otherwise upload maps privately to your error tracker and do not serve them.

 Why do stack traces from node app.ts (Node's type stripping) point at the right .ts lines without any source map?

Stripping keeps the positions: erased types become whitespace. Transforming compilers (tsc, bundlers) move code around, which is why they need maps.
