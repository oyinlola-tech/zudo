Reads walk the prototype chain. Only when the chain ends at null without a match is the result undefined.

Where a method is found and how it is called are separate questions. The call ada.describe() sets this to ada, so one shared method works on every object that inherits it.

Reads walk the chain; ordinary writes do not. They create or change an own property on the object you assign to.

A setter found on the chain intercepts the assignment. That is how one setter on a class prototype validates writes for every instance.

 A prototype has a non-writable property bank. In strict mode, what happens with ada.bank = "Other", where ada has no own bank?

An inherited read-only data property stops assignment, even though the write would go to ada. Object.defineProperty(ada, "bank", …) could still add an own one.

 ada has an own currency that shadows "NGN" on its prototype. After delete ada.currency, what is ada.currency?

delete only removes own properties. The prototype's property was never touched, so it is visible again.

 A prototype has items: [] and a method add(sku) { this.items.push(sku); }. Why do all carts share one list?

Only assignment creates own properties. Keep data on instances (set it in the constructor) and put only methods and constants on prototypes.

 What is at the end of the prototype chain of a normal object literal?

Object.prototype provides toString, hasOwnProperty and friends. Its [[Prototype]] is null, which ends every lookup.

 Why is Object.hasOwn(obj, key) safer than obj.hasOwnProperty(key)?

Methods found through the chain can be absent or replaced. A static function on Object does not depend on the object's chain at all.

 Why should you avoid Object.setPrototypeOf on objects in code that runs for every request?

Set the prototype when the object is created (Object.create, new, class). Linking prototypes once at start-up, as inherit does, is fine.

 What is obj.__proto__?

Use Object.getPrototypeOf and Object.create instead. The __proto__ accessor is also what prototype pollution attacks reach through.

 Which list describes what new Fn(args) does, in order?

Methods are not copied; the new object is linked to Fn.prototype and finds them by lookup. A returned object replaces the new one; a returned primitive is ignored.

 A constructor function ends with return { error: "not allowed" } in one branch. What does new give in that branch?

Step 3 of new: an object returned from the constructor replaces the new object. It is legal and surprising, so avoid it.

 For a constructor function Order, which statement is true?

The prototype property is only used by new. The function itself inherits call, apply and bind from Function.prototype.

Arrows (and methods written with method syntax) cannot be used with new. Use a class or a function declaration for constructors.

The new prototype object inherits constructor from Account.prototype. instanceof would still work (it checks the chain), but ada.constructor and anything that uses it would be wrong.

Both run the parent's setup code on the new object, so it gets the parent's own properties. The prototype link is the separate job of extends.

 What does obj instanceof Fn actually check?

It only walks the chain. An object from Object.create(Fn.prototype) passes without ever running Fn, and replacing Fn.prototype later makes old instances fail.

Each frame has its own Array.prototype, so instanceof compares against the wrong one. Array.isArray checks the kind of object directly and works across frames. (typeof an array is "object".)

for...in lists enumerable properties, own and inherited. Class syntax defines methods with enumerable: false, so only data shows up.
