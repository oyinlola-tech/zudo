Page code runs for (const b of document.querySelectorAll(".remove")) b.addEventListener("click", …) once at start-up. Why does the Remove button of an item added later do nothing?

Listeners belong to elements, not to selectors. A delegated listener on the list covers buttons added later, because their clicks bubble up to it.

 A listener is on <ul id="cart">. The user clicks the <span class="icon"> inside a Remove button inside an <li>. What are event.target and event.currentTarget?

target is where the event happened: the innermost element, the icon. currentTarget is the element whose listener is running: the list. That is why delegated code uses event.target.closest("button").

 Three listeners exist: (A) on document with { capture: true }, (B) on a button, (C) on document with no options. The button is clicked. In which order do they run?

The capture phase goes down from window first (A), then the target (B), then the bubble phase goes back up (C).

 A form wants to highlight whichever field has focus with a single listener on the <form>. Which event should it listen for?

focus and blur are among the few events that do not bubble. Their twins focusin and focusout do, so they work with delegation. (Focus also changes with the Tab key, not only with clicks.)

 A widget calls event.stopPropagation() in its click listener. What is the most likely side effect?

Stopping propagation hides the event from every listener further along the path. Other code that relies on the event bubbling silently breaks. Deciding with event.target is almost always better.

 What is the difference between preventDefault() and stopPropagation()?

They control two independent things. A link click with stopPropagation() still navigates; a link click with preventDefault() still reaches the document's listeners.

 What does { passive: true } on a touchmove listener mean?

Scrolling normally has to wait to see whether a listener cancels it. A passive listener cannot, so scrolling stays smooth. preventDefault() inside it is ignored.

 Why does a delegated cart listener use event.target.closest("[data-action]") instead of reading event.target.dataset.action directly?

event.target is the innermost element clicked. closest checks that element and then its ancestors, so it finds the button whether the click hit the button or something inside it.

 Which event suits each job: (1) live search results while the user types, (2) saving a quantity once the user has finished editing the box?

input fires on every edit, including paste and autofill. change fires when the user commits a value, for a text box when they leave it after editing.

 Why handle a form's submit event instead of the submit button's click?

A form can be submitted in several ways; all of them fire submit on the form. Call preventDefault() there, or the browser sends the form and reloads the page.

 What is the difference between form.requestSubmit() and form.submit()?

If your submit listener does validation or sends with fetch, calling form.submit() bypasses all of it. Use requestSubmit().

 A form has <input type="checkbox" name="leaveAtGate">. What does Object.fromEntries(new FormData(form)) contain for it?

FormData follows what a browser would send: unticked checkboxes are left out, ticked ones send their value, which defaults to "on". All values are strings. Convert on the way in: data.leaveAtGate === "on".

 The cart refuses quantities above 20 and disables the Place order button while an order is being sent. Which statement is right?

Browser checks are for the user's convenience. A user can edit the page, or skip it and send requests with curl. The server is the only place rules can be enforced.

 Why does this fail to remove the listener? button.addEventListener("click", () => pay(order)); // later button.removeEventListener("click", () => pay(order));

Listeners are matched by identity. Keep the function in a variable, use { once: true }, or pass a signal and call abort().

 A view adds listeners to window, document and three buttons. What is the simplest reliable way to remove them all when the view closes?

An aborted signal removes every listener registered with it. The same signal can also cancel the view's pending fetch calls.

 A test calls button.click(). What is event.isTrusted in the listener, and why?

Only events generated by the browser from real user input are trusted. Browsers allow some actions (pop-ups, full screen, clipboard) only from trusted events. Never use isTrusted as a security check on the server's behalf.

 The cart runs widget.dispatchEvent(new CustomEvent("cart:change", { detail })) and the header listens on document. The badge never updates. Why?

Built-in events like click bubble, but events you create default to bubbles: false, so only listeners on widget itself hear it.

 Which pairing is right?

A debounce waits for a quiet moment, so a search runs once per pause. A throttle runs at most once per period while events keep coming, so an indicator keeps moving without running on every event.

 Two scripts on a page both do checkoutButton.onclick = …. What happens?

An event-handler property is a single slot. addEventListener keeps a list, so independent scripts can each add their own listener.

 On a slow connection, a customer clicks Place order twice. Which change in the page prevents a second order from being sent?

The second submit arrives while the first is still waiting for the server. A flag checked at the start of the listener ignores it; disabling the button tells the user. The server should still refuse duplicates.
