When is the value of this inside a normal (non-arrow) function decided?

this behaves like a hidden parameter filled in by the call site. The same function gets different values from different calls.

 What is this inside whoAmI for the call shop.branch.whoAmI()?

Only the object directly before the method name counts: the value before the last dot (or bracket).

 In an ES module, a function that uses this is called as fn(), with no dot. What is this?

ES modules are strict mode, and a plain call in strict mode gets this = undefined. Reading a property of it throws, so the mistake shows up at once.

 In an old, non-strict script, a function called as count() runs this.total = (this.total || 0) + 1. What happens?

In sloppy mode a plain call gets this = globalThis, so the function writes to the global object. Every other script can see and break that value. Strict mode throws instead.

 Which code runs in sloppy mode?

Modules and classes are always strict; the directive makes anything strict. CommonJS files and classic browser scripts are sloppy unless they opt in.

 const { add } = basket; add("RICE-5"); throws Cannot read properties of undefined (reading 'items'). Why?

const { add } = basket is the same as const add = basket.add. The object is not carried along; only a call with a dot would supply it.

 What does the second argument in ["SALT"].map(basket.add, basket) do?

map, filter, forEach, find, some and every take an optional thisArg. It works, but a wrapper arrow (sku) => basket.add(sku) is clearer to most readers.

 What is the difference between fn.call(obj, a, b) and fn.apply(obj, [a, b])?

Both call now with an explicit this. Since spread exists, fn.call(obj, ...args) covers what apply was used for.

 What does const later = report.print.bind(report) do?

bind never calls anything and never changes the original function. It creates a bound function, which you can pass around safely.

 const bound = fn.bind(ada). Which call can make bound run fn with this = chidi?

Binding is permanent. The only call form that overrides it is new, which creates a fresh object and is not what any of these do.

 A constructor function is bound: const B = Account.bind(bank). What is this inside Account during new B("Ada")?

new is stronger than bind. The constructor fills in the new object, and bank is not touched. (Bound arrow functions still cannot be constructed, because arrows never can.)

 Where does an arrow function get its this?

Arrows have no this of their own. They look it up lexically, exactly as closures find outer variables. That is why arrows make good callbacks inside methods.

 An object literal in a module has total: () => this.items.length. What happens when you call cart.total()?

An object literal does not create a this; only functions do. The arrow uses the module's this. Write methods with method syntax: total() { … }.

 What does arrowFn.call(report) do to this inside the arrow?

Explicit binding only works on functions that have their own this. The arrow keeps using the this of the code around it.

 Older code often has const self = this; at the start of a method, then uses self inside function callbacks. Why?

Before arrow functions, a variable was the only way to carry the method's this into a nested function. An arrow callback does this automatically.

 A class declares handle = (event) => this.process(event); as a class field. What is true?

Field initialisers run for each new instance, with this being that instance. Detaching obj.handle is safe, at the cost of one function per instance.

 A parent class has refund = () => "refunded" as an arrow field. A child class tries super.refund() in its own refund field. What happens?

super.method reads from the parent's prototype. An arrow field is an own property of each instance, and the child's field overwrites it on the same instance.

 A function click listener is registered on a <ul> and handles clicks on the buttons inside it (event delegation). A button is clicked. What is this?

The browser calls a function listener with the element it is attached to. The clicked element is event.target. Reading those two properties is clearer than this.

 In Node.js, orders.on("paid", function (id) { … }) registers a listener on an EventEmitter. What is this when it runs?

EventEmitter calls function listeners with the emitter as this. An arrow listener keeps the surrounding this instead. To call your own method, register a wrapper.

 Why does bindAll read each prototype property with Object.getOwnPropertyDescriptor instead of proto[name]?

Accessors run code when read. Inspecting the descriptor finds real methods without triggering getters, and leaves getters in place.

 What is this inside notifier.remind when you write setTimeout(notifier.remind, 1000)?

The expression notifier.remind only reads the function; the call happens later, inside the timer. Pass () => notifier.remind() or a bound function instead.

 You need to pass mailer.send as a callback in one place. Which fix is the simplest and costs nothing elsewhere?

A wrapper arrow puts the dot back exactly where it is needed and leaves the class and its prototype untouched. Binding helpers pay off when many methods are handed out in many places.

 What is this at the top level of a file, outside every function?

ES modules are strict and have no top-level this. CommonJS wraps each file in a function called with this set to module.exports.

 What does this print? const naira = { symbol: "₦", format(kobo) { return `${this.symbol}${kobo / 100}`; }, }; const cedi = { symbol: "GH₵", format: naira.format }; console.log(naira.format(500), cedi.format(500));

Both objects hold the same function, but each call gets the object before its dot. Where the function was first written does not matter.

 What does this print? const account = { owner: "Ada", whose() { return this === undefined ? "nobody" : this.owner; }, }; const whose = account.whose; console.log(account.whose(), whose());

whose() is a plain call in a module (strict mode), so this is undefined.

 What does this print? function transfer(amount, note) { return `${this.owner}:${amount}:${note}`; } console.log(transfer.call({ owner: "Ada" }, 500, "rent")); console.log(transfer.apply({ owner: "Chidi" }, [200, "lunch"]));

call takes the arguments one by one; apply takes them as one array and spreads them into the parameters.

 What does this print? function fee(percent, amount) { return `${this.bank} ${(amount * percent) / 100}`; } const gtFee = fee.bind({ bank: "GT" }, 2); console.log(gtFee(5000), gtFee(1000, 99), gtFee.length);

bind fixed this and the first argument (2 percent). The next argument becomes amount; the extra 99 is ignored. The bound function expects one parameter fewer.

 What does this print? function name() { return this.name; } const first = name.bind({ name: "Ada" }); const second = first.bind({ name: "Chidi" }); console.log(first(), second(), second.call({ name: "Tunde" }));

The first bind is permanent. Binding the bound function again, or calling it with call, cannot change the this it passes to name.

The arrow uses the method's this, which is report. The function callback gets its own this from map's plain call: undefined (and ?. avoids the crash).

 What does this print? const cart = { items: ["rice", "oil"], countArrow: () => typeof this, countMethod() { return this.items.length; }, }; console.log(cart.countArrow(), cart.countMethod());

The arrow was written at the top level of the module, where this is undefined; calling it as cart.countArrow() does not change that. The method gets cart from the dot.

 What does this print? const accountProto = { get label() { return `${this.owner} (${this.balanceKobo / 100})`; }, }; const ada = Object.create(accountProto); ada.owner = "Ada"; ada.balanceKobo = 50000; console.log(ada.label);

The getter lives on the prototype, but this is the object the property was read on, ada. That is how one getter serves every object that inherits it.

The second argument of map is used as this for each callback call, so this.percent is 7.5.

 What does this print? class Till { pay() { return "paid"; } refund = () => "refunded"; } const a = new Till(); const b = new Till(); console.log(a.pay === b.pay, a.refund === b.refund, Object.keys(a));

pay lives once on the prototype. The arrow field is created for each instance as an own, enumerable property, so each till has its own refund.

new overrides the binding: Account ran with a fresh object, which is an instance of Account. bank was never touched.

 The Function constructor always creates a sloppy-mode function. What does this print? function strictKind() { return typeof this; } const sloppyKind = new Function("return typeof this;"); console.log(strictKind.call(42), sloppyKind.call(42), sloppyKind.call(undefined));

Strict mode passes the primitive as it is. Sloppy mode wraps a primitive in an object and replaces undefined with the global object, so both sloppy calls see an object.

Write myBind(fn, thisValue, ...fixedArgs) without using bind: it returns a function that calls fn with thisValue, the fixed arguments and then the new ones. Calling the result with call must not change this.

 function myBind(fn, thisValue, ...fixedArgs) { return fn; } function fee(percent, amount) { return `${this?.bank}: ${(amount * percent) / 100}`; } const gtFee = myBind(fee, { bank: "GT" }, 2); console.log(gtFee(5000)); console.log(gtFee.call({ bank: "Other" }, 1000)); function myBind(fn, thisValue, ...fixedArgs) { return (...laterArgs) => fn.apply(thisValue, [...fixedArgs, ...laterArgs]); } function fee(percent, amount) { return `${this?.bank}: ${(amount * percent) / 100}`; } const gtFee = myBind(fee, { bank: "GT" }, 2); console.log(gtFee(5000)); console.log(gtFee.call({ bank: "Other" }, 1000)); GT: 100 GT: 20

A closure remembers fn, thisValue and fixedArgs; apply calls with the chosen this. Returning an arrow means the call-site this is ignored, just like a real bound function.

 function bindMethods(obj, names) { return obj; } const cart = { items: [], add(sku) { this.items.push(sku); }, size() { return this.items.length; }, }; const { add, size } = bindMethods(cart, ["add", "size"]); try { add("RICE-5"); add("OIL-1"); console.log(size()); } catch (error) { console.log(error.name); } function bindMethods(obj, names) { for (const name of names) obj[name] = obj[name].bind(obj); return obj; } const cart = { items: [], add(sku) { this.items.push(sku); }, size() { return this.items.length; }, }; const { add, size } = bindMethods(cart, ["add", "size"]); try { add("RICE-5"); add("OIL-1"); console.log(size()); } catch (error) { console.log(error.name); } 2
