When does the block of an if statement run?

The condition does not have to be a boolean. JavaScript converts it with the truthy and falsy rules, so if ("hello") runs and if (0) does not.

 An if has an else. How many of the two blocks run?

With if … else, exactly one block runs: the if block when the condition is truthy, otherwise the else block.

 What does this print? const count = 0; if (count) { console.log("You have tasks"); } else { console.log("No tasks"); }

0 is falsy, so if (count) is false and the else block runs. Be careful with numbers: if 0 is a valid value, compare it on purpose, for example count !== undefined.

 What does this print? const title = " "; if (title) { console.log("has title"); } else { console.log("empty"); } if (title.trim() === "") { console.log("blank"); }

A string with a space is not empty, so it is truthy and if (title) passes. Trimming it gives "", so the second check catches it. That is why the lesson checks title.trim() === "".

 What does this print? const title = "Buy milk"; if (title.trim() === "") { console.log("A task needs a title"); } console.log("This line always runs");

The title is not empty, so the if block is skipped. The line after the block is not part of the if, so it always runs.

 In an if statement, what marks the block of code that belongs to it?

The condition goes in parentheses and the code to run goes between { and }. Indenting by two spaces does not change the meaning; it helps people see what belongs to the if.

 What does this print? const hoursLeft = 30; if (hoursLeft < 0) { console.log("Overdue"); } else if (hoursLeft < 24) { console.log("Due today"); } else if (hoursLeft < 24 * 7) { console.log("Due this week"); } else { console.log("Due later"); }

30 is not below 0 and not below 24, but it is below 168 (24 * 7). Only the first matching branch runs, so else is skipped.

 The conditions are in the wrong order. What does this print? const score = 95; if (score >= 50) { console.log("Pass"); } else if (score >= 90) { console.log("Excellent"); } else { console.log("Fail"); }

95 is at least 50, so the first branch runs and the rest are skipped. "Excellent" can never print. Put the most specific condition (score >= 90) first.

 In a chain of else if branches, several conditions can be true. Which rule does the lesson give?

Conditions are tested from top to bottom, and the first truthy one wins. A general condition at the top would hide the more specific ones below it.

 What does this print? const loggedIn = false; const role = "admin"; if (loggedIn) { if (role === "admin") { console.log("Show the admin panel"); } else { console.log("Show the normal dashboard"); } } else { console.log("Show the login page"); }

The outer condition loggedIn is false, so the inner if is never reached, even though the role is "admin". The outer else runs.

 Your function has four levels of nested if blocks. What does the lesson suggest?

One level of nesting is fine, but three or four are hard to follow. Guard clauses check each bad case on its own line and return, so the code stays flat.

 What does condition ? a : b give?

The ternary operator takes three parts: a condition, the value for truthy, and the value for falsy. It chooses between two values.

 What does this print? const count = 0; console.log(`${count} ${count === 1 ? "task" : "tasks"} left`);

count === 1 is false, so the ternary gives "tasks". Only exactly 1 uses the singular.

 What does this print? const done = false; const mark = done ? "x" : " "; console.log(`[${mark}] Buy milk`);

done is false, so the ternary gives the second value, a single space.

 When is a ternary the right tool?

Use a ternary to pick one of two values. For longer logic, or for choices that do things, use if. Never nest ternaries; they become unreadable.

 How does switch compare the value with each case?

switch uses strict equality. The string "200" and the number 200 are different types, so they do not match.

 What does default do in a switch?

default is the catch-all branch. Use it to handle unknown values, for example by printing Unknown status.

 What does this print? const status = "review"; switch (status) { case "todo": console.log("Not started"); break; case "in_progress": case "review": console.log("Someone is working on it"); break; case "done": console.log("Finished"); break; default: console.log(`Unknown status: ${status}`); }

Two cases with nothing between them share the same code. "review" matches, runs the shared line, and break leaves the switch.

 This switch has no break. What does it print? const level = "error"; switch (level) { case "error": console.log("page the on-call engineer"); case "warn": console.log("write to the error log"); case "info": console.log("write to the normal log"); }

Without break, JavaScript "falls through" and runs the code of every case below the match. Here it is on purpose; most of the time it is a bug.

 The programmer forgot one break. What does this print? const role = "editor"; switch (role) { case "admin": console.log("full access"); break; case "editor": console.log("can edit"); case "viewer": console.log("can read"); break; default: console.log("no access"); }

The "editor" case has no break, so it falls through into the "viewer" case. That case has a break, so default does not run.

 What does this print? function statusText(code) { switch (code) { case 200: return "OK"; case 404: return "Not Found"; default: return "Unknown"; } } console.log(statusText(404), "|", statusText("404"));

switch compares with ===. The string "404" is not the number 404, so it falls to default.

 Inside a function, the cases of a switch use return instead of break. Is that correct?

return ends the function straight away, so nothing after it runs. No break is needed.

 You let one case fall through into the next on purpose. What should you do?

Most fall through is a bug, so readers will assume yours is one too. A short comment tells them it is on purpose.

 When is switch clearer than a chain of else if?

switch fits one value with many exact options, like a status name. For ranges or different variables, use if and else if.

 What does this print? function check(n) { if (n < 0) return "negative"; console.log("checking", n); return "ok"; } console.log(check(-1)); console.log(check(2));

return ends the function straight away. For -1 the guard returns before the console.log. For 2 the guard is skipped and both lines run.

 What is a guard clause?

A guard clause checks one bad case at the top of a function and returns early. The happy path is then the last line, and the code stays flat.

 What does this print? function canEdit(user, task) { if (!user) return "no: not logged in"; if (task.ownerId !== user.id) return "no: not your task"; if (task.locked) return "no: task is locked"; return "yes"; } const task = { ownerId: 1, locked: true }; console.log(canEdit({ id: 2 }, task)); console.log(canEdit({ id: 1 }, task));

The first guard that matches wins. User 2 does not own the task, so the second guard returns. User 1 owns it, but it is locked, so the third guard returns.

 You write a function that decides whether a user may delete a task. Which design is safest?

For permissions, always fail closed: start from "no" and allow only after every check passed. If a check is missing or confused, the answer is still "no".

 When may you leave out the braces, as in if (!user) return "no";?

A block with one statement can skip its braces. The lesson keeps this for one-line guards, so it is always clear what the if controls.

 In the age check, why does the empty string need its own guard?

Number("") is 0, a real number. Without the guard, an empty form would pass the number checks and say "rejected: too young" instead of "age is required".

 What does this print? console.log(Number.isInteger(Number("abc")), Number.isInteger(Number("17.5")), Number.isInteger(Number(" 13 ")));

"abc" becomes NaN and "17.5" becomes 17.5; neither is a whole number. Number ignores the spaces around " 13 ", so it gives 13. One check rejects both text and decimals.

 What does this print? function checkAge(input) { if (input === undefined || input === null) return "invalid: age is required"; const text = String(input).trim(); if (text === "") return "invalid: age is required"; const age = Number(text); if (!Number.isInteger(age)) return "invalid: age must be a whole number"; if (age < 0 || age > 130) return "invalid: age must be between 0 and 130"; if (age < 13) return "rejected: too young"; if (age < 18) return "allowed with parental consent"; return "allowed"; } console.log(checkAge("13")); console.log(checkAge("18")); console.log(checkAge(" "));

13 is not below 13 but is below 18, so it needs consent. 18 is not below 18, so it is allowed. Spaces trim to "", which the guard catches before any number check.

 Why does the lesson test the ages 12, 13, 17 and 18 on purpose?

Boundary values sit right next to each rule's limit. If a comparison is off by one, only an edge value shows it.

 A value comes from a form, typed by a stranger. What should your function do first?

Outside input can be anything: empty, text, a decimal, a huge number. Throw out every bad input first; then the decision part is short and safe.

 What does this print? const total = NaN; console.log(total > 0, !(total > 0), total <= 0);

Every comparison with NaN is false, even <=. So !(total > 0) is a handy guard: it is true for negatives, zero and NaN.

 What does this print? function grade(score) { if (score >= 90) return "A"; if (score >= 80) return "B"; if (score >= 70) return "C"; return "F"; } console.log(grade(90), grade(79), grade(80), grade(69));

Each guard returns, so later checks do not need an upper limit. 79 fails >= 80 but passes >= 70, and 69 reaches the last line.

 The shipping(total, country) exercise starts with if (typeof total !== "number" || !(total > 0)) return "invalid total";. Which input does this guard not reject?

"80" is a string, so typeof rejects it. NaN and -5 fail total > 0. Only a positive number like 20 gets through.
