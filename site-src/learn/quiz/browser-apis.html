Where do fetch, localStorage and document come from?

The language defines values, functions and built-ins like JSON. Everything that touches the outside world comes from the host. Node.js is a different host that implements some of the same Web APIs (fetch, URL) and not others (document, localStorage).

 Your page uses the Clipboard API when it exists. What is the reliable way to decide?

Feature detection asks about the feature itself. Browser names in the user-agent string are unreliable and say nothing about which features a given version has, or whether the page is in a secure context where the API is allowed.

 When does the promise returned by fetch(url) reject?

A 404 or 500 is still a response, so fetch fulfils. Check response.ok. Invalid JSON makes response.json() reject, which is a separate promise.

 What does response.ok tell you?

ok is only a status check. A 201 is ok; a 304, 404 or 500 is not. The body may still be anything.

 A logging helper calls await response.text() to record the reply, and then the caller calls await response.json(). What happens, and what is the fix?

A response body is consumed by reading it (bodyUsed becomes true). response.clone() before the first read gives a second, independent body.

 Where should a web app keep a user's login session?

Any script on the page can read localStorage and sessionStorage, including an attacker's injected script. An HttpOnly cookie is sent with requests but is invisible to JavaScript.

 What is the difference between localStorage and sessionStorage?

Both store strings with the same methods. They differ in lifetime and scope. Neither is sent to the server; cookies are.

 A page calls localStorage.setItem("cart", …). Which pages receive a storage event?

The event exists to keep other tabs in step. The page that wrote the value already knows about it.

 A widget's reset button calls localStorage.clear(). Why is that a bad idea on most sites?

All scripts on an origin share one storage. Prefix your keys ("tasks-app:") and remove only your own.

 Why should code validate what it reads from localStorage, even though only your own code wrote it?

Stored data outlives the code that wrote it and is editable in developer tools. Treat it like any input: parse inside try, check the shape and version, and fall back to a default.

 What happens when localStorage.setItem would exceed the origin's quota?

Storage writes can throw (quota, disabled storage). An uncaught throw at start-up or in a save handler breaks the page, so wrap writes and keep working in memory.

 A single-page app calls history.pushState(null, "", "/tasks/7") when a task is opened, and renders the task. The user presses Back: the address changes to /tasks, but the page still shows task 7. What is missing?

The History API only manages entries and the address bar. On Back and Forward the browser fires popstate, and your code must render what the address now says.

 A search box updates the address with the current search term on every keystroke. Which call avoids filling the Back button with one entry per letter?

replaceState updates the current entry instead of adding one, so Back leaves the search page in one step.

 An SPA works when you click around, but reloading https://tasks.example/tasks/7 shows the server's 404 page. Why?

After a reload, the browser asks the server for the address in the bar. Static hosts have a "fallback" or "rewrite" setting that serves index.html for app routes.

 A countdown shows "30 seconds left" and subtracts 1 in a setInterval(…, 1000). Users who switch tabs come back to a clock that is far behind. Why, and what is the fix?

Counting ticks assumes each tick is exactly on time. Computing from a timestamp stays correct however late or rarely the callback runs. (requestAnimationFrame pauses completely in background tabs.)

 Why use requestAnimationFrame rather than setInterval(step, 16) for a JavaScript animation?

A 16 ms interval drifts against the screen's refresh and keeps running in hidden tabs. requestAnimationFrame matches the display (which may be 60, 120 or 144 Hz), so compute progress from its timestamp.

 An animation should last 300 ms. Its step function adds 5% to a width each frame. What goes wrong?

Frame rates differ between screens and drop when the device is busy. Progress = elapsed time ÷ duration gives the same animation everywhere.

 Which statement about a Web Worker is true?

Workers have their own global scope. Data sent with postMessage is copied (structured clone), so neither side can change the other's objects.

 For which job is a Web Worker most worthwhile?

A worker pays off for heavy CPU work that would freeze the page. Waiting for the network does not block the main thread at all, and DOM work cannot be done in a worker.

 A notes app saves the whole document to localStorage on every keystroke, and typing feels sluggish on large notes. Why?

Every write blocks the thread that also handles typing. Save after the user pauses (a debounce), and consider IndexedDB, which is asynchronous, for large data.
