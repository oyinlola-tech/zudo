# Software design and architecture

Give code a shape that survives growth: design principles, SOLID and design patterns solving real problems, layered and clean architecture, architecture styles, and a small framework you build yourself so no framework is magic.

- **12 lessons**
- **11 h** to read and try
- **Before this:** [TypeScript](https://zudojs.oyinlola.site/learn/typescript), [Backend engineering](https://zudojs.oyinlola.site/learn/backend)

0 of 12 lessons done

[Start lesson 1 →](https://zudojs.oyinlola.site/learn/design-principles)

## When you finish, you can

- Spot high coupling and low cohesion, and refactor it
- Apply SOLID, DRY, KISS and YAGNI with judgement
- Use factory, builder, adapter, decorator, proxy, strategy, observer, command and chain of responsibility where they solve a problem
- Structure a backend in layers with ports and adapters
- Compare monoliths, modular monoliths, microservices and event-driven systems
- Build and explain the parts of a backend framework

**You build:** A miniature TypeScript framework with a container, router, middleware and validation

MODULE 1

## Design principles

1. [1**Design principles through refactoring**Refactor a tangled order function step by step into validation, pricing, payment, storage and notification parts, with tests printed after every step.55 min](https://zudojs.oyinlola.site/learn/design-principles)
2. [2**SOLID, DRY, KISS and YAGNI**Meet SOLID, DRY, KISS and YAGNI through real invoice, promotion and reminder bugs, then see how each principle goes wrong when it is applied without judgement.55 min](https://zudojs.oyinlola.site/learn/design-solid)

MODULE 2

## Design patterns

1. [3**Creational patterns**Fix real object-creation bugs with factories, abstract factories and builders, then see why a DI container's singleton lifetime beats the singleton pattern.55 min](https://zudojs.oyinlola.site/learn/design-patterns-creational)
2. [4**Structural patterns**Wrap a third-party SMS SDK in an adapter, add retries, logging and caching with decorators, control access with proxies, and hide SQL behind a repository.60 min](https://zudojs.oyinlola.site/learn/design-patterns-structural)
3. [5**Behavioural patterns**Turn a shipping-fee switch into strategies, decouple order reactions with observers, make admin actions undoable commands, and build middleware as a chain.60 min](https://zudojs.oyinlola.site/learn/design-patterns-behavioral)

MODULE 3

## Architecture

1. [6**Backend architecture**Apply separation of concerns and SOLID to a whole backend: domain, application and infrastructure layers, ports, dependency injection and a composition root.45 min](https://zudojs.oyinlola.site/learn/backend-architecture)
2. [7**Clean architecture: ports and adapters**Rebuild the BookStore's order flow as domain, use cases, ports and adapters, run it over HTTP and a CLI, and enforce the dependency rule with a checker.55 min](https://zudojs.oyinlola.site/learn/arch-clean)
3. [8**Architecture styles**Compare monoliths, modular monoliths, microservices, events, messages, CQRS and gateways by simulating them in-process, with injected latency and failures.60 min](https://zudojs.oyinlola.site/learn/arch-styles)

MODULE 4

## Framework engineering

1. [9**What a framework does**Library vs framework and inversion of control, then every job a backend framework takes over: lifecycle, DI, routing, config, validation. Build a tiny one.30 min](https://zudojs.oyinlola.site/learn/frameworks)
2. [10**Build a mini framework, part 1: the core**Build the core of a small TypeScript framework (container, config, logger, lifecycle with rollback, application object) and compare each part with ZudoJS.60 min](https://zudojs.oyinlola.site/learn/framework-build-core)
3. [11**Build a mini framework, part 2: HTTP**Add a router, middleware, controllers, validation, error responses and an event bus to your mini framework, serve it with node:http, and compare it with ZudoJS.60 min](https://zudojs.oyinlola.site/learn/framework-build-http)
4. [12**Reading framework source**Answer questions the docs cannot by reading published ZudoJS packages: package boundaries, .d.ts files, generics, and a request traced through dist code.55 min](https://zudojs.oyinlola.site/learn/framework-read-source)
