@zudojs/api

HTTP API infrastructure for Zudo — request handling, routing, middleware, validation, error handling, and OpenAPI integration.

HTTP REST ROUTING

OVERVIEW

@zudojs/api defines the public surface of your application capabilities. It provides transport-agnostic operation definitions, a typed execution context, an interceptor pipeline, an operation registry, and a discriminated result type.

This package sits in Layer 3 (Application Architecture) of the Zudo stack. It depends only on Layer 1 foundation packages. HTTP handlers, CLI commands, message consumers, and RPC servers all execute through the same API operations.

Why?

Without a transport-agnostic API layer, business logic leaks into HTTP handlers, CLI parsers, or message consumers. @zudojs/api extracts operations into standalone, testable units that any transport can call.

INSTALLATION

# Install with npm npm install @zudojs/api # Or with pnpm pnpm add @zudojs/api
Peer dependencies

@zudojs/errors, @zudojs/constants, @zudojs/types, and @zudojs/schema are required. Install them if not already present.

QUICK START

Define an operation, register it, and execute it:

import { defineOperation, APIOperationRegistry, APIExecutor, createAPIContext, } from "@zudojs/api"; // 1. Define the operation const getUser = defineOperation({ name: "users.get", handler: async (input, context) => { return { id: input.id, name: "Alice" }; }, }); // 2. Register it const registry = new APIOperationRegistry(); registry.register(getUser); // 3. Execute it const executor = new APIExecutor(); const ctx = createAPIContext("req-001", {}); const result = await executor.execute(getUser, { id: "123" }, ctx); if (result.ok) { console.log(result.data); // { id: "123", name: "Alice" } } else { console.error(result.error); }

CORE CONCEPTS

fn defineOperation()

Creates a frozen APIOperation object. This is the primary entry point for defining application capabilities.

Signature

function defineOperation<TInput, TOutput>( options: DefineOperationOptions<TInput, TOutput> ): APIOperation<TInput, TOutput>

Options

PropertyTypeRequiredDescription
namestringYesUnique operation identifier. Dot notation recommended (e.g. "users.get").
inputunknownNoSchema definition for input validation (passed to @zudojs/schema).
outputunknownNoSchema definition for output validation.
handlerAPIHandler<TInput, TOutput>YesAsync function that implements the operation logic.
metadataAPIOperationMetadataNoDescription, tags, version, timeout, deprecation status.
timeoutnumberNoOperation timeout in ms. Defaults to 30,000.

Example: Full definition

const createOrder = defineOperation({ name: "orders.create", input: CreateOrderSchema, output: OrderSchema, handler: async (input, context) => { const userId = context.get(UserIdContextKey); return orderService.create({ ...input, userId }); }, metadata: { description: "Create a new order", tags: ["orders", "mutations"], version: "1.0", idempotent: true, }, timeout: 15_000, });

Example: Minimal definition

const ping = defineOperation({ name: "system.ping", handler: async () => ({ pong: true }), });

interface APIOperation<TInput, TOutput>

The frozen operation object returned by defineOperation(). Transport-agnostic — HTTP, CLI, gRPC, message queues all call the same operation.

PropertyTypeDescription
namestringUnique operation identifier.
inputunknownInput schema (optional).
outputunknownOutput schema (optional).
handlerAPIHandler<TInput, TOutput>Async handler function.
metadataAPIOperationMetadataDescription, tags, version, etc.
timeoutnumberTimeout in ms (default: 30,000).

PropertyTypeDescription
descriptionstringHuman-readable description.
tagsstring[]Tags for grouping and filtering.
deprecatedbooleanWhether the operation is deprecated.

idempotentbooleanWhether the operation is idempotent.

interface DefineOperationOptions<TInput, TOutput>

The options object passed to defineOperation(). Identical shape to APIOperation but used for creation rather than consumption.

type APIHandler<TInput, TOutput>

The handler function signature for operation implementations.

type APIHandler<TInput, TOutput> = ( input: TInput, context: APIContext, ) => Promise<TOutput>;

Example: Handler with context

const deleteUser = defineOperation({ name: "users.delete", handler: async (input, context) => { const userId = context.get(UserIdContextKey); const tenantId = context.get(TenantIdContextKey); // Access AbortSignal for cancellation context.signal?.throwIfAborted(); await userService.delete(input.id, { tenantId, requestedBy: userId }); return { deleted: true }; }, });

fn createAPIContext()

Creates a frozen APIContext instance with typed key-value storage.

function createAPIContext<TState>( requestId: string, state: TState, signal?: AbortSignal, ): APIContext<TState>

Parameters

ParamTypeDescription

Example: Context with state

interface AppState { db: DatabaseClient; cache: CacheAdapter; } const ctx = createAPIContext<AppState>( "req-abc-123", { db: dbClient, cache: cacheAdapter }, AbortSignal.timeout(5000), ); // Access state in handler const handler = async (input, context) => { const user = await context.state.db.query("SELECT * FROM users WHERE id = $1", [input.id]); return user; };

EXECUTOR

class APIExecutor

Executes operations through the interceptor pipeline. Catches handler errors and wraps them in APIResult failures.

class APIExecutor { constructor(interceptors?: APIInterceptor[]); async execute<TInput, TOutput>( operation: APIOperation<TInput, TOutput>, input: TInput, context: APIContext, ): Promise<APIResult<TOutput>>; }

Constructor

ParamTypeDefaultDescription
interceptorsAPIInterceptor[][]Ordered list of interceptors wrapping handler execution.

Example: Executor with interceptors

const executor = new APIExecutor([ loggingInterceptor, authInterceptor, validationInterceptor, rateLimitInterceptor, ]); const result = await executor.execute(getUser, { id: "123" }, ctx);

fn normalizeAPIError()

Converts unknown thrown values into Error instances. Used internally by the executor.

function normalizeAPIError( error: unknown, operationName?: string, ): Error
Note

If the thrown value is already an Error, it is returned as-is. Non-error throws (strings, numbers, objects) are wrapped in a new Error with a descriptive message.

INTERCEPTORS

interface APIInterceptor

Interceptors form a pipeline around handler execution. They can modify input, wrap output, log, authenticate, rate-limit, or abort operations. Interceptors run in order; each calls next() to continue the chain.

interface APIInterceptor { intercept<TInput, TOutput>( context: APIExecutionContext<TInput, TOutput>, next: () => Promise<APIResult<TOutput>>, ): Promise<APIResult<TOutput>>; }

Example: Logging interceptor

import { APIInterceptor } from "@zudojs/api"; const loggingInterceptor: APIInterceptor = { async intercept(context, next) { const start = Date.now(); console.log(`→ ${context.operation.name}`); const result = await next(); const duration = Date.now() - start; if (result.ok) { console.log(`✓ ${context.operation.name} (${duration}ms)`); } else { console.error(`✗ ${context.operation.name} (${duration}ms)`, result.error); } return result; }, };

Example: Auth interceptor

const authInterceptor: APIInterceptor = { async intercept(context, next) { const userId = context.get(UserIdContextKey); if (!userId) { return apiFailure(new APIAuthenticationError({ message: "Authentication required", })); } return next(); }, };

Example: Rate-limit interceptor

const rateLimitInterceptor: APIInterceptor = { async intercept(context, next) { const userId = context.get(UserIdContextKey) ?? "anonymous"; const allowed = await rateLimiter.check(userId, 100); if (!allowed) { return apiFailure(new APIRateLimitError({ message: "Rate limit exceeded", retryAfter: 60, })); } return next(); }, };

Example: Caching interceptor

const cacheInterceptor: APIInterceptor = { async intercept(context, next) { const cacheKey = `${context.operation.name}:${JSON.stringify(context.input)}`; const cached = await cache.get(cacheKey); if (cached) { return apiSuccess(cached); } const result = await next(); if (result.ok) { await cache.set(cacheKey, result.data, { ttl: 60_000 }); } return result; }, };

interface APIExecutionContext<TInput, TOutput>

Passed through the interceptor pipeline. Contains the operation, input, context, and the result (if the interceptor runs after the handler).

PropertyTypeDescription
operationAPIOperation<TInput, TOutput>The operation being executed.
inputTInputThe validated input.
contextAPIContextThe execution context.
resultAPIResult<TOutput> | undefinedResult after handler execution (only available in post-interceptors).

fn createNoopInterceptor()

Creates a no-op interceptor that simply calls next(). Useful as a default or placeholder.

function createNoopInterceptor(): APIInterceptor
import { createNoopInterceptor } from "@zudojs/api"; const executor = new APIExecutor([ loggingInterceptor, createNoopInterceptor(), // placeholder authInterceptor, ]);

OPERATION REGISTRY

class APIOperationRegistry

Central registry for all API operations. Enforces uniqueness, provides O(1) lookup by name, supports tag-based filtering, and can be frozen to prevent mutation.

class APIOperationRegistry { register(operation: APIOperation): void; get(name: string): APIOperation | undefined; has(name: string): boolean; require(name: string): APIOperation; getAll(): readonly APIOperation[]; findByTag(tag: string): readonly APIOperation[]; unregister(name: string): boolean; freeze(): void; isFrozen(): boolean; }

Methods

MethodReturnsDescription
register(op)voidRegister an operation. Throws if name already exists or registry is frozen.
get(name)APIOperation | undefinedLook up by name. Returns undefined if not found.
has(name)booleanCheck if operation exists.
require(name)APIOperationLook up by name. Throws if not found.
getAll()APIOperation[]Returns all registered operations.
findByTag(tag)APIOperation[]Filter operations by metadata tag.
unregister(name)booleanRemove an operation. Returns true if removed.
freeze()voidPrevent further mutations.
isFrozen()booleanCheck if registry is frozen.

Example: Full registry usage

const registry = new APIOperationRegistry(); registry.register(getUser); registry.register(createUser); registry.register(deleteUser); registry.register(listUsers); // Lookup const op = registry.get("users.get"); // Check existence if (registry.has("users.get")) { ... } // Require (throws if missing) const op2 = registry.require("users.get"); // Filter by tag const userOps = registry.findByTag("users"); // Get all const allOps = registry.getAll(); // Freeze (production) registry.freeze();

RESULT TYPES

All operation results use a discriminated union type. Check result.ok to determine success or failure — never throw from handlers.

type APIResult<T>

type APIResult<T> = APISuccess<T> | APIFailure;

APISuccess<T>

PropertyTypeDescription
oktrueDiscriminant — always true.
dataTThe operation output.

APIFailure

PropertyTypeDescription
okfalseDiscriminant — always false.
errorAPIErrorThe error that occurred.

Helper Functions

FunctionSignatureDescription
apiSuccess(data)<T>(data: T) => APISuccess<T>Create a success result.
apiFailure(error)(error: APIError) => APIFailureCreate a failure result.
isApiSuccess(result)<T>(result: APIResult<T>) => result is APISuccess<T>Type guard for success.
isApiFailure(result)<T>(result: APIResult<T>) => result is APIFailureType guard for failure.

Example: Working with results

import { apiSuccess, apiFailure, isApiSuccess, isApiFailure, } from "@zudojs/api"; // In a handler — always return result, never throw const handler = async (input, context) => { const user = await db.findUser(input.id); if (!user) { throw new APINotFoundError({ message: "User not found" }); } return user; }; // Caller side — check result const result = await executor.execute(getUser, { id: "123" }, ctx); if (isApiSuccess(result)) { console.log(result.data.name); } else if (isApiFailure(result)) { console.error(result.error.message); }

USE CASES

REST API with HTTP Transport

Define operations, expose them as HTTP endpoints. The HTTP layer translates request/response but business logic stays in the operation.

import { defineOperation, APIExecutor, APIOperationRegistry, createAPIContext } from "@zudojs/api"; import { APIValidationError, APINotFoundError } from "@zudojs/errors"; // Define operations const getUser = defineOperation({ name: "users.get", handler: async (input) => { const user = await db.findById(input.id); if (!user) throw new APINotFoundError({ message: "User not found" }); return user; }, }); // Register const registry = new APIOperationRegistry(); registry.register(getUser); // HTTP handler calls the executor app.get("/users/:id", async (req, res) => { const ctx = createAPIContext(req.id, {}, req.signal); const result = await executor.execute(getUser, { id: req.params.id }, ctx); if (result.ok) res.json(result.data); else res.status(mapErrorToStatus(result.error)).json({ error: result.error.message }); });

CQRS with Commands and Queries

Use operations as commands and queries. The registry separates read and write concerns.

// Commands (write side) const placeOrder = defineOperation({ name: "commands.orders.place", metadata: { tags: ["command", "orders"] }, handler: async (input, ctx) => { return orderService.place(input, ctx); }, }); // Queries (read side) const getOrder = defineOperation({ name: "queries.orders.get", metadata: { tags: ["query", "orders"] }, handler: async (input) => { return orderRepo.findById(input.id); }, }); // Register separately registry.register(placeOrder); registry.register(getOrder); // Find by tag const commands = registry.findByTag("command"); const queries = registry.findByTag("query");

Full Middleware Pipeline

Chain multiple interceptors for cross-cutting concerns: logging, auth, validation, rate-limiting, caching, metrics.

const executor = new APIExecutor([ timingInterceptor, // 1. Measure execution time loggingInterceptor, // 2. Log requests metricsInterceptor, // 3. Emit metrics authInterceptor, // 4. Check authentication rateLimitInterceptor, // 5. Rate limiting validationInterceptor, // 6. Validate input cacheInterceptor, // 7. Check cache ]); // Pipeline execution order: // timing → logging → metrics → auth → rateLimit → validation → cache → handler // If cache hits, handler is never called

Multi-Transport: HTTP + CLI + Message Queue

Same operation, different transports. Business logic is written once.

// Shared operation const processPayment = defineOperation({ name: "payments.process", handler: async (input, ctx) => paymentService.process(input), }); // HTTP transport app.post("/payments", async (req, res) => { const result = await executor.execute(processPayment, req.body, ctx); res.json(result); }); // CLI transport program.command("process-payment") .action(async (opts) => { const result = await executor.execute(processPayment, opts, ctx); console.log(result); }); // Message queue transport queue.consume("payment.process", async (msg) => { const result = await executor.execute(processPayment, msg.body, ctx); if (!result.ok) await dlq.send(msg); });

Multi-Tenant Isolation

Use context keys to enforce tenant isolation across all operations.

import { TenantIdContextKey, UserIdContextKey } from "@zudojs/api"; // Tenant-aware handler const listOrders = defineOperation({ name: "orders.list", handler: async (input, ctx) => { const tenantId = ctx.get(TenantIdContextKey); return db.query("SELECT * FROM orders WHERE tenant_id = $1", [tenantId]); }, }); // HTTP middleware sets tenant context app.use(async (req, res, next) => { const tenantId = await resolveTenant(req); req.ctx.set(TenantIdContextKey, tenantId); next(); });

Cancellation with AbortSignal

Propagate cancellation through the context signal.

const longRunningOp = defineOperation({ name: "analytics.generate", handler: async (input, ctx) => { const results = []; for (const chunk of input.data) { // Check if cancelled ctx.signal?.throwIfAborted(); results.push(await processChunk(chunk)); } return results; }, }); // Caller aborts after 5 seconds const controller = new AbortController(); setTimeout(() => controller.abort(), 5000); const ctx = createAPIContext("req-1", {}, controller.signal); const result = await executor.execute(longRunningOp, data, ctx);

COMPLETE EXAMPLE

A full user management API with operations, interceptors, registry, and executor.

import { defineOperation, APIOperationRegistry, APIExecutor, createAPIContext, apiSuccess, apiFailure, UserIdContextKey, TenantIdContextKey, } from "@zudojs/api"; import { APINotFoundError, APIValidationError, APIAuthenticationError, } from "@zudojs/errors"; // --- Operations --- const getUser = defineOperation({ name: "users.get", metadata: { tags: ["users"], description: "Get user by ID" }, handler: async (input, ctx) => { const user = await db.findUser(input.id); if (!user) throw new APINotFoundError({ message: "User not found" }); return user; }, }); const listUsers = defineOperation({ name: "users.list", metadata: { tags: ["users"] }, handler: async (input, ctx) => { const tenantId = ctx.get(TenantIdContextKey); return db.findUsers({ tenantId, limit: input.limit ?? 50 }); }, }); // --- Registry --- const registry = new APIOperationRegistry(); registry.register(getUser); registry.register(listUsers); registry.freeze(); // --- Interceptors --- const authInterceptor = { async intercept(ctx, next) { const userId = ctx.context.get(UserIdContextKey); if (!userId) return apiFailure(new APIAuthenticationError({ message: "Not authenticated" })); return next(); }, }; // --- Executor --- const executor = new APIExecutor([authInterceptor]); // --- Execute --- const ctx = createAPIContext("req-001", {}); ctx.set(UserIdContextKey, "user-abc"); ctx.set(TenantIdContextKey, "tenant-xyz"); const result = await executor.execute( registry.require("users.get"), { id: "user-abc" }, ctx, ); if (result.ok) { console.log("User:", result.data); } else { console.error("Error:", result.error.message); }

SUGGESTED IMPROVEMENTS

Input/Output Validation

Integrate @zudojs/schema validation directly in the executor. When an operation defines input or output schemas, validate automatically before/after handler execution.

Middleware Timing Metrics

Add built-in timing to the executor that records per-interceptor duration. Integrate with @zudojs/observability for automatic span creation.

Policy System

The MAX_POLICIES constant exists but policies aren't implemented yet. Add a policies field on operations with declarative authorization checks.

OpenAPI Integration

Auto-generate OpenAPI specs from the registry using @zudojs/openapi. Operation metadata (name, tags, description) maps 1:1 to OpenAPI operation objects.

Interceptor Deduplication

Prevent duplicate interceptors in the pipeline. Track by constructor reference or name to avoid accidental double-execution.

Streaming Operations

Add support for streaming handlers that yield partial results (e.g. AsyncGenerator). Useful for long-running queries or real-time feeds.

Operation Groups

Add registry.createGroup() to bundle related operations with shared interceptors. Simplifies multi-transport setup.

Dead Letter Queue Support

Integrate with @zudojs/queue to automatically retry failed operations with exponential backoff and dead letter routing.
