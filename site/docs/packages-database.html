@zudojs/database

PostgreSQL data-access layer for Zudo applications, built on Prisma 7 — a lifecycle-aware client, generic repositories with soft delete, a query builder that translates to Prisma where clauses, managed transactions, keyset pagination with signed cursors, migration and seed runners guarded by advisory locks, health checks with reconnect, and a bounded in-memory cache.

PRISMA 7 POSTGRESQL REPOSITORY PATTERN TRANSACTIONS MIGRATIONS

INSTALLATION

// npm npm install @zudojs/database @prisma/client @prisma/adapter-pg // pnpm pnpm add @zudojs/database @prisma/client @prisma/adapter-pg
Peer dependency: @prisma/client (>=7.0.0 <8) is a peer dependency. Prisma 7 connects through a driver adapter, so you also need one for PostgreSQL (@prisma/adapter-pg). @zudojs/errors 0.1.0 is a regular dependency.
PostgreSQL only. The migration, seed and lock helpers emit PostgreSQL SQL (advisory locks, $1 placeholders, BIGSERIAL). Requesting another dialect throws UnsupportedDialectError.

WHAT IT DOES

@zudojs/database provides the data-access layer for Zudo applications:

  • DatabaseClient — wraps a Prisma client with a connection lifecycle (de-duplicated connect()), raw queries, transactions and typed error normalisation
  • Database facade — a lazily created shared instance (getDatabase, connectDatabase, resetDatabase)
  • DatabaseConnectionManager — lifecycle events, scheduled health checks with timeout and overlap guard, reconnect with exponential back-off
  • BaseRepository — CRUD, bulk operations, soft delete, offset and keyset pagination, query-builder execution and transaction rebinding
  • QueryBuilder and 40 filter helpers — database-neutral filters translated to Prisma where / orderBy / select / include
  • TransactionManager, withTransaction, withTransactionRetry — managed transactions with context, error enrichment and retry of serialization failures
  • DatabaseUnitOfWork — one transaction for several repository operations
  • Pagination — offset helpers plus keyset helpers with HMAC-signed, shape-validated cursors
  • MigrationRunner / SeedRunner — versioned, tracked execution under PostgreSQL advisory locks, one transaction per item by default
  • DatabaseLockManager — advisory and row locks with lock_timeout, SKIP LOCKED / NOWAIT
  • MemoryDatabaseCache — LRU cache with TTL, background pruning and loader coalescing
  • Relations — typed relation definitions, a registry keyed by parent model, and toPrismaInclude
  • Health — checkDatabaseHealth, checkDatabaseReadiness, assertDatabaseHealth
Prisma stays visible. Repositories wrap a Prisma model delegate (prisma.user) and transaction callbacks receive Prisma's interactive transaction client. The package normalises errors, lifecycle and pagination; it does not hide Prisma.

WHERE IT SITS

APPLICATION LAYER (services, handlers, CQRS) │ repositories, query builder, transactions ▼ DATABASE LAYER (@zudojs/database) │ PrismaClientLike (structural), interactive $transaction, $queryRawUnsafe ▼ PRISMA CLIENT 7 (@prisma/client) + DRIVER ADAPTER (@prisma/adapter-pg) │ ▼ POSTGRESQL

The package depends on Prisma structurally: any object exposing $connect, $disconnect, $transaction, $queryRawUnsafe and $executeRawUnsafe satisfies PrismaClientLike. Nothing is read from the generated Prisma namespace at runtime, so a generated client living outside @prisma/client (the Prisma 7 default) works.

DATABASE CLIENT

DatabaseClient wraps a Prisma client with a connection lifecycle, raw query helpers, transactions and error normalisation.

interface DatabaseClientOptions { readonly prisma?: PrismaClientLike; // pre-built client (takes precedence) readonly adapter?: PrismaDriverAdapterLike; // used to construct a PrismaClient when prisma is absent readonly logger?: DatabaseLogger; readonly connectionTimeoutMs?: number; // client-side deadline for $connect (default 10 000) readonly logging?: boolean; // emit query duration/target to the logger } class DatabaseClient { constructor(options?: DatabaseClientOptions); // throws DatabaseError when neither prisma nor adapter is given connect(): Promise<void>; // concurrent calls share one in-flight attempt disconnect(): Promise<void>; // waits for an in-flight connect first ensureConnected(): Promise<void>; destroy(): Promise<void>; ping(options?: RawQueryOptions): Promise<void>; healthCheck(options?: RawQueryOptions): Promise<DatabaseClientHealth>; getStatus(): DatabaseStatus; // "disconnected" | "connecting" | "connected" | "disconnecting" | "error" getConnectedAt(): Date | undefined; getPrisma(): PrismaClientLike; transaction<T>(callback: (tx: DatabaseTransactionContext) => Promise<T>, options?: TransactionOptions): Promise<T>; queryRawUnsafe<T>(sql: string, values?: readonly unknown[], options?: RawQueryOptions): Promise<T>; executeRawUnsafe(sql: string, values?: readonly unknown[], options?: RawQueryOptions): Promise<number>; queryRaw<T>(query: Prisma.Sql, options?: RawQueryOptions): Promise<T>; executeRaw(query: Prisma.Sql, options?: RawQueryOptions): Promise<number>; }

Operation options

OptionTypeEffect
signalAbortSignalRejects with DatabaseAbortError (code ERR_ABORTED) as soon as the signal aborts, even mid-query.
timeoutMsnumberClient-side deadline (ERR_DATABASE_TIMEOUT, 503). The statement is not cancelled server-side; use statement_timeout for that.
metadataRecord<string, unknown>Merged into the metadata of any DatabaseError raised.
isolationLevel / timeoutMs / maxWaitMsTransactionOptionsForwarded to Prisma's interactive $transaction. Isolation levels are validated against SUPPORTED_ISOLATION_LEVELS.

Example

import { PrismaClient } from "@prisma/client"; import { PrismaPg } from "@prisma/adapter-pg"; import { createDatabaseClient } from "@zudojs/database"; const prisma = new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }), }); const client = createDatabaseClient({ prisma, connectionTimeoutMs: 5_000 }); await client.connect(); const rows = await client.queryRawUnsafe<{ id: string }[]>( 'SELECT "id" FROM "users" WHERE "email" = $1', ["alice@example.com"], { timeoutMs: 2_000 }, ); await client.transaction(async (tx) => { await tx.user.update({ where: { id }, data: { balance: { decrement: 100 } } }); await tx.ledger.create({ data: { userId: id, amount: 100 } }); }, { isolationLevel: "Serializable", timeoutMs: 10_000 }); await client.disconnect();

DATABASE FACADE

Database is a thin facade over one DatabaseClient. A shared instance is created lazily by getDatabase(); nothing connects at import time.

class Database { constructor(options?: DatabaseClientOptions | DatabaseClient); connect(): Promise<void>; disconnect(): Promise<void>; ensureConnected(): Promise<void>; ping(): Promise<void>; getStatus(): DatabaseStatus; healthCheck(): Promise<DatabaseClientHealth>; transaction<T>(callback, options?): Promise<T>; getClient(): DatabaseClient; getPrisma(): PrismaClientLike; destroy(): Promise<void>; } function createDatabase(options?): Database; function getDatabase(options?): Database; // shared instance; throws TypeError if options are passed once it exists function connectDatabase(options?): Promise<Database>; function disconnectDatabase(): Promise<void>; function resetDatabase(): Promise<void>; // clears the singleton first, then destroys it
import { connectDatabase, getDatabase, resetDatabase } from "@zudojs/database"; const db = await connectDatabase({ prisma }); // bootstrap const sameDb = getDatabase(); // anywhere else process.on("SIGTERM", () => void resetDatabase());

CONNECTION MANAGER

DatabaseConnectionManager adds lifecycle events, scheduled health checks and reconnect policy on top of a client. Pass an existing client so one Prisma instance is never tracked by two state machines.

interface DatabaseConnectionManagerOptions extends DatabaseClientOptions { readonly client?: DatabaseClient; // wrap an existing client readonly autoConnect?: boolean; // connect() during initialize() (default false) readonly healthCheckIntervalMs?: number; // scheduled checks; disabled when omitted readonly healthCheckTimeoutMs?: number; // default min(interval, 5000) readonly reconnect?: DatabaseReconnectOptions | false; } interface DatabaseReconnectOptions { readonly failureThreshold?: number; // consecutive failures before reconnecting (default 1) readonly maxAttempts?: number; // default 5 readonly baseDelayMs?: number; // default 500, doubles per attempt readonly maxDelayMs?: number; // default 30 000 } class DatabaseConnectionManager { initialize(): Promise<void>; connect(): Promise<void>; disconnect(): Promise<void>; ensureConnected(): Promise<void>; getStatus(): DatabaseStatus; healthCheck(): Promise<DatabaseClientHealth>; getLastHealth(): DatabaseHealth | undefined; // result of the last scheduled check runScheduledHealthCheck(): Promise<void>; // one tick; overlapping ticks are skipped startHealthChecks(): void; stopHealthChecks(): void; on(listener): () => void; off(listener): boolean; removeAllListeners(): void; getClient(): DatabaseClient; destroy(): Promise<void>; }

BASE REPOSITORY

BaseRepository is an abstract class over a Prisma model delegate. Extend it per model.

interface BaseRepositoryOptions { readonly modelName?: string; // used in error messages (default "DatabaseEntity") readonly idField?: string; // primary key field (default "id") readonly softDelete?: boolean | { field?: string }; // default field "deletedAt" readonly cursorSecret?: string; // HMAC secret for paginateCursor cursors readonly delegateKey?: string; // property on a transaction client (default lower-cased modelName) readonly relations?: RelationRegistry; // validates include definitions in findByQuery readonly relationParent?: unknown; // model key in the registry (default modelName) } abstract class BaseRepository<TEntity, TId = string, TCreate = Partial<TEntity>, TUpdate = Partial<TEntity>, TWhere = Record<string, unknown>> { constructor(delegate: RepositoryDelegate<...>, options?: BaseRepositoryOptions); }

Every method accepts DatabaseOperationOptions (signal, timeoutMs, metadata). Failures are mapped by mapRepositoryError: P2002 → 409 ERR_CONFLICT, P2025 → 404 ERR_NOT_FOUND, P2003 → 409, P2034 → retryable, P1xxx → 503 connection.

Example

import { BaseRepository, withTransaction } from "@zudojs/database"; interface User { id: string; email: string; name: string; deletedAt: Date | null } class UserRepository extends BaseRepository<User> { constructor(delegate: ConstructorParameters<typeof BaseRepository<User>>[0]) { super(delegate, { modelName: "User", softDelete: true, cursorSecret: process.env.CURSOR_SECRET }); } findByEmail(email: string) { return this.findOne({ email }); } } const users = new UserRepository(prisma.user); const alice = await users.create({ email: "alice@example.com", name: "Alice" }); await users.softDelete(alice.id); // reads now skip the row await users.withDeleted().findById(alice.id); // still visible here await withTransaction(client, async (tx) => { const txUsers = users.withTransaction(tx); // runs inside the transaction await txUsers.restore(alice.id); await txUsers.update(alice.id, { name: "Alice Doe" }); });

QUERY BUILDER

QueryBuilder accumulates a database-neutral definition (filter, sort, select, include, pagination) and translates it to Prisma arguments. build() returns a deeply frozen snapshot; mutating it cannot affect later builds.

const query = createQueryBuilder<"email" | "role" | "createdAt">() .where("role", "admin") // equals .whereContains("email", "@example.com") // whereOperator, whereNot, whereIn, whereNotIn, whereLessThan, ... .whereNotNull("createdAt") .or(equals("role", "owner"), equals("role", "admin")) // and() / or() / not() groups .orderByDesc("createdAt") // orderBy, orderByAsc, sort([...]) .select("email", "role") .include("profile") // relation names or includeRelation(...) .paginate({ page: 2, limit: 20 }) // page(), limit(), offset() ; const state = query.build(); // QueryBuilderState (frozen) const args = query.toPrismaArgs(); // { where, orderBy, skip, take, select } const admins = await users.findByQuery(query); query.clearFilters().clearSort().clearSelect().clearInclude().clearPagination().reset(); const copy = query.clone();

TRANSACTIONS

interface ManagedTransactionOptions extends TransactionOptions { readonly transactionId?: string; readonly metadata?: Record<string, unknown>; } class TransactionManager { constructor(client: DatabaseClient); execute<T>(callback: (tx, context) => Promise<T>, options?): Promise<T>; run<T>(callback, options?): Promise<{ result: T; context: TransactionContext }>; // context.status === "committed" } function withTransaction<T>(client, callback, options?): Promise<T>; function withTransactionRetry<T>(client, callback, options?: TransactionRetryOptions): Promise<T>; function getTransactionContextFromError(error): TransactionContext | undefined; // status "failed" function isTransactionActive(ctx) / isTransactionCommitted(ctx) / isTransactionFailed(ctx): boolean;

Failures are normalised to DatabaseError and enriched with transactionId, transactionStatus: "failed" and the supplied metadata. withTransactionRetry retries up to retries (default 3) with exponential back-off when isRetryableTransactionError matches (P2034, P2028, P1017, PostgreSQL 40001 / 40P01) or a custom shouldRetry returns true.

Retries re-run the whole callback. Side effects performed outside the transaction client (emails, queues) must be idempotent.
import { withTransactionRetry } from "@zudojs/database"; const order = await withTransactionRetry(client, async (tx, context) => { const stock = await tx.product.update({ where: { id }, data: { stock: { decrement: 1 } } }); return tx.order.create({ data: { productId: id, transactionId: context.transactionId } }); }, { isolationLevel: "Serializable", retries: 5, metadata: { userId } });

UNIT OF WORK

DatabaseUnitOfWork runs a callback in one transaction and tags failures with unitOfWork: true. Rebind repositories with withTransaction(tx) inside the callback; repositories built from the root client run outside the transaction.

import { createUnitOfWork } from "@zudojs/database"; const uow = createUnitOfWork(client); await uow.execute(async (tx) => { await users.withTransaction(tx).update(userId, { balance: 0 }); await ledger.withTransaction(tx).create({ userId, amount: -balance }); }, { timeoutMs: 15_000 });

MIGRATIONS

interface Migration { readonly version: number; // positive integer up to Number.MAX_SAFE_INTEGER (BIGINT column; timestamps like 20260908120000 are fine) readonly name: string; readonly up: (tx: DatabaseTransactionContext) => Promise<void>; readonly down?: (tx: DatabaseTransactionContext) => Promise<void>; } interface MigrationRunnerOptions { readonly tableName?: string; // default "_migrations" readonly lockKey?: string; // default "database:migrations" readonly dialect?: "postgresql"; // "mysql" / "sqlite" throw UnsupportedDialectError readonly transaction?: { timeoutMs?, maxWaitMs?, isolationLevel? }; readonly perItemTransaction?: boolean; // default true: one transaction per migration } class MigrationRunner { status(): Promise<MigrationStatus>; // { currentVersion, latestVersion, pending, applied } migrate() / run(): Promise<MigrationResult>; // { applied, skipped } rollback(): Promise<MigrationRecord | null>; rollback(steps: number): Promise<readonly MigrationRecord[]>; rollbackAll(): Promise<readonly MigrationRecord[]>; ensureMigrationTable(): Promise<void>; getAppliedMigrations(tx?) / getHistory(): Promise<readonly MigrationRecord[]>; }

Every entry point re-reads the applied history inside the advisory lock (pg_advisory_xact_lock with an FNV-1a 64 key), so two runners started together never apply or revert the same migration twice. With perItemTransaction: false the whole batch is one all-or-nothing transaction.

import { createMigrationRunner } from "@zudojs/database"; const runner = createMigrationRunner(client, migrations, { transaction: { timeoutMs: 60_000 } }); const { applied } = await runner.migrate(); const status = await runner.status();

SEEDS

interface Seed { readonly name: string; readonly order?: number; // stable sort; equal orders keep declaration order readonly run: (tx: DatabaseTransactionContext) => Promise<void>; readonly rollback?: (tx: DatabaseTransactionContext) => Promise<void>; } class SeedRunner { // options mirror MigrationRunnerOptions (table "_seeds", lock "database:seeds") status(): Promise<SeedStatus>; run(): Promise<SeedResult>; runOne(name: string): Promise<SeedRecord>; // idempotent rollback(): Promise<SeedRecord | null>; // most recently executed seed rollbackAll(): Promise<readonly SeedRecord[]>; ensureSeedTable(): Promise<void>; getAppliedSeeds(tx?) / getHistory(): Promise<readonly SeedRecord[]>; }

Seed records carry an execution sequence (BIGSERIAL), so rollbacks walk in reverse execution order even when every seed in a batch shares the same applied_at.

HEALTH CHECKS

checkDatabaseHealth(client, { timeoutMs? }) // { status: "healthy" | "degraded" | "unhealthy", healthy, latencyMs, checkedAt, message, error? } checkDatabaseReadiness(client, { timeoutMs? }) // { ready, latencyMs, checkedAt, message } assertDatabaseHealth(client, options?) // throws DatabaseUnhealthyError (503) with the real failure as cause isDatabaseHealthy(client, options?) // boolean getHealthCheckCause(health) // original error of an unhealthy result (non-enumerable)

The default timeout is 5 000 ms (DEFAULT_HEALTH_TIMEOUT_MS); latency above 75% of it reports degraded. Connection failures are reported with a fixed message, so host names from Prisma's messages never reach health output.

TESTING

There is no testing subpath. Because the client depends on Prisma structurally, a stub implementing PrismaClientLike is enough to exercise the lifecycle, runners, locks and repositories without a database. Repositories take any object implementing RepositoryDelegate.

import { DatabaseClient, MigrationRunner, noopDatabaseLogger, type PrismaClientLike } from "@zudojs/database"; const queries: string[] = []; const prisma: PrismaClientLike = { async $connect() {}, async $disconnect() {}, async $transaction(callback) { return callback(prisma as never); }, async $queryRawUnsafe(sql) { queries.push(sql); return []; }, async $executeRawUnsafe(sql) { queries.push(sql); return 1; }, }; const client = new DatabaseClient({ prisma, logger: noopDatabaseLogger }); await new MigrationRunner(client, migrations).migrate(); expect(queries[0]).toContain('CREATE TABLE IF NOT EXISTS "_migrations"');

FULL EXAMPLE

import { PrismaClient } from "@prisma/client"; import { PrismaPg } from "@prisma/adapter-pg"; import { BaseRepository, createConnectionManager, createDatabaseClient, createQueryBuilder, createMigrationRunner, withTransactionRetry, checkDatabaseHealth, } from "@zudojs/database"; const prisma = new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) }); const client = createDatabaseClient({ prisma }); const manager = createConnectionManager({ client, healthCheckIntervalMs: 30_000 }); await manager.connect(); await createMigrationRunner(client, migrations).migrate(); class OrderRepository extends BaseRepository<Order> { constructor(delegate: ConstructorParameters<typeof BaseRepository<Order>>[0]) { super(delegate, { modelName: "Order", softDelete: true }); } } const orders = new OrderRepository(prisma.order); const recent = await orders.findByQuery( createQueryBuilder<"status" | "total" | "createdAt">() .where("status", "completed") .whereGreaterThanOrEqual("total", 50) .orderByDesc("createdAt") .paginate({ page: 1, limit: 10 }), ); await withTransactionRetry(client, async (tx) => { const txOrders = orders.withTransaction(tx); await txOrders.update(recent[0]!.id, { status: "archived" }); }); const health = await checkDatabaseHealth(client); process.on("SIGTERM", () => void manager.destroy());

LIMITATIONS

  • PostgreSQL only. Migration, seed and lock helpers emit PostgreSQL SQL; other dialects throw UnsupportedDialectError.
  • No savepoints or nested transactions; Prisma interactive transactions are used as-is.
  • Connection pooling, SSL and the connection URL are configured on the Prisma driver adapter, not in this package.
  • timeoutMs and signal are client-side only; the database statement is not cancelled server-side.
  • The cache is process-local and not transaction-aware.
