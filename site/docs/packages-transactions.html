@zudojs/transactions

Transaction lifecycle management for the Zudojs framework. Provides a state-machine-driven transaction model, AsyncLocalStorage context propagation, adapter abstraction for database-specific behavior, savepoints, 7 propagation strategies, lifecycle hooks, and a transaction registry.

TRANSACTIONS SAVEPOINTS ROLLBACK STATE MACHINE ASYNC

INSTALLATION

// npm npm install @zudojs/transactions // pnpm pnpm add @zudojs/transactions // yarn yarn add @zudojs/transactions
Peer Dependencies: @zudojs/transactions depends on @zudojs/errors at version 0.1.0.

WHAT IT DOES

@zudojs/transactions provides a complete transaction abstraction for the Zudojs ecosystem:

  • → Transaction state machine with 7 lifecycle states (pending, active, committing, committed, rolling_back, rolled_back, failed)
  • → AsyncLocalStorage context propagation — transactions automatically propagate across async call chains
  • → Adapter abstraction for database-specific transaction behavior (begin, commit, rollback)
  • → Savepoint support for nested transactions without full isolation
  • → 7 propagation strategies: required, requires_new, supports, not_supported, mandatory, never, nested
  • → Lifecycle hooks: beforeBegin, afterBegin, beforeCommit, afterCommit, beforeRollback, afterRollback, onError
  • → Transaction registry for tracking all active transactions
  • → Timeout support with automatic rollback-only marking
  • → Retry configuration with fixed or exponential backoff
  • → 11 error types for every failure mode
  • → 7 lifecycle events for monitoring and observability
Core Principle: Transaction logic is adapter-agnostic. Your business code never calls database drivers directly — it works with the Transaction interface, and the adapter translates to the underlying database.

WHERE IT SITS

APPLICATION LAYER (CQRS, Events, Services)
TRANSACTION LAYER (@zudojs/transactions)
ADAPTER LAYER (Database-specific implementations)
DATABASE (PostgreSQL, MySQL, MongoDB)

Transactions sit between application code and database adapters. Application code calls the Transaction Manager; the manager coordinates with the adapter to execute begin/commit/rollback on the actual database.

TYPES

TransactionState

Lifecycle states a transaction passes through:

State Description
pendingTransaction created but not yet begun on the adapter
activeTransaction is open and can accept operations
committingCommit is in progress
committedTransaction successfully committed (terminal)
rolling_backRollback is in progress
rolled_backTransaction successfully rolled back (terminal)
failedTransaction failed irrecoverably (terminal)

TransactionPropagation

Propagation strategies when a transaction already exists:

Strategy Behavior
requiredJoin existing transaction (default)
requires_newAlways start a new transaction, suspending the existing one
supportsJoin existing if present, otherwise run without transaction
not_supportedSuspend existing transaction and run without one
mandatoryJoin existing transaction; throw if none exists
neverRun without transaction; throw if one exists
nestedStart a nested transaction using savepoints

TransactionIsolationLevel

type TransactionIsolationLevel = | "read_uncommitted" | "read_committed" | "repeatable_read" | "serializable";

TRANSACTION

createTransaction

Creates a new Transaction instance with internal state machine, callbacks, and metadata:

function createTransaction( options?: TransactionOptions, parentId?: string, ): Transaction

Internal Methods

The returned Transaction also exposes internal methods (prefixed with _) for the manager and adapter to use:

/** Set the adapter handle on the transaction. */ _setHandle(handle: unknown): void; /** Get the adapter handle from the transaction. */ _getHandle(): unknown; /** Transition the state machine. */ _transition(to: TransactionState): void; /** Mark the transaction as timed out. */ _markTimedOut(): void; /** Get all registered afterCommit callbacks. */ _getAfterCommitCallbacks(): Array<() => Promise<void>>; /** Get all registered afterRollback callbacks. */ _getAfterRollbackCallbacks(): Array<() => Promise<void>>;

Example

import { createTransaction } from "@zudojs/transactions"; const txn = createTransaction({ name: "create-order", timeout: 30000, metadata: { userId: "user_123" }, }); console.log(txn.id); // "txn_a1b2c3d4..." console.log(txn.state); // "pending" console.log(txn.startedAt); // Date.now()

ADAPTER

Adapter abstraction for database-specific transaction behavior.

createInMemoryAdapter

function createInMemoryAdapter(): TransactionAdapter

Creates an in-memory adapter for testing. Supports basic begin/commit/rollback with no savepoints.

createAdapter

function createAdapter( implementation: TransactionAdapter, capabilities: TransactionAdapterCapabilities, ): TransactionAdapter

Wraps an adapter with explicit capabilities. The capabilities are frozen.

Example: Custom Adapter

import { createAdapter } from "@zudojs/transactions"; import type { TransactionAdapter } from "@zudojs/transactions"; const pgAdapter: TransactionAdapter = createAdapter( { async begin(options) { // Start a PostgreSQL transaction return pgClient.query("BEGIN"); }, async commit(handle) { await pgClient.query("COMMIT"); }, async rollback(handle) { await pgClient.query("ROLLBACK"); }, }, { savepoints: true, nestedTransactions: false, isolationLevels: ["read_committed", "repeatable_read", "serializable"], readOnlyTransactions: true, timeouts: true, }, );

HOOKS

Lifecycle hooks and composition for transaction events.

mergeHooks

function mergeHooks( ...hookSets: readonly TransactionHooks[] ): TransactionHooks

Merges multiple hook sets into one. Later hooks run after earlier ones for each lifecycle event.

Example

import { mergeHooks } from "@zudojs/transactions"; const loggingHooks: TransactionHooks = { async beforeBegin({ transaction }) { console.log(`Starting transaction ${transaction.id}`); }, async afterCommit({ transaction }) { console.log(`Committed ${transaction.id}`); }, }; const auditHooks: TransactionHooks = { async afterBegin({ transaction }) { await auditLog("transaction.begin", transaction.id); }, async onError({ transaction, error }) { await auditLog("transaction.error", transaction.id, error); }, }; // Merge: logging runs first, then audit const hooks = mergeHooks(loggingHooks, auditHooks);

MANAGER

The Transaction Manager coordinates begin, commit, rollback, context, and propagation.

createTransactionManager

function createTransactionManager(options: TransactionManagerOptions): { begin(opts?: TransactionOptions): Promise<Transaction>; run<T>( callback: (transaction: Transaction) => Promise<T>, opts?: TransactionOptions, ): Promise<T>; commit(transaction: Transaction): Promise<void>; rollback(transaction: Transaction, reason?: unknown): Promise<void>; getCurrent(): Transaction | undefined; }

Methods

Method Purpose
begin(opts?)Start a new transaction. Handles propagation if one exists. Returns a Transaction.
run(callback, opts?)Begin, run callback, auto-commit on success, auto-rollback on error. Returns the callback result.
commit(txn)Commit a transaction with adapter coordination and hooks.
rollback(txn, reason?)Rollback a transaction with adapter coordination and hooks.
getCurrent()Get the current active transaction from the context (if any).

Example

import { createTransactionManager, createInMemoryAdapter } from "@zudojs/transactions"; const adapter = createInMemoryAdapter(); const manager = createTransactionManager({ adapter }); // Using run() — auto commit/rollback const result = await manager.run(async (txn) => { // Do work inside the transaction return { orderId: "ord_123" }; }); // Manual begin/commit/rollback const txn = await manager.begin({ name: "manual" }); try { // ... do work await manager.commit(txn); } catch (error) { await manager.rollback(txn, error); }

All error types extend TransactionError, which extends BaseError from @zudojs/errors.

Error ErrorCode When Thrown

TransactionCommitErrorDATABASE_TRANSACTIONCommit failed
TransactionRollbackErrorDATABASE_TRANSACTIONRollback failed

TransactionIsolationErrorVALIDATION_FAILEDIsolation level not supported by adapter

TransactionUnexpectedErrorCONFLICTA transaction exists but none was expected
TransactionCapabilityErrorNOT_IMPLEMENTEDAdapter does not support requested capability

Error Handling Pattern

import { TransactionError, TransactionCommitError, TransactionTimeoutError, } from "@zudojs/transactions"; try { await manager.run(async (txn) => { /* ... */ }); } catch (error) { if (error instanceof TransactionTimeoutError) { console.error("Transaction timed out", error.metadata); } else if (error instanceof TransactionCommitError) { console.error("Commit failed", error.metadata); } else if (error instanceof TransactionError) { console.error("Transaction error", error.code); } }

FULL INTEGRATION EXAMPLE

Complete working example: create adapter, create manager, begin/run/commit/rollback, use hooks, handle propagation, and use savepoints.

import { createTransactionManager, createInMemoryAdapter, createTransactionRegistry, createTransactionContext, mergeHooks, isTerminalState, summarizeTransaction, } from "@zudojs/transactions"; import type { TransactionHooks, TransactionAdapter } from "@zudojs/transactions"; // 1. Create a custom adapter with savepoint support const adapter: TransactionAdapter = { capabilities: { savepoints: true, nestedTransactions: true, isolationLevels: ["read_committed", "serializable"], readOnlyTransactions: true, timeouts: true, }, async begin(options) { console.log(`BEGIN ${options?.name ?? "unnamed"}`); return { id: Date.now().toString() }; }, async commit(handle) { console.log("COMMIT"); }, async rollback(handle, reason) { console.log(`ROLLBACK: ${reason}`); }, async createSavepoint(handle, name) { console.log(`SAVEPOINT ${name}`); }, async rollbackToSavepoint(handle, name) { console.log(`ROLLBACK TO SAVEPOINT ${name}`); }, async releaseSavepoint(handle, name) { console.log(`RELEASE SAVEPOINT ${name}`); }, }; // 2. Create hooks const loggingHooks: TransactionHooks = { async beforeBegin({ transaction }) { console.log(`[${transaction.id}] Starting`); }, async afterCommit({ transaction }) { console.log(`[${transaction.id}] Committed`); }, async afterRollback({ transaction }) { console.log(`[${transaction.id}] Rolled back`); }, async onError({ transaction, error }) { console.error(`[${transaction.id}] Error:`, error); }, }; // 3. Create context and registry const context = createTransactionContext(); const registry = createTransactionRegistry(); // 4. Create the manager const manager = createTransactionManager({ adapter, context, hooks: loggingHooks, }); // 5. Use run() for auto commit/rollback const order = await manager.run(async (txn) => { registry.register(txn); // Inner transaction with nested propagation const nested = await manager.begin({ propagation: "nested", name: "nested-check", }); console.log(summarizeTransaction(nested)); // ... do nested work await manager.commit(nested); registry.unregister(txn.id); return { orderId: "ord_456" }; }, { name: "create-order", timeout: 30000, isolation: "read_committed", }); // 6. Check transaction status const active = registry.getActive(); console.log("Active transactions:", active.length); // 7. Error handling with manual control const txn = await manager.begin({ propagation: "required", name: "manual-tx", }); try { // ... risky operations if (isTerminalState(txn.state)) return; await manager.commit(txn); } catch (error) { await manager.rollback(txn, error); }
