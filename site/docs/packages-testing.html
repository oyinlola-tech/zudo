@zudojs/testing

Testing utilities for the Zudojs ecosystem. Mock functions, spies, stubs, test clock, cleanup management, HTTP builders, assertion helpers, fixture factories, and full test context — everything you need for comprehensive testing.

TESTING MOCKS FIXTURES ASSERTIONS VITEST

INSTALLATION

// npm npm install @zudojs/testing // pnpm pnpm add @zudojs/testing // yarn yarn add @zudojs/testing
Peer Dependencies: @zudojs/testing depends on 14 packages: @zudojs/config, @zudojs/constants, @zudojs/container, @zudojs/errors, @zudojs/events, @zudojs/http, @zudojs/logger, @zudojs/messaging, @zudojs/middleware, @zudojs/queue, @zudojs/security, @zudojs/serialization, @zudojs/storage, @zudojs/types, @zudojs/validation. All at version 0.1.0.

WHAT IT DOES

@zudojs/testing provides a complete testing toolkit for Zudojs applications:

  • → Mock functions with call tracking and return value control
  • → Spy functions for wrapping real implementations with call recording
  • → Stub and stub class generators for replacing implementations
  • → Test clock for time control — advance, set, and reset simulated time
  • → Cleanup manager for resource disposal tracking
  • → Test context combining clock, cleanup, log/event/message recorders
  • → Test container with dependency overrides for DI testing
  • → Spy logger with call filtering by method, message, or metadata
  • → Test config manager for configuration testing
  • → Test event bus with published event recording
  • → Test message bus with dispatched message recording
  • → Test queue with job recording
  • → HTTP request/response builders with fluent API
  • → Assertion helpers for HTTP, errors, events, messages, serialization
  • → In-memory test storage for isolated storage testing
  • → Fixture factories for events and messages
  • → Test application combining container, logger, clock, cleanup
Core Principle: Tests should be fast, isolated, and deterministic. @zudojs/testing gives you tools that make every part of your Zudojs application testable without external dependencies.

CLEANUP MANAGER

Tracks resources that need disposal after tests. Registers cleanup functions and disposes them in reverse order.

Interface: CleanupManager

interface CleanupManager { readonly disposed: boolean; readonly count: number; register(entry: CleanupEntry): void; dispose(): Promise<void>; }

Type: CleanupEntry

type CleanupEntry = { readonly name: string; readonly fn: () => Promise<void> | void; };

Type: CleanupManagerOptions

type CleanupManagerOptions = { readonly onError?: (error: Error, name: string) => void; };

Function: createCleanupManager

function createCleanupManager( options?: CleanupManagerOptions ): CleanupManager;
Best Practice: Always call cleanup.dispose() in your test teardown. The cleanup manager runs entries in reverse registration order.

TEST CLOCK

Deterministic time control for tests. Advance, set, and reset simulated time without waiting for real time to pass.

Interface: TestClock

interface TestClock { readonly now: Date; readonly timestamp: number; set(date: Date | number): void; advance(ms: number): void; add(duration: Partial<Duration>): void; reset(): void; }

Function: createTestClock

function createTestClock( initialTime?: Date | number ): TestClock;

Example

import { createTestClock } from "@zudojs/testing"; const clock = createTestClock(new Date("2026-01-01T00:00:00Z")); expect(clock.timestamp).toBe(1735689600000); clock.advance(60000); // +1 minute expect(clock.now.toISOString()).toBe("2026-01-01T00:01:00.000Z"); clock.add({ hours: 2 }); // +2 hours expect(clock.now.getHours()).toBe(2); clock.reset(); // Back to original time

TEST STORAGE

In-memory key-value store for isolated storage testing. No external dependencies required.

Class: InMemoryTestStorage

class InMemoryTestStorage { constructor(initialData?: Record<string, unknown>); readonly size: number; get<T>(key: string): T | undefined; set(key: string, value: unknown): void; delete(key: string): boolean; has(key: string): boolean; clear(): void; keys(): string[]; }

Example

import { InMemoryTestStorage } from "@zudojs/testing"; const store = new InMemoryTestStorage({ "users:1": { id: "1", name: "Alice" }, }); store.set("users:2", { id: "2", name: "Bob" }); expect(store.size).toBe(2); expect(store.has("users:1")).toBe(true); const user = store.get("users:1"); expect(user).toEqual({ id: "1", name: "Alice" }); store.delete("users:2"); expect(store.keys()).toEqual(["users:1"]);
