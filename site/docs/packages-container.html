@zudojs/container

Token-based dependency injection container with scoped lifecycles and module awareness.

DEPENDENCY INJECTION CONTAINER TOKENS

OVERVIEW

@zudojs/container provides the dependency injection backbone for the Zudo framework. Every module, service, and adapter registers through the container, and every dependency is resolved through tokens — not manual wiring.

INSTALLATION

// npm npm install @zudojs/container // pnpm pnpm add @zudojs/container // Import everything import { createContainer, createToken } from "@zudojs/container"; // Import specific submodules import { ContainerScope } from "@zudojs/container/scope";

QUICK START

import { createContainer, createToken } from "@zudojs/container"; // 1. Define tokens const LoggerToken = createToken<Logger>("Logger"); const DatabaseToken = createToken<Database>("Database"); // 2. Create container and register services const container = createContainer(); container.register(LoggerToken, classProvider(ConsoleLogger)); container.register(DatabaseToken, factoryProvider( (logger) => new PostgresDatabase(logger), [LoggerToken] )); // 3. Resolve dependencies const db = container.resolve(DatabaseToken); // → creates ConsoleLogger, injects it into PostgresDatabase // 4. Dispose when done await container.dispose();
Tip: Use createStartedContainer() if you want the container ready immediately without calling start().

TOKEN SYSTEM

Tokens are unique identifiers for registered services. Three token kinds are supported: classes, symbols, and strings.

Token Types

// Token = Constructor | symbol | string type Token<T = unknown> = Constructor<T> | symbol | string; // InjectionToken wraps a Token with metadata interface InjectionToken<T> { readonly token: Token<T>; readonly description?: string; }

Creating Tokens

import { createToken, createGlobalToken } from "@zudojs/container"; // Scoped token — unique Symbol per call (recommended) const LoggerToken = createToken<Logger>("Logger"); // Global token — Symbol.for() across modules const ConfigToken = createGlobalToken<Config>("app:config"); // Use class constructor directly as a token const UserServiceToken = UserService; // Constructor doubles as token

Token Utilities

isConstructorToken(t)booleanType guard — typeof t === "function"

SCOPES (LIFETIME MANAGEMENT)<

Every registration has a scope that controls how many instances are created.

SINGLETON

One instance per container. Created on first resolve, then cached forever.

SCOPED

One instance per scope. Cached within a ContainerScopeContext. Shared across resolves in the same scope.

TRANSIENT

New instance every resolve. Never cached. Default scope.

import { ContainerScope } from "@zudojs/container"; ContainerScope.SINGLETON // "singleton" — one per container ContainerScope.SCOPED // "scoped" — one per scope ContainerScope.TRANSIENT // "transient" — new every time (default)

Scope Utilities

import { isSingletonScope, isScopedScope, isTransientScope, isCachedScope, describeContainerScope } from "@zudojs/constants"; isCachedScope(ContainerScope.SINGLETON) // true isCachedScope(ContainerScope.SCOPED) // true isCachedScope(ContainerScope.TRANSIENT) // false describeContainerScope(ContainerScope.SCOPED); // → "One instance per scope. Cached within a scope context."

PROVIDERS

Providers define how a token is satisfied. Four provider types are available.

ClassProvider

Instantiates a class with new Constructor() (no arguments).

import { classProvider, provideClass } from "@zudojs/container"; // Standalone provider const provider = classProvider(ConsoleLogger); // → { useClass: ConsoleLogger } (frozen) // Registration form (with token) const reg = provideClass(LoggerToken, ConsoleLogger); // → { provide: LoggerToken, useClass: ConsoleLogger } (frozen)

ValueProvider

Returns a pre-built value. Always resolved as SINGLETON scope.

import { valueProvider, provideValue } from "@zudojs/container"; const provider = valueProvider({ host: "localhost", port: 5432 }); // → { useValue: { host, port } } (frozen) const reg = provideValue(ConfigToken, { debug: true }); // → { provide: ConfigToken, useValue: { debug: true } } (frozen)

FactoryProvider

Calls a factory function with resolved dependencies as arguments.

import { factoryProvider, provideFactory } from "@zudojs/container"; const provider = factoryProvider( (logger, config) => new DatabaseService(logger, config), [LoggerToken, ConfigToken] ); // → { useFactory: fn, inject: [LoggerToken, ConfigToken] } (frozen) // Registration form const reg = provideFactory( DatabaseToken, (logger, config) => new DatabaseService(logger, config), [LoggerToken, ConfigToken] );

ExistingProvider

Aliases one token to another. The resolved value is the same instance.

import { existingProvider, provideExisting } from "@zudojs/container"; // Alias: LogToken resolves to the same instance as LoggerToken const reg = provideExisting(LogToken, LoggerToken); // → { provide: LogToken, useExisting: LoggerToken } (frozen)

Provider Type Guards

import { isClassProvider, isFactoryProvider, isValueProvider, isExistingProvider, isTokenProvider, hasInjectedDependencies } from "@zudojs/container"; isClassProvider({ useClass: MyClass }) // true isFactoryProvider({ useFactory: fn }) // true isValueProvider({ useValue: val }) // true isExistingProvider({ useExisting: tok }) // true hasInjectedDependencies({ useFactory: fn, inject: [] }) // true

CONTAINER API

The main Container class ties everything together.

Creating a Container

import { createContainer, createStartedContainer } from "@zudojs/container"; // Deferred start — must call .start() before resolving const c1 = createContainer(); c1.register(Token, provider); c1.start(); const val = c1.resolve(Token); // Immediate start — ready to resolve immediately const c2 = createStartedContainer(); const val2 = c2.resolve(Token);

REGISTRATION DETAILS

Each registration stores the token, provider, scope, metadata, and creation timestamp.

Registration Object

interface ContainerRegistration<T> { readonly token: Token<T>; readonly provider: ContainerProvider<T>; readonly scope: ContainerScope; readonly metadata: RegistrationMetadata; readonly initialized: boolean; readonly createdAt: Date; } interface RegistrationMetadata { readonly name?: string; readonly description?: string; readonly module?: string; readonly exported?: boolean; readonly metadata?: Readonly<Record<string, unknown>>; }

Registration Options

container.register(Token, provider, { scope: ContainerScope.SINGLETON, name: "AuthService", description: "Handles JWT authentication", module: "auth", exported: true, metadata: { version: "1.0" } });

Registration Utilities

import { describeRegistration, isSingletonRegistration, isScopedRegistration, shouldCacheRegistration, withRegistrationScope, withRegistrationMetadata } from "@zudojs/container"; describeRegistration(reg) // "AuthService [singleton]" isSingletonRegistration(reg) // true shouldCacheRegistration(reg) // true (singletons and scoped are cached) // Create a new registration with a different scope const scoped = withRegistrationScope(reg, ContainerScope.SCOPED);

REGISTRY

The ContainerRegistry stores all registrations with change event subscriptions.

Registry Operations

const reg = container.registry; reg.register(Token, provider, opts) // Register new token reg.replace(Token, provider, opts) // Replace existing reg.get(Token) // → registration | undefined reg.getOrThrow(Token) // → registration | throws reg.has(Token) // boolean reg.remove(Token) // boolean reg.size // number // Query reg.getAll() // all registrations reg.getTokens() // all tokens reg.getByModule("auth") // filter by module name reg.getByScope(ContainerScope.SINGLETON) // filter by scope reg.find(predicate) // custom filter

Change Events

const unsub = reg.subscribe((event) => { console.log(event.operation); // "register" | "replace" | "remove" | "clear" console.log(event.token); console.log(event.registration); console.log(event.timestamp); }); // Unsubscribe unsub();

SCOPED RESOLUTION

Create isolated scopes for request-level or lifecycle-level instance management.

// Create a scope from the container const scope = container.createScope({ name: "http-request-42", metadata: { userId: "usr_123" } }); // Resolve within scope — SCOPED instances are shared, TRANSIENT are new const auth = scope.resolve(AuthServiceToken); const auth2 = scope.resolve(AuthServiceToken); // auth === auth2 (same scoped instance) // Dispose scope — disposes all tracked scoped instances await scope.dispose(); // Scope can create nested scopes const nested = scope.createScope({ name: "nested" });
Note: Scopes are disabled by default. Pass allowScopes: true in container options to enable them.

LIFECYCLE MANAGEMENT

The container automatically tracks instances that implement Disposable or AsyncDisposable and disposes them in reverse order.

Disposable Interface

// Your service implements one of these: interface Disposable { dispose(): void; } interface AsyncDisposable { [Symbol.asyncDispose]?: () => Promise<void>; } // Example: a service with cleanup class DatabaseConnection implements AsyncDisposable { private pool = createPool(); [Symbol.asyncDispose] = async () => { await this.pool.drain(); }; }

Ownership Levels

OwnerScopeDisposal
CONTAINERContainer-level instancesDisposed on container.dispose()
SCOPEScope-level instancesDisposed on scope.dispose()

Fail-Fast Mode

// Default: collect all errors, throw ContainerDisposalError const c1 = createContainer({ lifecycle: { failFast: false } }); // Fail-fast: stop on first disposal error const c2 = createContainer({ lifecycle: { failFast: true } });

CONFIGURATION

Container behavior is fully configurable.

ContainerOptions

import { createContainer, ContainerLogLevel } from "@zudojs/container"; const container = createContainer({ name: "my-app", logLevel: ContainerLogLevel.INFO, autoDispose: true, // auto-dispose on container.dispose() allowScopes: true, // enable scope creation freezeRegistrations: false,// allow mutation after start registry: { allowDuplicates: false, // throw on duplicate registrations }, resolution: { autoRegisterClasses: true, // auto-register unregistered constructors detectCircularDependencies: true, maxResolutionDepth: 100, }, lifecycle: { failFast: false, }, metadata: { version: "1.0", environment: "production", }, });

CIRCULAR DEPENDENCY DETECTION

The container tracks the resolution path and detects cycles automatically.

// Circular dependency example const TokenA = createToken<ServiceA>("A"); const TokenB = createToken<ServiceB>("B"); container.register(TokenA, factoryProvider( (b) => new ServiceA(b), [TokenB] )); container.register(TokenB, factoryProvider( (a) => new ServiceB(a), [TokenA] )); container.resolve(TokenA); // throws CircularDependencyError: "Circular dependency detected: TokenA → TokenB → TokenA"
Warning: Circular dependency detection adds overhead. Disable it in production with detectCircularDependencies: false if you're sure your dependency graph is acyclic.

AUTO-REGISTRATION

When autoRegisterClasses: true, unregistered class tokens are automatically registered as TRANSIENT.

class UserService { getUser(id: string) { /* ... */ } } // No registration needed const service = container.resolve(UserService); // → new UserService() (auto-registered as TRANSIENT) // Disable with autoRegisterClasses: false

ERRORS

All errors extend BaseError from @zudojs/errors.

ErrorWhen Thrown
CircularDependencyErrorResolution path contains a cycle
DuplicateRegistrationErrorRegistering a token that already exists (and allowDuplicates is false)
RegistrationNotFoundErrorResolving/replacing a token that isn't registered
ProviderResolutionErrorProvider factory or constructor throws during creation
ContainerLifecycleErrorContainer is disposed or in an invalid state
ContainerDisposalErrorOne or more instances failed to dispose (aggregates errors)

TESTING

Containers are designed for test isolation. Create a fresh container per test.

import { describe, it, expect, beforeEach } from "vitest"; import { createContainer, createToken, valueProvider } from "@zudojs/container"; const ConfigToken = createToken<Config>("Config"); const LoggerToken = createToken<Logger>("Logger"); describe("AuthService", () => { let container: Container; beforeEach(() => { container = createStartedContainer(); // Register test doubles container.register(ConfigToken, valueProvider({ env: "test" })); container.register(LoggerToken, classProvider(NullLogger)); }); it("should resolve dependencies", () => { const config = container.resolve(ConfigToken); expect(config.env).toBe("test"); }); it("should isolate scopes per test", () => { const scope = container.createScope(); const svc = scope.resolve(ServiceToken); expect(svc).toBeDefined(); await scope.dispose(); }); afterEach(async () => { await container.dispose(); }); });

POTENTIAL IMPROVEMENTS

  • Factory injection metadata: Auto-infer factory dependencies from function parameter types via TypeScript reflection
  • Lazy resolution: Add LazyToken that returns a proxy resolving on first access
  • Module graph visualization: Export dependency graph as DOT/JSON for debugging
  • Health checks: Add container.healthCheck() that resolves all tokens and reports failures
  • Hot reload: Support replacing registrations without full disposal in development mode
