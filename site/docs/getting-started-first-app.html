Your First App

Scaffold a Zudo project with the CLI and build your first module.

SCAFFOLD CLI FIRST APP

Step 1: Project Setup

Create a new directory and initialize the project:

# Create and enter the project directory mkdir zudo-hello && cd zudo-hello # Initialize package.json npm init -y # Install Zudo core packages npm install @zudojs/core @zudojs/config @zudojs/logger @zudojs/errors # Install TypeScript as a dev dependency npm install -D typescript @types/node # Create tsconfig.json npx tsc --init --target ES2022 --module NodeNext --moduleResolution NodeNext --outDir dist --rootDir src --strict --esModuleInterop

TIP

Zudo requires Node.js ≥ 24 and TypeScript ≥ 7.0. Check your versions with node --version and npx tsc --version.

Your project structure should now look like this:

zudo-hello/
├── node_modules/
├── package.json
└── tsconfig.json

Step 2: Create Entry Point

Create the main application file at src/index.ts:

import { createContainer } from "@zudojs/core"; import { createLogger } from "@zudojs/logger"; // Create a logger instance const logger = createLogger({ level: "info", service: "hello-world", }); // Create the DI container const container = createContainer(); // Register the logger as a singleton container.register("logger", () => logger, { singleton: true }); // Define a simple service function greet(name: string): string { return `Hello, ${name}! Welcome to Zudo.`; } // Main function async function main() { logger.info("Starting Zudo application..."); // Resolve the logger from the container const log = container.resolve("logger"); // Use the greet function const message = greet("World"); log.info(message); // Log application readiness log.info("Application is ready!"); } // Run the application main().catch((err) => { console.error("Fatal error:", err); process.exit(1); });

WHAT THIS DOES

  • • Creates a createLogger instance for structured logging
  • • Creates a createContainer for dependency injection
  • • Registers the logger as a singleton service
  • • Defines a simple greet function
  • • Runs the app, resolving dependencies from the container

Step 3: Configuration

Create a configuration file at zudo.config.ts in the project root:

import { defineConfig } from "@zudojs/config"; export default defineConfig({ app: { name: "zudo-hello", version: "1.0.0", }, server: { port: 3000, host: "localhost", }, logging: { level: process.env.NODE_ENV === "production" ? "warn" : "info", }, });

WARNING

Never commit sensitive values (API keys, passwords, secrets) to your configuration file. Use environment variables for all sensitive configuration.

Your project structure now looks like:

zudo-hello/
├── node_modules/
├── src/
│   └── index.ts
├── package.json
├── tsconfig.json
└── zudo.config.ts

Step 4: Run the App

Compile and run the application:

# Compile TypeScript to JavaScript npx tsc # Run the compiled application node dist/index.js

You should see the following output:

[INFO] [hello-world] Starting Zudo application...
[INFO] [hello-world] Hello, World! Welcome to Zudo.
[INFO] [hello-world] Application is ready!

DEVELOPMENT MODE

For faster iteration during development, use npx tsx src/index.ts to run TypeScript directly without a compile step. Install tsx with npm install -D tsx.

Add these scripts to your package.json:

{ "scripts": { "build": "tsc", "start": "node dist/index.js", "dev": "tsx src/index.ts" } }

Now you can use:

# Development mode (no compile step) npm run dev # Production mode npm run build && npm start

What You Built

In just a few minutes, you've created a Zudo application with:

DI Container

Token-based dependency injection for managing application services and lifetimes.

Structured Logging

Contextual logging with levels, services, and structured output.

Layered Configuration

Config file + environment variables with priority ordering and validation.

TypeScript First

Full type safety with strict mode, typed configurations, and compile-time checks.
