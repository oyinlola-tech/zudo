@zudojs/runtime

Application runtime orchestrator for the Zudojs framework. Manages the complete lifecycle from creation through shutdown with deterministic dependency ordering, rollback, signal handling, readiness tracking, and health checks.

RUNTIME LIFECYCLE STARTUP SHUTDOWN ORCHESTRATION

INSTALLATION

// npm npm install @zudojs/runtime // pnpm pnpm add @zudojs/runtime // yarn yarn add @zudojs/runtime
Peer Dependencies: @zudojs/runtime depends on @zudojs/errors, @zudojs/constants, @zudojs/container, @zudojs/config, @zudojs/logger, @zudojs/events, and @zudojs/core. All at version 0.1.0.

WHAT IT DOES

@zudojs/runtime is the orchestrator that manages the complete application lifecycle. It ensures your application starts and stops correctly, in the right order, with full observability:

  • → Application lifecycle orchestration — manages the full state machine from creation through shutdown
  • → Dependency-ordered startup/shutdown — topological sort ensures modules start in correct order
  • → Rollback on failure — if startup fails, already-started modules are shut down in reverse order
  • → Process signal handling — catches SIGINT, SIGTERM, uncaughtException, unhandledRejection
  • → Readiness tracking — register checks that determine when the runtime is ready for traffic
  • → Health checks — track runtime health state (healthy, degraded, unhealthy)
  • → 19 event types — full lifecycle events emitted through the EventBus
  • → Multi-runtime registry — register, manage, and query multiple runtime instances
  • → Timeout protection — configurable startup and shutdown timeouts prevent hangs
  • → Test utilities — createTestRuntime, createMockModule, withTestRuntime for easy testing
Core Principle: The runtime is the single entry point for application lifecycle. All module startup, shutdown, and error handling flows through the runtime.

RUNTIME INTERFACE

Interface: Runtime

The primary API for application lifecycle management:

interface Runtime { /** Current runtime state. */ readonly state: RuntimeState; /** Current runtime status snapshot. */ readonly status: RuntimeStatus; /** Runtime context with logger, container, eventBus. */ readonly context: RuntimeContext; /** Whether the runtime is ready for traffic. */ readonly ready: boolean; /** Starts the runtime. */ start(): Promise<void>; /** Stops the runtime gracefully. */ stop(): Promise<void>; }

RuntimeDependencies

interface RuntimeDependencies { /** Map of module ID to Module instances. */ readonly modules: ReadonlyMap<string, Module>; /** Logger instance. */ readonly logger: Logger; /** DI container. */ readonly container: Container; /** Event bus for lifecycle events. */ readonly eventBus: EventBus; }

DefaultRuntime Class

The standard runtime implementation. Use createRuntime() to instantiate:

import { DefaultRuntime, createRuntime } from "@zudojs/runtime"; // Factory function (recommended) const runtime = createRuntime(dependencies, options); // Direct instantiation const runtime = new DefaultRuntime(dependencies, options);

STATE MACHINE

The runtime follows a strict state machine. Invalid transitions throw RuntimeStateError.

RuntimeState

type RuntimeState = | "created" // Initial state, runtime instantiated but not started | "initializing" // Running initialization hooks on modules | "initialized" // All modules initialized successfully | "starting" // Running start hooks on modules | "running" // All modules started, runtime is ready | "stopping" // Running shutdown hooks on modules | "stopped" // All modules stopped, runtime terminated | "failed"; // An error occurred during lifecycle

RuntimeFailureState

type RuntimeFailureState = | "initialization_failed" | "startup_failed" | "shutdown_failed";

State Transitions

From State Allowed Transitions
createdinitializing, stopped
initializinginitialized, failed
initializedstarting, stopping
startingrunning, failed
runningstopping
stoppingstopped, failed
stoppednone (terminal)
failednone (terminal)

Helper Functions

// Check if a transition is valid canTransition("created", "initializing"); // true canTransition("stopped", "running"); // false // Assert a transition (throws RuntimeStateError) assertTransition("created", "initializing"); // Check terminal states isTerminalState("stopped"); // true isTerminalState("running"); // false // Convenience checks canStart("created"); // true canStop("running"); // true isRunning("running"); // true hasFailed("failed"); // true

RuntimeStatus

interface RuntimeStatus { readonly state: RuntimeState; readonly ready: boolean; readonly running: boolean; readonly startedAt?: Date; readonly stoppedAt?: Date; readonly failedAt?: Date; readonly error?: RuntimeError; } // Create a status snapshot from a state const status = createStatus("running");

RuntimeStateTransition

interface RuntimeStateTransition { readonly from: RuntimeState; readonly to: RuntimeState; readonly timestamp: Date; readonly reason?: string; }

DEPENDENCY GRAPH

The dependency graph performs topological sorting of modules to determine startup order. It detects circular dependencies and identifies modules that can run in parallel.

Key Types

interface DependencyNode { readonly moduleId: string; readonly dependencies: readonly string[]; readonly dependents: readonly string[]; readonly depth: number; } interface DependencyGraph { readonly nodes: ReadonlyMap<string, DependencyNode>; readonly ordered: readonly string[]; readonly hasCircularDependency: boolean; readonly circularDependencies: readonly (readonly string[])[]; } interface DependencyResolutionResult { readonly order: readonly string[]; readonly parallelGroups: readonly (readonly string[])[]; readonly hasCircularDependency: boolean; readonly circularDependencies: readonly (readonly string[])[]; } interface ParallelModuleGroup { readonly modules: readonly string[]; readonly depth: number; }

Functions

// Build a dependency graph from modules const graph = buildDependencyGraph(modules); // Resolve execution order const result = resolveDependencies(modules); // Get modules that can run in parallel const groups = getParallelGroups(modules); // Validate for circular dependencies const valid = validateDependencies(modules);

MODULE LIFECYCLE

LifecyclePhase

type LifecyclePhase = "initialize" | "start" | "stop" | "destroy";

LifecycleManager

The LifecycleManager orchestrates module lifecycle hooks in dependency order:

class LifecycleManager { /** Initializes all modules in dependency order. */ async initialize(): Promise<LifecycleResult>; /** Starts all initialized modules. */ async start(): Promise<LifecycleResult>; /** Stops all running modules in reverse order. */ async stop(): Promise<LifecycleResult>; /** Destroys all modules. */ async destroy(): Promise<LifecycleResult>; /** Rolls back started modules on failure. */ async rollback(): Promise<void>; }

interface LifecycleResult { readonly phase: LifecyclePhase; readonly succeeded: readonly string[]; readonly failed: readonly LifecycleFailure[]; readonly durationMs: number; } interface LifecycleFailure { readonly moduleId: string; readonly phase: LifecyclePhase; readonly error: Error; readonly durationMs: number; }

LifecycleContext

interface LifecycleContext { readonly runtimeId: string; readonly environment: string; readonly phase: LifecyclePhase; readonly moduleId: string; readonly container: Container; readonly logger: Logger; }

ManagedModule

interface ManagedModule { readonly module: Module; readonly depth: number; readonly dependencies: readonly string[]; }

STARTUP & SHUTDOWN

executeStartup()

Runs the full startup sequence: initialize modules, then start them, in dependency order.

async function executeStartup( lifecycle: LifecycleManager, runtimeId: string, eventBus: EventBus, logger: Logger, emitEvents: boolean, ): Promise<void>;

rollbackStartup()

If startup fails, rolls back all modules that successfully started. Runs in reverse order.

async function rollbackStartup( lifecycle: LifecycleManager, logger: Logger, ): Promise<void>;

executeShutdown()

Gracefully shuts down all modules in reverse dependency order with timeout protection.

async function executeShutdown( lifecycle: LifecycleManager, runtimeId: string, eventBus: EventBus, logger: Logger, timeout: number, emitEvents: boolean, ): Promise<void>;

READINESS

Readiness tracking determines when the runtime is ready to accept traffic. Register named checks and the tracker evaluates them automatically.

ReadinessState

ERROR HIERARCHY

All error types are defined in @zudojs/errors and re-exported by this package.

Error When Thrown
RuntimeStateErrorInvalid state transition attempted
RuntimeStartErrorRuntime startup fails (includes phase and failedModuleId)
RuntimeStopErrorRuntime shutdown fails
RuntimeInitializationErrorModule initialization fails
RuntimeTimeoutErrorOperation exceeds configured timeout
RuntimeRollbackErrorRollback after failure also fails
RuntimeCircularDependencyErrorCircular dependency detected between modules
RuntimeDependencyErrorModule depends on unregistered module
RuntimeSignalErrorUnexpected process signal received
toRuntimeError()Converts unknown error to RuntimeError

Error Handling Pattern

import { RuntimeStartError, RuntimeTimeoutError, toRuntimeError, } from "@zudojs/runtime"; try { await runtime.start(); } catch (error) { if (error instanceof RuntimeStartError) { console.error(`Startup failed at phase: ${error.phase}`); if (error.failedModuleId) { console.error(`Failed module: ${error.failedModuleId}`); } } else if (error instanceof RuntimeTimeoutError) { console.error(`Operation "${error.operation}" timed out`); } else { const runtimeError = toRuntimeError(error, "startup"); console.error(runtimeError.message); } }

FULL INTEGRATION EXAMPLE

Complete working example: create modules, configure the runtime, start, handle signals, check readiness, and shut down gracefully.

import type { Module } from "@zudojs/core"; import { createLogger } from "@zudojs/logger"; import { createContainer } from "@zudojs/container"; import { createEventBus } from "@zudojs/events"; import { createRuntime, RuntimeRegistry, } from "@zudojs/runtime"; // 1. Define modules const databaseModule: Module = { id: "database", name: "Database", dependencies: [], async onInitialize() { console.log("Connecting to database..."); }, async onReady() { console.log("Database ready"); }, async onShutdown() { console.log("Closing database connections..."); }, async onDestroy() { console.log("Database destroyed"); }, }; const apiModule: Module = { id: "api", name: "API Server", dependencies: ["database"], async onInitialize() { console.log("Initializing API server..."); }, async onReady() { console.log("API server listening on :3000"); }, async onShutdown() { console.log("Closing API server..."); }, async onDestroy() { console.log("API server destroyed"); }, }; // 2. Create infrastructure const logger = createLogger({ name: "my-app" }); const container = createContainer(); const eventBus = createEventBus(); const modules = new Map([ ["database", databaseModule], ["api", apiModule], ]); // 3. Create and start runtime const runtime = createRuntime( { modules, logger, container, eventBus }, { environment: "production", applicationName: "my-api", applicationVersion: "1.0.0", handleSignals: true, shutdownTimeout: 30_000, }, ); await runtime.start(); console.log(`Runtime state: ${runtime.state}`); // "running" console.log(`Runtime ready: ${runtime.ready}`); // true // 4. Listen for events eventBus.subscribe("runtime.health.changed", (event) => { console.log(`Health: ${event.payload.currentState}`); }); // 5. Graceful shutdown (also handles SIGTERM/SIGINT automatically) process.on("SIGTERM", async () => { console.log("Received SIGTERM, shutting down..."); await runtime.stop(); process.exit(0); });
Multi-Runtime Example: For microservice architectures, use RuntimeRegistry to manage multiple runtimes:
const registry = new RuntimeRegistry(); registry.register(apiRuntime); registry.register(workerRuntime); await registry.startAll(); // Check all runtimes are ready if (registry.isAllReady()) { console.log("All runtimes ready"); } // Shutdown all runtimes process.on("SIGTERM", () => registry.stopAll());
