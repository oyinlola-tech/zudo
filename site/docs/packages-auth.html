@zudojs/auth

Authentication and authorization services — JWT tokens (access + refresh), password hashing (scrypt), session management, RBAC, OAuth2 strategies, and auth utilities.

AUTH JWT RBAC SESSIONS
Docs / Packages / @zudojs/auth

OVERVIEW

@zudojs/auth provides the full authentication and authorization stack for Zudo applications. It coordinates JWT token management, password hashing, session lifecycle, and permission checks into a single AuthService.

The package uses zero external dependencies for crypto — pure Node.js crypto module with HMAC SHA-256 for JWT signing and scrypt for password hashing.

Architecture Position

Sits in Layer 3 (Application). Delegates RBAC to @zudojs/permissions. Uses @zudojs/errors for error hierarchy and @zudojs/constants for branded types.

INSTALLATION

# Install with npm npm install @zudojs/auth # Or with pnpm pnpm add @zudojs/auth
Peer dependencies

@zudojs/errors, @zudojs/constants, and @zudojs/permissions are required.

QUICK START

import { createAuthService } from "@zudojs/auth"; const auth = createAuthService({ token: { accessSecret: process.env.JWT_ACCESS_SECRET, refreshSecret: process.env.JWT_REFRESH_SECRET, accessTtl: 900, // 15 minutes refreshTtl: 604800, // 7 days }, sessionStore: createMemorySessionStore(), findUser: async (id) => db.findUserById(id), verifyPassword: async (userId, pwd) => { const user = await db.findUserById(userId); return verifyPassword(pwd, user.passwordHash); }, sessionTtlSeconds: 86400, }); // Login const { user, tokens, sessionId } = await auth.login({ identifier: "alice@example.com", password: "securepassword", }); // Verify token const payload = auth.verifyToken(tokens.accessToken); // Check access const guard = await auth.checkAccess(user.id, user.roles, "posts:write");

fn verifyAccessToken()

Verifies signature, expiration, and token type for an access token.

function verifyAccessToken( token: JwtToken, config: TokenConfig, ): TokenVerificationResult
const result = verifyAccessToken(token, tokenConfig); if (result.valid) { console.log(result.payload.sub); // UserId console.log(result.payload.roles); // string[] } else { console.error(result.error); // "Token expired", "Invalid signature", etc. }

fn verifyRefreshToken()

Same as verifyAccessToken but validates against the refresh secret and expects typ: "refresh".

function verifyRefreshToken( token: JwtToken, config: TokenConfig, ): TokenVerificationResult

fn refreshAccessToken()

Exchanges a valid refresh token for a new token pair. Returns null if the refresh token is invalid or expired.

function refreshAccessToken( refreshToken: JwtToken, config: TokenConfig, options?: { roles?: readonly string[] }, ): TokenPair | null
const newPair = refreshAccessToken(refreshToken, config); if (newPair) { // New tokens issued res.json(newPair); } else { // Refresh token invalid — user must re-login res.status(401).json({ error: "Invalid refresh token" }); }

namespace jwt

Convenience namespace that re-exports all JWT utilities in one object.

import { jwt } from "@zudojs/auth"; jwt.createTokenPair(userId, config); jwt.verifyAccessToken(token, config); jwt.verifyRefreshToken(token, config); jwt.refreshAccessToken(refreshToken, config); jwt.parseBearerToken(authorizationHeader); jwt.isTokenExpired(token); jwt.extractUserId(token);

PASSWORD HASHING

fn hashPassword()

Hashes a plain-text password using scrypt with a random salt. Returns a string in format "scrypt$salt$hash".

async function hashPassword( password: string, saltLength?: number, // default: 32 bytes ): Promise<string>
const hash = await hashPassword("mySecurePassword"); // "scrypt$a1b2c3d4...$e5f6g7h8..." // Store in database await db.createUser({ email: "alice@example.com", passwordHash: hash });

fn verifyPassword()

Verifies a plain-text password against a stored hash. Uses timing-safe comparison.

async function verifyPassword( password: string, hashedPassword: string, ): Promise<boolean>
const user = await db.findByEmail(email); const valid = await verifyPassword(input.password, user.passwordHash); if (!valid) throw new InvalidCredentialsError();

fn needsRehash()

Checks if a stored hash uses outdated parameters and should be regenerated.

function needsRehash(hashedPassword: string): boolean
// After successful login, check if hash needs updating if (needsRehash(user.passwordHash)) { const newHash = await hashPassword(input.password); await db.updatePassword(user.id, newHash); }

fn generateRandomToken()

Generates a cryptographically secure random hex string. Use for password reset tokens, API keys, etc.

function generateRandomToken(length?: number): string
const resetToken = generateRandomToken(32); // "a1b2c3d4e5f6..." (64 hex chars) await db.createPasswordReset({ userId: user.id, token: resetToken, expiresAt: new Date(Date.now() + 3600_000), });

Complete Login Flow

import { createAuthService, createMemorySessionStore, hashPassword, verifyPassword, } from "@zudojs/auth"; // 1. Configure const auth = createAuthService({ token: { accessSecret: process.env.JWT_ACCESS_SECRET!, refreshSecret: process.env.JWT_REFRESH_SECRET!, accessTtl: 900, refreshTtl: 604800, issuer: "my-app", }, sessionStore: createMemorySessionStore(), findUser: async (id) => await db.findUserById(id), verifyPassword: async (userId, pwd) => { const user = await db.findUserById(userId); return user ? verifyPassword(pwd, user.passwordHash) : false; }, sessionTtlSeconds: 86400, }); // 2. Register user const hash = await hashPassword("securePass123"); await db.createUser({ email: "alice@example.com", passwordHash: hash, roles: ["user"] }); // 3. Login const { user, tokens, sessionId } = await auth.login( { identifier: "alice@example.com", password: "securePass123" }, { userAgent: req.headers["user-agent"], ip: req.ip } ); // 4. Send tokens to client res.json({ accessToken: tokens.accessToken, refreshToken: tokens.refreshToken }); // 5. Verify on subsequent requests const authHeader = req.headers.authorization; const token = parseBearerToken(authHeader); const payload = auth.verifyToken(token!); // 6. Refresh when access token expires const newTokens = await auth.refresh(refreshToken); // 7. Logout await auth.logout(sessionId);

method auth.checkAccess()

Checks if a user has a specific permission. When a PermissionEngine is configured, delegates to it. Otherwise falls back to simple wildcard matching (admin role gets all access, ownership checks).

async checkAccess( userId: UserId, userRoles: readonly string[], permission: string, // "resource:action" format resourceOwnerId?: UserId, // for ownership checks ): Promise<GuardResult>
// Check if user can write posts const result = await auth.checkAccess( user.id, user.roles, "posts:write", post.authorId, // ownership check ); if (result.allowed) { // Proceed } else { throw new AccessDeniedError(result.reason); }

Permission Format

Permissions use the "resource:action" format. Examples:

USE CASES

HTTP API Authentication

import { parseBearerToken, InvalidCredentialsError, TokenExpiredError } from "@zudojs/auth"; // Auth middleware app.use(async (req, res, next) => { const token = parseBearerToken(req.headers.authorization); if (!token) return res.status(401).json({ error: "Missing token" }); try { req.user = auth.verifyToken(token); next(); } catch (e) { if (e instanceof TokenExpiredError) { return res.status(401).json({ error: "Token expired", code: "TOKEN_EXPIRED" }); } res.status(401).json({ error: "Invalid token" }); } });

Role-Based Route Guard

// Admin-only route app.delete("/users/:id", requireAuth, async (req, res) => { const guard = await auth.checkAccess( req.user.sub, req.user.roles, "users:delete" ); if (!guard.allowed) { return res.status(403).json({ error: guard.reason }); } await db.deleteUser(req.params.id); res.json({ deleted: true }); });

Ownership-Based Access

app.put("/posts/:id", requireAuth, async (req, res) => { const post = await db.findPost(req.params.id); const guard = await auth.checkAccess( req.user.sub, req.user.roles, "posts:write", post.authorId // ownership check — user can edit own posts ); if (!guard.allowed) { return res.status(403).json({ error: "You can only edit your own posts" }); } await db.updatePost(req.params.id, req.body); res.json({ updated: true }); });

Token Refresh Flow

app.post("/auth/refresh", async (req, res) => { const { refreshToken } = req.body; try { const tokens = await auth.refresh(refreshToken); res.json(tokens); } catch (e) { res.status(401).json({ error: "Invalid refresh token" }); } });

Secure Password Storage

import { hashPassword, verifyPassword, needsRehash } from "@zudojs/auth"; // Registration const hash = await hashPassword(plainPassword); await db.createUser({ email, passwordHash: hash }); // Login verification const user = await db.findByEmail(email); const valid = await verifyPassword(inputPassword, user.passwordHash); if (!valid) throw new InvalidCredentialsError(); // Auto-upgrade hash parameters if (needsRehash(user.passwordHash)) { const newHash = await hashPassword(inputPassword); await db.updatePassword(user.id, newHash); }

Password Reset Token

import { generateRandomToken } from "@zudojs/auth"; // Generate reset token const token = generateRandomToken(32); await db.createPasswordReset({ userId: user.id, token: token, expiresAt: new Date(Date.now() + 3600_000), }); // Send email with reset link await email.send({ to: user.email, subject: "Password Reset", body: `Reset: https://app.com/reset?token=${token}`, }); // Verify reset token and update password const reset = await db.findPasswordReset(token); if (reset && reset.expiresAt > new Date()) { const newHash = await hashPassword(newPassword); await db.updatePassword(reset.userId, newHash); await db.deletePasswordReset(token); }

SUGGESTED IMPROVEMENTS

Token Revocation List

Add a TokenRevocationStore interface to track revoked token JTIs. The verifyAccessToken should check the revocation list before accepting.

OAuth2 Strategy Implementation

The AuthStrategy and OAuthConfig types exist but no concrete OAuth2 strategy is implemented. Add GoogleOAuthStrategy, GitHubOAuthStrategy, etc.

Brute Force Protection

Add an AccountLockout module that tracks failed attempts per user and triggers AccountLockedError after N failures.

API Key Authentication

ApiKeyCredentials type exists but no API key strategy is implemented. Add createApiKeyStrategy() for machine-to-machine auth.

Session Renewal

Add automatic session renewal when touch() is called and the session is past 50% of its TTL. Prevents session death during active use.

Multi-Factor Auth

Add TOTP/SMS MFA support as an additional AuthStrategy that wraps password authentication with a second factor.

Rate Limiting Integration

Integrate with @zudojs/security rate limiter to automatically apply per-IP and per-user rate limits to login endpoints.

Redis Session Store

Ship a createRedisSessionStore() implementation alongside the in-memory one for production use.
