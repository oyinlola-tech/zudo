@zudojs/plugins

Controlled extension system for the Zudojs framework. Provides plugin registration, dependency resolution with cycle detection, lifecycle management, and orchestration for Zudojs applications.

PLUGINS EXTENSIONS LIFECYCLE DEPENDENCIES

INSTALLATION

// npm npm install @zudojs/plugins // pnpm pnpm add @zudojs/plugins // yarn yarn add @zudojs/plugins
Peer Dependencies: @zudojs/plugins depends on @zudojs/errors, @zudojs/constants, and @zudojs/types. All at version 0.0.1.

WHAT IT DOES

@zudojs/plugins is the controlled extension system for Zudojs. It defines:

  • → Plugin registration and lifecycle management with validated state transitions
  • → Dependency resolution with topological sorting and cycle detection
  • → 11 plugin states with a validated state machine and transition rules
  • → Plugin context injection — container, config, logger, events, and abort signals
  • → Lifecycle hooks — install, initialize, start, stop, dispose
  • → Diagnostic health reports with per-plugin health status
  • → 14 error classes covering every failure mode
  • → Event system for lifecycle events with timestamps and error context
Core Principle: Plugins are self-contained extensions that follow a strict lifecycle. The plugin system resolves dependencies, enforces state transitions, and emits events — so you never have to orchestrate plugin order manually.

WHERE IT SITS

APPLICATION LAYER (CQRS, Events, Modules)
Registry Dependencies Lifecycle Events Diagnostics
PLUGIN SYSTEM (@zudojs/plugins)
RUNTIME LAYER (@zudojs/runtime, @zudojs/lifecycle)
INFRASTRUCTURE (DI, Config, Logger, Events)

The plugin system sits between the runtime layer and the application layer. It orchestrates plugin lifecycle and dependencies, providing a controlled extension point without coupling plugins to the core framework internals.

PLUGIN INTERFACE

Interface: Plugin

Every plugin in the Zudojs ecosystem implements this contract:

interface Plugin<TOptions = unknown> { readonly metadata: PluginMetadata; readonly dependencies?: readonly PluginDependency[]; readonly optionalDependencies?: readonly PluginDependency[]; install?(context: PluginContext, options: TOptions): void | Promise<void>; initialize?(context: PluginContext): void | Promise<void>; start?(context: PluginContext): void | Promise<void>; stop?(context: PluginContext): void | Promise<void>; dispose?(context: PluginContext): void | Promise<void>; }

PluginMetadata

interface PluginMetadata { readonly name: string; readonly version?: string; readonly description?: string; readonly author?: string; readonly homepage?: string; readonly keywords?: readonly string[]; readonly capabilities?: readonly string[]; }

PluginDependency

interface PluginDependency { readonly name: string; readonly version?: string; readonly optional?: boolean; }

Properties

Property Type Required Description
metadata PluginMetadata Yes Unique plugin identification with name, version, and capabilities.
dependencies PluginDependency[] No Required plugins that must be installed before this one.
optionalDependencies PluginDependency[] No Preferred plugins that enhance functionality but are not required.
install() Function No Called first. Register services, validate config, set up infrastructure.
initialize() Function No Called after install. Prepare resources, establish connections.
start() Function No Begin active processing. Listen for requests, consume messages.
stop() Function No Cease active processing. Stop accepting new work.
dispose() Function No Release all resources. Close connections, clear timers.

PLUGIN STATES

Plugins move through a strict state machine. Invalid transitions throw PluginStateError.

PluginState Type

type PluginState = | "registered" | "installing" | "installed" | "initializing" | "initialized" | "starting" | "started" | "stopping" | "stopped" | "disposing" | "disposed";

Valid State Transitions

From State Allowed Transitions
registeredinstalling
installinginstalled, failed
installedinitializing, stopping
initializinginitialized, failed
initializedstarting, stopping
startingstarted, failed
startedstopping
stoppingstopped, failed
stoppeddisposing, starting
disposingdisposed, failed
disposednone (terminal)

isValidTransition()

import { isValidTransition } from "@zudojs/plugins"; isValidTransition("registered", "installing"); // true isValidTransition("registered", "started"); // false isValidTransition("started", "stopping"); // true

State Diagram

registered → installing → installed → initializing → initialized → starting → started
↓                                                               ↓
failed ← installing, initializing, starting, stopping, disposing
stopped → disposing → disposed   |   stopped → starting (restart)

PLUGIN CONTEXT

The PluginContext is the controlled interface provided to plugins during lifecycle operations. It exposes framework services without leaking internals.

interface PluginContext { readonly plugin: PluginMetadata; readonly container?: PluginContainer; readonly config?: PluginConfig; readonly logger?: PluginLogger; readonly events?: PluginEvents; readonly signal: AbortSignal; onDispose(handler: () => void | Promise<void>): void; registerDisposable(disposable: { dispose(): void | Promise<void> }): void; }

Context Interfaces

Interface Methods Purpose
PluginContainerregister(token, provider)Register services in the DI container
PluginConfigget(key)Read configuration values
PluginLoggerinfo(), warn(), error()Structured logging with context
PluginEventson(), off(), emit()Subscribe to and emit framework events

createPluginContext()

import { createPluginContext } from "@zudojs/plugins"; const context = createPluginContext( { name: "my-plugin", version: "0.0.1" }, { container: myContainer, config: myConfig, logger: myLogger, events: myEvents, }, ); // Register cleanup handlers context.onDispose(async () => { await closeDatabase(); }); // Register disposable resources context.registerDisposable({ async dispose() { await clearInterval(timer); }, });

REGISTRY

The PluginRegistry manages plugin registration, lookup, and state tracking. Names are used as unique identifiers.

PluginRegistry Interface

interface PluginRegistry { register<TPlugin extends Plugin>(plugin: TPlugin, options?: unknown): void; get<TPlugin>(name: string): RegisteredPlugin<TPlugin> | undefined; has(name: string): boolean; list(): readonly RegisteredPlugin[]; remove(name: string): boolean; clear(): void; }

RegisteredPlugin

interface RegisteredPlugin<TPlugin extends Plugin = Plugin> { readonly plugin: TPlugin; readonly state: PluginState; readonly options?: unknown; readonly disposables: Array<{ dispose(): void | Promise<void> }>; registerDisposable(disposable: { dispose(): void | Promise<void> }): void; setState(state: PluginState): void; }

Methods

Method Signature Returns
register() register(plugin, options?): void void. Throws PluginAlreadyRegisteredError on duplicate.
get() get<T>(name): RegisteredPlugin<T> | undefined Registered plugin or undefined
has() has(name): boolean true if registered
list() list(): readonly RegisteredPlugin[] Frozen array of all registered plugins
remove() remove(name): boolean true if removed. Only works if state is registered or disposed.
clear() clear(): void Removes all plugins

DEPENDENCY RESOLUTION

The DependencyResolver performs topological sorting of plugins and detects missing dependencies and cycles.

DependencyResolution

interface DependencyResolution { readonly ordered: readonly string[]; readonly missing: readonly string[]; readonly cycles: readonly string[]; }

Resolution Algorithm

  1. Collect all plugins and their dependency declarations
  2. Check that all required (non-optional) dependencies are registered — collect missing names
  3. If any are missing, return early with the missing list
  4. Run DFS topological sort to determine startup order
  5. If a cycle is detected during DFS, return early with the cycle path
  6. Return the ordered list of plugin names for startup

assertResolutionValid()

import { DependencyResolver, assertResolutionValid, } from "@zudojs/plugins"; const resolver = new DependencyResolver(); const resolution = resolver.resolve(dependencyMap); // Throws PluginDependencyError or PluginDependencyCycleError assertResolutionValid(resolution); // Use ordered list for startup for (const name of resolution.ordered) { // start plugin in order }

LIFECYCLE

The LifecycleController executes lifecycle phases with state validation and event emission.

Methods

Method When Called Purpose
install() During startup Register services, validate config, set up infrastructure.
initialize() After install Prepare resources, establish connections.
start() After initialize Begin active processing.
stop() During shutdown Cease active processing, stop accepting work.
dispose() After stop Release resources, run registered disposables.

Lifecycle Flow

1. install() → register services, validate config
2. initialize() → prepare resources, connect
3. start() → begin active processing
4. stop() → cease processing (during shutdown)
5. dispose() → release all resources, run disposables

PLUGIN MANAGER

The PluginManager is the high-level orchestrator that coordinates the registry, dependency resolver, and lifecycle controller.

class PluginManager { register<TPlugin extends Plugin>(plugin: TPlugin): void; get<TPlugin>(name: string): TPlugin | undefined; has(name: string): boolean; list(): readonly Plugin[]; start(context: PluginContext): Promise<void>; stop(context: PluginContext): Promise<void>; diagnostics(): PluginDiagnosticReport; }

Methods

Method Purpose
register()Register a plugin. Wraps registry errors in PluginRegistrationError.
get()Retrieve a plugin by name from the registry.
has()Check if a plugin is registered.
list()Return all registered plugins.
start()Resolve dependencies, then run install → initialize → start in topological order.
stop()Stop and dispose all plugins in reverse order.
diagnostics()Build a full diagnostic report with health status per plugin.

EVENTS

The plugin system emits lifecycle events at each state transition. Events include the plugin metadata, current and previous state, timestamp, and any error.

PLUGIN_EVENTS Constant

const PLUGIN_EVENTS = { REGISTERED: "plugin:registered", INSTALLING: "plugin:installing", INSTALLED: "plugin:installed", INITIALIZING: "plugin:initializing", INITIALIZED: "plugin:initialized", STARTING: "plugin:starting", STARTED: "plugin:started", STOPPING: "plugin:stopping", STOPPED: "plugin:stopped", FAILED: "plugin:failed", DISPOSING: "plugin:disposing", DISPOSED: "plugin:disposed", } as const;

PluginLifecycleEvent

interface PluginLifecycleEvent { readonly plugin: PluginMetadata; readonly state: PluginState; readonly previousState?: PluginState; readonly timestamp: number; readonly error?: unknown; }

createPluginLifecycleEvent()

import { createPluginLifecycleEvent, PLUGIN_EVENTS, } from "@zudojs/plugins"; const event = createPluginLifecycleEvent( { name: "@zudojs/http" }, "started", "starting", ); // Subscribe to events events.on(PLUGIN_EVENTS.STARTED, (event) => { console.log(`Plugin ${event.plugin.name} started`); });

DIAGNOSTICS

Diagnostic reports provide health status for each plugin and aggregate counts across the system.

PluginHealthStatus

type PluginHealthStatus = "healthy" | "degraded" | "unhealthy";

PluginDiagnosticReport

interface PluginDiagnosticReport { readonly plugins: readonly PluginDiagnostic[]; readonly total: number; readonly healthy: number; readonly degraded: number; readonly unhealthy: number; readonly failed: number; }

Health Factory Functions

import { createHealthyHealth, createDegradedHealth, createUnhealthyHealth, } from "@zudojs/plugins"; // Healthy — plugin is started and running const ok = createHealthyHealth(); // { status: "healthy" } // Degraded — plugin is installed/initialized but not started const degraded = createDegradedHealth({ reason: "not started" }); // Unhealthy — plugin has failed const unhealthy = createUnhealthyHealth({ error: "connection refused" });

buildDiagnosticReport()

import { buildDiagnosticReport } from "@zudojs/plugins"; const report = buildDiagnosticReport([ { plugin: httpPlugin, state: "started" }, { plugin: authPlugin, state: "failed" }, ]); console.log(report.healthy); // 1 console.log(report.failed); // 1

Using PluginManager.diagnostics()

const manager = new PluginManager(); manager.register(httpPlugin); manager.register(authPlugin); await manager.start(context); const report = manager.diagnostics(); console.log(`Total: ${report.total}, Healthy: ${report.healthy}`);

ERROR HIERARCHY

All error types are defined in @zudojs/errors and re-exported by this package.

Error When Thrown

PluginRegistrationErrorFailed to register a plugin
PluginAlreadyRegisteredErrorDuplicate plugin name registration
PluginNotFoundErrorRequested plugin not in registry
PluginDependencyErrorRequired dependency not registered
PluginDependencyCycleErrorCircular dependency detected
PluginInitializationErrorPlugin.initialize() failed

Error Handling Pattern

import { isPluginError, PluginDependencyCycleError, PluginStateError, } from "@zudojs/plugins"; try { await manager.start(context); } catch (error) { if (isPluginError(error)) { console.error(`Plugin error: ${error.message}`); if (error instanceof PluginDependencyCycleError) { // Log cycle path and fix dependencies } if (error instanceof PluginStateError) { // Plugin attempted invalid transition } } }

FULL INTEGRATION EXAMPLE

Complete example: create plugins with metadata and dependencies, register them, start with context, check diagnostics, and handle shutdown.

import { PluginManager, createPluginContext, PLUGIN_EVENTS, } from "@zudojs/plugins"; import type { Plugin } from "@zudojs/plugins"; // 1. Define plugins const eventsPlugin: Plugin = { metadata: { name: "@zudojs/events", version: "0.0.1", description: "Event system", }, async install(ctx) { ctx.logger?.info("Events plugin installing"); }, async start(ctx) { ctx.logger?.info("Events plugin started"); }, async stop(ctx) { ctx.logger?.info("Events plugin stopped"); }, }; const httpPlugin: Plugin = { metadata: { name: "@zudojs/http", version: "0.0.1", description: "HTTP server", }, async install(ctx) { ctx.container?.register("httpServer", httpServer); ctx.logger?.info("HTTP plugin installing"); }, async start(ctx) { await httpServer.listen(3000); ctx.logger?.info("HTTP server listening on :3000"); }, async stop(ctx) { await httpServer.close(); }, async dispose(ctx) { ctx.logger?.info("HTTP plugin disposed"); }, }; // 2. Create PluginManager const manager = new PluginManager(); // 3. Register plugins manager.register(eventsPlugin); manager.register(httpPlugin); // 4. Create context const context = createPluginContext( { name: "app" }, { logger: myLogger, events: myEvents }, ); // 5. Start — resolves dependencies, runs lifecycle await manager.start(context); // 6. Check diagnostics const report = manager.diagnostics(); console.log(`Plugins: ${report.total}, Healthy: ${report.healthy}`); // 7. Handle events context.events?.on(PLUGIN_EVENTS.STARTED, (event) => { console.log(`✅ ${event.plugin.name} started`); }); // 8. Graceful shutdown process.on("SIGTERM", async () => { await manager.stop(context); process.exit(0); });
