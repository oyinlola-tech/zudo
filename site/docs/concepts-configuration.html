Configuration

Layered configuration with multiple sources and clear precedence.

CONFIG SOURCES ENV

Overview

@zudojs/config provides a layered configuration system where values are resolved from multiple sources with defined priority ordering. Configuration is validated against schemas at startup, and sensitive values are automatically redacted in logs.

Architecture Position

Sits in Layer 1 (Foundation). No internal dependencies beyond @zudojs/errors.

Config Sources

Configuration values are loaded from multiple sources. Each source has a priority level — higher priority sources override lower ones.

Source Description Priority
environment Environment variables (process.env) Highest
file JSON/YAML config files High
memory In-memory values set programmatically Medium
defaults Default values defined in code Low

Config Resolution & Priority

When a config key is read, the resolver checks each source in priority order and returns the first defined value. This allows environment-specific overrides without changing application code.

import { createConfigManager } from "@zudojs/config"; const config = createConfigManager({ sources: [ { type: "defaults", data: { port: 3000, host: "localhost" } }, { type: "file", path: "./config.json" }, { type: "environment", prefix: "APP_" }, ], }); // Resolution: env APP_PORT → file config.json → defaults const port = config.get("port"); // number

Schema Validation

Configuration is validated against a schema at startup. Invalid configuration fails fast with clear error messages, preventing runtime surprises.

import { createConfigManager } from "@zudojs/config"; import { z } from "zod"; const schema = z.object({ port: z.number().min(1).max(65535), host: z.string().min(1), database: z.object({ url: z.string().url(), poolSize: z.number().default(10), }), }); const config = createConfigManager({ schema }); // Throws ConfigurationError if validation fails await config.load();

Sensitive Value Handling

Configuration values matching sensitive patterns (password, secret, token, api_key) are automatically redacted in logs and error messages.

Security

Never log raw configuration objects. Use config.redact() to sanitize output before logging.

// Sensitive values are auto-redacted const config = createConfigManager({ sensitivePatterns: ["password", "secret", "token", "api_key"], }); // config.redact() returns sanitized copy console.log(config.redact()); // { db: { password: "[REDACTED]" }, apiKey: "[REDACTED]" }

Why Configuration Matters

  • 01 Environment parity — same config schema works in dev, staging, and production.
  • 02 Fail-fast validation — missing or invalid config is caught at startup, not at runtime.
  • 03 Security by default — sensitive values are never leaked in logs or error traces.
  • 04 Type safety — validated config is fully typed throughout your application.
