@zudojs/validation

Schema validation with Zod, 40+ constraints, parsers, composers, normalizers, transformers, registries, and circular/depth/size checks for the Zudojs framework.

VALIDATION ZOD SCHEMAS CONSTRAINTS TRANSFORMS

INSTALLATION

// npm npm install @zudojs/validation // pnpm pnpm add @zudojs/validation // yarn yarn add @zudojs/validation
Peer Dependencies: @zudojs/validation depends on zod and @zudojs/errors. Both are required at runtime.

WHAT IT DOES

@zudojs/validation provides a complete validation toolkit built on top of Zod:

  • → Zod-based schema validation with TypeScript type inference
  • → 40+ built-in constraints for strings, numbers, arrays, dates, and collections
  • → Validation result types with success/failure discrimination
  • → Validation composer for chaining and combining validation steps
  • → Validation parser with safe/throw modes for reusable parsing
  • → Validation normalizer for input sanitization and cleanup
  • → Validation transformer for type conversion after validation
  • → Validation registry for named rule storage and lookup
  • → Validation factory as a unified API for creating all components
  • → Circular reference detection in object graphs
  • → Depth and size estimation for serialization safety
  • → 7 error types with field-level issue reporting

WHERE IT SITS

APPLICATION LAYER (CQRS, Modules, Services)
VALIDATION LAYER (@zudojs/validation)
ZOD SCHEMA ENGINE
CONSTRAINTS / NORMALIZER / TRANSFORMER

Validation sits between application logic and data ingestion. It wraps Zod with a richer API: constraints, composition, parsing, normalization, transformation, and registries. Application code validates input through this layer before it reaches business logic.

RESULT TYPES

Every validation operation returns a discriminated union. The success field determines the variant.

interface ValidationIssue { readonly path: readonly (string | number)[]; readonly code: string; readonly message: string; readonly expected?: unknown; readonly received?: unknown; }

ValidationSuccess

ValidationFailure

interface ValidationFailure { readonly success: false; readonly data?: unknown; readonly issues: readonly ValidationIssue[]; }

ValidationResult

type ValidationResult<T> = ValidationSuccess<T> | ValidationFailure;

ValidationError

class ValidationError extends BaseError { readonly validationCode: ValidationErrorCode; readonly issues: readonly ValidationIssue[]; readonly context?: Readonly<Record<string, unknown>>; readonly timestamp: number; readonly fieldErrors: Readonly<Record<string, string>>; readonly formattedIssues: string; }

FULL INTEGRATION EXAMPLE

A complete example showing schemas, constraints, composition, parsing, normalization, transformation, and registry usage.

import { z, validate, parse, isValid, createValidator, createParser, createValidationRegistry, createValidationFactory, } from "@zudojs/validation"; import { email, uuid, nonEmptyString, minLength, maxLength, integer, positive, between, oneOf, minItems, createConstraint, } from "@zudojs/validation"; import { normalizeEmail, normalizeWhitespace, composeNormalizers, createNormalizer, } from "@zudojs/validation"; import { createValidationTransformer, validateAndTransform, } from "@zudojs/validation"; // 1. Define a Zod schema const CreateUserSchema = z.object({ name: z.string().min(1), email: z.string().email(), role: z.enum(["admin", "editor", "viewer"]), age: z.number().int().positive().optional(), tags: z.array(z.string()).min(1), }); // 2. Validate raw input const result = validate(CreateUserSchema, rawData); if (result.success) { console.log("Valid user:", result.data); } else { console.log("Errors:", result.issues); } // 3. Use constraints directly import { checkConstraints } from "@zudojs/validation"; const emailResult = checkConstraints([email, nonEmptyString], "user@example.com"); // 4. Create reusable validators const validateUser = createValidator(CreateUserSchema); const parseUser = createParser(CreateUserSchema); // 5. Use the factory const factory = createValidationFactory(); const userParser = factory.parser(CreateUserSchema); const parsed = userParser.safeParse(rawData); // 6. Register schemas and validate by name factory.registerSchema("CreateUser", CreateUserSchema, "User creation payload"); const registeredResult = factory.validateRegistered("CreateUser", rawData); // 7. Create a normalizer const normalizeUserInput = createNormalizer( composeNormalizers(normalizeWhitespace, normalizeEmail), { name: "UserInputNormalizer" }, ); // 8. Transform after validation const toCreateUserDTO = createValidationTransformer( (user) => ({ ...user, displayName: user.name.toUpperCase(), createdAt: new Date(), }), { name: "ToCreateUserDTO" }, ); const dtoResult = validateAndTransform( CreateUserSchema, rawData, (user) => ({ ...user, displayName: user.name.toUpperCase(), createdAt: new Date(), }), ); // 9. Build a custom constraint const minAge = createConstraint( (value) => value >= 18, { name: "min_age", code: "invalid_age", message: "Must be at least 18 years old.", }, ); // 10. Use registry directly const registry = createValidationRegistry(); registry.registerSchema("CreateUser", CreateUserSchema); registry.registerConstraints("AgeCheck", [positive, integer, minAge]); const lookupResult = registry.validate("CreateUser", rawData);
