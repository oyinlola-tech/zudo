@zudojs/cache

Caching primitives, adapters, tag-based invalidation, distributed locking, and metrics

CACHING INVALIDATION LOCKING

OVERVIEW

@zudojs/cache provides a complete caching infrastructure for the Zudo framework. It follows the adapter pattern — a pluggable CacheAdapter interface with a built-in MemoryCacheAdapter and a high-level CacheService orchestrator that coordinates key building, tag-based invalidation, distributed locking, metrics collection, and middleware pipelines.

The package is designed for zero-config usage with sensible defaults (5-minute TTL, 10K max entries, 50MB memory budget) while supporting full customization for production deployments.

KEY CONCEPTS

  • • CacheAdapter — Pluggable backend interface (Memory, Redis, etc.)
  • • CacheService — High-level orchestrator with get/set/invalidate/lock
  • • CacheStore — Adapter wrapper with middleware, events, and metrics
  • • Tag-based invalidation — Invalidate related keys by logical tags
  • • Cache-aside pattern — getOrSet() for read-through caching

INSTALLATION

// Install as part of the Zudo framework npm install @zudojs/cache // Or use the full framework npm install zudo

Peer dependencies: @zudojs/errors, @zudojs/types, @zudojs/serialization

ARCHITECTURE

The package follows a layered architecture where each component has a single responsibility:

CacheService                    ← High-level orchestrator
    ├── DefaultCacheStore         ← Adapter wrapper + middleware + events
    │       └── CacheAdapter      ← Pluggable backend interface
    ├── DefaultKeyBuilder         ← Key generation (prefix:namespace:key)
    ├── InMemoryTagStore          ← Bidirectional tag ↔ key mapping
    ├── CacheInvalidationManager ← Tag/pattern/namespace/key invalidation
    ├── CacheLockManager          ← Distributed locking with retries
    │       └── CacheLockStore    ← Lock backend interface
    └── InMemoryCacheMetrics     ← Hit/miss/latency/hot keys

Data Flow — Set with Tags

await cache.set("user:1", userData, { tags: ["users", "active"] }); // 1. CacheService checks if enabled // 2. DefaultKeyBuilder.build("user:1") → "zudojs:user:1" // 3. DefaultCacheStore.set() runs middleware chain // 4. MemoryCacheAdapter.set() stores in Map with TTL // 5. Metrics increment the set counter // 6. Event "cache.set" emitted to subscribers // 7. InMemoryTagStore.add() registers tag mappings

Data Flow — Invalidate by Tag

await cache.invalidateByTag(["users"]); // 1. InMemoryTagStore.getKeys("users") → ["zudojs:user:1", "zudojs:user:2"] // 2. For each key: adapter.delete(key) removes from cache // 3. InMemoryTagStore.invalidate("users") cleans up mappings // 4. Returns { cleared: 2 }

QUICK START

ZERO-CONFIG USAGE

The simplest way to start — everything uses sensible defaults.

import { createCacheService, createMemoryCacheAdapter } from "@zudojs/cache"; // Create with defaults (5min TTL, 10K entries, 50MB) const cache = createCacheService({ adapter: createMemoryCacheAdapter() }); // Connect before use await cache.connect(); // Basic operations await cache.set("user:1", { name: "Alice", role: "admin" }); const result = await cache.get("user:1"); // result: { hit: true, value: { name: "Alice", role: "admin" } } // Cache-aside pattern const user = await cache.getOrSet("user:1", async () => { return await db.findUser("1"); }, { ttl: 60000 }); // Disconnect when done await cache.disconnect();

CACHESERVICE

The CacheService is the primary entry point. It orchestrates all caching operations, delegates to the adapter, and coordinates tags, locking, and metrics.

Constructor

createCacheService(options: { adapter: CacheAdapter; // Required: backend adapter config?: CacheConfig; // Optional: enabled, defaultTtl, namespace, prefix, etc. keyBuilder?: CacheKeyBuilder; // Optional: custom key builder }): CacheService

Cache-Aside Pattern

// Returns cached value or computes fresh, then caches const result = await cache.getOrSet( "product:42", async () => await db.getProduct("42"), { ttl: 300000, tags: ["products"] } ); // result.value — the data // result.cached — true if from cache, false if freshly computed // Force refresh (skip cache) const fresh = await cache.getOrSet( "product:42", async () => await db.getProduct("42"), { forceRefresh: true } );

Distributed Locking

// Execute with exclusive lock (auto-releases in finally) const result = await cache.withLock( "rate-limit:user:1", async () => { const count = await redis.incr("requests"); if (count > 100) throw new Error("Rate limited"); return { allowed: true }; }, { ttl: 5000, retryAttempts: 3 } );

Disabled Mode

// When config.enabled = false, all operations are safe no-ops const cache = createCacheService({ adapter, config: { enabled: false } }); await cache.set("key", "value"); // no-op const r = await cache.get("key"); // { hit: false, value: null } await cache.has("key"); // false

DEFAULTCACHESTORE

Wraps a CacheAdapter with middleware pipeline, event emission, and metrics tracking. The store is used internally by CacheService but can also be used standalone.

import { createCacheStore, createMemoryCacheAdapter } from "@zudojs/cache"; const store = createCacheStore({ adapter: createMemoryCacheAdapter(), middlewares: [ // Custom middleware runs before every operation async (ctx, next) => { console.log(`[cache] ${ctx.operation} on ${ctx.key}`); const result = await next(); console.log(`[cache] done in ${Date.now() - ctx.startedAt}ms`); return result; } ] }); // Subscribe to events const sub = store.subscribe("cache.hit", (event) => { console.log(`Cache hit: ${event.key} in ${event.latencyMs}ms`); }); // Wildcard subscription store.subscribe("*", (event) => { metrics.record(event.type, event); }); // Unsubscribe sub.unsubscribe();

Event Types

Event Payload When
cache.hit{ key, latencyMs }Value found in cache
cache.miss{ key, latencyMs }Value not found
cache.set{ key, ttl }Value stored

cache.error{ key, error }Operation failed

MEMORYCACHEADAPTER

Built-in in-memory cache adapter backed by a Map. Uses FIFO eviction when capacity is reached and lazy expiration (entries removed on access, not by timers).

import { createMemoryCacheAdapter } from "@zudojs/cache"; // Default: 10,000 entries, 5-minute TTL const adapter = createMemoryCacheAdapter(); // Custom configuration const adapter = createMemoryCacheAdapter({ maxEntries: 5000, // Max entries before FIFO eviction defaultTtl: 60000 // Default TTL: 60 seconds });

Behavior

  • FIFO eviction: When maxEntries is reached, the oldest entry (first key in Map insertion order) is removed.
  • Lazy expiration: Expired entries are removed when accessed (get, has), not via background timers.
  • Glob patterns: clear() and keys() support * and ? glob patterns.
  • Batch operations: getMany, setMany, deleteMany for efficient bulk operations.
  • TTL extension: Use expire(key, ttl) to extend an entry's lifetime.

PRODUCTION NOTE

MemoryCacheAdapter is single-process only. For multi-instance deployments, implement a CacheAdapter backed by Redis, Memcached, or your preferred distributed store.

KEY BUILDER

Builds fully qualified cache keys with prefix, namespace, and separator. Validates key length (max 256) and character pattern.

import { createKeyBuilder } from "@zudojs/cache"; const builder = createKeyBuilder({ prefix: "myapp", // Default: "zudojs" separator: ":", // Default: ":" }); // Build a key builder.build("user:1"); // → "myapp:user:1" // Build with namespace builder.build("user:1", { namespace: "auth" }); // → "myapp:auth:user:1" // Create a scoped builder const authBuilder = builder.namespace("auth"); authBuilder.build("session:abc"); // → "myapp:auth:session:abc"

Key Format

[prefix][separator][namespace][separator][key]
  • Max length: 256 characters
  • Valid characters: a-zA-Z0-9._-:
  • Default prefix: zudojs
  • Default separator: :

TAG STORE

Bidirectional mapping between cache keys and logical tags. Tags let you invalidate groups of related keys without knowing them individually.

import { createTagStore } from "@zudojs/cache"; const tags = createTagStore(); // Associate tags with a key (bidirectional) await tags.add("zudojs:user:1", ["users", "active"]); await tags.add("zudojs:user:2", ["users", "inactive"]); // Get all keys for a tag const keys = await tags.getKeys("users"); // → ["zudojs:user:1", "zudojs:user:2"] // Get all tags for a key const tagList = tags.tagsForKey("zudojs:user:1"); // → ["users", "active"] // Invalidate a tag (removes all mappings) const result = await tags.invalidate("active"); // → { cleared: 1 }

CACHEINVALIDATIONMANAGER

Coordinates cache invalidation across multiple strategies: by tag, pattern, namespace, or individual key.

import { createInvalidationManager } from "@zudojs/cache"; const invalidator = createInvalidationManager({ adapter, tagStore }); // By tag — deletes all keys with "users" tag await invalidator.invalidateByTag(["users"]); // By pattern — glob matching await invalidator.invalidateByPattern("user:*"); // By namespace await invalidator.invalidateByNamespace("auth"); // Single key await invalidator.invalidateKey("zudojs:user:1"); // Multiple keys await invalidator.invalidateKeys(["key1", "key2"]); // Nuclear option — clear everything await invalidator.flushAll();

DISTRIBUTED LOCKING

Token-based lock store with retry logic for coordinating concurrent access to shared resources.

import { createLockManager } from "@zudojs/cache"; const locker = createLockManager({ retryAttempts: 3, // Default: 3 retryDelayMs: 100 // Default: 100ms }); // Execute under lock (auto-releases) await locker.withLock("resource:123", async () => { // Only one caller executes at a time const data = await loadResource(); data.version++; await saveResource(data); }, { ttl: 10000 }); // Manual acquire/release const lock = await locker.acquire("resource:123"); if (lock) { try { await doWork(); } finally { await lock.release(); } }

CACHE METRICS

Tracks cache operation metrics including hit/miss rates, latency histograms, and hot key analysis.

import { createCacheMetrics } from "@zudojs/cache"; const metrics = createCacheMetrics(); // Get overall stats const stats = metrics.getStats(); // { hits: 150, misses: 50, sets: 200, deletes: 10, errors: 2, hitRate: 0.75 } // Latency percentiles for a specific operation const latency = metrics.getLatencyStats("get"); // { count: 200, min: 0.1, max: 15.3, mean: 2.1, p50: 1.2, p95: 8.5, p99: 14.2 } // Hot keys (most accessed) const hot = metrics.getHotKeys(5); // [{ key: "user:1", hits: 45 }, { key: "product:42", hits: 38 }, ...] // Latency histogram const hist = metrics.getLatencyHistogram("get"); // [{ bucket: 1, count: 80 }, { bucket: 5, count: 95 }, ...]

Latency Buckets

[1ms, 5ms, 10ms, 25ms, 50ms, 100ms, 250ms, 500ms, 1000ms]

Maximum 1,000 samples per operation (older samples are trimmed).

SERIALIZERS

Two built-in serializers for converting cache values to/from storable formats.

JsonCacheSerializer

JSON serialization with optional type preservation (Date, BigInt, Map, Set, Uint8Array).

new JsonCacheSerializer({ preserveTypes: true })

RawCacheSerializer

Pass-through serializer. Returns values as-is. Use when the adapter handles serialization natively.

new RawCacheSerializer() // serialize(v) → v // deserialize(v) → v

USE CASES

1. HTTP Response Caching

const cache = createCacheService({ adapter }); app.get("/api/products", async (req, res) => { const result = await cache.getOrSet( `products:${req.query.category}`, async () => await db.getProducts(req.query.category), { ttl: 60000, tags: ["products"] } ); res.json(result.value); });

2. Rate Limiting with Locks

async function checkRateLimit(userId: string): Promise<boolean> { return cache.withLock(`ratelimit:${userId}`, async () => { const key = `requests:${userId}`; const result = await cache.get<number>(key); const count = result.value ?? 0; if (count >= 100) return false; await cache.set(key, count + 1, { ttl: 60000 }); return true; }); }

3. Session Management

const sessionCache = createCacheService({ adapter, config: { defaultTtl: 1800000 } // 30 min sessions }); // Store session await sessionCache.set(`session:${token}`, userData, { tags: [`user:${userData.id}`] }); // Invalidate all sessions for a user await sessionCache.invalidateByTag(["user:123"]);

4. Feature Flag Caching

async function isEnabled(flag: string, userId: string): Promise<boolean> { const result = await cache.getOrSet( `flag:${flag}:${userId}`, async () => await featureFlags.evaluate(flag, { userId }), { ttl: 300000, tags: [`flag:${flag}`] } ); return result.value; } // Invalidate when flag changes await cache.invalidateByPattern("flag:new-checkout:*");

5. Database Query Caching

async function getUserWithPosts(id: string) { return cache.getOrSet( `user-with-posts:${id}`, async () => { const user = await db.user.findUnique({ where: { id }, include: { posts: true } }); return user; }, { ttl: 120000, tags: [`user:${id}`, "user-posts"] } ); }

6. Health Monitoring

const health = await cache.healthCheck(); if (!health.healthy) { alerts.send(`Cache unhealthy: ${health.error?.message}`); } // Periodic metrics collection setInterval(() => { const stats = cache.getStats(); if (stats && stats.hitRate < 0.5) { console.warn(`Low cache hit rate: ${(stats.hitRate * 100).toFixed(1)}%`); } }, 60000);

SUGGESTED IMPROVEMENTS

1. Redis Adapter

Ship a built-in RedisCacheAdapter for production distributed caching. Implement the CacheAdapter interface with ioredis or node-redis.

2. Cache Warming

Add a warm() method that pre-populates the cache from a data source on startup, reducing cold-start misses.

3. Stale-While-Revalidate

Support staleTtl option in getOrSet() — return stale value immediately while refreshing in the background.

4. Cache Stampede Protection

Single-flight deduplication — if 10 requests hit the same missing key simultaneously, only one computes the value.

5. Compression Support

Add compress: true option to CacheConfig for large values. Integrate with zlib for automatic gzip compression.

6. Event Bus Integration

Emit cache events through @zudojs/events EventBus for cross-service cache invalidation in distributed systems.

7. Cache Prewarm Scheduler

Integrate with @zudojs/scheduler to automatically refresh expiring entries before they expire.

8. Multi-Layer Cache

Support L1 (memory) + L2 (Redis) cascade — check local memory first, fall back to distributed, write to both.
